# EA-002 — Educational Style Guide

**Programme:** Educational Excellence Programme EA-002  
**Status:** Binding — permanent Educational Style Guide for Version 1 onward  
**Effective:** 2026-08-01  
**Parent:** `EA002_EDUCATIONAL_AUTHORING_FRAMEWORK.md` · `EA002_TUTOR_VOICE_GUIDE.md` · EA-001 philosophies  
**Nature:** Writing and composition standards — not live subject content  

---

## 1. Purpose

Standardise how educational artefacts are written so Missions, Sessions, reading guidance, examples, worked reasoning, Reflection, Revision, terminology, and narrative continuity feel like one professional education house style.

This guide governs **form and craft**. Tutor Voice governs **spoken character**. EA-001 governs **educational law**. All three bind together.

---

## 2. House style principles

1. **One composition per surface** — one educational job, one primary ask.  
2. **Guidance over content** — point into CMP; do not republish it.  
3. **Concrete before abstract** — name the topic and skill before philosophy.  
4. **Assessable language** — verbs a tutor can mark.  
5. **Continuity always audible** — yesterday, today, tomorrow when known.  
6. **Honesty over theatre** — empty states beat placeholders; Study Progress ≠ Mastery.  
7. **Consistency over cleverness** — prefer the standard pattern; do not invent local dialects.

---

## 3. Mission writing

### 3.1 Structure (fixed order)

1. Topic identity (code + title)  
2. Distinct objective (actionable verb; ≠ heading)  
3. Bridge from prior learning  
4. Why now (specific)  
5. Concept focus (one idea/skill)  
6. Success criterion (countable)  
7. Material locus (CMP)  
8. Session intent (real stages)  
9. Expected benefit  
10. Handoff / Tomorrow  
11. Explainability (unique)

### 3.2 Style rules

- Objective ≤ ~160 characters preferred; one verb.  
- Bridge uses real prior title or lawful cold-start purpose.  
- Why-now must not be copy-pastable across Missions.  
- Hero surface: tutor brief only — no platform essays.  
- Optional exam cue only when accurate.

### 3.3 Mission style DO / DON’T

| DO | DON’T |
|----|-------|
| “Explain how a GLM uses a linear predictor and link for a non-normal response.” | “Study 4.2 — Understand and use generalised linear models” as objective |
| “Yesterday you finished classical linear models.” | No bridge |
| “CMP §4.2 through first worked example.” | “The material” |

Full mandatory elements: `EA001_MISSION_PHILOSOPHY.md` M1–M12.

## 4. Session writing

### 4.1 Overview

**One question:** Am I ready to begin?

Include: topic, objective, concept focus, stage structure, why-now (short), duration, Begin CTA.  
Exclude: CMP dump, Home restack, platform essays, multiple competing CTAs, placeholders.

### 4.2 Before / During / After Reading

| Phase | Style requirement |
|-------|-------------------|
| Before | 2–4 focus questions; locus; stop condition; duration honesty |
| During | Alive prompts; annotation task; pacing cues; return instruction |
| After | Closed-book or reduced-cue demand; feedback; reliable advance |

### 4.3 Session prose density

- Prefer scannable blocks over paragraphs of platform reassurance.  
- One instructional imperative per beat.  
- Advertise only stages that exist.

### 4.4 Session style DO / DON’T

| DO | DON’T |
|----|-------|
| Real topic on every stage label | “Today’s topic” |
| “After Example 2, return for recall.” | Empty reading + free-text only |
| “Session complete — Study Progress updated.” | “Topic mastered.” |

## 5. Reading guidance

### 5.1 Standard Guided Reading block

```text
LOCUS:   CMP §… / Example …
HUNT:    What to find or notice
ACTION:  Paraphrase / mark / attempt
STOP:    When to return to Kwalitec
RETURN:  What happens next (recall / practice)
```

### 5.2 Rules

- Selective attention, not “read the chapter.”  
- Never paste CMP prose as the episode body.  
- If locus cannot be resolved → block open; honest recovery — not placeholder.

### 5.3 Premium vs unacceptable

| Premium | Unacceptable |
|---------|--------------|
| Named section + hunt + stop + return | “Read the material for Today’s topic.” |
| “Write one definition in your own words.” | No cognitive demand |

## 6. Examples (student-facing)

### 6.1 Role of examples in Kwalitec

Kwalitec **references and guides** CMP/authorised examples. It may:

- Point to Example N  
- Insert pause points (“try before reveal”)  
- Ask for the middle step  
- Request a justification after the numeric answer  

It must **not** silently replace the publisher worked solution with an unofficial parallel textbook unless a Board-certified alternative material is the authorised CMP for that subject.

### 6.2 Style for example prompts

- Numbered steps when sequencing matters  
- Explicit “attempt before reveal”  
- Skill named (e.g. link justification, not “do the example”)

## 7. Worked reasoning

### 7.1 What “worked reasoning” means here

Short tutor scaffolding that helps the student *think*, not a full CMP proof dump.

Allowed:

- Hint ladders (weak → stronger) after an attempt  
- Error-focused prompts (“Check the support of the response before choosing the link”)  
- One-line rationale after objective checks  

Forbidden:

- Pasting multi-page CMP solutions as episode body  
- Revealing answers before the attempt when “try first” was promised  
- Inventing methods that contradict CMP for the subject  

### 7.2 Style pattern

1. Ask  
2. Attempt  
3. Hint (optional, progressive)  
4. Reveal / check against CMP  
5. One-sentence why

## 8. Reflection writing

### 8.1 Prompt set template

Always substitute real tokens:

1. Clearer: “What is clearer about **{concept_focus}**?”  
2. Uncertain: “What remains uncertain — **{option_a}**, **{option_b}**, or **{option_c}**?” (or free text bound to topic)  
3. Carry: “What will you carry into **{tomorrow_or_revision}**?”  

### 8.2 Rules

- Topic-specific every time  
- Student-authored capture  
- Soft evidence only  
- Required before educational Session close  

---

## 9. Revision writing

### 9.1 Label and trigger first

Every revision artefact leads with:

1. **Revision** label (not first-pass Learning language)  
2. **Why revise** (evidence or disclosed choice)  
3. **Narrow locus** (usually tighter than first-pass)  
4. **Deliberate rework action**  
5. **Success check** that does not claim first-pass mastery  

### 9.2 Style DO / DON’T

| DO | DON’T |
|----|-------|
| “Revise link-function justification — re-attempt Example 3 closed-book.” | Re-paste empty first-pass shell |
| “Trigger: reflection named link as fuzzy; high exam weight.” | “Nothing to revise” against unexplained high coverage |

## 10. Terminology

### 10.1 Canonical meanings (Lexicon-aligned)

| Term | Meaning in educational prose |
|------|------------------------------|
| **Mission** | Authorised primary educational focus for the day / period |
| **Session** | Focused practice workflow executing the Mission |
| **Learning Episode** | Bounded stage inside a Session |
| **CMP** | Authoritative course materials / content authority |
| **Syllabus** | Official structure, outcomes, exam scope |
| **Study Progress** | Lawful completion of study obligations — not mastery |
| **Estimated Mastery / Knowledge** | Twin-owned, evidence-gated estimates |
| **Reflection** | Student-authored metacognitive close |
| **Tomorrow Preview** | Continuity bridge to next lawful focus |
| **Revision** | Deliberate rework of previously studied material |
| **Tutor Voice / Study Sensei** | Calm specific guidance voice |

### 10.2 Terminology rules

- Do not treat Mission and Session as synonyms in educational authoring (product UI may say “Today’s Session” per Product Language Guide — authoring packs still distinguish entities).  
- Do not say “mastered” for Session complete.  
- Do not expose “Twin”, runtime names, or evidence-rank codes on primary study surfaces.  
- Prefer “CMP” or the subject’s official material name consistently within a package.

### 10.3 Banned student-facing strings (non-exhaustive)

`Today’s topic` · `TODO` · `TBD` · `lorem` · unfilled `{tokens}` · `highest-value next step` as sole rationale · `Mission ≠ mastery` essays on hero · milestone IDs · address-like contaminants

## 11. Narrative continuity

### 11.1 The continuous story

Every certified day should read as:

```text
Prior learning → Today’s Mission brief → Session work in CMP →
Recall/Practice → Reflection → Tomorrow Preview → (later) Revision when warranted
```

### 11.2 Continuity checklist for authors

- [ ] Bridge cites real prior work or lawful cold start  
- [ ] Why-now cites syllabus/evidence/exam skill  
- [ ] Episodes inherit Mission objective/focus  
- [ ] Reflection residues can feed tomorrow/revision  
- [ ] Tomorrow agrees with Mission handoff  
- [ ] Revision attaches to prior learning identity  
- [ ] No surface tells a second story about the same facts  

### 11.3 Continuity failures (style-level)

- Identical stamp rationales every day  
- Tomorrow that ignores today’s skill  
- Overview topic ≠ Mission topic  
- Reflection generic enough to fit any chapter

## 12. Formatting conventions (authoring packs)

| Element | Convention |
|---------|------------|
| Topic codes | Exact official codes (e.g. 4.2) |
| CMP loci | `CMP §…` / `Example …` / LO id when used in package |
| Lists | Prefer short numbered steps for procedures |
| Emphasis | Spare; never shout mastery |
| Duration | Integer minutes consistent with depth |
| Stage labels | Match Episode titles exactly |

Authoring packs may use Markdown for review; student rendering follows product templates — **substance** must survive template constraints without placeholder fallback.

## 13. Premium vs unacceptable atlas (quick reference)

| Domain | Premium signal | Unacceptable signal |
|--------|----------------|---------------------|
| Mission | Tutor brief with bridge + success + locus | Syllabus paste triple |
| Episode | Hunt + action + stop + recall | Empty shell |
| Session | Ready-to-begin Overview; reachable stages | Placeholder theatre; stuck continue |
| Reading | Selective CMP guidance | Chapter dump or “read the material” |
| Examples | Try-before-reveal against CMP | Unofficial parallel textbook paste |
| Worked reasoning | Hint after attempt | Full solution dump before attempt |
| Reflection | Topic triad, student-authored | Generic / fabricated |
| Revision | Evidence trigger + narrow rework | Empty shell / dual-truth empty state |
| Terminology | Lexicon-accurate | Mission/Session/Mastery muddle |
| Continuity | Audible arc | Stamp boilerplate / contaminant tomorrow |

## 14. Style QA checklist

Pass only if:

1. Structure matches the artefact class standard above.  
2. Terminology matches §10.  
3. Continuity checklist §11.2 is satisfied.  
4. Voice Guide PASS is plausible from the prose alone.  
5. No banned strings or CMP dumps.  
6. Duration and stage labels are honest.  

Fail → return to Educational Author before Tutor Review.

---

## 15. Closing

Style is how One Tutor scales across many authors.

Follow the patterns. Prefer clarity to novelty. When in doubt, write the brief you would stake your professional reputation on — then cut anything that sounds like a database or a brochure.
