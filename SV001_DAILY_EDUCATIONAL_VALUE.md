# SV-001 — Daily Educational Value (DEV)

**Programme:** Student Value Programme SV-001 — Student Value Validation  
**Construct:** Daily Educational Value (DEV)  
**Status:** Binding — primary student-value judgement construct  
**Effective:** 2026-08-01  
**Authority:** Educational Excellence Framework (Frozen) · Educational Operations (Frozen) · CE-001 PASS · DSH-001 PASS · DX-001 PASS  
**Nature:** Validation law only — **no** educational redesign; **no** Runtime A/C, SCI, Twin, recommendation, or catalogue changes; **no** application code; **no** new educational content; **no** governance amendments  

---

## 1. Purpose

Define **Daily Educational Value (DEV)** as the construct that sits **above** all editorial metrics when judging whether Kwalitec is succeeding for the student.

Editorial systems answer: *Is the catalogue certified, approved, contiguous, and publishable?*

DEV answers a different question:

> Did **today’s study day** leave the student better prepared, more honestly confident, and willing to return tomorrow?

A successful study day is not one that exists in the catalogue.  
It is one that improves the student’s study experience.

## 2. Hierarchy of judgement

### 2.1 Layers (superior → supporting)

| Layer | Owns | Role |
|-------|------|------|
| **Student Value (SV-001)** | **DEV** + Student Success Metrics | **Primary product objective** — quality of each lived study day |
| Product Usefulness (P-001.1) | KSI (K1–K8) | Composite educational usefulness of the companion — complementary, not a substitute for daily value |
| Delivery Experience (DX-001) | Delivery Quality Index | Editorial judgement that authored days *can* feel like a companion — necessary evidence, not student-lived DEV |
| Reliability (DSH-001) | Dependable Study Horizon | How long a student can **depend** on published days — uptime, not day quality |
| Catalogue (CE-001) | Published coverage | Inventory completeness |
| Operations (EO-001 / PR-001) | Volume lifecycle, Approver, backlog | How inventory is sealed and scheduled |
| Excellence (EA-001…EA-008) | Mission / Session / Campaign certification | Authoring quality gates |

### 2.2 One-line law

> **Editorial metrics prove the day is lawful to ship. DEV proves the day was worth studying.**

### 2.3 Separation rule (hard)

| Metric family | May decide product success? | May substitute for DEV? |
|---------------|----------------------------:|------------------------:|
| DEV / Student Success Metrics | **Yes — primary** | — |
| KSI | Supports Version 1 usefulness claims | **No** |
| DSH / CIH | Reliability / planning | **No** |
| CE Coverage % | Inventory | **No** |
| Publication status / Gate CG / MG / Session gates | Shipping eligibility | **No** |
| Editorial Operations cadence | Capacity | **No** |
| DX Delivery Quality Index | Pre-ship delivery judgement | **No** — may *inform* Founder expectation, never replace lived DEV |

**Forbidden claim:** “Coverage rose / DSH extended / Volume approved ⇒ student value improved.”  
**Allowed claim:** “Coverage / DSH / Approval enable more days that *can* be measured for DEV.”

## 3. Definition — Daily Educational Value

### 3.1 Formal definition

**Daily Educational Value (DEV)** is the judged educational worth of **one completed study day** from the student’s perspective, across seven mandatory dimensions (D1–D7).

DEV is assessed **after** the sitting (or at end-of-day for Founder Validation), using:

- the student’s answers to the seven value questions, and  
- observable study behaviours where available (CMP open/stop discipline, completion without thrashing, next-day return).

### 3.2 Unit of judgement

| Unit | Symbol | Role |
|------|--------|------|
| **Study day** | day | **Primary** — one Learning or Revision sitting as lived |
| **DEV day score** | 0–10 | Mean of D1–D7 for that day |
| **DEV run score** | 0–10 | Mean of DEV day scores across a Founder / beta run |
| **Return-worthy day** | binary | Day meets return threshold (see §5) |

Revision days are first-class: a light retrieval day with high D1–D7 can outrank a heavy Learning day that creates false confidence or fatigue.

### 3.3 What DEV is not

| Not | Why |
|-----|-----|
| Catalogue existence | Files ≠ lived value |
| Certification / Publication Approval | Lawful ≠ valuable |
| DSH length | Dependable ≠ good |
| Time-on-task / clicks | Activity vanity |
| Mastery % / readiness theatre | Constitution-aligned honesty forbids |
| DX score alone | Editorial preview ≠ student experience under fatigue and real CMP |
| Exam pass probability | Vision north star — measured later; DEV supports the daily loop that makes it possible |

## 4. The seven value dimensions

Every Mission / study day is evaluated with the same seven questions. Each dimension scores **0–10**.

| ID | Dimension | Student question | What “10” looks like | What “0” looks like |
|----|-----------|------------------|----------------------|---------------------|
| **D1** | **Direction clarity** | Did I know exactly what to do? | Opened Kwalitec and started without hunting, inventing a plan, or second-guessing the brief | Stared at Home / Mission / Session unsure where to begin |
| **D2** | **Decision-load relief** | Did Kwalitec reduce decision fatigue? | Fewer open questions about *what* and *why tonight* than studying solo with CMP alone | Added choices, dual homes, competing clocks, or opaque “next best” without reason |
| **D3** | **CMP craft** | Did today’s Mission improve how I use the CMP? | Clearer open / stop / out-of-scope habit; CMP felt more usable after the day | CMP dump, aimless reading, or guidance that made the book harder |
| **D4** | **Stopping integrity** | Did I stop at the correct point? | Knew when enough was enough; wrap-up matched the day’s claim; no invented extra chapters | Overran into tomorrow’s LO, or stopped mid-fog with no honest stop condition |
| **D5** | **Achievability** | Did today’s work feel achievable? | Load matched energy and budget; finished without heroic overtime or guilt collapse | Felt impossible, padded, or so trivial it wasted the evening |
| **D6** | **Return willingness** | Would I willingly return tomorrow? | Natural “see you tomorrow” — not obligation theatre | Relief that it’s over; dread or indifference about continuing |
| **D7** | **Honest confidence** | Did confidence rise **without** false confidence? | Clearer about what I can do *and* what I still cannot claim | Felt “ready” from progress chrome, or left more anxious with no skill gain |

### 4.1 Dimension notes

**D1 Direction clarity** protects Mission Philosophy (EA-001): a tutor brief the student can act on tonight.

**D2 Decision-load relief** is the anti-fatigue test. Kwalitec wins when it *removes* evening planning work — not when it adds dashboards to interpret.

**D3 CMP craft** is Guidance-Over-Content in student language. Improving CMP usage means better craft (selectivity, retrieval, stop), not more pages “covered.”

**D4 Stopping integrity** is trust in miniature. Wrong stops create either sprawl (false progress) or abandonment (decision returns to the student).

**D5 Achievability** is sustainable professional-exam life. Heroic days destroy D6.

**D6 Return willingness** is the product’s daily north dial for SV-001. Catalogue length cannot buy tomorrow’s return.

**D7 Honest confidence** is Constitution-aligned. Rising confidence that misreads Study Progress as exam readiness is a **fail**, even if the student feels good.

## 5. Scoring method

### 5.1 Day score

\[
\mathrm{DEV}_{\text{day}} = \frac{1}{7}\sum_{i=1}^{7} D_i
\]

Report mean to one decimal. Optionally report **min(D1…D7)** as a trust floor (a day with mean 8.0 but D7 = 2 is not a success).

### 5.2 Return-worthy threshold

A day is **return-worthy** only if **all** hold:

| Rule | Requirement |
|------|-------------|
| R1 | \(\mathrm{DEV}_{\text{day}} \geq 7.0\) |
| R2 | \(D6 \geq 7\) (willing return) |
| R3 | \(D7 \geq 6\) (no severe false-confidence / confidence-collapse fail) |
| R4 | No hard fail flag (see §5.3) |

### 5.3 Hard fail flags (any one ⇒ day not return-worthy; score still recorded)

| Flag | Trigger |
|------|---------|
| HF-01 | Student did not know what to do within ~5 minutes of opening the product (D1 collapse) |
| HF-02 | Product increased decision load vs solo CMP study (D2 ≤ 3) |
| HF-03 | Guidance caused CMP sprawl or dump without stop (D3/D4 collapse) |
| HF-04 | Stop condition absent or contradicted by wrap-up claims |
| HF-05 | False-confidence signal (readiness / % / journey chrome misread as exam readiness) without corrective honesty |
| HF-06 | Student would not return tomorrow for a reason attributable to today’s product experience (D6 ≤ 3) |

### 5.4 Run score

For a Founder Validation or Private Beta window of \(n\) study days:

\[
\mathrm{DEV}_{\text{run}} = \frac{1}{n}\sum_{d=1}^{n} \mathrm{DEV}_{\text{day},d}
\]

Also publish:

| Metric | Definition |
|--------|------------|
| **Return-worthy rate** | Share of days meeting §5.2 |
| **Trust floor** | Mean of per-day \(\min(D_i)\) |
| **False-confidence incidents** | Count of HF-05 |
| **Decision-fatigue incidents** | Count of HF-02 |

## 6. Evidence classes

| Class | Source | Weight in judgement |
|-------|--------|---------------------|
| **E-Lived** | Founder / beta student end-of-day answers to D1–D7 | **Primary** |
| **E-Behaviour** | Observed open → start latency; CMP open/stop; completion without thrashing; next-day return | Corroborating |
| **E-Editorial** | DX Delivery Quality, Gate CG, Mission uniqueness | Context only — may raise expectation, never inflate lived score |
| **E-Reliability** | DSH / CE / Publication status | Preconditions for *which* days can be lived at scale — not DEV |

**Honesty rule:** Pre-ship DX scores may be cited as “authored delivery expectation.” They must be labelled **editorial** and kept out of the DEV numerator.

## 7. Preconditions vs value

| State | What it means for DEV |
|-------|------------------------|
| DSH = 0 / not released | Student-lived DEV on the opening path is **blocked** for ordinary students; Founder may still score inventory days in Validation mode |
| Volume `approved` + `released` | Days become eligible for student-lived DEV measurement |
| High CE coverage, low DEV | Catalogue grows while product fails students — **SV fail** |
| High DEV on short DSH | Excellent days that run out — reliability residual, not value proof for exam horizon |
| High DX, low lived DEV | Authoring / delivery preview failed the fatigue test — investigate Runtime surface, not only packages |

DEV does not replace DSH. DSH does not replace DEV.  
**Product success requires both:** days worth studying, for long enough to matter.

## 8. Relationship to KSI

KSI (P-001.1) remains the **composite educational usefulness index** for Version 1 product claims.

| Construct | Grain | Question |
|-----------|-------|----------|
| **DEV** | One study day | Was *today* educationally valuable? |
| **KSI** | Whole companion | Is Kwalitec useful enough overall? |

DEV evidence feeds especially:

| DEV dimension | Primary KSI affinity |
|---------------|----------------------|
| D1, D2 | K1 Planning · K2 Recommendation |
| D3, D4 | K7 Revision support · learning craft |
| D5, D6 | K5 Motivation |
| D7 | K8 Explainability · honesty / Constitution |
| Cross-day return | Continuity of usefulness (supports G1 validation later) |

SV-001 does **not** amend KSI weights or baselines. It supplies the **daily** validation layer that editorial metrics lack.

## 9. Founder Validation vs Private Beta

| Mode | Who | DEV use |
|------|-----|---------|
| **Founder Validation** | Founder (or designated validator) walks released or Validation-mode days | Full D1–D7 scorecard per day; qualitative journal; hard-fail flags |
| **Private Beta** | Invited serious candidates | Same D1–D7 instrument + objective success metrics (see `SV001_STUDENT_SUCCESS_METRICS.md`) |

Founder Validation **may not** claim Private Beta proof.  
Private Beta **may not** claim exam-pass proof.  
Neither may claim student value from DSH/CE alone.

## 10. Student speech (plain language)

> **Daily Educational Value** is whether today’s study with Kwalitec was worth it: clear what to do, less decision fatigue, better use of your CMP, an honest stop, a doable load, willingness to come back tomorrow, and confidence that isn’t fake.

Forbidden: equating “we published more days” with “your study days got better.”

---

## 11. Consumption rules for future programmes

1. Programmes that change student-facing study days must state expected **DEV dimension** impact (D1–D7), not only DSH/CE/KSI.  
2. Editorial programmes (coverage, Approver, Volume ops) report **enablement**, not DEV gains, unless lived evidence exists.  
3. Commercial claims of “improves study” require DEV / Student Success evidence — not publication theatre.  
4. No redesign of EA / EO / Runtime / SCI / Twin / recommendations / catalogue under SV-001 authority.

---

## 12. Authority and freeze

- Educational Excellence (EA-001…EA-008) remains **frozen** — SV-001 consumes Mission/Session/Campaign quality; does not amend it.  
- Educational Operations (EO-001) remains **frozen** — SV-001 consumes Publication status; does not amend it.  
- CE-001 / DSH-001 remain binding **internal** reliability/coverage metrics.  
- DX-001 remains binding **editorial** delivery judgement.  
- SV-001 owns the **student-value validation** layer above them.
