## 1. Purpose

## 2. Journey map

```text
[Screened candidate]
        │
        ▼

        │
        ├─ Decline / no reply ──► Ops chase → Reminder → Closed interest (not Withdrawn)
        │
        ▼
 “I accept” (+ C1/C2 as required)
        │
        ▼
 Acceptance email → Account credentials / login
        │
        ▼
 First login (change temp password)
        │
        ▼

        │
        ▼
 In-product onboarding / calibration (existing product)
        │
        ▼
 Home → Today’s Session → ≥1 productive Session  (= Activated)
        │
        ├─ Blocked ──► Support (P1 same day)
        ├─ Confused ──► Support (P2) — product-as-is guidance
        ├─ Bug ──► Bug report path

        │
        ▼

        │
        ▼

        │

        └─ Complete interview
        │
        ▼
```

## 3. Stage-by-stage (participant lens)

| Stage | Participant sees / does | Ops behind the scenes |
|-------|-------------------------|------------------------|
| **Invitation** | Closed pilot invite; login details; privacy/consent asks; support promise | G-INVITE; account provisioned; Invited++ |
| **Acceptance** | Replies accept; receives “You’re in” | Accepted++; ITT-Accepted candidate |
| **Consent** | Yes/No to C1–C4; knows interview/quote optional | Consent log; no KPI without C1+C2 |
| **Account / first login** | Signs in; may change password | First-login note; P1 if blocked |
| **Orientation** | Checklist: Home, Session, Reflection, support | Welcome send; day 1–2 soft check |
| **First mission** | Completes a real study Session | Activated++; never-activated chase at day 7 |
| **Ongoing study** | Ordinary personal cadence ≥4 weeks preferred | Week buckets; light check-ins optional |
| **Support / bugs** | Reply to support; honest feedback welcome | Severity SLAs; no engine redesign from ops |
| **Withdrawal** | Can leave measurement and/or account without blame | Withdrawn++; acknowledgement |
| **Interview** | Optional structured conversation ~week 4 | C3 required; decline ≠ access loss |
| **Completion** | Thank-you; no pass-rate claim | Completed++; hand-off to study authority |

---

## 4. What the participant is told (non-negotiable)

- Invite-only Early Access — **not** a public launch.  
- Study companion for exam preparation — **not** a pass guarantee.  
- Bugs may occur; honest feedback preferred.  
- Educational packages are **frozen** for this wave.  
- Measurement consent required only for aggregate study metrics inclusion.  
- Interview and quote consent are optional.  
- Support: security/privacy immediate; cannot-study same business day.

---

## 5. What the participant never experiences under OP discipline

- Public registration / ads funnel.  
- Promises of Version 1 production-ready or marketing pass rates.  
- Pressure to stay “for the metrics.”  
- Loss of access because they declined an interview.  
- Ops-driven changes to Recommendation Engine, Student Twin, Runtime, or packages mid-wave.

---

## 6. Emotional / trust checkpoints (ops awareness)

| Moment | Trust risk | Ops response |
|--------|------------|--------------|
| Invite claims too strong | Expectation mismatch (R-08) | Claim-discipline templates only |
| Login fails | “Product is broken / I’m locked out” | P1 same day; no blame |
| First Session confusing | “I don’t know what to do” | Orientation + Home/Session guidance; log P2 |
| Bug during study | Frustration | Acknowledge Early Access; triage honestly |
| Asks “will this make me pass?” | Over-trust | Explicit no-guarantee; point to study companion purpose |
| Wants data deleted | Privacy anxiety | Privacy Review workflow; verify identity; SLA |
| Misses days | Guilt / silence | No shame chase; optional light check-in; inactivity ≠ withdrawal |
