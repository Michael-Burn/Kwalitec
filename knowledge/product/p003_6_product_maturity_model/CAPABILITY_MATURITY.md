## 1. Purpose

Define every major capability assessed under the Product Maturity Model: what the capability **is**, what organisational purpose it serves, and what evidence class can raise it.

Levels are assigned only in [`MATURITY_ASSESSMENT.md`](MATURITY_ASSESSMENT.md).

## 2. Capability catalogue

### Architecture

| Field | Definition |
|---|---|
| **Purpose** | One lawful Education OS structure: layering, Runtime A authority, constitutions, ADRs, no second educational brain under production defaults. |
| **Organisational question** | Can the organisation design, constrain, and verify structural law without parallel educational architectures? |
| **Raises with** | Authoritative baseline; Architecture Constitution; ADR currency; architecture tests green; G2 declaration board when filed. |
| **Does not raise with** | Feature volume; Twin substrate alone; tracker COMPLETE without constitutional claim-window memo. |

### Runtime A

| Field | Definition |
|---|---|

## 3. Capability groups (board navigation)

| Group | Capabilities | Typical investment mode |
|---|---|---|
| **Educational runtime** | Runtime A, Recommendation, Planning, Readiness, Explainability, Journey | Evidence + thin-floor remediation |

## 4. Assessment fields (required per capability)

Every capability in [`MATURITY_ASSESSMENT.md`](MATURITY_ASSESSMENT.md) records:

| Field | Meaning |
|---|---|
| **Current Level** | 1–5 per Product Maturity Model scale |
| **Evidence** | Cited paths / statuses only |
| **Confidence** | High / Medium / Low on the level assignment |
| **Outstanding Work** | Evidence or ops still required to raise (or keep honest) |
| **Next Review Trigger** | Event that forces re-assessment |
