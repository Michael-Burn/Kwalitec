# Feedback Model — Adaptive Assessment

**Programme:** ILE-001 — Adaptive Assessment Experience  
**Version:** 1.0  
**Status:** Design  
**Effective:** 2026-07-28  

---

## Purpose

Define what the learner sees **before**, **during**, **immediately after**, and **long after** an Adaptive Assessment session — including Tutor involvement and Mission updates.

Feedback is educational speech: evidence, meaning (already decided), and next action. It is not a marks report.

---

## Feedback principles

1. **Evidence over identity** — never “you are a 42% student.”  
2. **What / why / next / uncertain** — always addressable.  
3. **Immediate ≠ final mastery** — short feedback now; Twin belief updates through Reasoning.  
4. **Progressive disclosure** — brief by default; depth on request (Tutor / Explain).  
5. **One next action** — do not flood with tips that compete with Mission.

---

## Before (entry frame)

Student must see:

| Element | Purpose |
|---|---|
| **Session type name** | Sets expectations (Quick Check, etc.) |
| **Why now** | Intent in one plain sentence |
| **Effort estimate** | Minutes or item-band |
| **What answers are for** | “Helps keep your study plan accurate” (not grading) |
| **Controls** | Start; optional defer/decline if Mission allows; how to pause later |

Optional: syllabus location (“On: {topic}”).

**Must not show:** countdown punishment, peer percentiles, pass criteria, fake mastery bars.

---

## During

| Element | Purpose |
|---|---|
| **Progress** | Calm “3 of 5” — not a score bar |
| **Stem + response** | One job per screen |
| **Optional confidence** | When session type warrants |
| **Hint** | Available without shame; recorded as evidence |
| **Micro-feedback (optional)** | Brief correctness clarity when pedagogically useful — still non-theatrical |
| **Pause / exit** | Always reachable |

Tone: steady coach. “Take your time.” No public ranking chrome.

If item-level feedback is shown mid-session, it must not invent Twin mastery language.

---

## Immediately after (session summary)

Default closure pattern:

```
You completed a {session type} on {objective / focus}.
Here’s what this check showed about your understanding.
What’s still uncertain: {honest gap or “enough for now”}.
Next: {single Mission / Tutor-surfaced next action}.
```

| Include | Exclude |
|---|---|
| Evidence themes (solid / shaky / needs rebuild) | Percentage-as-identity |
| Specific misconception gentle name when known | Leaderboard / cohort comparison |
| How uncertainty can shrink | Exam pass prediction |
| Link: Explain this result (Tutor) | Alternate shadow recommendation contradicting Home |
| Save & done / return to Mission | Forced immediate retry loop |

**Incomplete session variant:** acknowledge pause; state that evidence may be partial; do not fabricate confidence.

---

## Long after (continuity)

Adaptive Assessment value compounds when outcomes remain findable without dashboard sprawl.

| Surface | What student sees |
|---|---|
| **Same-day Mission** | Adjusted steps if Twin refresh warrants; still one primary Next |
| **Next day Home** | Continuity: today’s session reflects yesterday’s evidence honestly |
| **Insights / readiness (existing surfaces)** | Drivers updated with honest confidence — no assessment-only parallel truth |
| **Learning Timeline (ILE-004 later)** | Check appears as a journey event with purpose + outcome summary |
| **Decision Journal (where present)** | Accepted assessment-related recommendations remain auditable |

Long-after feedback must not silently rewrite history or hide that a check informed the plan.

---

## Tutor involvement

| Moment | Tutor role |
|---|---|
| **During** | Generally quiet unless student requests help; no auto-grading chat |
| **Immediately after** | Optional “Explain this result” — narrates evidence + decided next action |
| **Later** | Can recall recent check meaning using Twin / feedback summaries — never re-scores |

Tutor must / must never: align with `AP-002/TUTOR_INTEGRATION.md` (explain, encourage, interpret, point next — never grade or invent authority).

---

## Mission updates

| Timing | Behaviour |
|---|---|
| **During check** | Mission remains the container; assessment is a step, not a hijack |
| **On complete** | Observations flow through platform path; Mission may refresh remaining steps or defer changes to next generation |
| **On incomplete** | Preserve progress; do not mark educational success from abandonment |
| **Density** | Completing a check may suppress further checks the same day per policy |

Student copy examples:

- Prefer: “We’ll use this to guide practice.”  
- Avoid: “Mission failed because you scored below 70%.”

---

## Feedback by session type (emphasis)

| Type | Immediate feedback emphasis |
|---|---|
| Quick Check | Brief evidence + continue Mission |
| Deep Check | Confirmation vs remaining uncertainty; careful next step |
| Recovery Check | Welcome / dignity; re-orientation next |
| Confidence Check | Calibration narrative + how to reduce uncertainty |
| Revision Check | Hold / reinforce / recover |
| Readiness Check | Prioritised focus + explicit non-guarantee |

---

## Accessibility and tone

- Correct/incorrect states clear without colour-only encoding  
- Language plain; no Twin/pipeline jargon  
- Encouraging without false mastery claims  
- Errors/outages: direct, human, trust-preserving  

---

## Success criterion

After feedback, the student can answer:

1. What did this check look at?  
2. What is clearer now?  
3. What is still unsure?  
4. What do I do next?

If they only remember a score emotion, feedback failed.
