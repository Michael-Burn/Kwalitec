# Founder Governance Model

**Programme:** GP-001 — Founder Governance Model  
**Version:** 1.0  
**Status:** Active — permanent operating model  
**Effective:** 2026-07-26  
**Authority:** Product governance procedure under `knowledge/GOVERNANCE.md`  
**Does not:** Amend Vision 2030, Evidence Hierarchy, Claim Standard, P-002.1 gate evidence, Educational Constitution, EVF criteria, or Runtime A  

---

## 1. Purpose

Define how Kwalitec is **actually governed today**: by a single founder exercising multiple named **capacities**, while preserving the same evidence, accountability, and release standards previously written for a multi-role organisation.

---



## 2. Operating model


| Statement                                                                 | Status                                       |
| ------------------------------------------------------------------------- | -------------------------------------------- |
| Kwalitec is founder-operated                                              | **True**                                     |
| Distinct Product / Engineering / Operations / Privacy / Board staff exist | **False** (current state)                    |
| Product Board remains the release recommendation authority                | **True** (capacity held by Founder as Chair) |
| Evidence requirements are reduced because the org is small                | **False — forbidden**                        |
| Independent separation of duties is permanently abandoned                 | **False** — deferred until scale             |


**Control statement:**

> Small organisation does not mean weak governance. It means one accountable person must still complete every required review and file every required evidence artefact — under the correct capacity label.

## 5. Product Board under founder operation



### 5.1 Authority preserved

> **Only the Product Board may recommend GO or NO GO** on Version 1 production-ready declaration.

That sentence remains binding. Under this model, the Founder **is** the Board for quorum purposes when acting as Chair and completing capacity reviews required by the Charter and P-002.1 — **provided** each required capacity review is recorded.

### 5.2 Quorum adaptation (founder-operated)


| Meeting type                       | Founder-operated quorum                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Monthly / milestone / evidence     | Founder acting as Chair **and** completing Product Owner + Evidence Lead capacity checks                                 |
| Release review                     | Founder acting as Chair **and** filing Founder Reviews for every capacity in the Approval Matrix for that decision class |
| Stage 1 enrollment reconsideration | Founder as Chair + Critical evidence filed (CE-01…CE-05) — no invented GO                                                |


**Not waived:** hard-gate FAIL → NO-GO; Evidence Hierarchy; claim freezes; dry-run / kill-switch / privacy evidence.

### 5.3 Independent second assessor (not waived by founder model)

Where gate law requires an **independent** second person (notably **G1.7** independent KSI re-score), founder capacity concentration **does not** satisfy that requirement. Options:

1. Engage an external or second natural person as assessor, **or**
2. Keep G1.7 **HOLD** / FAIL until independence is available, **or**
3. Use the documented Product-owner dispute-resolution path **only** where P-002.1 explicitly allows it after divergence — not as a substitute for never running a second score.

## 6. Founder Review record (standard form)

Material approvals use this form (replace fictional multi-person signature blocks):


| Field              | Required                                                      |
| ------------------ | ------------------------------------------------------------- |
| **Founder Review** | Short title / gate ID (e.g. OR-01 Privacy — Product capacity) |
| **Reviewer**       | Founder name (real person; never fabricated)                  |
| **Date**           | ISO date of review                                            |
| **Decision**       | Approve / Reject / Confirm / HOLD / DEFER (as applicable)     |
| **Notes**          | Capacity exercised; evidence paths checked; residuals         |


Where prior law required **two** signatories (e.g. Product + Security/ops), require **two Founder Review rows** — one per capacity — not a silent merge into a single unchecked tick.

## 7. Deferred independent governance


| Trigger to introduce separation of duties     | Example                                                                                                                    |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Second operator / engineer hired              | Split Operations Owner or Engineering Owner                                                                                |
| External privacy counsel / DPO retained       | Privacy Owner may remain Founder with counsel advisory; counsel does not invent Stage 1 mandatory DPO unless scope expands |
| Board expands beyond founder                  | Chair may remain Founder; other Representatives become distinct people                                                     |
| Public launch / multi-jurisdiction processing | Revisit Privacy Owner independence and G10 package                                                                         |


Until then: **document concentration honestly** (PR-027) rather than inventing multi-person theatre.
