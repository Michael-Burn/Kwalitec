## Purpose

This folder defines **the permanent constitutional lifecycle coordinating constitutional execution** from initiation through context loading, rule and constraint evaluation, outcome assembly and publication, and honest closure.

It answers *how constitutional execution is organised from initiation through execution completion*, *what the lifecycle must optimise*, *which recognised stages organise execution*, *what the lifecycle may and must never do*, and *how lifecycle progress is constitutionally explained* — without implementing Runtime A, creating constitutional authority, interpreting constitutional law independently, producing constitutional decisions, amending constitutional specifications, determining compliance, certifying implementations, or elevating lifecycle machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, or application services.

> **The Constitutional Execution Engine Lifecycle coordinates constitutional execution.  
> It consumes completed execution contexts and produces execution outcomes without creating constitutional authority or constitutional decisions.  
> It never becomes constitutional authority.**

## Architectural requirement

The Execution Engine Lifecycle coordinates **constitutional execution**.

| Lawful | Unlawful |
|--------|----------|
| Coordinate constitutional execution through recognised stages | Interpret constitutional law independently |
| Consume completed execution contexts | Create constitutional authority |
| Evaluate constitutional rules | Produce constitutional decisions (governance dispositions) |
| Evaluate constitutional constraints | Determine compliance |
| Produce execution outcomes | Certify implementations |
| Preserve execution state | Amend constitutional law |
| Preserve determinism, repeatability, consistency, explainability, fidelity | Redefine constitutional meaning |
| Explain context / rules / constraints / outcomes / boundaries | Replace constitutional authority |

**The Execution Engine Lifecycle coordinates constitutional execution.  
It executes constitutional rules without creating constitutional authority or constitutional decisions.**

1. Confirm a completed resolved execution context exists under WS1 / MS001–MS003 — refuse lifecycle theatre against incomplete preparation.
2. Confirm the published Constitutional Execution Engine Model (WS2 / MS001) is in force — refuse lifecycle theatre that invents engine components outside CEE-01…CEE-07.
3. Read `CONSTITUTIONAL_EXECUTION_ENGINE_LIFECYCLE_MODEL.md` for stack position and integrity rules.
4. Optimise under `LIFECYCLE_OBJECTIVES.md`.
5. Sequence under `LIFECYCLE_STAGES.md` (CEEL-01…CEEL-07 only).
6. Enforce hard stops under `LIFECYCLE_BOUNDARIES.md`.
7. Require explainability contracts from `LIFECYCLE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing lifecycle narration.
8. Do not implement lifecycle machinery that contradicts this corpus without amending it first — and do not treat lifecycle outcomes as compliance, certification, constitutional decisions, or constitutional amendment.
