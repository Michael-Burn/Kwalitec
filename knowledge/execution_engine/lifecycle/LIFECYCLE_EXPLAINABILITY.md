## 1. Purpose

An expert IFoA tutor who cannot say *which completed execution context* was consumed — which constitutional rules were evaluated, which constraints were evaluated, which execution outcomes were produced, and which limits remained intact — is not coaching; they are performing.

After Programmes VI–IX have made meaning, ownership, tips, context, contracts, evidence, runtime, conformance, verification, compliance, certification, and evolution speech speakable, after Workstream 1 has made preparation speech speakable, and after WS2 / MS001 has made engine-component speech speakable, Programme X still needs one lifecycle-speech answer:

> **“Which execution context was consumed, which constitutional rules were evaluated, which constraints were evaluated, which execution outcomes were produced, and which constitutional boundaries remained intact?”**

That answer must cover every material execution lifecycle without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, inventing completed context, interpreting independently, producing constitutional decisions, determining compliance, certifying implementations, freezing a stack as law, inventing unpublished CEE or CEEL types, replacing WS1 preparation, or presenting closure as educational quality.

## 2. What Lifecycle Explainability Is

**Constitutional Execution Engine Lifecycle Explainability** is the constitutional obligation to narrate **coordination of named constitutional execution activities through published CEEL stages** — consuming a completed execution context, evaluating published rules and constraints under published CEE components, and producing execution outcomes — not to invent a second tutor voice from CI machinery, not to grade the student, and not to replace constitutional authority.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Execution context consumed** | Named completed resolved execution context (WS1 / MS003) used as input | Which execution context was consumed? |
| **Constitutional rules evaluated** | Named published rule identities evaluated at CEEL-03 under CEE-01 / CEE-02 | Which constitutional rules were evaluated? |
| **Constraints evaluated** | Named hard constraint identities evaluated at CEEL-04 under CEE-03 | Which constraints were evaluated? |
| **Execution outcomes produced** | Named reconstructable outcomes from CEEL-05 / CEEL-06 | Which execution outcomes were produced? |
| **Boundaries remaining intact** | Explicit confirmation that forbidden interpretation / governance authorship / redefinition / mutation / substitution did not occur | Which constitutional boundaries remained intact? |

Lifecycle Explainability is:

- **coordination-centred** — it narrates completed context → rules → constraints → outcomes under law;
- **catalogue-bound** — every justification cites published CEEL and CEE identities;
- **corpus-bound** — every justification cites published rules and specifications;
- **context-honest** — every material justification cites identifiable completed context consumed (or names the hard stop when none exist);
- **rule-honest** — every material justification cites which published rules were evaluated (or names the hard stop);
- **constraint-honest** — every material justification cites which constraints were evaluated (or names the hard stop);
- **outcome-honest** — every material lifecycle cites which execution outcomes were produced;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-interpretive** — explanation never presents soft amendment as “evaluation”;
- **non-authoritative** — closure is never narrated as a freeze of stack authority or a substitute for published corpora;
- **non-governance** — outcomes are never narrated as compliance, certification, or other constitutional decisions;
- **quality-honest** — closure is never narrated as mastery, readiness, or educational quality;
- **mutation-honest** — explanation never hides artefact changes performed “so execution could proceed”;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, WS1 preparation speech, WS2 / MS001 engine speech, or Programme IX governance speech;
- **audit-aligned** — explanation components match CEELO-04 / CEELO-05 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions or private stage shortcuts.

Lifecycle Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–IX / WS1 / WS2 MS001 meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for CC findings, CT lineage speech, CV verification speech, CCM compliance-determination speech, CRT certification-recognition speech, or CEE engine-component speech;
- a CI status page, coverage report, or linter summary presented as constitutional coordination;
- a freeze of implementations, stacks, vendors, or releases as constitutional law;
- a licence to narrate invented completed context, independent interpretation, or constitutional decisions as if they were lawful inputs or outcomes.

## 3. Mandatory Explainability Questions

Every material constitutional execution engine lifecycle must be able to answer:

### CEELEQ-01 — Which execution context was consumed?

**Required content**

- Named completed resolved execution context identity (WS1 / MS003 fulfilment, with supporting resolution / context references as applicable)
- Binding between completed-context identity and the initiated CEEL-01 concern
- Confirmation that unpublished customs, invented contexts, or incomplete preparation were not used as completed context

**Defect if**

- “The system executed” with no completed-context reference
- Anonymous “the build” or “the pipeline” without identifiable completed context
- Completed context invented, rewritten, or re-completed as execution without disclosure and hard stop

---

### CEELEQ-02 — Which constitutional rules were evaluated?

**Required content**

- Named published constitutional rule identities evaluated at CEEL-03
- Binding to CEE-01 / CEE-02 component application where material
- Explicit note of rules excluded as out of scope under the completed context
- Confirmation that unpublished customs were not evaluated as rules

**Defect if**

- “Rules ran” with no rule identities
- Soft-selected convenient rules with silent omission of inconvenient published ones
- Soft-amended or independently interpreted “rules” narrated as published evaluation

---

### CEELEQ-03 — Which constraints were evaluated?

**Required content**

- Named hard constraint identities evaluated at CEEL-04
- Binding to CEE-03 component application where material
- Dispositions (satisfied / violated / inapplicable) under published meaning
- Confirmation that constraints were not waived by coordination prose

**Defect if**

- “Constraints were fine” with no constraint identities
- Hidden violations so publication looks clean
- Invented soft limits that rewrite published hard constraints

---

### CEELEQ-04 — Which execution outcomes were produced?

**Required content**

- Named reconstructable execution outcomes from CEEL-05 / CEEL-06
- Binding to completed-context identity, rule identities, constraint identities, and producing CEEL stages
- Explicit distinction: these are *execution outcomes*, not compliance seals, certifications, or constitutional decisions
- Exception / refuse dispositions where material

**Defect if**

- “Execution succeeded” with no outcome identities
- Outcomes narrated as compliance, certification, or constitutional decisions
- Silent disappearance of refuse / stop / escalate dispositions

---

### CEELEQ-05 — Which constitutional boundaries remained intact?

**Required content**

- Explicit confirmation that the lifecycle did not redefine constitutional meaning
- Explicit confirmation that the lifecycle did not determine compliance or certify implementations
- Explicit confirmation that the lifecycle did not amend constitutional law or replace constitutional authority
- Explicit confirmation that the lifecycle did not interpret constitutional law independently or produce constitutional decisions
- Explicit confirmation that implementation artefacts were not mutated under coordination pretext
- Explicit confirmation that implementation neutrality was preserved (no stack freeze)

**Defect if**

- Closure narrated as new law, EIP replacement, or authority freeze
- Boundary silence when stages completed under demo urgency
- “Trust us, boundaries held” without speakable confirmation
