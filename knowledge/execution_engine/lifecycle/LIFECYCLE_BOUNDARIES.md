## 1. Purpose

A lifecycle that silently becomes a second constitution — rewriting specs so stages “complete,” inventing educational meaning in “outcomes,” licensing runtime behaviour under a closed seal, inventing completed context to force CEEL-03, interpreting constitutional law independently, producing constitutional decisions under an execution badge, treating a preferred implementation as the new standard, mutating artefacts mid-lifecycle, or freezing a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional execution engine lifecycle coordination** (Programme X / WS2 / MS002) and **constitutional authorship / educational judgement / runtime authorship / context preparation / engine-component authorship / governance authorship / artefact mutation / authority substitution** (Constitution / EIP / Programmes VI–IX / WS1 / WS2 MS001 / permitted writers).

## 2. Boundary Principles

1. **Coordinate, do not legislate.** The lifecycle organises constitutional execution; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as law” are hard stops as standards.
3. **Published stages only.** Unpublished CEEL customs are unlawful.
4. **Published engine components only.** CEEL-03…CEEL-06 invoke CEE-01…CEE-07 only.
5. **Completed context only.** Lifecycles without identifiable completed execution context are theatre.
6. **Exactly as published.** Successful progress never rewrites specification meaning.
7. **No independent interpretation.** Applying published rules is not inventing new constitutional meaning.
8. **Authority first.** Published corpora remain the sole constitutional standard.
9. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to closure.
10. **Closed ≠ quality.** Lifecycle closure never grades learning, mastery, readiness, or product success.
11. **Closed ≠ compliant.** The lifecycle never determines compliance or replaces Programme IX / WS3.
12. **Closed ≠ certified.** The lifecycle never certifies implementations or replaces Programme IX / WS4.
13. **Closed ≠ constitutional decision.** Execution outcomes never become governance dispositions.
14. **No redefinition.** Programme VI questions, EIP claim classes, WS1 preparation meaning, CEE component meaning, and Programme IX judgement meanings survive coordination intact.
15. **No authority substitution.** A closed lifecycle never replaces the corpus for the next judgement.
16. **No artefact mutation.** Coordination never rewrites implementation artefacts to manufacture passable execution.
17. **No bypass.** Product urgency never waives constitutional lifecycle requirements.
18. **Determinism / repeatability / consistency.** Race-dependent or private stage shortcuts are defects.
19. **Explain the stop.** Students, developers, and auditors should hear when the lifecycle must refuse progress or closure.
20. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or authority replacement via lifecycle closure.

## 3. What the Lifecycle May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate constitutional execution** | Organise activities through CEEL-01…CEEL-07 |
| **Consume completed execution contexts** | Bind named WS1 / MS003 completed contexts without inventing or rewriting them |
| **Evaluate constitutional rules** | At CEEL-03, apply published rules under CEE-01 / CEE-02 |
| **Evaluate constitutional constraints** | At CEEL-04, assess hard limits under CEE-03 |
| **Invoke published engine components** | Apply CEE-01…CEE-07 as published by WS2 / MS001 |
| **Produce execution outcomes** | Assemble and publish reconstructable outcomes for downstream decision architecture |
| **Preserve execution state** | Keep speakable progress records (not educational state, not governance disposition) |
| **Publish execution artefacts** | Communicate outcomes under published honesty rules |
| **Refuse unlawful progress** | Prefer honest refuse / stop / escalate over improvisation |
| **Remain deterministic, repeatable, and consistent** | Same published inputs → same stage outcomes and dispositions |
| **Remain implementation-neutral** | Honour lifecycle law across lawful equivalent stacks |
| **Preserve constitutional fidelity** | Apply rules exactly as published; never soft-amend |
| **Explain lifecycle progress** | Answer context / rules / constraints / outcomes / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **coordinate constitutional execution**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CEE or CEEL types, invent CT links, author runtime behaviour, judge educational quality, determine compliance, certify implementations, produce constitutional decisions, or modify artefacts under coordination pretext.

## 4. What the Lifecycle Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Redefine constitutional meaning** | Programme VI / EIP / sibling corpora own meaning | Execute against published meaning; never redefine it |
| **Determine compliance** | CCM / CCL / CCC own obligation status and compliance completion | Never narrate closure as a compliance determination |
| **Certify implementations** | CRT / CRTL / CRTC own recognition | Never narrate closure as certification |
| **Amend constitutional law** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or refuse |
| **Interpret constitutional law independently** | Applying published rules ≠ inventing meaning | Cite published law only; refuse unpublished standards |
| **Produce constitutional decisions** | Governance dispositions belong to Programme IX / successor decision architecture under published law | Publish execution outcomes only |
| **Create constitutional authority** | Published corpora remain the standard after any closure | Keep artefacts as recognised subjects, never as next-cycle law |
| **Replace constitutional authority** | Lifecycle machinery never becomes the corpus | Keep closure as coordination end, not law replacement |
| **Replace Educational Interpretation Principles** | EIP is upstream law | Apply EIP as published; never rewrite claim classes |
| **Invent completed execution context** | WS1 owns preparation / resolution / completion | Consume completed context; refuse invented inputs |
| **Invent engine components** | WS2 / MS001 owns CEE-01…CEE-07 | Invoke published components only |
| **Invent lifecycle stages** | Only CEEL-01…CEEL-07 are lawful | Refuse unpublished stage customs |
| **Modify implementation artefacts** | Coordination is not a mutation licence | Consume context and rules as found; refuse when identity is insufficient |
| **Invent traceability** | CT owns lawful lineage | Preserve established relationships in records; refuse invented links |
| **Freeze a stack as law** | Implementation neutrality is mandatory | Honour equivalent lawful stacks; refuse stack canonisation |
| **Waive hard constraints** | Constraints are constitutional limits | Evaluate and record; refuse progress rather than waive |
| **Perform verification** | CV / CVL / CVC own evidence evaluation | Never re-author verification under an execution badge |
| **Re-run WS1 preparation** | Context completion is upstream | Load completed context; refuse incomplete preparation theatre |
| **Elevate Twin / Adaptive / CI greens as law** | Product signals are not constitutional standards | Cite published rules and completed context only |

## 5. Boundary Tests (Hard Stops)

A proposed lifecycle activity is **unlawful** if any of the following are true:

1. It would create, modify, or deprecate a constitutional specification.
2. It would redefine Programme VI educational meaning or EIP claim classes.
3. It would invent or rewrite a completed execution context.
4. It would invent a CEEL stage outside CEEL-01…CEEL-07.
5. It would invent a CEE component outside CEE-01…CEE-07.
6. It would interpret constitutional law independently or soft-amend specifications.
7. It would produce a constitutional decision (conformance / verification / compliance / certification / evolution disposition).
8. It would determine compliance or certify an implementation.
9. It would replace constitutional authority or EIP.
10. It would modify implementation artefacts “so execution can proceed.”
11. It would privilege a language, framework, store, CI vendor, or topology as constitutional law.
12. It would waive hard constraints by coordination prose.
13. It would present lifecycle closure as mastery, readiness, educational quality, or perpetual conformity.
14. It would erase reconstructable stage / context / rule / constraint identities required for explainability.

Any affirmative answer is a **hard stop**. Prefer refuse / stop / escalate over improvisation.
