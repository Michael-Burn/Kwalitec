## 1. Purpose

An expert IFoA tutor does not optimise “pipeline green” or “engine finished.” The tutor optimises **lawful execution honesty**: only when constitutional rules are applied consistently, deterministically, repeatably, explainably, and with fidelity to published authority may constitutional execution be said to have occurred.

These objectives bind every Constitutional Execution Engine run and every successor machinery that claims to perform constitutional execution.

---

## 2. Primary Objective

### CEEO-01 — Execute constitutional rules consistently

**Definition.** Ensure that every material engine run applies the published constitutional rules identified in the completed execution context **consistently** — same rule identities, same published meaning, same closed CEE-01…CEE-07 component discipline — so execution does not silently favour one rule set, one exception theatre, or one operator narrative over another.

**Includes:**

- Binding every material run to identifiable published rules named in the completed context (Constitution / EIP / Programme VI–IX as assembled under WS1).
- Applying the closed CEE-01…CEE-07 catalogue required by published law for the concern.
- Treating equivalent completed contexts under the same published rules with the same dispatch and execution discipline.
- Preferring lawful refuse / exception coordination over inventing unpublished rules so execution can “finish anyway.”
- Keeping consistent rule execution distinct from compliance determination, certification, educational quality, mastery, readiness, or constitutional amendment.

**Excludes:**

- Treating CI greens, ticket fields, Twin estimates, Adaptive scores, or UI ticks as proof that constitutional rules were executed consistently.
- Soft-selecting convenient rules and omitting inconvenient published ones.
- Optimising for throughput, latency, or demo continuity as a substitute for consistent rule application.
- Declaring consistency “close enough” without documenting which published rules were applied.

**Tutor rationale.** Professional exam preparation fails when software pretends two identical scripts were marked under different secret rules. Consistency is care; selective execution is harm.

---

## 3. Supporting Objectives

### CEEO-02 — Preserve determinism

**Definition.** Ensure that the same completed execution context and the same published constitutional rules yield the same execution disposition — so constitutional execution is fixed by reconstructable inputs, not by race, operator whim, ambient product state, or hidden randomness.

**Tutor rationale.** A coach who cannot say why yesterday’s mark differed from today’s identical script has abandoned educational law for chance.

**Manifestations:**

- Identical completed context identity + identical published rule set ⇒ identical dispatch (CEE-01), execution (CEE-02), constraint evaluation (CEE-03), and outcome collection (CEE-04) dispositions — or the same honest refuse / exception disposition.
- Material non-determinism (race-dependent ordering that changes outcomes; ambient unread state; silent randomisation) is a defect.
- Determinism concerns *constitutional disposition*, not wall-clock performance of a particular stack.
- “It usually works” is never a substitute for deterministic constitutional execution.

---

### CEEO-03 — Preserve repeatability

**Definition.** Ensure that every material engine run is **reproducible** from reconstructable inputs — completed context identity, published rule identities, constraint set, and engine component traces — so execution is not operator-dependent, silently mutable, or erasable after the fact.

**Tutor rationale.** A coach who cannot reconstruct yesterday’s marking cannot stand behind today’s judgement. Non-repeatable execution is constitutional amnesia.

**Manifestations:**

- Execution cites corpus paths, rule identities, and completed-context identities, not only ticket IDs or commit SHAs.
- Continuity (EIP-005) forbids erasing prior lawful execution history to simplify the next run.
- Opaque “ambient” execution without reconstructable inputs is a defect.
- Same published inputs → same execution outcomes (or same honest refuse / exception disposition).
- Downstream decision architecture must be able to re-read the published outcomes without reinventing them.

---

### CEEO-04 — Preserve explainability

**Definition.** Ensure that every material engine run can answer which constitutional rules were executed, which constraints were evaluated, which execution outcomes were produced, which execution state transitions occurred, and which constitutional boundaries remained intact — without rewriting constitutional meaning.

**Tutor rationale.** A coach who cannot say *which rules* were applied to the script is performing, not teaching.

**Manifestations:**

- Execution narration obeys [`ENGINE_EXPLAINABILITY.md`](ENGINE_EXPLAINABILITY.md) (CEEEQ-01…CEEEQ-05).
- Students, developers, and auditors receive truthful speech appropriate to audience vocabulary — not different truths.
- Missing explanation for a material engine component is a defect.
- Explanation never pretends that naming rules equals determining compliance, certifying implementations, or amending law.

---

### CEEO-05 — Preserve constitutional fidelity

**Definition.** Ensure that every material engine run applies constitutional rules **exactly as published**, preserves constitutional authority, preserves Educational Interpretation Principles, and preserves implementation neutrality — so execution never soft-amends specifications, replaces EIP, freezes a stack as law, or elevates engine machinery into constitutional authority.

**Tutor rationale.** A coach who rewrites the syllabus mid-mark because the answer key was inconvenient has ceased to be a coach. Fidelity is the difference between execution and legislation.

**Manifestations:**

- Rules are executed as cited in the completed context; clarifying notes never rewrite published text.
- EIP principles referenced in the completed context remain intact; engine prose never substitutes new interpretation principles.
- No stack, vendor, language, framework, store, or CI tool is required or privileged by engine law.
- Execution outcomes remain subordinate to Constitution / EIP / Programmes VI–IX / WS1 — never become a soft constitution.
- Boundary preservation (CEEEQ-05) is a first-class fidelity obligation, not optional narration.

## 4. Objective Composition

Material constitutional execution must serve **all** of CEEO-01…CEEO-05. No objective may be traded away for delivery urgency.

| If this is sacrificed… | …the failure mode is |
|------------------------|----------------------|
| CEEO-01 Consistency | Selective or contradictory rule application |
| CEEO-02 Determinism | Identical inputs yield unreproducible dispositions |
| CEEO-03 Repeatability | Execution becomes theatre — unreproducible and unaccountable |
| CEEO-04 Explainability | Students / auditors cannot reconstruct what was executed |
| CEEO-05 Fidelity | Soft amendment, EIP replacement, stack freeze, or authority substitution |

> **Objectives optimise the integrity of constitutional rule execution.  
> They never authorise amending law, replacing EIP, determining compliance, or certifying implementations inside the engine.**
