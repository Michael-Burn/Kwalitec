## 1. Purpose

An expert IFoA tutor who cannot say *which execution context* was consumed — which constitutional rules were executed, which constraints were evaluated, which execution outcomes were published, and which limits remained intact — is not closing honestly; they are performing.

After Programmes VI–IX have made meaning, ownership, tips, context, contracts, evidence, runtime, and governance speech speakable, after WS1 has made preparation / resolution / context-completion speech speakable, and after WS2 / MS001–MS002 have made engine and lifecycle speech speakable, Programme X still needs one execution-completion-speech answer:

> **“Which execution context was consumed, which constitutional rules were executed, which constraints were evaluated, which execution outcomes were published, and which constitutional boundaries remained intact?”**

That answer must cover every material affirmed (or refused) completion without inventing educational success, implying independent interpretation, producing or implying constitutional decisions, implying compliance, implying certification, transferring authority, minting tips, inventing state, rewriting specifications, freezing a stack as law, or modifying constitutional law.

## 2. What Execution-Engine Completion Explainability Is

**Constitutional Execution Engine Completion Explainability** is the constitutional obligation to narrate **fulfilment (or lawful refusal of fulfilment) of the required constitutional execution lifecycle** — not to invent a second tutor voice from CI complete badges, and not to grade the student, mint a constitutional decision, or freeze a stack as law.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Execution context consumed** | Named completed execution context (WS1 / MS003) loaded under CEEL-02 | Which execution context was consumed? |
| **Constitutional rules executed** | Named published rules evaluated under CEEL-03 / CEE discipline | Which constitutional rules were executed? |
| **Constraints evaluated** | Named hard constitutional constraints evaluated under CEEL-04 / CEE-03 | Which constraints were evaluated? |
| **Execution outcomes published** | Named reconstructable outcomes published under CEEL-06 / CEE-07 | Which execution outcomes were published? |
| **Boundaries intact** | Explicit confirmation that forbidden overclaims / amendments / substitutions did not occur | Which constitutional boundaries remained intact? |

Execution-Engine Completion Explainability is:

- **fulfilment-centred** — it narrates why CEEC criteria hold (or why close is refused);
- **catalogue-bound** — every justification cites published CEE / CEEL / CEEC identities where applicable;
- **corpus-bound** — every justification cites published specifications, completed context, rules, constraints, outcomes, and named stage / publication records;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-interpretive / non-decisional** — completion is never narrated as independent interpretation or constitutional decision;
- **quality-honest** — complete is never narrated as mastery, readiness, or educational quality;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, WS1 context / resolution / completion speech, WS2 / MS001 engine speech, or WS2 / MS002 lifecycle speech;
- **audit-aligned** — explanation components match CEECO-05 reconstruction needs;
- **authority-honest** — explanations must not paper over authority inference or stack canonisation.

Execution-Engine Completion Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–IX / WS1 / WS2 meaning;
- a quality report on learning, coaching, or exam readiness;
- a claim that independent constitutional interpretation occurred;
- a claim that constitutional decisions were produced;
- a compliance certificate or substitute for Programme IX findings;
- a certification instrument or implementation approval;
- a substitute for WS2 / MS001 engine explainability or WS2 / MS002 lifecycle explainability (compose with; do not replace);
- a substitute for WS1 / MS003 context-completion explainability (compose with; do not collapse);
- a rendering system, UI template, CI badge, engine visualiser, or analytics dashboard;
- a claim that clear completion speech guarantees learning, a pass, conformity, certification, approval, or lawful constitutional decision;
- a licence to present process exits, ticket graphs, or pipeline greens as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material completion judgement (affirm or refuse close) should answer all five questions:

### CEECQ-01 — Which execution context was consumed?

Name the primary completed execution context identity (WS1 / MS003 CECC-completed resolved context) loaded under CEEL-02 for the concern — or name which required completed context remains unavailable / refused when refusing close. Never narrate invented, rewritten, or incomplete context as lawful consumption. “Context happened somewhere” is not a constitutional completed-context identity.

### CEECQ-02 — Which constitutional rules were executed?

Name the primary published Constitution / EIP / Programme VI / VII / VIII / IX rule identities evaluated under CEEL-03 / CEE-01 / CEE-02 for the concern — or name which required rules remain unevaluated / refused when refusing close. Include lawful early-stop evaluation outcomes honestly. Never narrate a skipped mandatory rule as evaluated because a later pipeline job glowed green. “It ran in CI” is not a constitutional rule identity.

### CEECQ-03 — Which constraints were evaluated?

Name the primary hard constitutional constraints evaluated under CEEL-04 / CEE-03 for the concern — or name which required constraints remain unevaluated / violated / refused when refusing close. Never narrate waived or soft-amended hard stops as successful evaluation. “Constraints assumed OK” is not a constitutional constraint identity.

### CEECQ-04 — Which execution outcomes were published?

Name the primary execution outcome identities published under CEEL-06 / CEE-07 for the concern — or name which required outcomes remain unpublished / refuse-published when refusing close. Never narrate log volume, ticket graphs, or CI annotations alone as constitutional outcomes. Distinguish:

- **execution outcomes** — reconstructable results of lawful rule and constraint evaluation for downstream decision architecture;
- **execution state** — speakable progress / closure of constitutional execution (not educational state, not governance disposition);
- **continuity honesty** — prior lawful execution history not erased for convenience (EIP-005).

Never narrate published outcomes as “student is ready,” “mastery confirmed,” “decision issued,” “compliant,” “certified,” “law updated,” or “this stack is now constitutional.”

### CEECQ-05 — Which constitutional boundaries remained intact?

Confirm the hard stops in `COMPLETION_BOUNDARIES.md` that were checked — especially non-independent-interpretation, non-production of constitutional decisions, non-determination of compliance, non-certification of implementations, non-amendment of constitutional law, non-replacement of constitutional authority, implementation neutrality, determinism / repeatability honesty, and non-equation of completion with educational success or constitutional truth.

When refusing close, name which boundary would have been breached by affirming completion (for example: inventing decisions from outcomes; narrating “executed therefore compliant”; waiving unfinished rule evaluation; erasing audit trails; freezing a stack as law).

## 5. Defective Explanation Patterns

The following explanation patterns are constitutionally defective:

1. “Execution completed because CI is green.”
2. “Rules were applied somehow / somewhere.”
3. “Constraints were fine — we didn’t check explicitly.”
4. “Outcomes published” without naming reconstructable outcome identity.
5. “Complete therefore decided / compliant / certified / student ready / law updated.”
6. “Context prepared (CECC) therefore execution complete (CEEC).”
7. “Runtime cycle complete therefore constitutional execution complete.”
8. Soft-amending published rule meaning in the explanation so close can finish.
9. Elevating a preferred stack, vendor, or CI tool as the reason completion holds.
10. Erasing or refusing to cite prior lawful execution history to simplify the narrative.
11. Treating mute badges, spinners, or exit codes as substitutes for CEECQ answers.
12. Narrating refuse / defer / escalate stops as if mandatory evaluation completed.
