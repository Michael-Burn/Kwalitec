## 1. Purpose

An expert IFoA tutor does not optimise “number of tips in a feed.” The tutor optimises **coherent, lawful educational packaging**: the student sees which authorised pieces of guidance belong together, who owns each, and how they relate — without inventing a compromise tip or hiding conflict disposition.

These objectives bind every Educational Recommendation Engine assembly behaviour and surface.

---

## 2. Primary Objective

### RAO-01 — Organise lawful recommendations

**Definition.** Ensure that constitutionally valid educational recommendations are organised into a coherent recommendation set — or that an honest empty / single-member set is presented — without inventing members when no lawful artefacts exist.

**Includes:**

- Collecting WS3 / MS001-complete recommendations that lawfully apply in the same educational moment.
- Ordering or grouping for educational clarity without inventing ranking as constitutional law.
- Including acted-upon, deferred, queued, superseded, or merged-disposition members when Conflict Resolution has lawfully dispositioned concurrency and material honesty requires them.
- Preferring an honest empty set over fabricated filler tips.
- Keeping set membership equal to the truthful count of admissible constituents.

**Excludes:**

- Generating motivational filler tips to “complete” a set layout.
- Optimising for tip volume, feed length, or engagement as a substitute for educational honesty.
- Packaging incomplete slogans as set members.
- Inventing a mega-tip that replaces multiple coach artefacts under an assembly label.

**Tutor rationale.** Professional exam preparation fails when advice arrives as chaos — or when packaging invents advice to fill slots. Organisation is educational care; invention is educational harm.

---

## 3. Supporting Objectives

### RAO-02 — Preserve recommendation ownership

**Definition.** Ensure that assembling a recommendation set never transfers, invents, absorbs, or obscures the constitutional owner of any constituent recommendation.

**Tutor rationale.** A set that “helpfully” attributes everything to “Kwalitec” or to an assembly engine destroys Authority Model layering even if the UI feels cleaner.

**Manifestations:**

- Each constituent retains ERC-02 ownership from WS3 / MS001.
- Set-level ownership references name constituent owners — never replace them with Recommendation Engine / UI / “the system.”
- Delegation bounds remain owner-accountable; assembly does not become the owner.
- Forbidden ownership moves in `ASSEMBLY_BOUNDARIES.md` are hard stops.

---

### RAO-03 — Preserve constitutional provenance

**Definition.** Ensure that packaging a set never erases, invents, or silently substitutes the documented sources, evidence warrants, and constitutional references of each constituent.

**Tutor rationale.** Provenance is how tips remain auditable. A set that looks coherent but cannot reconstruct why each tip was lawful is educationally unlawful packaging.

**Manifestations:**

- Contributing ERS classes and underlying artefacts remain reconstructable per constituent.
- Supporting educational evidence claim types survive packaging (EIP-002 / EIP-006 honesty).
- Constitutional references (ERC-05) remain available for developer / auditor traces.
- Undocumented heuristics, A/B winners, and engagement scores never become substitute provenance.

---

### RAO-04 — Maintain internal consistency

**Definition.** Ensure the recommendation set does not contradict Conflict Resolution dispositions, present dual primary without lawful warrant, orphan material siblings, or mix lawful and invented members.

**Tutor rationale.** Students should not receive a set that says two tips are both “the” next step, or that hides a deferred tip that still matters for trust. Consistency is honesty at set scale.

**Manifestations:**

- At most one acted-upon primary unless a published RO-03 merge pathway authorises a merged primary.
- Deferred / superseded / queued / rejected-as-unlawful members labelled consistently with RO outcomes.
- No constituent that fails WS3 / MS001 completeness (C1–C7) admitted as a recommendation member.
- Workflow and authority context attached to the set do not contradict constituent ERC-04 / ERC-02 facts.

---

### RAO-05 — Support explainable recommendation sets

**Definition.** Ensure every material recommendation set can answer why recommendations appear together, how they relate, which constitutional sources contributed, and how provenance has been preserved (`ASSEMBLY_EXPLAINABILITY.md`).

**Tutor rationale.** Opaque batches feel like a black box even when each tip underneath is sound. Set explainability is part of educational integrity (EIP-003; EL-008).

**Manifestations:**

- Trace links from set organisation → constituent relations → sources → provenance preservation.
- Student speech without internal IDs; developer traces with document and component IDs.
- Explainability never used to invent certainty no constituent claimed, or to invent a conflict winner assembly did not receive from WS2 / MS002.

## 4. Objective Catalogue

| ID | Objective | One-line definition |
|----|-----------|---------------------|
| **RAO-01** | Organise lawful recommendations | Form a coherent set from valid artefacts — or honest emptiness |
| **RAO-02** | Preserve recommendation ownership | Packaging never rewrites who owns each tip |
| **RAO-03** | Preserve constitutional provenance | Sources, evidence honesty, and refs survive the set |
| **RAO-04** | Maintain internal consistency | No dual primary, no disposition contradiction, no invented members |
| **RAO-05** | Support explainable recommendation sets | Why together · relations · sources · provenance always answerable |

Additional objectives may be added only by amending this document.

---

## 5. Priority Among Objectives

When objectives appear to tension:

1. **RAO-02 (ownership)** and **RAO-03 (provenance)** precede packaging convenience.
2. **RAO-04 (consistency)** precedes motivational brevity that would hide disposition or invent dual primary.
3. **RAO-05 (explainability)** precedes feed aesthetics that would hide why tips appear together.
4. **RAO-01 (organisation)** prefers honest empty / single sets over invented members that would satisfy layout metrics.
5. None of RAO-01…RAO-05 authorises re-resolving Conflict Resolution or inventing Programme VI meaning.

Product metrics may proxy these objectives. Proxies that invert this order are educationally unlawful.

## 6. Relationship to Recommendation Objectives (WS3 / MS001)

| Recommendation objective (MS001) | Assembly relationship |
|----------------------------------|----------------------|
| **ERO-01** Communicate guidance | Assembly organises *already-communicable* artefacts; it does not invent speech |
| **ERO-02** Preserve meaning | Assembly inherits meaning-preservation and must not rewrite it at set scale |
| **ERO-03** Unify lawful outputs | MS001 unifies *components of one tip*; MS002 organises *multiple tips* — both packaging, neither meaning creation |
| **ERO-04** Support learner decision-making | Assembly must not obscure choice by dual primary or hidden disposition |
| **ERO-05** Remain fully explainable | Per-tip explainability remains mandatory; set explainability is additional |

Both catalogues bind. Satisfying assembly objectives never relaxes MS001 artefact law.

---

## 7. Non-Objectives

The following are **not** assembly objectives under this Framework:

- Maximising tip count, feed length, or notification batch size
- Ranking coaches by undocumented scores
- Re-resolving conflicts already governed by WS2 / MS002
- Optimising engagement, click-through, or “completeness theatre”
- Substituting Twin / Adaptive infrastructure authority for Programme VI meaning
- Treating assembly as state mutation or workflow execution
- Guaranteeing exam passes or learning outcomes

---

## 8. Closing

Assembly objectives keep Kwalitec’s recommendation sets tutor-like: organised, ownership-faithful, provenance-honest, consistent, and explainable.

When a surface would optimise feed density over RAO-02, RAO-03, or RAO-04, **stop**.  
When organisation would require inventing members or re-resolving conflicts, **refuse or amend Programme VI / conflict law** — do not assemble by reinterpretation.

> **Organise lawful recommendations. Preserve ownership and provenance. Explain the set.**
