## 1. Purpose

Without named conflict kinds, product pressure invents informal stories: “recovery always wins,” “merge the tips,” or “pick whatever the UI showed last.”

This catalogue makes concurrency **speakable and classifiable** so resolution principles and outcomes can apply without discretionary invention.

---

## 2. Preconditions for a Constitutional Conflict

A situation is a **constitutional educational conflict** under this Framework only when **all** of the following hold:

| Precondition | Meaning |
|--------------|---------|
| **P1 — Multiple artefacts** | Two or more educational recommendations, priorities, or orchestration claims are present |
| **P2 — Each is constitutionally valid** | Each artefact is authorised by its Programme VI owner within its Authority Model domain (or is a lawful orchestration claim within WS1 bounds) |
| **P3 — Competition for action** | They cannot all be treated as the *primary acted-upon* educational outcome at the same coordination moment |
| **P4 — Ownership is not in dispute** | No two components claim ownership of the *same* decision class (AP-01 holds for each artefact’s class) |

If P2 fails for an artefact, the situation is **rejection of an unlawful claim** (see `RESOLUTION_OUTCOMES.md` — RO-05), not peer conflict among equals.

If P4 fails, the situation is an **ownership dispute** — out of this catalogue. Refuse and consult the Authority Model; do not classify as CT-xx for merge or ranking.

## 3. Conflict Type Catalogue

| ID | Conflict kind | One-line definition |
|----|---------------|---------------------|
| **CT-01** | Concurrent recommendations | Multiple owners emitted valid recommendations that each seek primary action now |
| **CT-02** | Competing educational priorities | Distinct educational priorities are each warranted but cannot all lead |
| **CT-03** | Temporary authority contention | Temporary primary focus and standing guidance both seek action |
| **CT-04** | Superseding recommendations | A later valid recommendation claims to replace an earlier one’s *action* |
| **CT-05** | Workflow timing conflicts | Orchestration timing places multiple valid artefacts in the same action window |

Additional kinds may be added only by amending this document. Silence is not a new conflict type.

---

## 4. CT-01 — Concurrent Recommendations

**Definition:** Two or more Programme VI owners have each emitted a **constitutionally valid recommendation**, and more than one of those recommendations seeks to be the student’s **primary acted-upon guidance** in the same coordination moment.

| Element | Example (illustrative, not algorithmic) |
|---------|------------------------------------------|
| Artefacts | Daily Coach day priority; Revision Coach revision warrant; both valid |
| Competition | Both present as “do this now” candidates |
| Not this type | Daily Coach inventing a tip without warrant (unlawful — not concurrent *valid* peers) |
| Not this type | Daily and Revision both claiming ownership of “what to do today” (ownership dispute — MS001) |

**Coordination concern:** Which valid recommendation is acted upon as primary; what happens to the others (defer / queue / supersede per principles).

**Ownership invariant:** Each owner remains owner of its recommendation’s decision class after disposition.

---

## 5. CT-02 — Competing Educational Priorities

**Definition:** Distinct **educational priorities** (for example recovery posture vs ordinary day progress vs examination preparation) are each **warranted** under Programme VI meaning, but the student cannot lawfully treat all of them as the leading educational obligation at once.

| Element | Example (illustrative) |
|---------|------------------------|
| Artefacts | Recovery Coach restorative priority; Daily Coach coverage-under-plan priority; both warranted |
| Competition | Leading obligation conflict — which priority governs *now* |
| Distinct from CT-01 | CT-02 emphasises *priority classes* (what kind of educational obligation leads); CT-01 emphasises *emitted recommendation artefacts* |
| Overlap | A living situation may instantiate both CT-01 and CT-02; principles still apply without merging meanings |

**Coordination concern:** Which priority class governs the acted-upon outcome for this moment, without collapsing Recovery into Daily or Exam into Revision.

**Ownership invariant:** Priority selection for action does not transfer domain ownership of the non-leading priority.

---

## 6. CT-03 — Temporary Authority Contention

**Definition:** A **temporary primary focus** (for example recovery-led primary question, examination-window focus, or narrow delegation under AP-04) contends with **standing guidance** from another domain (for example ordinary Daily Coach day priority or Master Planner published plan intent) for acted-upon status.

| Element | Example (illustrative) |
|---------|------------------------|
| Temporary focus | Recovery is primary educational question for this period |
| Standing guidance | Daily Coach still has a valid day artefact under the Canonical Study Plan |
| Competition | Temporary primary vs standing day action |
| Not ownership transfer | Recovery does not become owner of Daily Coach’s domain; Daily does not absorb Recovery |

**Coordination concern:** Temporary primary may lawfully govern acted-upon action for the contention window; standing artefacts are deferred or queued — not rewritten or owned by the temporary focus.

**Ownership invariant:** AP-06 / AP-07 — temporary focus suspends *competing primary actions*, not ownership of other domains. Restoration returns acted-upon rights without rewriting meaning.

**Relationship to MS001:** This type *implements the coordination face* of temporary primary focus already recognised in Authority Principles. It does not invent new owners.

---

## 7. CT-04 — Superseding Recommendations

**Definition:** A **later** constitutionally valid recommendation claims to **replace the acted-upon status** of an **earlier** valid recommendation — without claiming the earlier owner’s decision class.

| Element | Example (illustrative) |
|---------|------------------------|
| Earlier | Daily Coach recommended Topic A as today’s primary under plan |
| Later | Same-day disruption → Recovery Coach emits restorative recommendation that supersedes *action* on Topic A for now |
| What supersedes | Acted-upon status / primary action |
| What does not supersede | Ownership of Daily Coach’s day-priority domain; meaning of the earlier recommendation |

**Coordination concern:** Explicit supersession of action with preservation of the earlier artefact’s owner and meaning (often as deferred or queued).

**Unlawful lookalikes:**

- Silent overwrite of another coach’s meaning “because the new tip is better”
- Supersession that pretends to transfer ownership
- UI replacing earlier guidance without citing CT-04 and preservation

---

## 8. CT-05 — Workflow Timing Conflicts

**Definition:** Programme VII Workstream 1 **orchestration timing** (stage movement, pause/resume, handoff, concurrent open workflows, or completion adjacency) places **multiple valid educational artefacts** into the **same action window**, creating competition for primary action even when each artefact was emitted lawfully in its own workflow path.

| Element | Example (illustrative) |
|---------|------------------------|
| Timing pressure | Resume after await coincides with a new recovery event; both bring valid outputs |
| Competition | Which workflow’s authorised outcome is acted upon now |
| Orchestration role | WS1 surfaces the concurrency; MS002 dispositions action |
| Unlawful | Workflow Engine inventing a third tip to “smooth timing” |

**Coordination concern:** Disposition among valid artefacts that collided because of orchestration timing — not inventing educational meaning to fill a timing gap.

**Ownership invariant:** Workflow timing never becomes educational ownership (Authority Model AD for Workflow Engine remains orchestration-only).

## 9. Non-Conflicts (Explicit Exclusions)

The following are **not** conflict types under this Framework:

| Situation | Correct treatment |
|-----------|-------------------|
| Two components claim the same decision class | Ownership dispute → Authority Model (AP-01); refuse |
| One artefact is unlawful / out of domain | Reject as unlawful (RO-05); do not peer-rank with valid peers |
| Missing evidence or awaited Programme VI output | Workflow pause / await (WS1 transitions) — not conflict among equals |
| Product wants a single tip for marketing | Presentation pressure — not a constitutional conflict kind |
| Version 2 Adaptive score disagrees with Programme VI | Consume V2 for delivery; Programme VI remains educational law — not CT-xx “engine war” |
| Desire to rewrite the Canonical Study Plan mid-conflict | Escalate to Master Planner pathways — not conflict merge |

## 10. Classification Discipline

When classifying a living situation:

1. Confirm P1–P4.
2. Assign the primary CT-xx (and secondary if both CT-01 and CT-02 apply).
3. Apply `RESOLUTION_PRINCIPLES.md` — do not invent a new type mid-flight.
4. Select outcomes only from `RESOLUTION_OUTCOMES.md`.
5. Record explainability per `RESOLUTION_EXPLAINABILITY.md`.

If classification is unclear, **amend this catalogue** or **refuse action** — do not invent an unnamed conflict kind in Runtime A.

---

## 11. Closing

Conflict types name *coordination problems*, not *ownership wars* and not *meaning rewrites*.

> **Classify the concurrency. Preserve the owners. Leave meaning intact.**
