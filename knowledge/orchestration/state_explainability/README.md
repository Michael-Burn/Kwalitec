## Purpose

This folder defines **how Kwalitec explains a learner's constitutional educational context and its progression through contextual state transitions** — why the learner is currently in a named EST posture, how that context lawfully evolved, and what explanations must never invent.

It answers:

> **“Why is the learner currently in this constitutional educational context, and how did that context lawfully evolve?”**

It does **not** redefine educational meaning, execute workflows, transfer authority, create recommendations, imply mastery or success, or implement Runtime A.

> **Educational state explanations communicate constitutional context only.  
> They do not redefine educational meaning, execute workflows, transfer authority, or create recommendations.**

## Architectural requirement

Educational state explanations must **faithfully describe** contextual representation and lawful contextual succession.

They must **never**:

| Lawful | Unlawful |
|--------|----------|
| Name the current EST posture and why it exists | Imply educational success or learner mastery from context alone |
| Describe lawful CST succession and continuity | Imply workflow completion from succession alone |
| Reference constitutional warrants and published rules | Redefine Programme VI educational meaning while “explaining” |
| Reference workflow progression as supporting context | Claim the State Engine executed a workflow or transferred ownership |
| Cite supporting contextual evidence honestly | Reinterpret Educational Evidence or Twin estimates |
| Keep student and developer speech truth-aligned | Expose runtime implementation details as constitutional justification |

If a proposed narration would require inventing EST/CST types, evaluative overclaim, ownership transfer, tip minting, or unpublished rules, **amend the owning constitutional corpora first** — or refuse the narration. Explainability never gains authority by storytelling.

## Distinction from sibling corpora

| Corpus | Answers | Does not answer |
|--------|---------|-----------------|
| **WS4 / MS001 Educational State Model** | What EST types exist; entry/exit; non-claim prohibitions | Unified explanation contract spanning live context *and* progression (this corpus) |
| **WS4 / MS001 `STATE_EXPLAINABILITY.md`** | Static-context speech themes (ESQ-01…ESQ-04) | Full explainability model with principles, components, boundaries, and progression patterns (this corpus specialises and binds) |
| **WS4 / MS002 Transition Framework** | When context may succeed; CST/condition/boundary law | Unified permission-of-speech narrative across initial state and multi-step progression (this corpus) |
| **WS4 / MS002 `TRANSITION_EXPLAINABILITY.md`** | Transition-moment speech (STQ-01…STQ-04) | Full context-and-progression explanation contract including component catalogue (this corpus) |
| **WS1 Workflow / Transition / Completion explainability** | Why flow started, moved, or completed | Why *context representation* is live or succeeded (this corpus) |
| **WS2 Authority Decision Explainability** | Why a component was *permitted* to decide | Why a *contextual posture* is live (this corpus) |
| **WS3 Recommendation Set Explainability** | Why a tip set exists and how to interpret it | Why EST context frames that guidance (this corpus) |
| **Programme VI `*_EXPLAINABILITY.md`** | Why *this educational answer* emerged | Why *this focus context* is live and how it evolved (this corpus) |
| **This Educational State Explainability** | Why in this context / how it evolved / what constitutional facts an explanation must carry | Algorithms, Runtime A, UI rendering, EST/CST catalogues, meaning rewrites |

**Binding distinction:** MS001 owns the EST catalogue and static-context speech themes. MS002 owns CST succession law and transition-moment speech themes. MS003 owns the **constitutional explanation contract** for educational state — spanning initial context, single and multiple transitions, and workflow-referenced progression — without amending either catalogue or transition law.

## How to use this corpus

1. Read `EDUCATIONAL_STATE_EXPLAINABILITY.md` first.
2. Treat principles in `EXPLANATION_PRINCIPLES.md` as binding for every educational-state narration path.
3. Require the information set in `EXPLANATION_COMPONENTS.md` before student- or developer-facing context speech.
4. Enforce limits in `EXPLANATION_BOUNDARIES.md` — refuse narration that invents meaning, mastery, ownership, tips, or unpublished rules.
5. Use `EXPLANATION_EXAMPLES.md` as illustrative patterns, not as a closed catalogue of product copy.
6. When current EST posture is at stake, consult [`../state/`](../state/) — explain what that Model already authorises.
7. When succession is at stake, consult [`../state_transitions/`](../state_transitions/) — explain what that Framework already authorises.
8. When educational meaning is at stake, defer to Programme VI explainability — this corpus frames *context and progression*, not *what the tutor meant*.
9. Keep consistency with MS001 ESQ-01…ESQ-04 and MS002 STQ-01…STQ-04; MS003 unifies them under ESEQ-01…ESEQ-05 without replacing underlying law.
10. Do not implement behaviours that contradict this corpus without amending it first.
