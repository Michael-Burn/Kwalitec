## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabi such as CM1/CS1 and peers).

An expert IFoA tutor does not only *assemble* lawful advice into a coherent package — the tutor can also *say why* that package exists, how its pieces were organised, and how the student should read primary versus waiting guidance. After MS001 has closed each tip and MS002 has organised the set, the platform still needs one constitutional explanation question answered consistently:

> **“Why does this recommendation set exist, how were its constituent recommendations assembled, and how should it be interpreted?”**

That answer must cover single-member sets, multi-coach packages, post-disposition sets, and workflow-situated sets — without inventing educational meaning, transferring ownership, re-resolving conflicts, executing workflows, or publishing undeclared rules.

This document records that tutor posture so every future Educational Recommendation Engine subsystem has a single educational reference for *how recommendation sets are explained*.

> **Recommendation Set Explainability describes constitutional reasoning about set existence, assembly, and interpretation.  
> It does not create recommendations, alter ownership, resolve conflicts, or orchestrate workflows.**

## 2. What Recommendation Set Explainability Is

**Recommendation Set Explainability** is the constitutional contract for narrating **why a recommendation set is the live educational package**, **how its constitutionally valid members were organised**, **how the set should be read** (primary vs waiting, empty honesty, limits), and **which published constitutional facts support that narration**.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Recommendation set** | Organised collection of lawful recommendation artefacts (MS002) | What package is live? |
| **Set existence warrant** | Constitutional reason this package is presented now | Why does this set exist? |
| **Assembly description** | Faithful account of how constituents were organised under MS002 | How were members assembled? |
| **Interpretation guidance** | How to read relations, dispositions, and limits without inventing meaning | How should the set be interpreted? |
| **Provenance preservation** | Retention of sources, owners, evidence, and constitutional refs after packaging | Did narration preserve integrity? |
| **Lawful set speech** | Audience-appropriate narration that remains ownership-true and meaning-true | What may be said constitutionally? |

Recommendation Set Explainability is:

- **constitutional** — it cites published assembly, ownership, disposition, and tip law, not product preference;
- **set-centred** — its core job is *why this package / how organised / how to read it*, not *why this tip is educationally good* (MS001 + Programme VI own that);
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in underlying truth;
- **layer-honest** — it frames packaging; it does not replace coach meaning, permission speech, or workflow narration;
- **non-inventive** — it never creates tips, merges meanings, transfers owners, or invents unpublished winners;
- **consistent** — single-member, multi-coach, post-disposition, and workflow-driven paths share one explanation contract.

Recommendation Set Explainability is **not**:

- a second Recommendation Assembly Framework;
- a second Educational Recommendation Model;
- a rewrite of Programme VI educational meaning;
- a conflict resolution or ranking engine;
- a workflow stage sequencer;
- a rendering, UI, template, or analytics system;
- a claim that a clear set explanation guarantees student success or mastery.

## 3. Educational Purpose

Recommendation Set Explainability exists so that:

1. **Set existence is speakable** — students and developers can hear why *this* package is live now.
2. **Assembly is transparent** — organisation is narrated as packaging of lawful artefacts, not as tip invention.
3. **Interpretation is honest** — primary vs waiting, empty sets, and limits are dignified and clear.
4. **Ownership stays visible** — each constituent’s owner remains named; no set-owner absorbs members.
5. **Provenance stays reconstructable** — sources, dispositions, evidence refs, and constitutional citations survive speech.
6. **Layers stay distinct** — meaning, ownership, disposition, orchestration, tip artefact, and set packaging remain separable in speech.

## 5. Four Recommendation Set Explanation Questions (Binding)

Every material recommendation set explanation must answer these four questions.

### RSEQ1 — Why does this recommendation set exist?

Name the constitutional warrant for presenting this package now — lawful constituents available (or honest emptiness), workflow / event situating when material, and refusal of invented filler.

### RSEQ2 — How were its constituent recommendations assembled?

Describe organisation under MS002: which complete artefacts became members, which sources contributed, how ownership was indexed, and that assembly organised rather than created.

### RSEQ3 — How should the set be interpreted?

State how members relate (primary vs waiting / deferred / superseded action), what limits apply (empty, single-member, thin evidence), and what the set does *not* mean (not a new Study Plan, not mastery, not a mega-coach tip).

### RSEQ4 — How have provenance, ownership, and constitutional integrity been preserved?

Confirm each constituent’s sources, owner, evidence honesty, and constitutional refs remain reconstructable; confirm conflict dispositions (if any) were referenced not re-resolved; confirm no ownership transfer or meaning rewrite in speech.

All four RSEQs are mandatory for material set narrations. Omitting RSEQ3 when relations or limits would confuse the student is an architectural defect. Omitting RSEQ4 provenance / ownership preservation is always an architectural defect.

**Consistency with MS002 RAQ:** RSEQ1…RSEQ4 specialise and bind the set-explanation contract. They are compatible with RAQ-01…RAQ-04 in [`../recommendation_assembly/ASSEMBLY_EXPLAINABILITY.md`](../recommendation_assembly/ASSEMBLY_EXPLAINABILITY.md). Where this corpus specialises (principles, components, boundaries, patterns), it binds; where MS002 owns underlying assembly law, MS002 remains authoritative.
