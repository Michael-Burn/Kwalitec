> **Recommendation set explanations may describe recommendation organisation,  
> reference constitutional provenance,  
> and explain workflow context.  
> They must never invent recommendations,  
> redefine educational meaning,  
> transfer ownership,  
> reinterpret evidence,  
> or introduce unpublished constitutional rules.**

---

## 1. Purpose

Boundaries prevent explanation from becoming a back door: narration that quietly invents tips, transfers ownership, rewrites evidence, re-resolves conflicts, or exposes runtime guts as if they were educational law.

These boundaries bind every recommendation-set explanation path. Crossing them makes the narration **unlawful** even if motivationally effective.

---

## 2. Boundary Catalogue

| ID | Boundary | One-line rule |
|----|----------|---------------|
| **RSEB-01** | Describe recommendation organisation | Explanations may describe how lawful members are organised in the set |
| **RSEB-02** | Reference constitutional provenance | Explanations may cite published sources, owners, dispositions, and evidence refs |
| **RSEB-03** | Explain workflow context | Explanations may reference orchestration situating as coordination context |
| **RSEB-04** | No recommendation invention | Explanations must not invent tips, filler members, or mega-coach compromises |
| **RSEB-05** | No educational meaning rewrite | Explanations must not redefine Programme VI educational meaning |
| **RSEB-06** | No ownership transfer | Explanations must not imply transferred, absorbed, or dual set ownership |
| **RSEB-07** | No evidence reinterpretation | Explanations must not reinterpret Educational Evidence or Twin estimates |
| **RSEB-08** | No unpublished constitutional rules | Explanations must not introduce ranking, scores, or undeclared winner / packaging rules |
| **RSEB-09** | No conflict re-resolution in speech | Explanations must not invent dispositions or packaging-time winners |
| **RSEB-10** | No runtime implementation as law | Explanations must not present implementation details as constitutional set warrant |

## 3. What Recommendation Set Explanations May Do

### RSEB-01 — Describe Recommendation Organisation

**Permitted:** Narrate why members appear together, how they relate, and how the set coheres — citing published MS002 assembly law.

| Lawful | Unlawful lookalike |
|--------|-------------------|
| “These tips already apply; we show them together so the priority is clear.” | “We invented a combined tip so the list looks complete.” |
| Developer cites RAC-01 / RAC-07 / assembly warrant | Developer cites “card carousel preferred three tips” |

### RSEB-02 — Reference Constitutional Provenance

**Permitted:** Cite contributing sources, owners, conflict dispositions, evidence references, and constitutional document refs that already authorised the set and its members.

| Lawful | Unlawful lookalike |
|--------|-------------------|
| “This comes from your Study Plan and recovery coaching.” | “The app decided from engagement heatmaps.” |
| Developer: ERS map + owner index + RO refs | Undocumented heuristic as provenance |

### RSEB-03 — Explain Workflow Context

**Permitted:** Mention that a workflow started, handed off, escalated, or concluded — as *orchestration context* that situates why the set is live — without attributing tip content to the Workflow Engine.

| Lawful | Unlawful lookalike |
|--------|-------------------|
| “You’ve returned to study, so today’s coaching and your Study Plan sit together.” | “The workflow recommends Topic X.” |
| Developer: `workflow_explainability_ref=…; tip_owners=[…]` | Developer: `owner=workflow` for tip meaning |

## 4. What Recommendation Set Explanations Must Not Do

### RSEB-04 — Must Not Invent Recommendations

**Forbidden:** Using explanation to invent set members, filler tips, averaged mega-coach compromises, or silent siblings that were never MS001-complete artefacts.

| Forbidden narration | Why |
|---------------------|-----|
| “Here’s an extra tip so you have a full set.” | Assembly / set speech organises — does not create (RSEP-02 / RSEP-08) |
| Narrating a compromise tip without RO-03 published pathway | Unpublished merge |
| Empty set replaced by motivational slogans presented as recommendations | Non-invention duty |

**Lawful alternative:** Speak empty / single-member honesty; refuse invention; amend Programme VI / MS001 if a real tip is needed.

### RSEB-05 — Must Not Redefine Educational Meaning

**Forbidden:** Using explanation to reinterpret, rewrite, or silently edit Programme VI meanings or the substance of authorised recommendations.

| Forbidden narration | Why |
|---------------------|-----|
| “That waiting tip wasn’t really needed…” (to erase a deferral) | Disposition ≠ meaning invalidation |
| Relabel Recovery as Revision in speech to simplify packaging | Domain non-reinterpretation |
| Claim mastery / pass certainty from clear set narration | EIP-006 adjacency |

**Lawful alternative:** Preserve meaning; explain organisation and interpretation only; link Programme VI / MS001 explainability for educational warrant.

### RSEB-06 — Must Not Transfer Ownership

**Forbidden:** Speech that makes packaging, UI proximity, temporary primary action, or “the recommendation set” sound like transferred, absorbed, or dual ownership.

| Forbidden narration | Why |
|---------------------|-----|
| “The recommendation set owns today’s advice.” | No constitutional set-owner absorbs domains (RSEP-03) |
| “Recovery now owns your daily plan because it leads the set.” | Leading action ≠ ownership transfer |
| “We merged coaches into one owner for packaging.” | AP-01 / assembly ownership preservation |

**Lawful alternative:** Index owners per constituent; distinguish *acted-upon / leading* from *standing owner*; never invent a mega-owner.

### RSEB-07 — Must Not Reinterpret Evidence

**Forbidden:** Treating set explanation as a licence to reclassify Educational Evidence, invent observations, or mint Estimated Knowledge / Mastery from packaging clarity or UI completion.

| Forbidden narration | Why |
|---------------------|-----|
| “Because the set is clear, we know you understand…” | Evidence / mastery law |
| Set speech that rewrites Evidence Model classifications | Evidence Pipeline / EIP-002 owns meaning |
| Twin facet names in student copy as set provenance proof | Wrong audience + wrong authority |

**Lawful alternative:** Reference published evidence warrants on constituents; leave reclassification to rightful writers under EIP-001 / Evidence law.

### RSEB-08 — Must Not Introduce Unpublished Constitutional Rules

**Forbidden:** Presenting scores, ranks, optimiser confidence, A/B winners, engagement metrics, or tribal “usually we package X with Y” customs as constitutional set law.

| Forbidden narration | Why |
|---------------------|-----|
| “The algorithm ranked these tips into a set.” | Unpublished precedence |
| Soft hierarchy not written in MS001/MS002/WS2 | Amend owning corpora first — or refuse |
| “Ops preferred this batch order” as educational warrant | Product preference ≠ constitutional law |

**Lawful alternative:** Cite only published Constitution / EIP / MS001 / MS002 / WS1 / WS2 rules. If a real packaging-law gap exists, amend owning corpora — do not narrate around it.

### RSEB-09 — Must Not Re-Resolve Conflicts in Speech

**Forbidden:** Inventing winners, silent averages, or packaging-time dispositions that contradict or bypass Conflict Resolution outcomes.

| Forbidden narration | Why |
|---------------------|-----|
| “The set picked the better tip.” | Assembly / explanation reference disposition; they do not decide it |
| Hide dual primary by omitting a waiting sibling | Disposition fidelity (RSEP-07) |
| Narrate RO-03 merge without published pathway | Exceptional merge only |

**Lawful alternative:** Reference published RO outcomes; preserve deferred meanings; align with Resolution Explainability.

### RSEB-10 — Must Not Present Runtime Implementation as Law

**Forbidden:** Presenting queues, service names, feature flags, database rows, job IDs, stack traces, or adapter paths as the *constitutional reason* the set exists or was assembled.

| Forbidden as justification | Permitted as non-authoritative ops context (developer-only, clearly labelled) |
|----------------------------|-------------------------------------------------------------------------------|
| “Because `RecommendationService` batched first…” | Optional ops breadcrumbs *after* constitutional citations, never instead of them |
| “Flag `X` forced a three-tip carousel” | Flag may gate delivery; it does not create assembly law |
| “Row id 12345 won packaging” | Persistence identity ≠ set warrant |

**Architectural requirement:** Constitutional justification precedes any implementation breadcrumb. Implementation detail never substitutes for RSEC-02 / RSEC-07.

## 5. Boundary Interaction with MS001 / MS002 / WS2

| Sibling law | Explanation boundary effect |
|-------------|----------------------------|
| MS001 complete artefacts only | RSEB-04 forbids incomplete slogan members in speech |
| MS002 organise-don’t-create | RSEB-01 / RSEB-04 bind assembly narration |
| MS002 ownership preservation | RSEB-06 forbids set-owner absorption |
| MS002 no conflict re-resolution | RSEB-09 binds disposition speech |
| WS2 RP-01 / RP-02 preservation | RSEB-05 / RSEB-06 bind meaning and ownership |
| WS2 RP-04 rule-bound resolution | RSEB-08 forbids score stories |
| WS1 workflow boundaries | RSEB-03 forbids orchestration-as-tutor |

Explanation boundaries **do not amend** MS001/MS002/WS2. They constrain how those corpora are spoken.

---

## 6. Refusal Duty for Unlawful Narration

If a proposed explanation would require crossing RSEB-04…RSEB-10:

1. **Refuse** the narration path, or
2. **Amend** the owning constitutional corpus first (MS001 artefact law, MS002 assembly, WS2 disposition, Programme VI meaning, EIP), then explain the amended law.

Silent “helpful” copy that crosses a boundary is an architectural defect, not a UX win.

---

## 7. Completeness vs Boundaries

Satisfying `EXPLANATION_COMPONENTS.md` does **not** authorise crossing these boundaries. A complete component set that invents tips or ownership remains unlawful.

Conversely, a boundary-respecting explanation that omits mandatory components remains incomplete (RSEP-05).

Both completeness and boundaries are required.

---

## 8. Closing

Recommendation set explanations are trustworthy only inside these limits:

> **May describe organisation, reference provenance, and explain workflow context.  
> Must never invent recommendations, redefine meaning, transfer ownership, reinterpret evidence, introduce unpublished rules, re-resolve conflicts in speech, or treat runtime guts as educational law.**
