## 1. Purpose

Collaborating services that silently become a second constitution — transferring ownership by call graph, merging duties into whoever holds the thread, or skipping contracts because “the other service was already authorised” — destroy student trust and educational integrity.

This document draws a bright line between **lawful collaboration** (Programme VIII WS3 / MS002) and **constitutional authorship / responsibility redistribution** (forbidden relative to Constitution / EIP / Programmes VI–VII / VIII WS1–WS2 / WS3 MS001).

---

## 2. Boundary Principles

1. **Coordinate, do not author.** Collaboration arranges published responsibilities; it does not write them.
2. **Preserve MS001 duties.** Each RS participant keeps its permitted and prohibited responsibilities.
3. **No ownership transfer.** Invocation never transfers constitutional ownership between services or components.
4. **No responsibility merger.** Composition never collapses RS types into unpublished mega-services.
5. **Contracts authorise.** RC-01…RC-07 bind every material collaborative act; callee success never substitutes for caller (or specialist) RC bindings.
6. **Artefacts only.** Only published constitutional artefacts may be exchanged.
7. **Evidence non-reinterpretation.** Classifications stay with EIP-002 / WS2 law through every handoff.
8. **Events non-invention.** CE types stay with WS1 event-processing law.
9. **Specification immutability at runtime.** Code never amends constitutional corpora by side effect of collaboration.
10. **Technology silence.** Buses, DI, meshes, queues, APIs, languages, and frameworks are not constitutional architecture.
11. **Explain the stop.** Students and developers should hear when collaboration must refuse.
12. **No emergency exemption.** Load, deadlines, and demos never mint collaborative constitutional power.

## 3. What Runtime Services May Do When Collaborating (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Invoke authorised runtime services** | Compose RS-01…RS-07 under recognised RSC-01…RSC-07 patterns without absorbing authorship |
| **Exchange published constitutional artefacts** | Pass contracts dispositions, evidence records, CE traces, workflow / tip / state artefacts, and audit refs exactly as published |
| **Coordinate execution** | Sequence, parallelise, delegate, condition, evidence-gate, event-initiate, or audit-compose under catalogue rules |
| **Preserve execution records** | Leave reconstructable trails of participants, patterns, contracts, artefacts, and outputs (RS-07 / RSC-07) |
| **Refuse unlawful collaboration** | Prefer honest stop / defer / escalate over improvisation or forced merge |
| **Remain replaceable** | Honour RSC meanings in any compliant implementation (RSCO-05) |
| **Explain collaboration** | Answer participants / contracts / artefacts / outputs / preserved boundaries without rewriting meaning |

These actions **coordinate**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, or rewrite the Runtime Service Model.

## 4. What Runtime Services Must NEVER Do When Collaborating

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Transfer constitutional ownership** | Programme VII WS2 owns ownership; MS001 services are executors, not owners | Invoke specialists; keep ownership with published owners |
| **Merge constitutional responsibilities** | MS001 closes RS-01…RS-07 duties as distinct capabilities | Compose under RSC patterns; narrate non-absorption |
| **Bypass runtime contracts** | Programme VIII WS1 owns RC catalogue and authorisation | Require named RC bindings for each material collaborative act |
| **Reinterpret constitutional evidence** | EIP-002 / EIP-006 / WS2 own observational truth and claim honesty | Exchange classifications unchanged; refuse when ineligible |
| **Modify constitutional specifications** | Constitution / EIP / Programmes VI–VIII / MS001 are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law via collaboration |
| **Invent unpublished collaboration patterns** | This corpus owns RSC-01…RSC-07 | Use recognised patterns or refuse |
| **Invent educational meaning / tips / state / events** | Programmes VI–VII / WS1 CE law own those catalogues | Consume / execute published artefacts only |
| **Absorb EIP-001 mutation rights by chaining calls** | State Authority Matrix owns writers | Route writes only to permitted writers |
| **Elevate orchestration technology into constitutional architecture** | RSCI-10 / RSCO-05 | Keep buses / DI / meshes / queues / workers out of the constitutional stack |
| **Treat Twin / Adaptive / UI as collaborative authors** | They are consumers / delivery surfaces | Keep them subordinate to Runtime Service + collaboration law |
| **Present scores as constitutional warrant for collaboration** | Scores are operational proxies | Cite published corpora, patterns, and evidence classes |
| **Become irreplaceable by collaborative design** | Replaceability of services and patterns | Keep collaboration implementation-independent |

## 6. Boundary Checks (Pre-Collaboration)

Before a material runtime service collaboration, constitutional compliance requires affirmative answers:

1. **Pattern named?** Which RSC-01…RSC-07 pattern(s) apply?
2. **Participants named?** Which RS-01…RS-07 services participate, and in which roles?
3. **Contracts bound?** Which RC-01…RC-07 contracts authorise each material act?
4. **Responsibilities preserved?** Does each participant remain within its MS001 permitted / prohibited lists (no merger / transfer)?
5. **Artefacts published?** Are all exchanged items published constitutional artefacts?
6. **Evidence lawful?** If evidence is exchanged or gating, is it consumed under WS2 / RC-02 without reinterpretation?
7. **Events lawful?** If events initiate or continue collaboration, are they published CE classes under WS1 / MS002?
8. **Outputs authorised?** Are all intended collaborative outputs published classes?
9. **Technology silent?** Is any bus / DI / mesh / stack choice being treated as constitutional authorisation? (Must be no.)
10. **Stop explainable?** If any check fails, can the collaboration refuse / defer / escalate with speakable reasons?

A failed check is a **hard stop**, not a soft warning.

## 7. Composition Boundaries (Specialised)

When RS services collaborate under RSC patterns:

| Rule | Meaning |
|------|---------|
| **No ownership transfer** | Call graphs never reassign Programme VII ownership domains |
| **No absorption** | The caller does not inherit the callee’s authorship or expand its own prohibited list |
| **No silent skip** | Required specialised responsibilities cannot be omitted by collaboration convenience |
| **No contract bypass** | Prior authorisation for one act never substitutes for another act’s RC bindings |
| **No evidence reinterpretation** | Artefacts keep claim class through handoffs |
| **Shared truth** | All collaborative acts share one constitutional truth for explainability and audit |
| **MS001 unchanged** | Collaboration never amends the Runtime Service Model by side effect |

These rules specialise — and never weaken — MS001 `SERVICE_BOUNDARIES.md` §7 Composition Boundaries.

## 8. Out of Scope

This milestone does **not** implement:

- Runtime A collaboration graphs or adapters
- Service orchestration engines
- Dependency injection topologies
- Message buses, microservices, REST APIs
- Queues, schedulers, or workers
- Databases, analytics, or UI enforcement layers

Those may later *obey* these boundaries. They do not *define* them.

## 9. Closing Statement

> **A collaboration that transfers ownership, merges responsibilities, bypasses contracts, reinterprets evidence, or modifies specifications is not “flexible architecture.”  
> It is constitutional failure — regardless of how elegant the orchestration looks.**
