## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabi such as CM1/CS1 and peers).

An expert IFoA tutor does not invent the syllabus, redefine mastery mid-lesson, or silently rewrite yesterday’s plan because a calendar widget is convenient. After the Constitution and EIP have defined *educational truth*, after Programme VI has defined *what educational questions mean*, and after Programme VII has defined *how decisions flow, who owns them, what tips may say, and what context may exist*, the platform still needs one execution answer:

> **“What constitutional rules govern software execution?”**

That answer must ensure runtime implementations consume published law, execute only authorised actions, preserve educational integrity, remain replaceable, and stay fully explainable — without creating, reinterpreting, or replacing constitutional law.

This document records that posture so every future Runtime A (and successor) subsystem has a single constitutional reference for *how software may execute educational architecture*.

> **The Runtime Contract Model describes constitutional consumption and execution.  
> It does not create educational meaning, invent ownership, mint tips, or implement Runtime A.**

## 2. What a Constitutional Runtime Contract Is

A **constitutional runtime contract** is the binding obligation by which a **runtime implementation** may **consume published constitutional specifications** and **execute published constitutional rules** — without becoming a source of educational truth.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Constitutional producer** | The Constitution, EIP, Programme VI, or Programme VII corpus that publishes the law being executed | Who authored the law? |
| **Constitutional consumer** | The runtime implementation bound by the contract (Runtime A and lawful successors) | Who executes? |
| **Published rule** | A documented constitutional condition, workflow stage, authority domain, recommendation artefact, state posture, or evidence classification | What may be executed? |
| **Execution act** | A software action that applies a published rule to concrete learner circumstances | What did runtime do? |
| **Constitutional integrity** | Preservation of meaning, ownership, evidence honesty, continuity, and explainability through execution | Was law preserved? |
| **Replaceability** | The obligation that any runtime may be substituted if it continues to honour the same contracts | Is runtime law, or merely executor? |

A constitutional runtime contract is:

- **consumer-bound** — runtime consumes law; it does not publish it;
- **producer-respecting** — every material execution cites a constitutional producer;
- **implementation-independent** — contracts bind behaviour, not a specific language, framework, or service layout;
- **integrity-preserving** — execution never quietly rewrites meaning, ownership, evidence, tips, or state;
- **audit-capable** — execution leaves reconstructable constitutional traces;
- **explainable** — students and developers can answer which contract ran and under which corpus;
- **replaceable** — Runtime A is an executor label, not a constitutional monopoly.

A constitutional runtime contract is **not**:

- a second Educational Constitution or EIP;
- a Programme VI coach, planner, or meaning authority;
- a Programme VII workflow, authority, recommendation, or state engine;
- a licence to invent tips, mastery, readiness, or educational context from heuristics;
- a database schema, API contract, DTO, message queue, or UI surface;
- a claim that successful execution guarantees learning or a pass.

## 3. Runtime A as Constitutional Consumer

**Runtime A** is the current named constitutional consumer of Kwalitec educational architecture.

Runtime A (and any successor runtime implementation):

| Obligation | Meaning |
|------------|---------|
| **Consume constitutional specifications** | Read Constitution, EIP, Programme VI, and Programme VII as authoritative law |
| **Execute published constitutional rules** | Apply only documented conditions, workflows, ownership maps, recommendation artefacts, and state postures |
| **Preserve constitutional integrity** | Refuse actions that would redefine meaning, authority, evidence, tips, or context |
| **Remain implementation-independent** | Honour contracts regardless of stack, storage, or delivery technology |
| **Remain replaceable** | Never treat a particular codebase as constitutional truth |

### 3.1 What Runtime A never becomes

Runtime A never becomes:

- a constitutional authority that authors educational meaning;
- a reinterpretation layer that “improves” Programme VI coach questions in code;
- a recommendation mint that invents tips without Programme VII / VI warrant;
- a state inventor that declares educational context outside published EST/CST law;
- an evidence reclassifier that treats coverage, time, or confidence as understanding;
- an owner of the Constitution, EIP, Programme VI, or Programme VII corpora.

> **Runtime implementations are constitutional executors.  
> They must never become constitutional authors.**

## 5. Educational Purpose

The Runtime Contract Model exists so that:

1. **Law remains upstream of code** — software executes published specifications; it does not quietly become the specification.
2. **Educational meaning survives delivery** — coaches and planners keep their questions when runtime runs.
3. **Governance survives scale** — ownership, evidence, continuity, and mutation rights remain intact under load and iteration.
4. **Audit remains possible** — every material runtime action can be reconstructed against constitutional producers.
5. **Explainability remains honest** — execution speech describes what ran; it does not redefine what learning means.
6. **Runtimes remain replaceable** — constitutional truth outlives any particular implementation.
