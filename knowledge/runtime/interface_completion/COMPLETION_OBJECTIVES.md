## 1. Purpose

An expert IFoA tutor does not optimise “facade finished,” “GraphQL stitch succeeded,” or “SDK batch drained.” The tutor optimises **honest closing of coordinated constitutional interaction**: when the published composition duties among specialist interfaces are done, the tutor can say so — without pretending the student has mastered the topic, without pretending a lone execution cycle, a service collaboration, or a whole educational workflow is finished, without rewriting who owns which interaction contract because the composed calls stopped cleanly, and without elevating a transport technology into law.

These objectives bind every Runtime A interface-composition-completion behaviour and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### RICCO-01 — Confirm lawful interface composition

**Definition.** Ensure that runtime affirms interface composition completion only when a published composition under MS001 / MS002 has fulfilled its constitutional composition responsibilities — or honestly refuses close when fulfilment criteria are not met.

**Includes:**

- Assessing only compositions that lawfully opened under RI-01…RI-07 participants, RIC-01…RIC-07 patterns, and RC-01…RC-07 authorisation.
- Affirming completion only when `COMPLETION_CRITERIA.md` conditions hold.
- Preferring lawful “not yet” / refuse-close over inventing a “composed enough” status for product convenience.
- Distinguishing lawful stop dispositions (refuse / defer / escalate as published composition outcomes) from abandoned composition duties.
- Binding every material completion judgement to reconstructable constitutional references.

**Excludes:**

- Declaring complete because an HTTP response succeeded, a GraphQL stitch resolved, a gRPC gateway exited, an SDK batch finished, or a UI spinner stopped.
- Treating Twin / Adaptive / Experience / Mission heuristics as composition completion warrants.
- Optimising for latency, fan-in, or engagement as a substitute for fulfilment honesty.
- Collapsing “composition complete” into “execution complete,” “collaboration complete,” “student succeeded,” “workflow complete,” or “constitution updated.”

**Tutor rationale.** Professional exam preparation fails when software celebrates unfinished coordination — or celebrates finished facade choreography as finished learning or finished tutoring duties. Honest confirmation is care; composition-completion theatre is harm.

## 3. Supporting Objectives

### RICCO-02 — Preserve interface identities

**Definition.** Ensure that affirming composition completion never merges, absorbs, renames-away, or redefines the named identities and permitted / prohibited exposures established by the Runtime Interface Model (MS001) for any participant.

**Tutor rationale.** A close that “helpfully” lets the initiator become every specialist, or invents a mega-interface because the facade ended, destroys the RI catalogue even if the completion UX looks tidy.

**Manifestations:**

- Completion consumes MS001 identities; it does not amend them.
- Forbidden actions in `COMPLETION_BOUNDARIES.md` are hard stops — especially identity merger and capability redefinition.
- MS001 RIO / boundary obligations and MS002 RICO-02 remain binding at close.
- Affirmed completion never grants EIP-001 mutation rights or new RI catalogue entries by proximity to a finished composition.

---

### RICCO-03 — Preserve implementation independence

**Definition.** Ensure that RICC completion meanings bind *fulfilment of published composition responsibilities*, not languages, frameworks, REST, GraphQL, gRPC, HTTP, WebSockets, SDKs, authentication stacks, networking topologies, or API styles.

**Tutor rationale.** If “composition complete” only exists as an OpenAPI operation succeeded or a BFF aggregate returned 200, the transport has become unlawful constitutional furniture.

**Manifestations:**

- Completion criteria describe constitutional conditions — never required stacks.
- REST, GraphQL, gRPC, HTTP, SDKs, auth, and networking are delivery options, not completion law.
- Replaceability of Runtime A (and successors) survives any particular composition topology.

---

### RICCO-04 — Preserve auditability

**Definition.** Ensure that every material composition completion judgement leaves a reconstructable constitutional trail: which interfaces participated, which RIC pattern completed, which contracts authorised the composition, which constitutional artefacts were exchanged, which composition records were created, and which boundaries were preserved.

**Tutor rationale.** A tutor team that cannot later say *why* coordinated interface work was closed cannot be trusted. Composition completion without audit is educational amnesia with more moving parts.

**Manifestations:**

- Audit records preserve constitutional references for the whole composition graph, not only technical request logs or gateway exit codes.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance on any material participant is a defect, not an acceptable optimisation.
- RI-06 / RIC audit composition obligations apply to all material composition completion judgements.

---

### RICCO-05 — Preserve explainability

**Definition.** Ensure that runtime interface composition completion remains speakable under EIP-003: students and developers can answer the mandatory composition-completion explainability questions without receiving redefined educational meaning, false learning claims, false execution claims, false collaboration claims, false workflow claims, merged identities, redefined capabilities, or invented constitutional amendments.

**Tutor rationale.** Opaque “composition done” recreates black-box tutoring with a facade costume. Clear completion speech is part of educational honesty.

**Manifestations:**

- Explanations cite participants, patterns, contracts, artefacts, and boundaries (`COMPLETION_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores, HTTP codes, stitch success, gateway health, SDK batch counts, and optimiser confidence are never presented as constitutional fulfilment warrant.
- Explanation never becomes a back door to invent tips, mastery, execution completion, collaboration completion, workflow close, mega-interfaces, or law change.

---

### RICCO-06 — Preserve composition-completion determinism

**Definition.** Ensure that the same published composition facts — participating interfaces, RIC pattern, contracts, exchanged inputs, produced outputs, learner constitutional inputs as classified, and published corpora — yield the same completion judgement class (affirm / not yet / refuse close) — absent a published non-deterministic exception (none are granted by this Model for educational or constitutional meaning).

**Tutor rationale.** A coach team that sometimes declares composition complete and sometimes not for the same published facts, depending on which worker woke first or which gateway retry won, is not coaching; they are gambling with educational honesty under composed load.

**Manifestations:**

- Criteria evaluation is corpus-bound and reproducible.
- Infrastructure concurrency, sharding, retry jitter, and race-dependent “aggregate winners” must not change the completion judgement class.
- Race-dependent “composition done” flags are constitutional defects.
- “Eventually consistent composition fulfilment” is a constitutional defect.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RICCO-01 conflicts with declaring done for product theatre | Lawful confirmation wins — refuse / not-yet |
| RICCO-02 conflicts with “one mega-interface is simpler after close” | Identity preservation wins |
| RICCO-03 conflicts with locking completion meanings to one protocol or SDK | Implementation independence wins |
| RICCO-04 conflicts with log volume reduction that erases participant / artefact refs | Auditability wins |
| RICCO-05 conflicts with cryptic gateway jargon as student completion speech | Explainability honesty wins |
| RICCO-06 conflicts with race-dependent composition-done flags | Determinism wins |

No supporting objective authorises violating RICCO-01.  
No composition-completion objective authorises violating MS001 RIO-01…RIO-06 for any participant, or MS002 RICO-01…RICO-06 for the composition being closed.

These objectives specialise — and never weaken — MS001 interface objectives, MS002 composition objectives, and sibling Programme VIII completion objectives for the *interface-composition-completion* horizon.

---

## 5. Non-Objectives

Runtime interface composition completion does **not** optimise for:

- learner progress theatre, mastery badges, or pass certainty as a side-effect of close;
- collapsing Runtime Execution Completion (REC), Evidence Consumption Completion (ECC), or Service Collaboration Completion (RSCC) into composition close;
- collapsing Programme VII workflow completion into facade exit;
- inventing educational certainty when warrants are incomplete;
- making a particular protocol, SDK, gateway, or interface topology irreplaceable;
- using Twin / Adaptive / UI / gateway signals as substitutes for fulfilment criteria;
- merging interface identities “temporarily” because composition ended;
- treating documentation as optional commentary on “composition done” flags in code.

---

## 6. Closing Statement

> **A runtime that closes compositions quickly, quietly, and constitutionally unfaithfully is a failed educational system.  
> A runtime that affirms composition completion only when published composition responsibilities are fulfilled — with interface identities, implementation independence, audit, explainability, and determinism intact — is doing its only composition-completion job.**
