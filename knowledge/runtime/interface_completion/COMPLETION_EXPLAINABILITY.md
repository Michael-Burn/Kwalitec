## 1. Purpose

An expert IFoA tutor who cannot say *which specialist interfaces finished coordinating* — which composition pattern completed, which contracts authorised the composition, which artefacts were exchanged, and which limits were preserved — is not closing honestly; they are performing with a facade costume.

After Programmes VI and VII have made meaning, ownership, tips, context, and orchestration fulfilment speakable, after Programme VIII WS1–WS3 have made contracts, events, execution completion, evidence handling, services, and collaboration completion speakable, and after WS4 / MS001–MS002 have made interfaces and composition speakable, Programme VIII WS4 / MS003 still needs one composition-completion-speech answer:

> **“Which runtime interfaces participated, under which composition pattern and contracts, exchanging which artefacts, while preserving which constitutional boundaries?”**

That answer must cover every material affirmed (or refused) composition completion without inventing educational success, implying execution completion, implying service collaboration completion, merging identities, redefining capabilities, minting tips, inventing state, rewriting evidence, claiming workflow close, or modifying constitutional law.

## 2. What Composition Completion Explainability Is

**Runtime Interface Composition Completion Explainability** is the constitutional obligation to narrate **fulfilment (or lawful refusal of fulfilment) of published composition responsibilities** — not to invent a second tutor voice from HTTP codes, GraphQL stitches, or celebration UI.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Interfaces participated** | Named RI-01…RI-07 interaction contracts and composition roles | Which runtime interfaces participated? |
| **Pattern completed** | Named RIC-01…RIC-07 coordination form(s) whose published steps finished or lawfully stopped | Which composition pattern completed? |
| **Contracts authorising** | Named RC-01…RC-07 binding(s) that authorised the composition | Which constitutional contracts authorised the composition? |
| **Artefacts exchanged** | Published constitutional artefacts (inputs / outputs) handed between participants | Which constitutional artefacts were exchanged? |
| **Boundaries preserved** | Explicit confirmation that forbidden mergers / redefinitions / overclaims / inventions / amendments did not occur | Which constitutional boundaries were preserved? |

Composition Completion Explainability is:

- **fulfilment-centred** — it narrates why RICC criteria hold (or why close is refused);
- **participant-centred** — it names which RI interfaces participated under which RIC pattern;
- **catalogue-bound** — every justification cites published RI / RIC / RC identities where applicable;
- **artefact-honest** — only published constitutional artefacts appear in the exchange story;
- **identity-honest** — explanation confirms non-merger and non-redefinition of MS001 identities and capabilities;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip / educational-completion speech, Programme VII ownership / workflow / workflow-completion speech, Programme VIII REC / ECC / RSCC speech, MS001 interface speech, or MS002 composition speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, execution completion, collaboration completion, workflow close, mega-interfaces, or law change;
- **technology-silent** — explanation never treats REST, GraphQL, gRPC, HTTP, SDKs, auth, or networking as constitutional warrant;
- **audit-aligned** — explanation components match RI-06 / RIC reconstruction needs;
- **determinism-honest** — explanations must not paper over race-dependent composition-done flags.

Composition Completion Explainability is **not**:

- a rewrite of Programme VI educational meaning or educational-completion explainability;
- a substitute for Programme VII workflow-completion explainability;
- a substitute for WS1 execution-completion, WS2 evidence-consumption-completion, or WS3 collaboration-completion explainability;
- a substitute for MS001 interface or MS002 composition explainability corpora;
- a rendering system, UI template, log shipper, tracing product, API console, or analytics dashboard;
- a claim that clear composition-completion speech guarantees learning, execution completion, or a pass;
- a licence to present scores, HTTP codes, stitch success, gateway health, SDK batch counts, or optimiser confidence as constitutional proof;
- a narrative that “the initiator now is every specialist because composition closed.”

## 3. Mandatory Explanation Questions

Every material composition completion judgement (affirm or refuse close) should answer all five questions:

### RICCAQ-01 — Which runtime interfaces participated?

Name the RI-01…RI-07 interfaces and their composition roles (initiator, participant, specialist, gate, recorder, inspector). If completion is refused, name the participants that were assessed and state that fulfilment was not affirmed. “Gateway healthy” or “endpoints were up” is not a constitutional participant identity.

### RICCAQ-02 — Which composition pattern completed?

Name the RIC-01…RIC-07 pattern(s) that applied and whether they reached published terminal coordination or a published refuse / defer / escalate stop. If refusing close, name which pattern duties remained outstanding. “Aggregate succeeded” or “BFF exited” is not a constitutional pattern identity.

### RICCAQ-03 — Which constitutional contracts authorised the composition?

Name the primary RC-01…RC-07 contract(s) whose obligations were met for the composed interactions (or which failed when refusing close). Cross-cutting compositions name all bound contracts. “Interface was available,” “HTTP returned 200,” “GraphQL resolved,” or “SDK method was called” are not constitutional authorisation.

### RICCAQ-04 — Which constitutional artefacts were exchanged?

Name only published artefact classes handed between participants: constitutional requests / inputs, dispositions, evidence records, validation outcomes, CE processing records, recommendation artefacts / sets, EST/CST postures, workflow events, audit refs, authorised outputs, or explicit refuse/defer/escalate outcomes. Missing required exchanges or required outputs must be spoken when refusing close.

### RICCAQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `COMPLETION_BOUNDARIES.md` that were checked — especially non-merger of interface identities, non-redefinition of constitutional capabilities, non-implication of execution completion, non-implication of service collaboration completion, non-implication of workflow completion, non-implication of educational success, and non-modification of constitutional specifications.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational or constitutional law |
|----------|----------|----------------------------------------------------|
| **Student** | That the system finished the coordinated constitutional machine steps it was allowed to take among its specialist interfaces, what happened next (if anything), and what was *not* being claimed — in plain educational language | Internal RICC/RIC/RI/RC IDs as theatre; “you have mastered this”; “your study plan is complete” from composition close alone; “the engine finished learning for you”; protocol traces; optimiser scores as “proof you are ready” |
| **Developer / auditor** | Full RICCAQ-01…05 answers, corpus paths, RI/RIC/RC IDs, RICC criteria map, boundary checks, determinism / continuity notes, provenance | Product success metrics, HTTP codes, stitch success, gateway health, SDK batch counts, or latency SLOs substituted for constitutional refs; silent collapse into REC / ECC / RSCC / Programme VII workflow-completion speech; silent claim that identities merged |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.
