## 1. Purpose

Runtime that silently turns “composition finished” into “student succeeded,” “execution completed,” “collaboration completed,” “workflow closed,” “identities merged,” “capabilities redefined,” or “the Constitution now says X” destroys student trust and educational integrity.

This document draws a bright line between **lawful composition-completion confirmation** (Programme VIII / WS4 / MS003) and **educational / execution / collaboration / orchestration / authorship / identity-merger judgements** owned elsewhere.

---

## 2. Boundary Principles

1. **Confirm composition, do not author meaning.** Completion affirms fulfilment of published interface coordination duties; it does not create educational truth.
2. **Composition only.** Learning, mastery, and progress are never inferred from close.
3. **Not execution completion.** Programme VIII / WS1 / MS003 owns execution-cycle fulfilment.
4. **Not service collaboration completion.** Programme VIII / WS3 / MS003 owns collaboration fulfilment.
5. **Not workflow completion.** Programme VII owns orchestration fulfilment.
6. **Not identity merger.** MS001 owns the interface catalogue; close never merges or redefines it.
7. **Not capability redefinition.** Composition close never invents or rewrites constitutional capabilities.
8. **Published criteria only.** REST, GraphQL, gRPC, HTTP, SDKs, and gateway exits are not fulfilment law.
9. **Published records only.** Composition audit continuity is constitutional, not free-form tracing theatre.
10. **Reference participants, patterns, and artefacts honestly.** Named RI interfaces, RIC patterns, and exchanged artefacts may be cited; MS001 / MS002 law is not rewritten by citing them.
11. **Meaning non-reinterpretation.** Programme VI questions survive close intact.
12. **Evidence non-reinterpretation.** Classifications stay with the Evidence Model.
13. **State non-invention.** Context postures stay with WS4 EST/CST law.
14. **Recommendation non-invention.** Tips stay with WS3 + Programme VI owners.
15. **Determinism.** Race-dependent composition completion is a defect.
16. **Implementation independence.** Protocols and SDKs never become constitutional furniture.
17. **Explain the stop.** Students and developers should hear when close must be refused.
18. **No emergency exemption.** Load, deadlines, and demos never mint composition-completion power.

## 3. What Runtime Interface Composition Completion May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Confirm composition fulfilment** | Affirm RICC-01…RICC-05 when published criteria hold for a lawful composition |
| **Reference participating interfaces** | Cite RI-01…RI-07 participants and composition roles under MS001 / MS002 — without merging or redefining the RI catalogue |
| **Reference composition patterns** | Cite RIC-01…RIC-07 pattern(s) whose published steps finished or lawfully stopped — without inventing unpublished facades |
| **Reference constitutional artefacts exchanged** | Cite published inputs / outputs / artefacts handed between participants — without reinterpreting them |
| **Preserve audit continuity** | Keep reconstructable RI-06 / RIC / RC-07 trails intact across retries, replacements, and redeploys (EIP-005) |
| **Refuse unlawful close** | Prefer honest not-yet / refuse-close over improvisation, merger, or capability theatre |
| **Remain deterministic** | Same published inputs → same completion judgement class |
| **Remain replaceable** | Honour completion law in any compliant implementation |
| **Explain completion** | Answer participants / patterns / contracts / artefacts / boundaries without rewriting meaning |

These actions **confirm**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, certify mastery, affirm REC/ECC/RSCC by declaration, close Programme VII workflows, merge RI identities, or redefine constitutional capabilities.

## 4. What Runtime Interface Composition Completion Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Merge interface identities** | MS001 owns the RI catalogue; MS002 forbids merger by composition | Keep each participant’s MS001 identity and exposures intact |
| **Redefine constitutional capabilities** | Capabilities are published under WS1–WS3 / MS001 law; close does not invent them | Consume published capabilities; escalate for corpus amendment |
| **Imply execution completion** | Programme VIII / WS1 / MS003 owns REC fulfilment | Affirm composition completion only; require REC corpus for execution-cycle close |
| **Imply service collaboration completion** | Programme VIII / WS3 / MS003 owns RSCC fulfilment | Affirm composition completion only; require RSCC corpus for collaboration close |
| **Imply workflow completion** | Programme VII WS1 / MS003 owns orchestration fulfilment | Affirm composition completion only; require Programme VII corpus for workflow close |
| **Imply educational success** | Educational success is not a composition property | Say composition responsibilities are fulfilled; remain silent on mastery / progress / pass |
| **Modify constitutional specifications** | Constitution / EIP / Programmes VI–VIII are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law in a composition-completion handler |
| **Imply Programme VI educational completion** | Coach / planner completion models own educational fulfilment where defined | Keep educational completion judgements with Programme VI |
| **Imply Evidence Consumption Completion** | WS2 / MS003 owns ECC fulfilment | Affirm composition completion only; require ECC corpus for evidence-handling close |
| **Redefine MS001 / MS002 meanings at close** | Interface and composition law are not rewritten by “done” | Consume published catalogues; escalate for corpus amendment |
| **Invent tips / state / evidence classes at close** | WS3 / WS4 / EIP-002 writers own those artefacts | Surface only already-authorised composition outputs or none |
| **Treat REST / GraphQL / gRPC / HTTP / SDK / gateway exits as fulfilment** | Operational proxies are not completion law | Evaluate RICC-01…RICC-05 |
| **Treat Twin / Adaptive / UI done-flags as publishers of completion law** | They are consumers / delivery surfaces | Require published criteria or refuse |
| **Become irreplaceable by composition topology** | RICCO-03 replaceability | Keep completion law implementation-independent |
| **Erase continuity to force a clean close** | EIP-005 | Preserve history; re-enter at published points |

## 6. Boundary Checks (Pre-Affirmation)

Before a material composition completion is affirmed, confirmation requires affirmative answers:

| Check | Question |
|-------|----------|
| **ICCB-01 Composition lawfulness** | Did a published MS001 / MS002 composition exist (not completion theatre for never-started coordination)? |
| **ICCB-02 Criteria** | Do RICC-01…RICC-05 hold? |
| **ICCB-03 Identity non-merger** | Does affirmation avoid merging or absorbing MS001 interface identities? |
| **ICCB-04 Capability non-redefinition** | Does affirmation avoid redefining constitutional capabilities? |
| **ICCB-05 Execution non-claim** | Does affirmation avoid implying execution completion or REC completion? |
| **ICCB-06 Collaboration non-claim** | Does affirmation avoid implying service collaboration completion or RSCC completion? |
| **ICCB-07 Learner-success non-claim** | Does affirmation avoid implying learner success, progress, mastery, or pass? |
| **ICCB-08 Workflow non-claim** | Does affirmation avoid implying Programme VII workflow completion? |
| **ICCB-09 Spec immutability** | Does affirmation avoid modifying constitutional specifications? |
| **ICCB-10 Participant honesty** | Are references limited to published RI participants without inventing mega-interfaces? |
| **ICCB-11 Pattern honesty** | Are pattern references limited to published RIC-01…RIC-07 identities? |
| **ICCB-12 Artefact honesty** | Are exchanged artefacts limited to published constitutional classes without reinterpretation? |
| **ICCB-13 Record honesty** | Do composition records support the judgement without substituting protocol / SDK theatre? |
| **ICCB-14 Continuity** | Is audit continuity preserved (EIP-005)? |
| **ICCB-15 Determinism** | Is the judgement reproducible from published inputs? |
| **ICCB-16 Explainability** | Can RICCAQ questions in `COMPLETION_EXPLAINABILITY.md` be answered honestly? |

Any failed check → not yet / refuse close. Do not “best-effort” invent fulfilment.
