## Authority

This document is the constitutional overview of the **Runtime Service Model** for Kwalitec.

It is subordinate to the Educational Constitution, Educational Interpretation Principles (EIP), Programme VI educational meaning corpora, Programme VII orchestration corpora, and Programme VIII Workstream 1 Runtime Contract / Event Processing / Execution Completion Models and Workstream 2 Evidence Consumption / Validation / Completion Models. It governs **what constitutional execution capabilities runtime implementations may expose** — its objectives, recognised service types, hard boundaries, and explainability. It does not authorise implementation shortcuts that contradict the Constitution, and it does not invent educational meaning, alter ownership, mint recommendations, invent educational state, rewrite Programme VI / VII law, or redefine Programme VIII WS1 / WS2 contracts.

Authority order for runtime services:

> **This Runtime Service Model (Programme VIII / Workstream 3 / MS001) defines which constitutional execution capabilities runtime implementations may expose under that law.**  
> Downstream Runtime A, product surfaces, Twin, Adaptive, and narration must obey these service meanings — never become constitutional authors by service naming, module layout, or product convenience.

## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabi such as CM1/CS1 and peers).

An expert IFoA tutor does not invent the syllabus, redefine mastery mid-lesson, or silently rewrite yesterday’s plan because a calendar widget is convenient. After the Constitution and EIP have defined *educational truth*, after Programme VI has defined *what educational questions mean*, after Programme VII has defined *how decisions flow*, and after Programme VIII WS1 / WS2 have defined *which contracts, events, completions, and evidence rules bind software*, the platform still needs one service answer:

> **“What constitutional execution capabilities may runtime implementations expose?”**

That answer must ensure runtime services consume published contracts, evidence, and events; execute only published constitutional responsibilities; produce only authorised execution outputs; remain deterministic, auditable, explainable, and replaceable — without creating constitutional meaning, authority, or governance.

This document records that posture so every future Runtime A (and successor) subsystem has a single constitutional reference for *which execution capabilities may exist*.

> **The Runtime Service Model describes constitutional execution capabilities.  
> It does not create educational meaning, invent ownership, mint tips, or implement Runtime A.**

## 2. What a Constitutional Runtime Service Is

A **constitutional runtime service** is a named **execution capability** that a **runtime implementation** may expose to **execute published constitutional responsibilities** — without becoming a source of educational truth, authority, or governance.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Constitutional producer** | The Constitution, EIP, Programme VI, Programme VII, or Programme VIII WS1 / WS2 corpus that published the responsibility being executed | Who authored the law? |
| **Constitutional consumer** | The runtime implementation (or another authorised runtime service) that invokes the capability | Who executes? |
| **Constitutional contract** | An RC-01…RC-07 binding that authorises the service act | What authorised execution? |
| **Constitutional evidence** | Published warrants / observations / orchestration artefacts consumed exactly as classified | What was consumed? |
| **Constitutional event** | A published CE-class stimulus received, evaluated, or emitted under event-processing law | What event was processed? |
| **Authorised execution output** | A published execution record, disposition, surfaced artefact, or audit trail the service is permitted to produce | What resulted? |
| **Replaceability** | The obligation that any service implementation may be substituted if it continues to honour the same RS catalogue | Is the service law, or merely executor? |

A constitutional runtime service is:

- **responsibility-bound** — it executes published duties; it does not invent them;
- **contract-consuming** — every material act cites one or more RC bindings;
- **evidence-honest** — it consumes evidence as published; it never reclassifies;
- **event-lawful** — it processes only published event classes under WS1 / MS002;
- **implementation-independent** — services name capabilities, not languages, frameworks, or topologies;
- **integrity-preserving** — execution never quietly rewrites meaning, ownership, tips, or state;
- **audit-capable** — execution leaves reconstructable constitutional traces;
- **explainable** — students and developers can answer which service ran and under which law;
- **replaceable** — a named module is an executor label, not a constitutional monopoly.

A constitutional runtime service is **not**:

- a second Educational Constitution or EIP;
- a Programme VI coach, planner, or meaning authority;
- a Programme VII workflow, authority, recommendation, or state engine;
- a Runtime Contract or Evidence Model that invents new RC / EC / EV types by proximity;
- a licence to invent tips, mastery, readiness, or educational context from heuristics;
- a Python class, Flask blueprint, microservice, REST API, queue worker, DI container, database schema, or UI surface;
- a claim that successful service execution guarantees learning or a pass.

## 3. Runtime Services as Constitutional Executors

Runtime services (and any successor capability catalogue) must:

| Obligation | Meaning |
|------------|---------|
| **Consume constitutional contracts** | Honour RC-01…RC-07 as published in Programme VIII WS1 / MS001 |
| **Consume constitutional evidence** | Receive and apply evidence under WS2 consumption / validation / completion law |
| **Consume constitutional events** | Process CE-class stimuli under WS1 / MS002 event-processing law |
| **Execute published constitutional responsibilities** | Apply only documented duties from Constitution / EIP / Programmes VI–VIII |
| **Produce authorised execution outputs** | Emit only published output classes (records, dispositions, surfaced artefacts, audit trails) |
| **Remain implementation-independent** | Honour RS meanings regardless of stack, storage, or delivery technology |
| **Remain replaceable** | Never treat a particular codebase or service mesh as constitutional truth |

### 3.1 What runtime services never become

Runtime services never become:

- constitutional authorities that author educational meaning;
- reinterpretation layers that “improve” Programme VI coach questions in code;
- recommendation mints that invent tips without Programme VII / VI warrant;
- state inventors that declare educational context outside published EST/CST law;
- evidence reclassifiers that treat coverage, time, or confidence as understanding;
- governance engines that redefine ownership, permission, or conflict disposition;
- owners of the Constitution, EIP, Programme VI, Programme VII, or Programme VIII WS1 / WS2 corpora.

> **Runtime services are constitutional execution capabilities.  
> They must never become constitutional authors.**

## 5. Educational Purpose

The Runtime Service Model exists so that:

1. **Capabilities remain subordinate to law** — service catalogues describe what may execute; they do not become the Constitution.
2. **Contracts remain the authorisation layer** — RS capabilities execute only under RC bindings.
3. **Evidence and events survive delivery** — consumption and processing stay honest under WS2 / WS1 law.
4. **Determinism remains possible** — the same published inputs yield the same authorised outputs.
5. **Audit remains possible** — every material service act can be reconstructed against constitutional producers.
6. **Explainability remains honest** — service speech describes what ran; it does not redefine what learning means.
7. **Implementations remain replaceable** — constitutional truth outlives any particular service technology.
