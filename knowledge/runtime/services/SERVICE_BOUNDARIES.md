> reinterpret evidence,  
> invent recommendations,

## 1. Purpose

Runtime services that silently become a second constitution — rewriting meaning in modules, inventing tips in adapters, or skipping contracts because a queue delivered a message — destroy student trust and educational integrity.

This document draws a bright line between **lawful service execution** (Programme VIII WS3) and **constitutional authorship** (Constitution / EIP / Programmes VI–VII / VIII WS1–WS2 law).

---

## 2. Boundary Principles

1. **Execute, do not author.** Services apply published responsibilities; they do not write them.
2. **Contracts authorise.** RC-01…RC-07 bind every material service act.
3. **Evidence non-reinterpretation.** Classifications stay with EIP-002 / WS2 law.
4. **Events non-invention.** CE types stay with WS1 event-processing law.
5. **Meaning non-redefinition.** Programme VI questions and envelopes survive delivery.
6. **Authority non-absorption.** Ownership stays with Programme VII WS2.
7. **Recommendation non-invention.** Tips stay with Programme VII WS3 + Programme VI owners.
8. **State non-invention.** Context postures stay with Programme VII WS4 EST/CST law.
9. **Specification immutability at runtime.** Code never amends constitutional corpora by side effect.
10. **Contract non-bypass.** Product convenience never skips RC bindings.
11. **Technology silence.** Languages, frameworks, queues, APIs, DI, and databases are not constitutional architecture.
12. **Explain the stop.** Students and developers should hear when service execution must refuse.
13. **No emergency exemption.** Load, deadlines, and demos never mint constitutional power.

## 3. What Runtime Services May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Execute constitutional contracts** | Apply RC-01…RC-07 bindings to concrete learner circumstances (RS-01 and specialised services) |
| **Consume constitutional evidence** | Receive and apply published warrants under WS2 / RC-02 (RS-02) |
| **Consume constitutional events** | Receive, evaluate, and execute published CE stimuli under WS1 / MS002 (RS-03) |
| **Produce authorised execution records** | Emit published dispositions, traces, surfaced artefacts, and audit records |
| **Invoke other authorised runtime services** | Compose RS-01…RS-07 without absorbing their authorship |
| **Refuse unlawfully requested acts** | Prefer honest stop / defer / escalate over improvisation |
| **Remain replaceable** | Honour RS meanings in any compliant implementation (RSO-05 / RSO-06) |
| **Explain execution** | Answer service / contracts / evidence / outputs / boundaries without rewriting meaning |

These actions **execute**. They do **not** publish a new Constitution, invent coach questions, mint tips, or author ownership maps.

## 4. What Runtime Services Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Redefine educational meaning** | Programme VI owns coach / planner questions and envelopes | Consume published meaning; escalate for corpus amendment |
| **Redefine authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority / Conflict corpora; refuse domain absorption |
| **Reinterpret evidence** | EIP-002 / EIP-006 / WS2 own observational truth and claim honesty | Consume classifications; leave writers to permitted paths |
| **Invent recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface lawful artefacts or no-recommendation |
| **Modify constitutional specifications** | Constitution / EIP / Programmes VI–VIII are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law in services |
| **Bypass constitutional contracts** | Programme VIII WS1 owns RC catalogue and authorisation | Require named RC bindings before material acts |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Apply published postures / transitions only (RS-06) |
| **Invent constitutional events** | Programme VIII WS1 / MS002 owns CE catalogue | Process only published event classes (RS-03) |
| **Mint mastery / readiness from convenience** | Knowledge & Mastery and Evidence authorities own estimates | Preserve claim ladder; refuse overclaim |
| **Erase educational history** | EIP-005 Continuity | Preserve lawful history across retries and replacements |
| **Elevate implementation technology into constitutional architecture** | RSI-09 / RSO-05 | Keep Python / Flask / DI / microservices / REST / queues / workers / databases out of the constitutional stack |
| **Treat Twin / Adaptive / UI as constitutional authors** | They are consumers / delivery surfaces | Keep them subordinate to Runtime Service + upstream corpora |
| **Present scores as constitutional warrant** | Scores are operational proxies | Cite published corpora and evidence classes |
| **Become irreplaceable by design** | RSO-06 replaceability | Keep services implementation-independent |

## 6. Boundary Checks (Pre-Execution)

Before a material runtime service act, constitutional compliance requires affirmative answers:

1. **Service named?** Which RS-01…RS-07 capability is executing?
2. **Contracts bound?** Which RC-01…RC-07 contracts authorise the act?
3. **Responsibility published?** Which Constitution / EIP / Programme VI / VII / VIII artefact publishes the duty?
4. **Evidence lawful?** If evidence is used, is it consumed under WS2 / RC-02 without reinterpretation?
5. **Events lawful?** If events are used, are they published CE classes under WS1 / MS002?
6. **Outputs authorised?** Are all intended outputs published classes (not invented tips / states / meanings)?
7. **Composition honest?** If other RS services are invoked, do they stay within their permitted responsibilities?
8. **Technology silent?** Is any stack choice being treated as constitutional authorisation? (Must be no.)
9. **Stop explainable?** If any check fails, can the service refuse / defer / escalate with speakable reasons?

A failed check is a **hard stop**, not a soft warning.

---

## 7. Composition Boundaries

When RS services invoke each other:

| Rule | Meaning |
|------|---------|
| **No absorption** | The caller does not inherit the callee’s authorship or expand its own prohibited list |
| **No silent skip** | Required specialised responsibilities (evidence, audit, authority) cannot be omitted by composition convenience |
| **Shared truth** | All composed acts share one constitutional truth for explainability and audit |
| **RC still binds** | Composition never bypasses contract authorisation |

---

## 8. Out of Scope

This milestone does **not** implement:

- Runtime A service graphs or adapters
- Python / Flask / DI / microservice topologies
- REST APIs, queues, schedulers, or workers
- Databases, analytics, or UI enforcement layers

Those may later *obey* these boundaries. They do not *define* them.

---

## 9. Closing Statement

> **A runtime service that redefines meaning, reinterprets evidence, invents recommendations, modifies specifications, or bypasses contracts is not “flexible architecture.”  
> It is constitutional failure — regardless of how elegant the implementation looks.**
