## 1. Purpose

An expert IFoA tutor does not optimise “services deployed” or “endpoints hot.” The tutor optimises **faithful educational execution**: the student experiences the constitutional voice that was already authorised — with honest evidence, intact ownership, reconstructable history, and replaceable machinery.

These objectives bind every Runtime A service capability and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### RSO-01 — Execute constitutional responsibilities

**Definition.** Ensure that runtime services apply only published constitutional responsibilities from the Constitution, EIP, Programme VI, Programme VII, and Programme VIII WS1 / WS2 — or honestly refuse when no published responsibility authorises the act.

**Includes:**

- Consuming RC-01…RC-07 contracts before material execution.
- Consuming published constitutional evidence under WS2 law.
- Consuming published constitutional events under WS1 / MS002 law.
- Executing only RS-01…RS-07 catalogue capabilities for material acts.
- Producing only authorised execution outputs (records, dispositions, surfaced artefacts, audit trails).
- Preferring lawful refusal / deferral / escalation over invented certainty.

**Excludes:**

- Inventing unpublished responsibilities, tips, owners, evidence classes, or state postures “to keep the product moving.”
- Optimising for engagement, latency, or conversion as a substitute for constitutional fidelity.
- Treating Version 2 Adaptive / Twin / Experience heuristics as replacements for Programmes VI–VIII.
- Executing “close enough” approximations of constitutional responsibilities without documenting a corpus amendment.

**Tutor rationale.** Professional exam preparation fails when the software coach improvises educational law. Service execution is care; improvisation is harm.

---

## 3. Supporting Objectives

### RSO-02 — Preserve deterministic behaviour

**Definition.** Ensure that the same published constitutional inputs — contracts, evidence, events, and learner circumstances as classified — yield the same authorised execution outputs for a given service capability, absent a published corpus amendment.

**Tutor rationale.** A tutor who gives contradictory advice for identical warrants is not adaptive; they are unreliable. Determinism is educational honesty under load and iteration.

**Manifestations:**

- Service outcomes are reconstructable from published inputs and catalogue rules.
- Hidden heuristics, A/B winners, or undocumented “smart defaults” are not constitutional inputs.
- Non-determinism introduced by infrastructure (clocks, queues, caches) must not invent educational meaning.
- Refusal / deferral / escalate dispositions are first-class deterministic outcomes when law requires them.

---

### RSO-03 — Preserve auditability

**Definition.** Ensure that every material service execution leaves a reconstructable constitutional trail: which RS service ran, which RC contracts authorised it, which evidence and events were consumed, and which authorised outputs were produced.

**Tutor rationale.** A tutor who cannot later say *why* yesterday’s advice was given cannot be trusted. Services without audit are educational amnesia.

**Manifestations:**

- Audit records preserve constitutional references, not only technical logs.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance is a defect, not an acceptable optimisation.
- RS-07 Audit Service obligations apply to all material executions (directly or by composition).

---

### RSO-04 — Preserve explainability

**Definition.** Ensure that service execution remains speakable under EIP-003: students and developers can answer the constitutional service explainability questions without receiving redefined educational meaning.

**Tutor rationale.** Opaque service graphs recreate black-box tutoring. Clear service speech is part of educational honesty.

**Manifestations:**

- Explanations cite services, contracts, evidence, outputs, and boundaries (`SERVICE_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores and optimiser confidence are never presented as constitutional warrant.
- Explanation never becomes a back door to invent tips or mastery.

---

### RSO-05 — Remain implementation independent

**Definition.** Ensure that RS-01…RS-07 meanings bind *capabilities*, not languages, frameworks, process topologies, storage engines, or API styles.

**Tutor rationale.** If “Contract Execution” only exists as a Flask blueprint, the blueprint has become unlawful constitutional furniture.

**Manifestations:**

- Catalogue entries describe purpose, inputs, outputs, producers, consumers, and permitted / prohibited responsibilities — never required stacks.
- Python classes, DI containers, microservices, REST, queues, and workers are delivery options, not constitutional types.
- Cross-cutting composition of services is described constitutionally, not as a mandatory mesh.

---

### RSO-06 — Remain replaceable

**Definition.** Ensure that any named runtime service implementation is treated as a replaceable executor. Constitutional truth must outlive frameworks, services, databases, and deployment topology.

**Tutor rationale.** If the product can only tell educational truth while a particular service graph exists, that graph has become an unlawful constitution.

**Manifestations:**

- Successor implementations must honour the same RS catalogue and boundaries.
- Storage formats and APIs are delivery details; they are not educational law.
- “Only this microservice can decide” is a governance failure unless the Constitution / Programmes say so.
- RSO-05 implementation independence is the precondition of RSO-06 replaceability.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RSO-01 conflicts with engagement metrics | Constitutional responsibility execution wins |
| RSO-02 conflicts with “smart” non-deterministic personalisation without published warrant | Determinism / honest refusal wins |
| RSO-03 conflicts with log volume reduction that erases constitutional refs | Auditability wins |
| RSO-04 conflicts with cryptic internal jargon as student speech | Explainability honesty wins |
| RSO-05 conflicts with locking RS meanings to one framework | Implementation independence wins |
| RSO-06 conflicts with lock-in to a single service mesh | Replaceability wins |

No supporting objective authorises violating RSO-01.

---

## 5. Non-Objectives

Runtime services do **not** optimise for:

- tip volume, click-through, or streak theatre as educational success;
- inventing educational certainty when warrants are incomplete;
- collapsing Programmes VI–VIII into one mega-service;
- making any RS implementation irreplaceable;
- using Twin / Adaptive estimates as substitutes for constitutional producers;
- treating documentation as optional commentary on code behaviour;
- elevating queues, schedulers, workers, or DI into constitutional architecture.

---

## 6. Closing Statement

> **A runtime service that is fast, polished, and constitutionally unfaithful is a failed educational system.  
> A runtime service that is replaceable, auditable, deterministic, and faithful to published responsibilities is doing its only job.**
