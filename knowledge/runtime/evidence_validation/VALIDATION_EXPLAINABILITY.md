## 1. Purpose

An expert IFoA tutor who cannot say *which warrant* was checked — which validation applied, which contracts authorised the check, what eligibility resulted, and which limits were preserved — is not coaching; they are performing.

After Programmes VI and VII have made meaning, ownership, tips, and context speakable, after Programme VIII WS1 has made contract / event / completion speech speakable, and after Programme VIII WS2 / MS001 has made consumption speech speakable, Programme VIII still needs one validation-speech answer:

> **“Which constitutional evidence was validated, under which constitutional validation, authorised by which contracts, yielding which eligibility outcome, while preserving which boundaries?”**

That answer must cover every material evidence validation without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting evidence, fabricating provenance, inventing unpublished EV types, or presenting eligibility as educational quality.

---

## 2. What Evidence Validation Explainability Is

**Constitutional Evidence Validation Explainability** is the constitutional obligation to narrate **validation of published evidence under published contracts** — not to invent a second tutor voice from validator machinery, and not to grade the student.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Evidence validated** | Named EC-01…EC-07 category (and upstream warrant / artefact ID when applicable) | Which evidence was validated? |
| **Validation applied** | Named EV-01…EV-07 category(ies) | Which constitutional validation was applied? |
| **Authorising contracts** | Named RC-01…RC-07 binding(s) that authorised validation / contemplated consumption | Which constitutional contracts authorised validation? |
| **Eligibility outcome** | eligible / ineligible / defer / escalate (and composition notes) | What eligibility outcome resulted? |
| **Boundaries preserved** | Explicit confirmation that forbidden modifications / reinterpretations / provenance inventions / substitutes / bypasses did not occur | Which constitutional boundaries were preserved? |

Evidence Validation Explainability is:

- **eligibility-centred** — it narrates checks → disposition under law;
- **catalogue-bound** — every justification cites published EV, EC, and RC identities;
- **corpus-bound** — every justification cites published producers;
- **non-transformative** — explanation never becomes a back door to rewrite warrants;
- **quality-honest** — eligibility is never narrated as mastery, readiness, or educational quality;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, WS1 contract / event / completion speech, or MS001 consumption speech;
- **audit-aligned** — explanation components match RC-07 / EV-07 reconstruction needs;
- **determinism-honest** — explanations must not paper over race-dependent dispositions.

Evidence Validation Explainability is **not**:

- a rewrite of EIP-002 Educational Evidence meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for MS001 consumption explainability or WS1 contract / event / completion explainability corpora;
- a rendering system, UI template, log shipper, schema console, or analytics dashboard;
- a claim that clear validation speech guarantees learning or a pass;
- a licence to present scores, acks, cache hits, or optimiser confidence as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material constitutional evidence validation should answer all five questions:

### EVEQ-01 — Which evidence was validated?

Name the primary EC-01…EC-07 category. When an upstream warrant or Programme VII artefact applies, also name it (for example EC-01 ← EIP-002 observation class; EC-03 ← workflow completion evidence ID). Unpublished payload names are not constitutional evidence.

### EVEQ-02 — Which constitutional validation was applied?

Name the primary EV-01…EV-07 category(ies). Cross-cutting validation names all bound categories (for example EV-01 + EV-02 + EV-03 + EV-06 + EV-07). “Schema compiled” is not a constitutional validation.

### EVEQ-03 — Which constitutional contracts authorised validation?

Name the primary RC-01…RC-07 contract(s). Cross-cutting validation names all bound contracts (for example RC-02 + RC-05 + RC-07). “Validator service was reachable” is not a constitutional contract.

### EVEQ-04 — What eligibility outcome resulted?

Distinguish:

- **eligible** — required checks passed; consumption may proceed under MS001 exactly as published;
- **ineligible** — required checks failed; consumption for the contemplated act must not proceed;
- **defer** — published law requires waiting (for example missing non-forged provenance still expected under continuity);
- **escalate** — published law requires human / corpus / authority escalation paths.

Never narrate eligibility as “student is ready,” “mastery confirmed,” or “evidence improved.”

### EVEQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `VALIDATION_BOUNDARIES.md` that were checked — especially non-modification, non-reinterpretation, non-invention of provenance, non-creation of substitute evidence, non-bypass of validation requirements, and non-equation of eligibility with educational quality or constitutional truth.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **EVEC-01** | Evidence identity | Named EC-01…EC-07 (+ upstream warrant / artefact ID when applicable) |
| **EVEC-02** | Validation identity | Named EV-01…EV-07 binding(s) |
| **EVEC-03** | Contract identity | Named RC-01…RC-07 binding(s) |
| **EVEC-04** | Authorising corpus refs | Documented constitutional producers |
| **EVEC-05** | Integrity note | Confirmation that evidence was intact as published (or failed EV-01) |
| **EVEC-06** | Provenance note | Producer / succession / continuity refs confirmed (or failed EV-02) |
| **EVEC-07** | Eligibility disposition | eligible / ineligible / defer / escalate with composition |
| **EVEC-08** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **EVEC-09** | Determinism note | Disposition reproducibility from published inputs |
| **EVEC-10** | Refusal / deferral honesty | When no lawful eligibility existed, say so |
| **EVEC-11** | Continuity note | Prior lawful history not erased (EIP-005) |
| **EVEC-12** | Non-claim honesty | Explicit refusal of mastery / pass / quality / meaning-rewrite / evidence-invention / substitute-evidence overclaim |
| **EVEC-13** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |

Components are **constitutional content obligations**, not database columns, API fields, schema headers, or UI widgets. Persistence and rendering are out of scope for this milestone.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | Whether a warrant could lawfully support the next step, why a stop occurred, and what limits apply — in plain educational language | Internal EV/EC/RC IDs as theatre; validator traces; scores as “proof you are ready”; eligibility as mastery |
| **Developer / auditor** | Full EVEQ-01…05 answers, corpus paths, EV/EC/RC IDs, eligibility composition, boundary checks, determinism notes | Product success metrics, cache hits, or ack counts substituted for constitutional refs; eligibility framed as educational quality |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 6. Layering with Upstream Explainability

| Layer | Corpus job | Evidence-validation speech role |
|-------|------------|----------------------------------|
| EIP-002 Educational Evidence meaning | What observational warrants of understanding are | Confirm intact classifications; never rewrite or grade quality |
| Programme VI coach / planner explainability | Why educational guidance is warranted | Never reinterpret via validators |
| Programme VII workflow / completion explainability | How orchestration flowed / what completion evidence held | Validate when EC-03 is at stake |
| Programme VII authority explainability | Why a component was permitted to decide | Narrate EV-04 under RC-04 |
| Programme VII recommendation explainability | Why a tip / set is speakable | Validate before surfacing under EC-05 / RC-05 |
| Programme VII state explainability | Why context is live / how it succeeded | Narrate EV-05 under RC-06 |
| Programme VIII contract explainability (WS1 / MS001) | Which runtime contract executed under which law | Compose with; do not replace |
| Programme VIII event / completion explainability | Which event / execution cycle applied | Compose with when stimuli or completion referenced validated evidence |
| Programme VIII evidence consumption explainability (WS2 / MS001) | Which constitutional evidence was consumed under which contract | Follows eligibility; compose with ECEQ speech |
| **Programme VIII evidence validation explainability (WS2 / MS002)** | **Which evidence was validated under which EV / RC with which eligibility** | **This document** |

A complete material journey may carry every layer that applied. Validation speech without upstream warrant is hollow. Upstream warrant without EV/EC/RC identity and eligibility disposition invites silent reimplementation drift.
