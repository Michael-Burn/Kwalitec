## 1. Purpose

Runtime that silently turns “evidence was handled” into “student succeeded,” “warrant was high quality,” “workflow closed,” “ownership moved,” or “the Constitution now says X” destroys student trust and educational integrity.

This document draws a bright line between **lawful evidence-consumption-completion confirmation** (Programme VIII / WS2 / MS003) and **educational / quality / orchestration / authorship judgements** owned elsewhere.

---

## 2. Boundary Principles

1. **Confirm evidence handling, do not author meaning.** Completion affirms fulfilment of published evidence duties; it does not create educational truth.
2. **Evidence handling only.** Learning, mastery, progress, and evidence quality are never inferred from close.
3. **Not workflow completion.** Programme VII owns orchestration fulfilment.
4. **Not execution-cycle completion by itself.** WS1 / MS003 owns runtime execution-cycle fulfilment (orthogonal).
5. **Not constitutional amendment.** Close never patches law.
6. **Exactly as published.** Close never reinterprets or modifies warrants.
7. **Published criteria only.** Timers, acks, cache hits, and queue emptiness are not fulfilment law.
8. **Published records only.** Audit continuity is constitutional, not free-form log theatre.
9. **Reference validation honestly.** EV outcomes may be cited; validation law is not rewritten by citing them.
10. **Reference consumed evidence honestly.** EC instances may be cited; evidence meaning is not rewritten by citing them.
11. **Reference hand-off honestly.** Authorised recipients may be cited; hand-off never invents new sinks or mutation rights.
12. **Authority non-transfer.** Ownership stays with the Authority Model.
13. **Meaning non-reinterpretation.** Programme VI questions survive close intact.
14. **Evidence non-reinterpretation / non-modification.** Classifications and content stay with published producers.
15. **State / tip non-invention.** Context postures and recommendations stay with WS4 / WS3 + Programme VI owners.
16. **Determinism.** Race-dependent completion is a defect.
17. **Explain the stop.** Students and developers should hear when close must be refused.
18. **No emergency exemption.** Load, deadlines, and demos never mint completion power.

## 3. What Runtime Completion May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Confirm evidence lifecycle completion** | Affirm ECC-01…ECC-05 when published criteria hold for a lawful evidence-handling concern |
| **Reference validation outcomes** | Cite EV-01…EV-07 dispositions that belonged to the concern under MS002 — without redefining EV law or judging educational quality |
| **Reference consumed evidence** | Cite EC-01…EC-07 instances consumed under MS001 — without reinterpreting or modifying them |
| **Reference execution hand-off** | Cite authorised constitutional recipients / process hand-offs required by published path law |
| **Preserve audit continuity** | Keep constitutional refs intact across retries, replacements, and redeploys (EIP-005) |
| **Refuse unlawful close** | Prefer honest not-yet / refuse-close over improvisation |
| **Remain deterministic** | Same published inputs → same completion judgement class |
| **Remain replaceable** | Honour completion law in any compliant implementation |
| **Explain completion** | Answer evidence / validations / contracts / responsibilities / boundaries without rewriting meaning |

These actions **confirm**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, certify mastery, certify evidence quality, or close Programme VII workflows by declaration.

## 4. What Runtime Completion Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Reinterpret evidence** | Producers / EIP-002 / Programme VI–VII own evidence meaning | Consume and cite exactly as published; escalate for corpus amendment |
| **Modify evidence** | Completion is non-transformative | Leave warrants unchanged; refuse / escalate when intact handling is impossible |
| **Imply educational success** | Educational success is not an evidence-handling property | Say evidence-handling responsibilities are fulfilled; remain silent on mastery / progress / pass |
| **Imply evidence quality** | Quality / sufficiency judgements are not this Model’s job | Cite eligibility / consumption fulfilment only; never announce “strong enough” warrants |
| **Imply workflow completion** | Programme VII WS1 / MS003 owns orchestration fulfilment | Affirm evidence consumption completion only; require Programme VII corpus for workflow close |
| **Imply WS1 execution-cycle completion** | Programme VIII / WS1 / MS003 owns REC fulfilment | Affirm ECC completion only; require REC corpus for execution-cycle close |
| **Alter constitutional specifications** | Constitution / EIP / Programmes VI–VIII are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law in a completion handler |
| **Imply Programme VI educational completion** | Coach / planner completion models own educational fulfilment where defined | Keep educational completion judgements with Programme VI |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority / Conflict corpora; refuse domain absorption at close |
| **Invent tips / state / evidence classes at close** | WS3 / WS4 / EIP-002 writers own those artefacts | Surface only already-authorised outputs or none |
| **Treat timers / acks / cache hits / queue-empty as fulfilment** | Operational proxies are not completion law | Evaluate ECC-01…ECC-05 |
| **Treat Twin / Adaptive / UI done-flags as publishers of completion law** | They are consumers / delivery surfaces | Require published criteria or refuse |
| **Become irreplaceable by completion topology** | Replaceability | Keep completion law implementation-independent |
| **Erase continuity to force a clean close** | EIP-005 | Preserve history; re-enter at published points |

## 6. Boundary Checks (Pre-Affirmation)

Before a material evidence consumption completion is affirmed, confirmation requires affirmative answers:

| Check | Question |
|-------|----------|
| **ECB-C-01 Handling lawfulness** | Did published WS2 / MS001–MS002 handling exist (not completion theatre for never-started work)? |
| **ECB-C-02 Criteria** | Do ECC-01…ECC-05 hold? |
| **ECB-C-03 Non-reinterpretation** | Does affirmation avoid reinterpreting constitutional evidence meaning? |
| **ECB-C-04 Non-modification** | Does affirmation avoid modifying, enriching, or rewriting warrants? |
| **ECB-C-05 Learner-success non-claim** | Does affirmation avoid implying learner success, progress, mastery, or pass? |
| **ECB-C-06 Quality non-claim** | Does affirmation avoid implying evidence quality or educational sufficiency? |
| **ECB-C-07 Workflow non-claim** | Does affirmation avoid implying Programme VII workflow completion? |
| **ECB-C-08 Execution-cycle non-claim** | Does affirmation avoid implying WS1 REC completion by itself? |
| **ECB-C-09 Authority** | Does affirmation avoid transferring ownership / inventing permission? |
| **ECB-C-10 Spec immutability** | Does affirmation avoid modifying constitutional specifications? |
| **ECB-C-11 Validation honesty** | Are validation references limited to published EV outcomes without rewriting EV law? |
| **ECB-C-12 Consumption honesty** | Are consumed-evidence references limited to published EC instances without rewriting EC law? |
| **ECB-C-13 Hand-off honesty** | Were hand-offs only to authorised constitutional processes? |
| **ECB-C-14 Record honesty** | Do evidence records support the judgement without substituting ack / cache theatre? |
| **ECB-C-15 Continuity** | Is audit continuity preserved (EIP-005)? |
| **ECB-C-16 Determinism** | Is the judgement reproducible from published inputs? |
| **ECB-C-17 Explainability** | Can ECCQ questions in `COMPLETION_EXPLAINABILITY.md` be answered honestly? |

Any failed check → not yet / refuse close. Do not “best-effort” invent fulfilment.
