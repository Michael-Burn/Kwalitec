## 1. Purpose

An expert IFoA tutor who cannot say *which constitutional execution* finished — which contracts were satisfied, which events were processed, which outputs were produced, and which limits were preserved — is not closing honestly; they are performing.

After Programmes VI and VII have made meaning, ownership, tips, context, and orchestration fulfilment speakable, and after MS001 / MS002 have made contracts and event processing speakable, Programme VIII still needs one completion-speech answer:

> **“Which constitutional execution completed, under which contracts, processing which events, producing which outputs, while preserving which boundaries?”**

That answer must cover every material affirmed (or refused) completion without inventing educational success, transferring authority, minting tips, inventing state, rewriting evidence, claiming workflow close, or modifying constitutional law.

---

## 2. What Execution Completion Explainability Is

**Runtime Execution Completion Explainability** is the constitutional obligation to narrate **fulfilment (or lawful refusal of fulfilment) of published execution responsibilities** — not to invent a second tutor voice from exit codes or celebration UI.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Execution completed** | Named published execution cycle / path identity under MS001 / MS002 | Which constitutional execution completed? |
| **Contracts satisfied** | Named RC-01…RC-07 binding(s) whose obligations were met for the cycle | Which constitutional contracts were satisfied? |
| **Events processed** | Named CE-01…CE-07 instances (and upstream stimuli when applicable) that belonged to the cycle | Which constitutional events were processed? |
| **Outputs produced** | Published execution results / records authorised for the cycle | Which execution outputs were produced? |
| **Boundaries preserved** | Explicit confirmation that forbidden overclaims / inventions / transfers / amendments did not occur | Which constitutional boundaries were preserved? |

Execution Completion Explainability is:

- **fulfilment-centred** — it narrates why REC criteria hold (or why close is refused);
- **catalogue-bound** — every justification cites published RC / CE identities where applicable;
- **corpus-bound** — every justification cites published producers and path law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip / educational-completion speech, Programme VII ownership / workflow / workflow-completion speech, or MS001 / MS002 contract / event speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, workflow close, or law change;
- **audit-aligned** — explanation components match RC-07 reconstruction needs;
- **determinism-honest** — explanations must not paper over race-dependent completion flags.

Execution Completion Explainability is **not**:

- a rewrite of Programme VI educational meaning or educational-completion explainability;
- a substitute for Programme VII workflow-completion explainability;
- a substitute for MS001 contract or MS002 event explainability corpora;
- a rendering system, UI template, log shipper, broker console, or analytics dashboard;
- a claim that clear completion speech guarantees learning or a pass;
- a licence to present scores, timers, acks, or optimiser confidence as constitutional proof.

## 3. Mandatory Explanation Questions

Every material completion judgement (affirm or refuse close) should answer all five questions:

### CEAQ-01 — Which constitutional execution completed?

Name the published execution cycle / path identity and its constitutional concern. If completion is refused, name the cycle that was assessed and state that fulfilment was not affirmed. “Job finished” or “handler returned” is not a constitutional execution identity.

### CEAQ-02 — Which constitutional contracts were satisfied?

Name the primary RC-01…RC-07 contract(s) whose obligations were met for the cycle (or which failed when refusing close). Cross-cutting cycles name all bound contracts (for example RC-03 + RC-05 + RC-07). “Service healthy” is not a constitutional contract.

### CEAQ-03 — Which constitutional events were processed?

Name CE-01…CE-07 instances that belonged to the cycle. When an upstream Programme VII stimulus applies, also name it (for example CE-02 ← WE-03). If the cycle processed no constitutional events, say so explicitly — do not invent event theatre. Unpublished payload names are not constitutional events.

### CEAQ-04 — Which execution outputs were produced?

Name only published output classes: workflow advances / events, authority dispositions, recommendation artefacts / sets, EST/CST postures, audit / execution records, or explicit refuse/defer/escalate outcomes. Missing required outputs must be spoken when refusing close.

### CEAQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `COMPLETION_BOUNDARIES.md` that were checked — especially non-redefinition of meaning, non-implication of learner success, non-implication of workflow completion, non-transfer of authority, and non-modification of constitutional specifications.

| ID | Component | Obligation |
|----|-----------|------------|
| **CEAC-01** | Execution identity | Named published cycle / path (or assessed cycle if refuse) |
| **CEAC-02** | Judgement class | Affirm / not yet / refuse close |
| **CEAC-03** | Criteria map | Which REC-01…REC-05 held or failed |
| **CEAC-04** | Contract identity | Named RC-01…RC-07 binding(s) |
| **CEAC-05** | Event identity | Named CE-01…CE-07 (+ upstream stimulus ID when applicable), or explicit none |
| **CEAC-06** | Authorising corpus refs | Documented constitutional producers / path law |
| **CEAC-07** | Output catalogue | What published artefacts / dispositions / records resulted |
| **CEAC-08** | Execution record refs | RC-07 / CE-06 trails supporting the judgement |
| **CEAC-09** | Boundary preservation record | Confirmation that forbidden acts / overclaims did not occur |
| **CEAC-10** | Determinism note | Judgement reproducibility from published inputs |
| **CEAC-11** | Continuity note | Prior lawful history not erased (EIP-005) |
| **CEAC-12** | Non-claim honesty | Explicit refusal of mastery / progress / workflow-complete / constitution-amendment overclaim |
| **CEAC-13** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |
| **CEAC-14** | Provenance integrity | Constitutional refs survived packaging into speech / audit |

Components are **constitutional content obligations**, not database columns, API fields, queue headers, or UI widgets. Persistence and rendering are out of scope for MS003.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational or constitutional law |
|----------|----------|----------------------------------------------------|
| **Student** | That the system finished the constitutional machine steps it was allowed to take, what happened next (if anything), and what was *not* being claimed — in plain educational language | Internal REC/RC/CE IDs as theatre; “you have mastered this”; “your study plan is complete” from runtime close alone; broker traces; optimiser scores as “proof you are ready” |
| **Developer / auditor** | Full CEAQ-01…05 answers, corpus paths, RC/CE IDs, REC criteria map, boundary checks, determinism / continuity notes, provenance | Product success metrics, ack counts, or latency SLOs substituted for constitutional refs; silent collapse into Programme VII workflow-completion speech |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 6. Layering with Upstream Explainability

| Layer | Corpus job | Completion speech role |
|-------|------------|------------------------|
| Programme VI coach / planner explainability | Why educational guidance is warranted / when educational completion holds | Consume; do not rewrite; do not certify |
| Programme VII workflow explainability | How orchestration flowed | May reference; never absorb as runtime completion |
| Programme VII workflow-completion explainability | Why orchestration responsibilities are fulfilled | Orthogonal neighbour — compose carefully; never substitute |
| Programme VII authority explainability | Why a component was permitted to decide | Confirm no transfer at close |
| Programme VII recommendation explainability | Why a tip / set is speakable | Narrate only authorised outputs already produced |
| Programme VII state explainability | Why context is live / how it succeeded | Narrate only published postures already produced |
| Programme VIII contract explainability (MS001) | Which runtime contract executed under which law | Compose with; do not replace |
| Programme VIII event explainability (MS002) | Which constitutional event was processed under which contract | Compose with; do not replace |
| **Programme VIII completion explainability (MS003)** | **Which constitutional execution completed under which contracts / events / outputs / boundaries** | **This document** |

A complete material journey may carry every layer that applied. Completion speech without upstream warrant is hollow. Upstream warrant without REC / RC / CE honesty invites silent “done” drift.
