## 1. Purpose

An expert IFoA tutor does not optimise “jobs drained,” “handlers exited,” or “green checkmarks shown.” The tutor optimises **honest closing of constitutional work**: when the published execution duties for a cycle are done, the tutor can say so — without pretending the student has mastered the topic, without pretending a whole educational workflow is finished, and without rewriting the syllabus because the machinery stopped cleanly.

These objectives bind every Runtime A completion behaviour and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### RECO-01 — Confirm lawful execution

**Definition.** Ensure that runtime affirms completion only when a published execution cycle under MS001 / MS002 has fulfilled its constitutional execution responsibilities — or honestly refuses close when fulfilment criteria are not met.

**Includes:**

- Assessing only cycles that lawfully opened under RC-01…RC-07 (and CE processing when events applied).
- Affirming completion only when `COMPLETION_CRITERIA.md` conditions hold.
- Preferring lawful “not yet” / refuse-close over inventing a “done enough” status for product convenience.
- Distinguishing lawful stop dispositions (refuse / defer / escalate as published outcomes) from abandoned duties.
- Binding every material completion judgement to reconstructable constitutional references.

**Excludes:**

- Declaring complete because a queue drained, a process exited, or a UI spinner stopped.
- Treating Twin / Adaptive / Experience / Mission heuristics as completion warrants.
- Optimising for throughput, latency, or engagement as a substitute for fulfilment honesty.
- Collapsing “execution complete” into “student succeeded,” “workflow complete,” or “constitution updated.”

**Tutor rationale.** Professional exam preparation fails when software celebrates unfinished work — or celebrates finished machinery as finished learning. Honest confirmation is care; completion theatre is harm.

---

## 3. Supporting Objectives

### RECO-02 — Preserve constitutional integrity

**Definition.** Ensure that affirming execution completion never redefines Programme VI meaning, transfers ownership, invents tips, invents EST/CST postures, reinterprets Evidence, bypasses Programme VII workflow law, or modifies constitutional specifications.

**Tutor rationale.** A close that “helpfully” rewrites revision as first learning, or coverage as mastery, or ownership as “whoever finished the job,” destroys constitutional layering even if the completion UX looks tidy.

**Manifestations:**

- Completion consumes published law; it does not amend it.
- Forbidden actions in `COMPLETION_BOUNDARIES.md` are hard stops.
- MS001 RCO-02 / RCO-03 and MS002 EPO-03 integrity obligations remain binding at close.
- Affirmed completion never grants EIP-001 mutation rights by proximity to a finished cycle.

---

### RECO-03 — Preserve deterministic execution

**Definition.** Ensure that the same published cycle facts, the same published learner constitutional inputs, and the same published corpora yield the same completion judgement class (affirm / not yet / refuse close) — absent a published non-deterministic exception (none are granted by this Model for educational or constitutional meaning).

**Tutor rationale.** A coach who sometimes declares a cycle complete and sometimes not for the same published facts, depending on which server woke first, is not coaching; they are gambling with educational honesty.

**Manifestations:**

- Criteria evaluation is corpus-bound and reproducible.
- Infrastructure concurrency, sharding, and retry jitter must not change the completion judgement class.
- Race-dependent “done” flags are constitutional defects.
- “Eventually consistent execution fulfilment” is a constitutional defect.

---

### RECO-04 — Support auditability

**Definition.** Ensure that every material completion judgement leaves a reconstructable constitutional trail: which cycle / path completed, which contracts were satisfied, which events were processed (if any), which outputs and records were produced, and which boundaries were preserved.

**Tutor rationale.** A tutor who cannot later say *why* a cycle was closed cannot be trusted. Completion without audit is educational amnesia dressed as cleanliness.

**Manifestations:**

- Audit records preserve constitutional references, not only technical exit codes.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance is a defect, not an acceptable optimisation.
- RC-07 Audit Contract obligations apply to all material completion judgements.

---

### RECO-05 — Support explainability

**Definition.** Ensure that runtime execution completion remains speakable under EIP-003: students and developers can answer the mandatory completion explainability questions without receiving redefined educational meaning, false learning claims, false workflow claims, or invented constitutional amendments.

**Tutor rationale.** Opaque “done” recreates black-box tutoring. Clear completion speech is part of educational honesty.

**Manifestations:**

- Explanations cite execution identity, contracts, events, outputs, and boundaries (`COMPLETION_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores, timers, ack counts, and optimiser confidence are never presented as constitutional fulfilment warrant.
- Explanation never becomes a back door to invent tips, mastery, workflow close, or law change.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RECO-01 conflicts with declaring done for product theatre | Lawful confirmation wins — refuse / not-yet |
| RECO-02 conflicts with convenience rewriting at close | Integrity wins |
| RECO-03 conflicts with race-dependent completion flags | Determinism wins |
| RECO-04 conflicts with log volume reduction that erases constitutional refs | Auditability wins |
| RECO-05 conflicts with cryptic internal jargon as student completion speech | Explainability honesty wins |

No supporting objective authorises violating RECO-01.

These objectives specialise — and never weaken — MS001 RCO-01…RCO-06 and MS002 EPO-01…EPO-05 for the execution-completion horizon.

---

## 5. Non-Objectives

Runtime execution completion does **not** optimise for:

- learner progress theatre, mastery badges, or pass certainty as a side-effect of close;
- collapsing Programme VII workflow completion into runtime handler exit;
- inventing educational certainty when warrants are incomplete;
- making a particular engine, queue, or service irreplaceable;
- using Twin / Adaptive / UI / broker signals as substitutes for fulfilment criteria;
- treating documentation as optional commentary on “done” flags in code.

---

## 6. Closing Statement

> **A runtime that closes cycles quickly, quietly, and constitutionally unfaithfully is a failed educational system.  
> A runtime that affirms completion only when published execution responsibilities are fulfilled — with integrity, determinism, audit, and explainability intact — is doing its only completion job.**
