## 1. Purpose

Runtime that silently turns “handler finished” into “student succeeded,” “workflow closed,” “ownership moved,” or “the Constitution now says X” destroys student trust and educational integrity.

This document draws a bright line between **lawful execution-completion confirmation** (Programme VIII / MS003) and **educational / orchestration / authorship judgements** owned elsewhere.

---

## 2. Boundary Principles

1. **Confirm execution, do not author meaning.** Completion affirms fulfilment of published duties; it does not create educational truth.
2. **Execution only.** Learning, mastery, and progress are never inferred from close.
3. **Not workflow completion.** Programme VII owns orchestration fulfilment.
4. **Not constitutional amendment.** Close never patches law.
5. **Published criteria only.** Timers, acks, and queue emptiness are not fulfilment law.
6. **Published records only.** Audit continuity is constitutional, not free-form log theatre.
7. **Reference events honestly.** Processed CE instances may be cited; event law is not rewritten by citing them.
8. **Authority non-transfer.** Ownership stays with the Authority Model.
9. **Meaning non-reinterpretation.** Programme VI questions survive close intact.
10. **Evidence non-reinterpretation.** Classifications stay with the Evidence Model.
11. **State non-invention.** Context postures stay with WS4 EST/CST law.
12. **Recommendation non-invention.** Tips stay with WS3 + Programme VI owners.
13. **Determinism.** Race-dependent completion is a defect.
14. **Explain the stop.** Students and developers should hear when close must be refused.
15. **No emergency exemption.** Load, deadlines, and demos never mint completion power.

## 3. What Runtime Completion May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Confirm execution completion** | Affirm REC-01…REC-05 when published criteria hold for a lawful cycle |
| **Reference processed constitutional events** | Cite CE-01…CE-07 instances that belonged to the cycle under MS002 — without redefining CE law |
| **Reference execution records** | Point to RC-07 / CE-06 reconstructable trails that support the judgement |
| **Preserve audit continuity** | Keep constitutional refs intact across retries, replacements, and redeploys (EIP-005) |
| **Refuse unlawful close** | Prefer honest not-yet / refuse-close over improvisation |
| **Remain deterministic** | Same published inputs → same completion judgement class |
| **Remain replaceable** | Honour completion law in any compliant implementation |
| **Explain completion** | Answer execution / contracts / events / outputs / boundaries without rewriting meaning |

These actions **confirm**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, certify mastery, or close Programme VII workflows by declaration.

---

## 4. What Runtime Completion Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Redefine constitutional meaning** | Programme VI / Constitution / EIP own educational and integrity meaning | Consume published meaning; escalate for corpus amendment |
| **Imply learner success** | Educational success is not an execution property | Say execution responsibilities are fulfilled; remain silent on mastery / progress / pass |
| **Imply workflow completion** | Programme VII WS1 / MS003 owns orchestration fulfilment | Affirm runtime execution completion only; require Programme VII corpus for workflow close |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority / Conflict corpora; refuse domain absorption at close |
| **Modify constitutional specifications** | Constitution / EIP / Programmes VI–VIII are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law in a completion handler |
| **Imply Programme VI educational completion** | Coach / planner completion models own educational fulfilment where defined | Keep educational completion judgements with Programme VI |
| **Invent tips / state / evidence classes at close** | WS3 / WS4 / EIP-002 writers own those artefacts | Surface only already-authorised outputs or none |
| **Treat timers / acks / queue-empty as fulfilment** | Operational proxies are not completion law | Evaluate REC-01…REC-05 |
| **Treat Twin / Adaptive / UI done-flags as publishers of completion law** | They are consumers / delivery surfaces | Require published criteria or refuse |
| **Become irreplaceable by completion topology** | RCO-06 replaceability | Keep completion law implementation-independent |
| **Erase continuity to force a clean close** | EIP-005 | Preserve history; re-enter at published points |

## 6. Boundary Checks (Pre-Affirmation)

Before a material execution completion is affirmed, confirmation requires affirmative answers:

| Check | Question |
|-------|----------|
| **CB-01 Cycle lawfulness** | Did a published MS001 / MS002 cycle exist (not completion theatre for never-started work)? |
| **CB-02 Criteria** | Do REC-01…REC-05 hold? |
| **CB-03 Meaning** | Does affirmation avoid redefining Programme VI educational meaning? |
| **CB-04 Learner-success non-claim** | Does affirmation avoid implying learner success, progress, mastery, or pass? |
| **CB-05 Workflow non-claim** | Does affirmation avoid implying Programme VII workflow completion? |
| **CB-06 Authority** | Does affirmation avoid transferring ownership / inventing permission? |
| **CB-07 Spec immutability** | Does affirmation avoid modifying constitutional specifications? |
| **CB-08 Event honesty** | If events apply, are references limited to published processed CE instances without rewriting CE law? |
| **CB-09 Record honesty** | Do execution records support the judgement without substituting ack theatre? |
| **CB-10 Continuity** | Is audit continuity preserved (EIP-005)? |
| **CB-11 Determinism** | Is the judgement reproducible from published inputs? |
| **CB-12 Explainability** | Can CEAQ questions in `COMPLETION_EXPLAINABILITY.md` be answered honestly? |

Any failed check → not yet / refuse close. Do not “best-effort” invent fulfilment.
