## 1. Purpose

An expert IFoA tutor who cannot say *why* a coordinated boundary action happened — which interfaces participated, which composition pattern applied, which artefacts were exchanged, what resulted, and which boundaries were preserved — is not coaching; they are performing with a prettier facade.

After Programmes VI–VII, Programme VIII WS1–WS3, and WS4 / MS001 have made meaning, ownership, tips, context, contracts, events, evidence, services, and individual interface interactions speakable, Programme VIII WS4 / MS002 still needs one composition-speech answer:

> **“Which interfaces participated, under which composition pattern and artefacts, producing which outputs, while preserving which constitutional boundaries?”**

That answer must cover every material composition without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting evidence, or merging interface identities.

---

## 2. What Composition Explainability Is

**Runtime Interface Composition Explainability** is the constitutional obligation to narrate **coordination among named RI interaction contracts under recognised RIC patterns** — not to invent a second tutor voice, elevate a protocol facade into educational law, or claim that calling another interface merged identities.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Interfaces participated** | Named RI-01…RI-07 interaction contracts and composition roles | Which interfaces participated? |
| **Composition pattern used** | Named RIC-01…RIC-07 coordination form(s) | Which composition pattern was used? |
| **Artefacts exchanged** | Authorised constitutional artefacts passed between participants | Which constitutional artefacts were exchanged? |
| **Outputs produced** | Authorised composition dispositions, artefacts, audit trails, diagnostic records | Which constitutional outputs were produced? |
| **Boundaries preserved** | Explicit confirmation that identities were not merged, capabilities not redefined, technology not elevated, contracts not bypassed, specifications not modified | Which constitutional boundaries were preserved? |

Composition explainability is:

- **participant-centred** — it narrates which RI interfaces composed under which RIC pattern;
- **artefact-honest** — only authorised constitutional artefacts appear in the exchange story;
- **identity-honest** — explanation confirms non-merger and non-absorption of RI identities;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, Programme VIII contract / evidence / service speech, or MS001 interface speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, or mega-interfaces;
- **technology-silent** — explanation never treats REST, GraphQL, gRPC, HTTP, SDKs, or gateways as constitutional warrant;
- **audit-aligned** — explanation components match RI-06 reconstruction needs.

Composition explainability is **not**:

- a rewrite of Programme VI educational meaning explainability;
- a substitute for MS001 interface explainability or Programme VIII contract / event / evidence / service / collaboration explainability;
- a rendering system, UI template, OpenAPI description, log shipper, tracing product, or analytics dashboard;
- a claim that clear composition speech guarantees learning or a pass;
- a licence to present scores, hop counts, or optimiser confidence as constitutional proof;
- a narrative that “the facade owns what the nested interface decided.”

## 3. Mandatory Explanation Questions

Every material runtime interface composition should answer all five questions:

### RICQ-01 — Which interfaces participated?

Name the RI-01…RI-07 interfaces and their composition roles (initiator, participant, specialist, gate, recorder, inspector). Keep each identity distinct — never collapse them into an unnamed mega-interface.

### RICQ-02 — Which composition pattern was used?

Name the RIC-01…RIC-07 pattern(s) that applied. “We batched the calls,” “the BFF aggregated,” “the SDK composed clients,” or “GraphQL resolved nested fields” are not constitutional pattern identities.

### RICQ-03 — Which constitutional artefacts were exchanged?

Distinguish:

- Contract dispositions and evaluation records;
- EIP-002 Educational Evidence / Programme VI warrants / Programme VII orchestration artefacts;
- WS2 validation eligibility outcomes when they gated composition;
- Published CE event processing records when event-facing;
- Recommendation artefacts / sets, EST/CST postures, workflow events as applicable;
- Service catalogue invocation / collaboration refs when RIC-06 applies;
- Explicit refuse / defer / escalate / diagnostic artefacts.

Never present coverage, time, engagement, or Twin estimates as understanding evidence unless the Evidence Model permits that classification. Never treat stack payloads as constitutional artefacts by default.

### RICQ-04 — Which constitutional outputs were produced?

Name only published output classes: composition dispositions, workflow events, authority dispositions, recommendation artefacts / sets, EST/CST postures, evidence-consumption records, service outputs, audit records, diagnostic reports, or explicit refuse/defer/escalate outcomes for the composition as a whole and for material participants.

### RICQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `COMPOSITION_BOUNDARIES.md` that were checked — especially:

- no merger of interface identities;
- no redefinition of constitutional capabilities;
- no exposure of implementation technology as law;
- no bypass of runtime contracts;
- no modification of constitutional specifications;
- no transfer of constitutional responsibilities;
- no alteration of constitutional evidence.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | What happened next, which kinds of help coordinated at the boundary, why it was allowed, what evidence supported it, and what limits apply — in plain educational language | Internal RIC/RI/RC IDs as theatre; protocol traces; optimiser scores as “proof you are ready”; “the system facade owns this now” |
| **Developer / auditor** | Full RICQ-01…05 answers, corpus paths, pattern IDs, interface IDs, artefact exchange graph, boundary checks, non-merger record | Product success metrics or framework / protocol names substituted for constitutional refs |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 9. Out of Scope

- explanation renderers or UI copy systems;
