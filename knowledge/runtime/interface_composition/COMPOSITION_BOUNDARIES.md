## 1. Purpose

Composing interfaces that silently become a second constitution — merging RI identities into one facade, redefining capabilities by endpoint grouping, or skipping contracts because “the other interface was already authorised” — destroy student trust and educational integrity.

This document draws a bright line between **lawful composition** (Programme VIII WS4 / MS002) and **constitutional authorship / identity merger** (forbidden relative to Constitution / EIP / Programmes VI–VII / VIII WS1–WS3 / WS4 MS001).

---

## 2. Boundary Principles

1. **Coordinate, do not author.** Composition arranges published interaction contracts; it does not write them.
2. **Preserve MS001 identities.** Each RI participant keeps its named identity and permitted / prohibited exposures.
3. **No identity merger.** Composition never collapses RI types into unpublished mega-interfaces.
4. **No responsibility transfer.** Nesting or sequencing never transfers constitutional duties between interfaces.
5. **No capability redefinition.** Aggregation never invents new RI / RS exposures by convenience.
6. **Contracts authorise.** RC-01…RC-07 bind every material composed interaction; callee success never substitutes for caller (or specialist) RC bindings.
7. **Artefacts only.** Only authorised constitutional artefacts may be exchanged.
8. **Evidence non-alteration.** Classifications stay with EIP-002 / WS2 law through every handoff.
9. **Specification immutability at runtime.** Code never amends constitutional corpora by side effect of composition.
10. **Technology silence.** REST, GraphQL, gRPC, HTTP, WebSockets, SDKs, auth stacks, languages, and frameworks are not constitutional architecture.
11. **Explain the stop.** Students and developers should hear when composition must refuse.
12. **No emergency exemption.** Load, deadlines, and demos never mint compositional constitutional power.

## 3. What Runtime Interface Composition May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate constitutional interfaces** | Compose RI-01…RI-07 under recognised RIC-01…RIC-07 patterns without absorbing identities |
| **Exchange authorised constitutional artefacts** | Pass contract dispositions, evidence records, CE traces, execution artefacts, service outputs, audit refs, and diagnostic reports exactly as published |
| **Preserve interface identities** | Keep each participating RI speakable and distinct in audit and explanation |
| **Preserve explainability** | Answer participants / pattern / artefacts / outputs / preserved boundaries without rewriting meaning |
| **Refuse unlawful composition** | Prefer honest stop / defer / escalate over improvisation or forced merge |
| **Remain technology-neutral** | Honour RIC meanings in any compliant implementation (RICO-03 / RICO-06) |
| **Preserve audit records** | Leave reconstructable trails of participants, patterns, artefacts, and outputs (RI-06) |

These actions **coordinate**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, redefine the Runtime Interface Model, or elevate transports into law.

## 6. Boundary Checks (Pre-Composition)

Before a material runtime interface composition, constitutional compliance requires affirmative answers:

1. **Pattern named?** Which RIC-01…RIC-07 pattern(s) apply?
2. **Participants named?** Which RI-01…RI-07 interfaces participate, and in which roles?
3. **Identities distinct?** Does each participant remain a speakable MS001 RI (no mega-interface merger)?
4. **Capabilities published?** Are all exposed capabilities already published under WS3 / MS001 (no redefinition)?
5. **Contracts bound?** Which RC-01…RC-07 contracts authorise each material interaction?
6. **Artefacts authorised?** Are all exchanged items authorised constitutional artefacts?
7. **Evidence lawful?** If evidence is exchanged or gating, is it consumed under WS2 / RC-02 without alteration?
8. **Outputs authorised?** Are all intended composition outputs published classes?
9. **Technology silent?** Is any REST / GraphQL / gRPC / HTTP / SDK / auth choice being treated as constitutional authorisation? (Must be no.)
10. **Stop explainable?** If any check fails, can the composition refuse / defer / escalate with speakable reasons?

A failed check is a **hard stop**, not a soft warning.

## 7. Composition Boundaries (Specialised)

When RI interfaces compose under RIC patterns:

| Rule | Meaning |
|------|---------|
| **No identity merger** | Composition graphs never invent unpublished mega-interfaces |
| **No absorption** | The outer / initiator does not inherit the inner / specialist’s identity or expand its own prohibited list |
| **No silent skip** | Required specialised interfaces cannot be omitted by composition convenience |
| **No contract bypass** | Prior authorisation for one interaction never substitutes for another interaction’s RC bindings |
| **No capability redefinition** | Grouping endpoints never invents new RI / RS catalogue entries |
| **No evidence alteration** | Artefacts keep claim class through handoffs |
| **No technology as law** | Protocol / SDK / gateway choices never expand constitutional power |
| **Shared truth** | All composed interactions share one constitutional truth for explainability and audit |
| **MS001 unchanged** | Composition never amends the Runtime Interface Model by side effect |

These rules specialise — and never weaken — MS001 `INTERFACE_BOUNDARIES.md` composition rules and `INTERFACE_TYPES.md` §10 Composition Rules.

## 8. Out of Scope

This milestone does **not** implement:

- REST APIs, GraphQL, gRPC, HTTP, or WebSockets
- SDKs, authentication, or networking stacks
- Framework code or dependency injection
- Runtime A composition graphs or adapters
- Databases, analytics, or UI enforcement layers

Those may later *obey* these boundaries. They do not *define* them.
