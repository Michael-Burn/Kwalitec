## 1. Purpose

An expert IFoA tutor does not optimise “gateways composed” or “OpenAPI paths batched.” The tutor optimises **faithful coordinated exposure**: each specialist API keeps its identity, each bound interface keeps its integrity, the student experiences one constitutional truth, history remains reconstructable, and the machinery stays replaceable.

These objectives bind every Runtime A API composition and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### RACO-01 — Coordinate constitutional API exposure

**Definition.** Ensure that runtime API composition arranges authorised RA-01…RA-07 exposures so that published constitutional interfaces are exposed together when law requires composition — or honestly refuses when no published pattern and contracts authorise the coordination.

**Includes:**

- Selecting only recognised RAC-01…RAC-07 patterns for material compositions.
- Ensuring every participating exposure maps to a recognised RA API under MS001.
- Exposing only published RI-01…RI-07 interfaces through participating APIs.
- Exchanging only authorised constitutional artefacts between participants.
- Producing only authorised constitutional outputs (dispositions, artefacts, audit trails, diagnostic records).
- Preferring lawful refusal / deferral / escalation over invented composition certainty.

**Excludes:**

- Inventing unpublished composition patterns, mega-APIs, or “implied gateways” to keep the product moving.
- Optimising for latency, fan-in, or engagement as a substitute for constitutional fidelity.
- Treating Version 2 Adaptive / Twin / Experience heuristics as replacements for Programmes VI–VIII or MS001.
- Coordinating “close enough” approximations of constitutional APIs without documenting a corpus amendment.

**Tutor rationale.** Professional exam preparation fails when software collapses specialist exposure boundaries for convenience. Composition is care; identity-collapse is harm.

## 3. Supporting Objectives

### RACO-02 — Preserve API identity

**Definition.** Ensure that every composing RA participant retains the named identity and permitted / prohibited exposures established by the Runtime API Model (MS001). Composition may coordinate; it must never merge, rename-away, or absorb API identities into an unpublished mega-API.

**Tutor rationale.** A tutor who “helps” by speaking as every specialist at once has not coordinated — they have erased accountability. APIs that dissolve into one gateway become unlawful mega-authorities.

**Manifestations:**

- Composed exposures name each participating RA distinctly in audit and explanation.
- Pattern selection never invents a new RA type by silent merger.
- Callers do not inherit callees’ exposures or expand their own prohibited lists.
- MS001 catalogue rules (composition, not absorption) remain binding at every handoff.

---

### RACO-03 — Preserve interface integrity

**Definition.** Ensure that every runtime interface exposed through composing APIs retains the published meaning, permitted exposures, and prohibited acts established by the Runtime Interface Model. Composition may coordinate API exposure of interfaces; it must never redefine, absorb, or invent RI contracts.

**Tutor rationale.** An exposure layer that quietly rewrites the interaction contract it claims to surface has stopped exposing law and started inventing it.

**Manifestations:**

- Each material exposure names the bound RI-01…RI-07 interface distinctly.
- Composition never invents unpublished RI types by aggregating API endpoints.
- Bound RI permitted / prohibited exposures remain intact through every composed handoff.
- WS4 interface composition (RIC-*) may be observed or required; it is never redefined by RAC naming.

---

### RACO-04 — Preserve implementation independence

**Definition.** Ensure that RAC-01…RAC-07 meanings bind *coordination forms*, not languages, frameworks, protocols, OpenAPI documents, API gateways, BFF layers, or deployment topologies.

**Tutor rationale.** If “Sequential Composition” only exists as a GraphQL stitch or gateway chain, that transport has become unlawful constitutional furniture.

**Manifestations:**

- Pattern entries describe purpose, participating APIs, permitted / prohibited composition, and outputs — never required stacks.
- REST, GraphQL, gRPC, HTTP, OpenAPI, API gateways, and auth stacks are delivery options, not constitutional pattern types.
- Cross-cutting composition is described constitutionally, not as a mandatory gateway architecture.

---

### RACO-05 — Preserve explainability

**Definition.** Ensure that composition remains speakable under EIP-003: students and developers can answer the constitutional composition explainability questions without receiving redefined educational meaning, merged API identities, or redefined interfaces.

**Tutor rationale.** Opaque gateway graphs recreate black-box tutoring. Clear composition speech is part of educational honesty.

**Manifestations:**

- Explanations cite participating APIs, patterns, exposed interfaces, artefacts, and preserved boundaries (`COMPOSITION_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores and optimiser confidence are never presented as constitutional warrant for composition.
- Explanation never becomes a back door to invent tips, mastery, mega-APIs, or interface redefinitions.

---

### RACO-06 — Preserve auditability

**Definition.** Ensure that every material composition leaves a reconstructable constitutional trail: which RAC pattern applied, which RA APIs participated, which RI interfaces were exposed, which artefacts were exchanged, which outputs were produced, and which boundaries were preserved.

**Tutor rationale.** A tutor team that cannot later say *which specialist exposure boundaries held* cannot be trusted. Composition without audit is educational amnesia with a prettier gateway.

**Manifestations:**

- Audit records preserve constitutional references for the whole composition graph, not only technical hop logs.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance on any material participant is a defect, not an acceptable optimisation.
- RA-06 Audit API obligations apply to composed exposures (directly or via RAC-07 Diagnostic Composition when inspection is the primary act).

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RACO-01 conflicts with engagement or latency metrics | Constitutional coordination wins |
| RACO-02 conflicts with “one mega-API is simpler” | API identity preservation wins |
| RACO-03 conflicts with redefining RI contracts for gateway convenience | Interface integrity wins |
| RACO-04 conflicts with locking RAC meanings to one protocol facade | Implementation independence wins |
| RACO-05 conflicts with cryptic internal gateway jargon as student speech | Explainability honesty wins |
| RACO-06 conflicts with log volume reduction that erases participant / artefact refs | Auditability wins |

No supporting objective authorises violating RACO-01.  
No composition objective authorises violating MS001 API objectives for any participant, or WS4 interface integrity for any exposed RI.

---

## 5. Non-Objectives

Runtime API composition does **not** optimise for:

- endpoint aggregation count, OpenAPI path batching, or protocol fashion as educational success;
- inventing educational certainty when warrants are incomplete;
- collapsing Programmes VI–VIII or RA-01…RA-07 into one mega-API;
- redefining RI-01…RI-07 by composing convenient exposure endpoints;
- making any gateway, OpenAPI document, or SDK irreplaceable;
- using Twin / Adaptive estimates as substitutes for constitutional producers;
- treating documentation as optional commentary on wire behaviour;
- elevating REST, GraphQL, gRPC, HTTP, OpenAPI, API gateways, or auth stacks into constitutional architecture;
- transferring responsibilities “temporarily” for product convenience.

---

## 6. Closing Statement

> **A composition that is fast, elegant, and constitutionally unfaithful is a failed educational boundary.  
> A composition that preserves API identities and interface integrity, remains auditable and explainable, and coordinates only published exposure contracts is doing its only job.**
