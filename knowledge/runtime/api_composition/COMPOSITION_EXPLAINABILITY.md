## 1. Purpose

An expert IFoA tutor who cannot say *why* a coordinated exposure happened — which APIs participated, which composition pattern applied, which runtime interfaces were exposed, which artefacts were exchanged, and which boundaries were preserved — is not coaching; they are performing with a prettier gateway.

After Programmes VI–VII, Programme VIII WS1–WS4, and WS5 / MS001 have made meaning, ownership, tips, context, contracts, events, evidence, services, interfaces, and individual API exposures speakable, Programme VIII WS5 / MS002 still needs one composition-speech answer:

> **“Which APIs participated, under which composition pattern, exposing which runtime interfaces, exchanging which artefacts, while preserving which constitutional boundaries?”**

That answer must cover every material composition without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting evidence, merging API identities, or redefining interfaces.

---

## 2. What Composition Explainability Is

**Runtime API Composition Explainability** is the constitutional obligation to narrate **coordination among named RA exposure contracts under recognised RAC patterns** — not to invent a second tutor voice, elevate a protocol gateway into educational law, claim that calling another API merged identities, or claim that composition redefined interfaces.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **APIs participated** | Named RA-01…RA-07 exposure contracts and composition roles | Which APIs participated? |
| **Composition pattern used** | Named RAC-01…RAC-07 coordination form(s) | Which composition pattern was used? |
| **Runtime interfaces exposed** | Named RI-01…RI-07 interaction contracts surfaced through participating APIs | Which runtime interfaces were exposed? |
| **Artefacts exchanged** | Authorised constitutional artefacts passed between participants | Which constitutional artefacts were exchanged? |
| **Boundaries preserved** | Explicit confirmation that identities were not merged, interfaces not redefined, internals not exposed, contracts not bypassed, specifications not modified | Which constitutional boundaries were preserved? |

Composition explainability is:

- **participant-centred** — it narrates which RA APIs composed under which RAC pattern;
- **interface-honest** — every material exposure names the bound RI without redefinition;
- **artefact-honest** — only authorised constitutional artefacts appear in the exchange story;
- **identity-honest** — explanation confirms non-merger and non-absorption of RA identities;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, Programme VIII contract / evidence / service / interface speech, or MS001 API speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, mega-APIs, or interface redefinitions;
- **technology-silent** — explanation never treats REST, GraphQL, gRPC, HTTP, OpenAPI, or gateways as constitutional warrant;
- **audit-aligned** — explanation components match RA-06 reconstruction needs.

Composition explainability is **not**:

- a rewrite of Programme VI educational meaning explainability;
- a substitute for MS001 API explainability, WS4 interface / interface-composition explainability, or Programme VIII contract / event / evidence / service / collaboration explainability;
- a rendering system, UI template, OpenAPI description, log shipper, tracing product, or analytics dashboard;
- a claim that clear composition speech guarantees learning or a pass;
- a licence to present scores, hop counts, or optimiser confidence as constitutional proof;
- a narrative that “the gateway owns what the nested API decided” or “composition redefined the interface.”

## 3. Mandatory Explanation Questions

Every material runtime API composition should answer all five questions:

### RACQ-01 — Which APIs participated?

Name the RA-01…RA-07 APIs and their composition roles (initiator, participant, specialist, gate, recorder, inspector). Keep each identity distinct — never collapse them into an unnamed mega-API.

### RACQ-02 — Which composition pattern was used?

Name the RAC-01…RAC-07 pattern(s) that applied. “We batched the calls,” “the gateway aggregated,” “OpenAPI composed paths,” “the BFF stitched,” or “GraphQL resolved nested fields” are not constitutional pattern identities.

### RACQ-03 — Which runtime interfaces were exposed?

Name the RI-01…RI-07 interaction contracts surfaced through each participating API. Confirm that each interface retained its published meaning — never narrate interface redefinition, absorption, or mega-interface invention as success. When WS4 interface composition applied, name observed RIC patterns without replacing WS4 explainability.

### RACQ-04 — Which constitutional artefacts were exchanged?

Distinguish:

- Contract dispositions and evaluation records;
- EIP-002 Educational Evidence / Programme VI warrants / Programme VII orchestration artefacts;
- WS2 validation eligibility outcomes when they gated composition;
- Published CE event processing records when event-facing;
- Recommendation artefacts / sets, EST/CST postures, workflow events as applicable;
- Service catalogue invocation / collaboration refs when RA-04 applies;
- Interface exposure records and any RIC observation refs when RAC-05 applies;
- Explicit refuse / defer / escalate / diagnostic artefacts.

Never present coverage, time, engagement, or Twin estimates as understanding evidence unless the Evidence Model permits that classification. Never treat stack payloads, gateway headers, or OpenAPI envelopes as constitutional artefacts by default.

### RACQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `COMPOSITION_BOUNDARIES.md` that were checked — especially:

- no merger of API identities;
- no redefinition of runtime interfaces;
- no exposure of implementation internals as law;
- no bypass of runtime contracts;
- no modification of constitutional specifications;
- no transfer of constitutional responsibilities;
- no alteration of constitutional evidence.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | What happened next, which kinds of help were exposed together, why it was allowed, what evidence supported it, and what limits apply — in plain educational language | Internal RAC/RA/RI/RC IDs as theatre; protocol traces; optimiser scores as “proof you are ready”; “the system gateway owns this now” |
| **Developer / auditor** | Full RACQ-01…05 answers, corpus paths, pattern IDs, API IDs, interface IDs, artefact exchange graph, boundary checks, non-merger and interface-integrity records | Product success metrics or framework / protocol / gateway names substituted for constitutional refs |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.
