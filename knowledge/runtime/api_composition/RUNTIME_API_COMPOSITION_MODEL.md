## 2. What Runtime API Composition Is

**Runtime API composition** is a named **coordination relationship** among **recognised constitutional runtime APIs** (RA-01…RA-07) that **coordinates constitutional exposure** — without becoming a source of educational truth, collapsing distinct exposure contracts into one mega-API, redefining published runtime interfaces, or transferring constitutional responsibilities between APIs.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Participating APIs** | Named RA-01…RA-07 exposure contracts that take part | Which APIs participated? |
| **Composition pattern** | A recognised RAC-01…RAC-07 coordination form | How do they compose? |
| **Exposed interfaces** | Published RI-01…RI-07 interaction contracts surfaced through participating APIs | Which runtime interfaces were exposed? |
| **Exchanged artefacts** | Authorised constitutional artefacts passed between participating APIs | What was exchanged? |
| **Preserved API identities** | Each participant’s MS001 API identity remains intact and speakable | Did anyone become a mega-API? |
| **Preserved interface integrity** | Bound RI contracts retain their published meanings and exposures | Were interfaces redefined? |
| **Composition outputs** | Authorised constitutional outputs produced by the coordinated exposures | What resulted? |
| **Technology silence** | Composition patterns name coordination forms, not transports or gateways | Is composition law, or merely wiring? |

Runtime API composition is:

- **coordination-only** — it sequences, parallels, conditions, nests, or specialises exposure; it does not author law;
- **identity-preserving** — each RA participant keeps its MS001 catalogue identity;
- **interface-integrity-preserving** — composition never redefines, absorbs, or invents RI contracts;
- **responsibility-preserving** — composition never transfers or merges constitutional duties between APIs;
- **artefact-honest** — only authorised constitutional artefacts are exchanged;
- **contract-honouring** — every material composed exposure remains under published RC bindings;
- **implementation-independent** — patterns name coordination forms, not REST, GraphQL, gRPC, HTTP, OpenAPI, or gateways;
- **integrity-preserving** — composition never quietly rewrites meaning, ownership, tips, evidence, or specifications;
- **audit-capable** — composed exposures leave reconstructable constitutional traces;
- **explainable** — students and developers can answer which APIs composed and under which pattern.

Runtime API composition is **not**:

- a second Educational Constitution, EIP, or Runtime API Model;
- a merger of RA-01…RA-07 into a single undifferentiated exposure contract;
- a redefinition of published RI-01…RI-07 interaction contracts;
- a transfer of constitutional responsibilities between APIs or components;
- a licence to invent unpublished composition patterns, interfaces, tips, mastery, or educational context;
- a REST facade, GraphQL schema stitch, gRPC gateway, HTTP aggregator, OpenAPI composition, API gateway, auth middleware, or network topology;
- a claim that successful composition guarantees learning or a pass;
- an amendment to MS001 API identities by proximity or convenience;
- a substitute for WS4 interface composition (RIC-*) — API composition coordinates exposure contracts; interface composition coordinates interaction contracts.
