## 1. Purpose

Composing APIs that silently become a second constitution — merging RA identities into one gateway, redefining interfaces by endpoint grouping, or skipping contracts because “the other API was already authorised” — destroy student trust and educational integrity.

This document draws a bright line between **lawful composition** (Programme VIII WS5 / MS002) and **constitutional authorship / identity merger / interface redefinition** (forbidden relative to Constitution / EIP / Programmes VI–VII / VIII WS1–WS4 / WS5 MS001).

---

## 2. Boundary Principles

1. **Coordinate, do not author.** Composition arranges published exposure contracts; it does not write them.
2. **Preserve MS001 identities.** Each RA participant keeps its named identity and permitted / prohibited exposures.
3. **No identity merger.** Composition never collapses RA types into unpublished mega-APIs.
4. **No interface redefinition.** Composition never alters, absorbs, or invents RI-01…RI-07 contracts.
5. **No responsibility transfer.** Nesting or sequencing never transfers constitutional duties between APIs.
6. **Contracts authorise.** RC-01…RC-07 bind every material composed exposure; callee success never substitutes for caller (or specialist) RC bindings.
7. **Artefacts only.** Only authorised constitutional artefacts may be exchanged.
8. **Evidence non-alteration.** Classifications stay with EIP-002 / WS2 law through every handoff.
9. **Specification immutability at runtime.** Code never amends constitutional corpora by side effect of composition.
10. **Technology silence.** REST, GraphQL, gRPC, HTTP, OpenAPI, API gateways, auth stacks, languages, and frameworks are not constitutional architecture.
11. **Explain the stop.** Students and developers should hear when composition must refuse.
12. **No emergency exemption.** Load, deadlines, and demos never mint compositional constitutional power.

## 3. What Runtime API Composition May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate published runtime APIs** | Compose RA-01…RA-07 under recognised RAC-01…RAC-07 patterns without absorbing identities |
| **Exchange authorised constitutional artefacts** | Pass contract dispositions, evidence records, CE traces, execution artefacts, service outputs, audit refs, and diagnostic reports exactly as published |
| **Preserve API identities** | Keep each participating RA speakable and distinct in audit and explanation |
| **Preserve explainability** | Answer participants / pattern / interfaces / artefacts / preserved boundaries without rewriting meaning |
| **Refuse unlawful composition** | Prefer honest stop / defer / escalate over improvisation or forced merge |
| **Remain implementation-independent** | Honour RAC meanings in any compliant implementation (RACO-04) |
| **Preserve audit records** | Leave reconstructable trails of participants, patterns, interfaces, artefacts, and outputs (RA-06) |

These actions **coordinate**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, redefine the Runtime API Model, redefine runtime interfaces, or elevate transports into law.

## 6. Boundary Checks (Pre-Composition)

Before a material runtime API composition, constitutional compliance requires affirmative answers:

1. **Pattern named?** Which RAC-01…RAC-07 pattern(s) apply?
2. **Participants named?** Which RA-01…RA-07 APIs participate, and in which roles?
3. **Identities distinct?** Does each participant remain a speakable MS001 RA (no mega-API merger)?
4. **Interfaces published and intact?** Which RI-01…RI-07 interfaces are exposed, and are they unchanged (no redefinition)?
5. **Contracts bound?** Which RC-01…RC-07 contracts authorise each material exposure?
6. **Artefacts authorised?** Are all exchanged items authorised constitutional artefacts?
7. **Evidence lawful?** If evidence is exchanged or gating, is it consumed under WS2 / RC-02 without alteration?
8. **Outputs authorised?** Are all intended composition outputs published classes?
9. **Technology silent?** Is any REST / GraphQL / gRPC / HTTP / OpenAPI / gateway / auth choice being treated as constitutional authorisation? (Must be no.)
10. **Stop explainable?** If any check fails, can the composition refuse / defer / escalate with speakable reasons?

A failed check is a **hard stop**, not a soft warning.

## 7. Composition Boundaries (Specialised)

When RA APIs compose under RAC patterns:

| Rule | Meaning |
|------|---------|
| **No identity merger** | Composition graphs never invent unpublished mega-APIs |
| **No absorption** | The outer / initiator does not inherit the inner / specialist’s identity or expand its own prohibited list |
| **No interface redefinition** | Bound RI contracts retain published meaning through every handoff |
| **No silent skip** | Required specialised APIs cannot be omitted by composition convenience |
| **No contract bypass** | Prior authorisation for one exposure never substitutes for another exposure’s RC bindings |
| **No evidence alteration** | Artefacts keep claim class through handoffs |
| **No technology as law** | Protocol / OpenAPI / gateway choices never expand constitutional power |
| **No internals as law** | Private schemas, adapter paths, stack traces, and gateway configs are never constitutional artefacts |
| **Shared truth** | All composed exposures share one constitutional truth for explainability and audit |
| **MS001 unchanged** | Composition never amends the Runtime API Model by side effect |
| **WS4 unchanged** | Composition never amends the Runtime Interface Model by side effect |

These rules specialise — and never weaken — MS001 `API_BOUNDARIES.md` and WS4 interface boundary law.

## 8. Out of Scope

This milestone does **not** implement:

- REST, GraphQL, gRPC, HTTP, or OpenAPI
- Authentication, networking, or API gateways
- Framework code or dependency injection
- Runtime A composition graphs or adapters
- Databases, analytics, or UI enforcement layers

Those may later *obey* these boundaries. They do not *define* them.
