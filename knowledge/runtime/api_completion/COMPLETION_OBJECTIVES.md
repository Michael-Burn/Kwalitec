## 1. Purpose

An expert IFoA tutor does not optimise “gateway finished,” “GraphQL stitch succeeded,” or “OpenAPI aggregate drained.” The tutor optimises **honest closing of coordinated constitutional exposure**: when the published composition duties among specialist APIs are done, the tutor can say so — without pretending the student has mastered the topic, without pretending an interface composition, a lone execution cycle, a service collaboration, or a whole educational workflow is finished, without rewriting who owns which exposure contract because the composed calls stopped cleanly, without redefining the interfaces those APIs exposed, and without elevating a transport technology into law.

These objectives bind every Runtime A API-composition-completion behaviour and every successor runtime that claims constitutional compliance.

## 2. Primary Objective

### RACCO-01 — Confirm lawful API composition

**Definition.** Ensure that runtime affirms Runtime API composition completion only when a published composition under MS001 / MS002 has fulfilled its constitutional composition responsibilities — or honestly refuses close when fulfilment criteria are not met.

**Includes:**

- Assessing only compositions that lawfully opened under RA-01…RA-07 participants, RAC-01…RAC-07 patterns, published RI exposures, and RC-01…RC-07 authorisation.
- Affirming completion only when `COMPLETION_CRITERIA.md` conditions hold.
- Preferring lawful “not yet” / refuse-close over inventing a “composed enough” status for product convenience.
- Distinguishing lawful stop dispositions (refuse / defer / escalate as published composition outcomes) from abandoned composition duties.
- Binding every material completion judgement to reconstructable constitutional references.

**Excludes:**

- Declaring complete because an HTTP response succeeded, a GraphQL stitch resolved, a gRPC gateway exited, an OpenAPI aggregate finished, an SDK batch finished, or a UI spinner stopped.
- Treating Twin / Adaptive / Experience / Mission heuristics as composition completion warrants.
- Optimising for latency, fan-in, or engagement as a substitute for fulfilment honesty.
- Collapsing “API composition complete” into “interface composition complete,” “execution complete,” “collaboration complete,” “student succeeded,” “workflow complete,” or “constitution updated.”

**Tutor rationale.** Professional exam preparation fails when software celebrates unfinished coordination — or celebrates finished gateway choreography as finished learning or finished tutoring duties. Honest confirmation is care; composition-completion theatre is harm.

## 3. Supporting Objectives

### RACCO-02 — Preserve API identity

**Definition.** Ensure that affirming composition completion never merges, absorbs, renames-away, or redefines the named identities and permitted / prohibited exposures established by the Runtime API Model (MS001) for any participant.

**Tutor rationale.** A close that “helpfully” lets the initiator become every specialist, or invents a mega-API because the gateway ended, destroys the RA catalogue even if the completion UX looks tidy.

**Manifestations:**

- Completion consumes MS001 identities; it does not amend them.
- Forbidden actions in `COMPLETION_BOUNDARIES.md` are hard stops — especially identity merger and interface redefinition.
- MS001 RAO / boundary obligations and MS002 RACO-02 remain binding at close.
- Affirmed completion never grants EIP-001 mutation rights or new RA catalogue entries by proximity to a finished composition.

---

### RACCO-03 — Preserve interface integrity

**Definition.** Ensure that affirming composition completion never redefines, absorbs, invents, or silently alters the published RI-01…RI-07 interaction contracts that participating APIs exposed.

**Tutor rationale.** A close that pretends composition “improved” an interface, invented a mega-interface, or absorbed a specialist RI into a gateway narrative has rewritten WS4 law under an “API done” costume.

**Manifestations:**

- Completion consumes published RI meanings; it does not amend them.
- Exposed interfaces remain attributable to their published WS4 identities.
- MS002 RACO interface-integrity obligations remain binding at close.
- Affirmed completion never invents unpublished RI types by aggregation convenience.

---

### RACCO-04 — Preserve implementation independence

**Definition.** Ensure that RACC completion meanings bind *fulfilment of published composition responsibilities*, not languages, frameworks, REST, GraphQL, gRPC, HTTP, OpenAPI, WebSockets, SDKs, authentication stacks, networking topologies, API gateways, or API styles.

**Tutor rationale.** If “composition complete” only exists as an OpenAPI operation succeeded or a BFF aggregate returned 200, the transport has become unlawful constitutional furniture.

**Manifestations:**

- Completion criteria describe constitutional conditions — never required stacks.
- REST, GraphQL, gRPC, HTTP, OpenAPI, gateways, auth, and networking are delivery options, not completion law.
- Replaceability of Runtime A (and successors) survives any particular composition topology.

---

### RACCO-05 — Preserve explainability

**Definition.** Ensure that Runtime API composition completion remains speakable under EIP-003: students and developers can answer the mandatory composition-completion explainability questions without receiving redefined educational meaning, false learning claims, false interface-composition claims, false execution claims, false collaboration claims, false workflow claims, merged identities, redefined interfaces, or invented constitutional amendments.

**Tutor rationale.** Opaque “composition done” recreates black-box tutoring with a gateway costume. Clear completion speech is part of educational honesty.

**Manifestations:**

- Explanations cite participants, patterns, interfaces, requests, responses, and boundaries (`COMPLETION_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores, HTTP codes, stitch success, gateway health, OpenAPI aggregate counts, SDK batch counts, and optimiser confidence are never presented as constitutional fulfilment warrant.
- Explanation never becomes a back door to invent tips, mastery, interface composition completion, execution completion, collaboration completion, workflow close, mega-APIs, redefined interfaces, or law change.

---

### RACCO-06 — Preserve auditability

**Definition.** Ensure that every material composition completion judgement leaves a reconstructable constitutional trail: which APIs participated, which RAC pattern completed, which Runtime Interfaces were exposed, which constitutional requests were processed, which constitutional responses were returned, which composition records were created, and which boundaries were preserved.

**Tutor rationale.** A tutor team that cannot later say *why* coordinated API work was closed cannot be trusted. Composition completion without audit is educational amnesia with more moving parts.

**Manifestations:**

- Audit records preserve constitutional references for the whole composition graph, not only technical request logs or gateway exit codes.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance on any material participant is a defect, not an acceptable optimisation.
- RA-06 / RAC audit composition obligations apply to all material composition completion judgements.

---

### RACCO-07 — Preserve composition-completion determinism

**Definition.** Ensure that the same published composition facts — participating APIs, RAC pattern, exposed interfaces, contracts, processed requests, produced responses, learner constitutional inputs as classified, and published corpora — yield the same completion judgement class (affirm / not yet / refuse close) — absent a published non-deterministic exception (none are granted by this Model for educational or constitutional meaning).

**Tutor rationale.** A coach team that sometimes declares composition complete and sometimes not for the same published facts, depending on which worker woke first or which gateway retry won, is not coaching; they are gambling with educational honesty under composed load.

**Manifestations:**

- Criteria evaluation is corpus-bound and reproducible.
- Infrastructure concurrency, sharding, retry jitter, and race-dependent “aggregate winners” must not change the completion judgement class.
- Race-dependent “composition done” flags are constitutional defects.
- “Eventually consistent composition fulfilment” is a constitutional defect.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RACCO-01 conflicts with declaring done for product theatre | Lawful confirmation wins — refuse / not-yet |
| RACCO-02 conflicts with “one mega-API is simpler after close” | Identity preservation wins |
| RACCO-03 conflicts with “composition improved the interface” | Interface integrity wins |
| RACCO-04 conflicts with locking completion meanings to one protocol, gateway, or OpenAPI shape | Implementation independence wins |
| RACCO-05 conflicts with cryptic gateway jargon as student completion speech | Explainability honesty wins |
| RACCO-06 conflicts with log volume reduction that erases participant / interface / response refs | Auditability wins |
| RACCO-07 conflicts with race-dependent composition-done flags | Determinism wins |

No supporting objective authorises violating RACCO-01.  
No composition-completion objective authorises violating MS001 RAO objectives for any participant, MS002 RACO-01…RACO objectives for the composition being closed, or WS4 interface integrity.

These objectives specialise — and never weaken — MS001 API objectives, MS002 composition objectives, and sibling Programme VIII completion objectives for the *API-composition-completion* horizon.

---

## 5. Non-Objectives

Runtime API composition completion does **not** optimise for:

- learner progress theatre, mastery badges, or pass certainty as a side-effect of close;
- collapsing Runtime Interface Composition Completion (RICC), Runtime Execution Completion (REC), Evidence Consumption Completion (ECC), or Service Collaboration Completion (RSCC) into API composition close;
- collapsing Programme VII workflow completion into gateway exit;
- inventing educational certainty when warrants are incomplete;
- making a particular protocol, gateway, OpenAPI document, or API topology irreplaceable;
- using Twin / Adaptive / UI / gateway signals as substitutes for fulfilment criteria;
- merging API identities “temporarily” because composition ended;
- redefining Runtime Interfaces “for convenience” because composition ended;
- treating documentation as optional commentary on “composition done” flags in code.
