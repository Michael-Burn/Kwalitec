## 2. What Composition Completion Explainability Is

**Runtime API Composition Completion Explainability** is the constitutional obligation to narrate **fulfilment (or lawful refusal of fulfilment) of published API composition responsibilities** — not to invent a second tutor voice from HTTP codes, GraphQL stitches, OpenAPI aggregates, or celebration UI.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **APIs participated** | Named RA-01…RA-07 exposure contracts and composition roles | Which Runtime APIs participated? |
| **Pattern completed** | Named RAC-01…RAC-07 coordination form(s) whose published steps finished or lawfully stopped | Which composition pattern completed? |
| **Runtime Interfaces exposed** | Named RI-01…RI-07 interaction contracts surfaced through participating APIs | Which Runtime Interfaces were exposed? |
| **Constitutional requests processed** | Published constitutional requests accepted and processed under law | Which constitutional requests were processed? |
| **Constitutional responses returned** | Published constitutional responses produced by the composition | Which constitutional responses were returned? |
| **Boundaries preserved** | Explicit confirmation that forbidden mergers / redefinitions / overclaims / inventions / amendments did not occur | Which constitutional boundaries were preserved? |

Composition Completion Explainability is:

- **fulfilment-centred** — it narrates why RACC criteria hold (or why close is refused);
- **participant-centred** — it names which RA APIs participated under which RAC pattern;
- **catalogue-bound** — every justification cites published RA / RAC / RI / RC identities where applicable;
- **interface-honest** — only published Runtime Interfaces appear in the exposure story, without redefinition;
- **request-honest** — only authorised constitutional requests appear in the processing story;
- **response-honest** — only authorised constitutional responses appear in the return story;
- **identity-honest** — explanation confirms non-merger of MS001 API identities and non-redefinition of Runtime Interfaces;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip / educational-completion speech, Programme VII ownership / workflow / workflow-completion speech, Programme VIII REC / ECC / RSCC / RICC speech, MS001 API speech, or MS002 composition speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, interface composition completion, execution completion, collaboration completion, workflow close, mega-APIs, redefined interfaces, or law change;
- **technology-silent** — explanation never treats REST, GraphQL, gRPC, HTTP, OpenAPI, gateways, auth, or networking as constitutional warrant;
- **audit-aligned** — explanation components match RA-06 / RAC reconstruction needs;
- **determinism-honest** — explanations must not paper over race-dependent composition-done flags.

Composition Completion Explainability is **not**:

- a rewrite of Programme VI educational meaning or educational-completion explainability;
- a substitute for Programme VII workflow-completion explainability;
- a substitute for WS1 execution-completion, WS2 evidence-consumption-completion, WS3 collaboration-completion, or WS4 interface-composition-completion explainability;
- a substitute for MS001 API or MS002 composition explainability corpora;
- a rendering system, UI template, OpenAPI description, log shipper, tracing product, API console, or analytics dashboard;
- a claim that clear composition-completion speech guarantees learning, interface composition completion, execution completion, or a pass;
- a licence to present scores, HTTP codes, stitch success, gateway health, OpenAPI aggregate counts, SDK batch counts, or optimiser confidence as constitutional proof;
- a narrative that “the initiator now is every specialist because composition closed” or “composition redefined the interface.”

## 3. Mandatory Explanation Questions

Every material composition completion judgement (affirm or refuse close) should answer all six questions:

### RACCAQ-01 — Which Runtime APIs participated?

Name the RA-01…RA-07 APIs and their composition roles (initiator, participant, specialist, gate, recorder, inspector). If completion is refused, name the participants that were assessed and state that fulfilment was not affirmed. “Gateway healthy” or “endpoints were up” is not a constitutional participant identity.

### RACCAQ-02 — Which composition pattern completed?

Name the RAC-01…RAC-07 pattern(s) that applied and whether they reached published terminal coordination or a published refuse / defer / escalate stop. If refusing close, name which pattern duties remained outstanding. “Aggregate succeeded,” “BFF exited,” or “OpenAPI composed” is not a constitutional pattern identity.

### RACCAQ-03 — Which Runtime Interfaces were exposed?

Name the RI-01…RI-07 interaction contracts surfaced through each participating API. Confirm that each interface retained its published meaning — never narrate interface redefinition, absorption, or mega-interface invention as success. When WS4 interface composition applied, name observed RIC patterns without replacing WS4 explainability or implying RICC completion.

### RACCAQ-04 — Which constitutional requests were processed?

Name only published request classes processed by participating APIs: constitutional requests citing interfaces, contracts, evidence, events, service responsibilities, dispositions, EST/CST postures, workflow events, audit refs, refuse/defer/escalate outcomes, or other corpus-published inputs. Missing required request processing must be spoken when refusing close.

### RACCAQ-05 — Which constitutional responses were returned?

Name only published response classes produced by the composition: dispositions, artefacts, audit trails, diagnostic records, refuse/defer/escalate outcomes, or other corpus-published results. Missing required responses must be spoken when refusing close. Responses remain attributable to participating RA identities — never collapsed into an unpublished mega-response author.

### RACCAQ-06 — Which constitutional boundaries were preserved?

Confirm the hard stops in `COMPLETION_BOUNDARIES.md` that were checked — especially non-merger of API identities, non-redefinition of Runtime Interfaces, non-implication of interface composition completion, non-implication of service collaboration completion, non-implication of execution completion, non-implication of workflow completion, non-implication of educational success, and non-modification of constitutional specifications.
