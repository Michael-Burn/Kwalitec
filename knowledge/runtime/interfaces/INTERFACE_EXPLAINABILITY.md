## 1. Purpose

An expert IFoA tutor who cannot say *what was asked at the boundary*, *which capability was exposed*, and *what lawful result returned* is not coaching; they are performing.

After Programmes VI–VII and Programme VIII WS1–WS3 have made meaning, ownership, tips, context, contracts, evidence, and services speakable, Programme VIII WS4 still needs one interaction-speech answer:

> **“What constitutional interface was used, which capability was exposed, what was exchanged, and which boundaries were preserved?”**

That answer must cover every material interface interaction without inventing educational meaning, transferring authority, minting tips, inventing state, altering evidence, or elevating transports into law.

---

## 2. What Runtime Interface Explainability Is

**Runtime Interface Explainability** is the constitutional obligation to narrate **interaction under published law** — not to invent a second tutor voice or a protocol story that substitutes for constitutional producers.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Interface used** | Named RI-01…RI-07 binding(s) for the interaction | Which constitutional interface was used? |
| **Capability exposed** | Published RS / WS1 / WS2 capability surfaced through the interface | Which constitutional capability was exposed? |
| **Inputs received** | Authorised constitutional request shapes actually accepted | Which constitutional inputs were received? |
| **Outputs returned** | Authorised constitutional dispositions / artefacts / audit / diagnostic records returned | Which constitutional outputs were returned? |
| **Boundaries preserved** | Explicit confirmation that forbidden exposures / redefinitions / bypasses / alterations did not occur | Which constitutional boundaries were preserved? |

Runtime Interface Explainability is:

- **interaction-centred** — it narrates what was exposed and exchanged under law;
- **capability-bound** — every justification cites published capabilities, not wire methods;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, or Programme VIII contract / evidence / service speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, mastery, or policy;
- **technology-neutral** — protocol names may appear as ops breadcrumbs, never as constitutional warrant;
- **audit-aligned** — explanation components match RI-06 reconstruction needs.

Runtime Interface Explainability is **not**:

- a rewrite of Programme VI educational meaning explainability;
- a substitute for contract, evidence, service, workflow, authority, recommendation, or state explainability corpora;
- a rendering system, UI template, OpenAPI description, log shipper, or analytics dashboard;
- a claim that clear interaction speech guarantees learning or a pass;
- a licence to present scores, latency, or optimiser confidence as constitutional proof.

## 3. Mandatory Explanation Questions

Every material interface interaction should answer all five questions:

### RIEQ-01 — Which constitutional interface was used?

Name the primary RI-01…RI-07 interface(s). Cross-cutting interactions name all bound interfaces (for example RI-05 + RI-06).

### RIEQ-02 — Which constitutional capability was exposed?

Cite the published RS-01…RS-07 capability and/or WS1 / WS2 responsibility that the interface surfaced. “This REST route,” “this gRPC method,” or “this SDK client” are not constitutional capabilities.

### RIEQ-03 — Which constitutional inputs were received?

Distinguish:

- RC bindings and published condition evaluations;
- EIP-002 / WS2 evidence artefacts (when actually used);
- Published CE-class events;
- Programme VI warrants / Programme VII orchestration artefacts;
- Explicit refuse / diagnostic scopes for non-executing interactions.

Never present coverage, time, engagement, or Twin estimates as understanding evidence unless the Evidence Model permits that classification.

### RIEQ-04 — Which constitutional outputs were returned?

Name only published output classes: dispositions, workflow events, recommendation artefacts / sets, EST/CST postures, audit records, diagnostic reports, or explicit refuse/defer/escalate outcomes.

### RIEQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `INTERFACE_BOUNDARIES.md` that were checked — especially non-exposure of internals as law, non-redefinition of meaning, non-bypass of contracts, non-alteration of evidence, and non-modification of specifications.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **RIEC-01** | Interface identity | Named RI-01…RI-07 binding(s) |
| **RIEC-02** | Capability refs | Published RS / WS1 / WS2 capability identity |
| **RIEC-03** | Input catalogue | Authorised constitutional request shapes received |
| **RIEC-04** | Output catalogue | Authorised constitutional artefacts / dispositions returned |
| **RIEC-05** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **RIEC-06** | Refusal / deferral honesty | When no lawful exposure existed, say so |
| **RIEC-07** | Continuity note | Prior lawful history not erased (EIP-005) |
| **RIEC-08** | Non-claim honesty | Explicit refusal of mastery / pass / meaning-rewrite / policy-invention overclaim |
| **RIEC-09** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |
| **RIEC-10** | Technology-neutrality note | Transport / SDK names (if present) marked as non-constitutional |
| **RIEC-11** | Provenance integrity | Constitutional refs survived packaging into speech / audit |

Components are **constitutional content obligations**, not database columns, API fields, OpenAPI schemas, or UI widgets. Persistence and rendering are out of scope for MS001.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | What was requested next, why it was allowed, what came back, and what limits apply — in plain educational language | Internal RI IDs as theatre; stack traces; protocol status codes as “proof you are ready” |
| **Developer / auditor** | Full RIEQ-01…05 answers, capability paths, interface IDs, boundary checks, provenance | Product success metrics or transport details substituted for constitutional refs |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 6. Layering with Upstream Explainability

| Layer | Corpus job | Interface speech role |
|-------------------|---------------------|
| Programme VI coach / planner explainability | Why educational guidance is warranted | Consume; do not rewrite |
| Programme VII workflow / authority / recommendation / state explainability | How orchestration, ownership, tips, and context are speakable | Narrate exposure under RI-05 (as applicable) |
| Programme VIII contract explainability | Which runtime contract executed under which law | Narrate exposure under RI-01 |
| Programme VIII evidence explainability | How evidence was consumed / validated | Narrate exposure under RI-02 |
| Programme VIII service explainability | Which service capability ran under which law | Narrate exposure under RI-04 / specialised RIs |
| **Programme VIII interface explainability** | **Which interaction contract exposed which capability and exchanged what** | **This document** |

A complete material journey may carry every layer that applied. Interface speech without upstream warrant is hollow. Upstream warrant without interface identity invites silent reimplementation drift behind transports.

## 9. Out of Scope

- explanation renderers or UI copy systems;

## 10. Closing Statement

> **If a runtime interface cannot say which interface was used, which capability was exposed, which inputs were received, which outputs were returned, and which boundaries were preserved, the interaction is not yet constitutionally explainable — and must not be presented as educational law.**
