## 1. Purpose

An expert IFoA tutor does not optimise “endpoints hot” or “SDK methods shipped.” The tutor optimises **faithful educational exposure**: authorised consumers receive only the constitutional capabilities that were already published — with honest boundaries, reconstructable history, and technology-neutral interaction meaning.

These objectives bind every Runtime A interface interaction and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### RIO-01 — Expose constitutional capabilities

**Definition.** Ensure that runtime interfaces surface only published constitutional execution capabilities from Programme VIII WS3 (RS-01…RS-07) and related WS1 / WS2 lawful responsibilities — or honestly refuse when no published capability authorises the interaction.

**Includes:**

- Mapping material interactions to recognised RI-01…RI-07 interface types.
- Exposing only capabilities already published under the Runtime Service Model and related Programme VIII corpora.
- Consuming only published constitutional request shapes (contracts, evidence, events, service responsibilities).
- Returning only authorised constitutional outputs (dispositions, artefacts, audit trails, diagnostic records).
- Preferring lawful refusal / deferral / escalation over invented exposure.

**Excludes:**

- Inventing unpublished capabilities, request shapes, or output classes “to keep the product moving.”
- Optimising for engagement, latency, or conversion as a substitute for constitutional fidelity.
- Treating Version 2 Adaptive / Twin / Experience heuristics as replacements for Programmes VI–VIII.
- Exposing “close enough” approximations of constitutional capabilities without documenting a corpus amendment.

**Tutor rationale.** Professional exam preparation fails when the software coach improvises educational law at the boundary. Capability exposure is care; improvisation is harm.

---

## 3. Supporting Objectives

### RIO-02 — Preserve constitutional boundaries

**Definition.** Ensure that interface interactions never redefine educational meaning, redefine authority, invent recommendations, bypass contracts, alter evidence, or modify constitutional specifications.

**Tutor rationale.** A polished API that silently rewrites mastery, ownership, or evidence classifications destroys constitutional layering even if the protocol feels clean.

**Manifestations:**

- Interfaces expose capabilities; they do not author meaning or policy.
- Forbidden actions in `INTERFACE_BOUNDARIES.md` are hard stops.
- Contract, evidence, and service boundaries survive every interaction.
- Product urgency never mints new constitutional exposure rights.

---

### RIO-03 — Preserve implementation independence

**Definition.** Ensure that Runtime Interface meanings bind behaviour, not a specific language, framework, protocol, SDK, or deployment topology. Any compliant implementation may honour the same RI catalogue.

**Tutor rationale.** If educational truth can only be exposed through one stack or wire format, that stack has become an unlawful constitution.

**Manifestations:**

- RI-01…RI-07 are technology-neutral interaction contracts.
- Successor runtimes must honour the same interface catalogue and boundaries.
- REST, GraphQL, gRPC, HTTP, WebSockets, and SDKs are delivery details — never educational law.
- “Only this protocol can decide” is a governance failure unless the Constitution / Programmes say so.

---

### RIO-04 — Preserve auditability

**Definition.** Ensure that every material interface interaction leaves a reconstructable constitutional trail: which interface ran, which capability was exposed, which inputs were received, which outputs were returned, and which boundaries were preserved.

**Tutor rationale.** A tutor who cannot later say *what was asked and what was returned under which law* cannot be trusted. Interfaces without audit are educational amnesia at the boundary.

**Manifestations:**

- Audit records preserve constitutional references, not only technical access logs.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance is a defect, not an acceptable optimisation.
- RI-06 Audit Interface obligations apply to material interactions across the catalogue.

---

### RIO-05 — Preserve explainability

**Definition.** Ensure that interface interactions remain speakable under EIP-003: students and developers can answer the constitutional explainability questions without receiving redefined educational meaning.

**Tutor rationale.** Opaque boundary behaviour recreates black-box tutoring. Clear interaction speech is part of educational honesty.

**Manifestations:**

- Explanations cite interface, capability, inputs, outputs, and boundaries (`INTERFACE_EXPLAINABILITY.md`).
- Student speech and developer traces share one truth with different vocabulary.
- Scores and optimiser confidence are never presented as constitutional warrant.
- Explanation never becomes a back door to invent tips, mastery, or policy.

---

### RIO-06 — Remain technology neutral

**Definition.** Ensure that no networking choice, framework, authentication stack, or SDK becomes part of the constitutional architecture. Interface law describes interaction contracts; transports obey those contracts.

**Tutor rationale.** Treating HTTP routes, gRPC methods, or SDK clients as educational authorities recreates the very technology lock-in Programme VIII exists to prevent.

**Manifestations:**

- Constitutional documents name RI types, not route tables.
- AuthN/AuthZ mechanisms may gate access operationally; they never redefine who owns educational meaning.
- Protocol migrations must preserve RI catalogue semantics.
- Framework convenience never rewrites Programme VIII WS1–WS3 law.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| RIO-01 conflicts with engagement metrics | Constitutional capability exposure wins |
| RIO-02 conflicts with convenience rewriting at the boundary | Boundary preservation wins |
| RIO-03 conflicts with lock-in to a single protocol | Implementation independence wins |
| RIO-04 conflicts with log volume reduction that erases constitutional refs | Auditability wins |
| RIO-05 conflicts with cryptic internal jargon as student speech | Explainability honesty wins |
| RIO-06 conflicts with elevating a transport into architecture law | Technology neutrality wins |

No supporting objective authorises violating RIO-01.

---

## 5. Non-Objectives

Runtime interfaces do **not** optimise for:

- endpoint count, SDK method count, or protocol fashion as educational success;
- inventing educational certainty when warrants are incomplete;
- collapsing Programmes VI–VIII into one mega-API;
- making a particular transport irreplaceable;
- using Twin / Adaptive estimates as substitutes for constitutional producers;
- treating documentation as optional commentary on wire behaviour;
- defining educational meaning, authority, governance, or execution policy at the interface layer.

---

## 6. Closing Statement

> **An interface that is fast, polished, and constitutionally unfaithful is a failed educational boundary.  
> An interface that is technology-neutral, auditable, and faithful to published capabilities is doing its only job.**
