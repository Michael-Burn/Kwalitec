## 1. Purpose

Runtime that silently turns “collaboration finished” into “student succeeded,” “execution succeeded,” “workflow closed,” “ownership moved,” “duties merged,” or “the Constitution now says X” destroys student trust and educational integrity.

This document draws a bright line between **lawful collaboration-completion confirmation** (Programme VIII / WS3 / MS003) and **educational / execution / orchestration / authorship / responsibility-redistribution judgements** owned elsewhere.

---

## 2. Boundary Principles

1. **Confirm collaboration, do not author meaning.** Completion affirms fulfilment of published coordination duties; it does not create educational truth.
2. **Collaboration only.** Learning, mastery, and progress are never inferred from close.
3. **Not execution completion.** Programme VIII / WS1 / MS003 owns execution-cycle fulfilment.
4. **Not workflow completion.** Programme VII owns orchestration fulfilment.
5. **Not responsibility redistribution.** MS001 owns the service catalogue; close never merges or redefines it.
6. **Not ownership transfer.** Invocation and close never move constitutional ownership.
7. **Published criteria only.** Buses, DI, hop counts, and saga exits are not fulfilment law.
8. **Published records only.** Collaboration audit continuity is constitutional, not free-form tracing theatre.
9. **Reference participants and artefacts honestly.** Named RS services and exchanged artefacts may be cited; MS001 / MS002 law is not rewritten by citing them.
10. **Meaning non-reinterpretation.** Programme VI questions survive close intact.
11. **Evidence non-reinterpretation.** Classifications stay with the Evidence Model.
12. **State non-invention.** Context postures stay with WS4 EST/CST law.
13. **Recommendation non-invention.** Tips stay with WS3 + Programme VI owners.
14. **Determinism.** Race-dependent collaboration completion is a defect.
15. **Implementation independence.** Orchestrators never become constitutional furniture.
16. **Explain the stop.** Students and developers should hear when close must be refused.
17. **No emergency exemption.** Load, deadlines, and demos never mint collaboration-completion power.

## 3. What Runtime Collaboration Completion May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Confirm collaboration fulfilment** | Affirm RSCC-01…RSCC-05 when published criteria hold for a lawful collaboration |
| **Reference participating services** | Cite RS-01…RS-07 participants and collaboration roles under MS001 / MS002 — without redefining the RS catalogue |
| **Reference exchanged constitutional artefacts** | Cite published artefacts handed between participants — without reinterpreting them |
| **Preserve collaboration audit records** | Keep reconstructable RS-07 / RSC-07 / RC-07 trails intact across retries, replacements, and redeploys (EIP-005) |
| **Refuse unlawful close** | Prefer honest not-yet / refuse-close over improvisation, merger, or ownership theatre |
| **Remain deterministic** | Same published inputs → same completion judgement class |
| **Remain replaceable** | Honour completion law in any compliant implementation |
| **Explain completion** | Answer participants / patterns / contracts / artefacts / boundaries without rewriting meaning |

These actions **confirm**. They do **not** publish a new Constitution, invent coach questions, mint tips, author ownership maps, certify mastery, affirm REC/ECC by declaration, close Programme VII workflows, or merge RS responsibilities.

## 4. What Runtime Collaboration Completion Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Transfer constitutional ownership** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority / Conflict corpora; refuse domain absorption at close |
| **Merge service responsibilities** | MS001 owns the RS catalogue; MS002 forbids merger by composition | Keep each participant’s MS001 permitted / prohibited duties intact |
| **Imply execution completion** | Programme VIII / WS1 / MS003 owns REC fulfilment | Affirm collaboration completion only; require REC corpus for execution-cycle close |
| **Imply educational success** | Educational success is not a collaboration property | Say collaboration responsibilities are fulfilled; remain silent on mastery / progress / pass |
| **Modify constitutional specifications** | Constitution / EIP / Programmes VI–VIII are amended only under their governance | Change code to obey law, or propose a corpus amendment — never patch law in a collaboration-completion handler |
| **Imply Programme VII workflow completion** | Programme VII WS1 / MS003 owns orchestration fulfilment | Affirm collaboration completion only; require Programme VII corpus for workflow close |
| **Imply Programme VI educational completion** | Coach / planner completion models own educational fulfilment where defined | Keep educational completion judgements with Programme VI |
| **Imply Evidence Consumption Completion** | WS2 / MS003 owns ECC fulfilment | Affirm collaboration completion only; require ECC corpus for evidence-handling close |
| **Redefine MS001 / MS002 meanings at close** | Service and collaboration law are not rewritten by “done” | Consume published catalogues; escalate for corpus amendment |
| **Invent tips / state / evidence classes at close** | WS3 / WS4 / EIP-002 writers own those artefacts | Surface only already-authorised collaborative outputs or none |
| **Treat buses / DI / hop counts / saga exits as fulfilment** | Operational proxies are not completion law | Evaluate RSCC-01…RSCC-05 |
| **Treat Twin / Adaptive / UI done-flags as publishers of completion law** | They are consumers / delivery surfaces | Require published criteria or refuse |
| **Become irreplaceable by collaboration topology** | RSCCO-05 replaceability | Keep completion law implementation-independent |
| **Erase continuity to force a clean close** | EIP-005 | Preserve history; re-enter at published points |

## 6. Boundary Checks (Pre-Affirmation)

Before a material collaboration completion is affirmed, confirmation requires affirmative answers:

| Check | Question |
|-------|----------|
| **SCCB-01 Collaboration lawfulness** | Did a published MS001 / MS002 collaboration exist (not completion theatre for never-started coordination)? |
| **SCCB-02 Criteria** | Do RSCC-01…RSCC-05 hold? |
| **SCCB-03 Ownership non-transfer** | Does affirmation avoid transferring constitutional ownership? |
| **SCCB-04 Responsibility non-merger** | Does affirmation avoid merging or redefining MS001 service responsibilities? |
| **SCCB-05 Execution non-claim** | Does affirmation avoid implying execution success or REC completion? |
| **SCCB-06 Learner-success non-claim** | Does affirmation avoid implying learner success, progress, mastery, or pass? |
| **SCCB-07 Workflow non-claim** | Does affirmation avoid implying Programme VII workflow completion? |
| **SCCB-08 Spec immutability** | Does affirmation avoid modifying constitutional specifications? |
| **SCCB-09 Participant honesty** | Are references limited to published RS participants without inventing mega-services? |
| **SCCB-10 Artefact honesty** | Are exchanged artefacts limited to published constitutional classes without reinterpretation? |
| **SCCB-11 Record honesty** | Do collaboration records support the judgement without substituting hop / ack theatre? |
| **SCCB-12 Continuity** | Is audit continuity preserved (EIP-005)? |
| **SCCB-13 Determinism** | Is the judgement reproducible from published inputs? |
| **SCCB-14 Explainability** | Can RSCCAQ questions in `COMPLETION_EXPLAINABILITY.md` be answered honestly? |

Any failed check → not yet / refuse close. Do not “best-effort” invent fulfilment.
