## 1. Purpose

An expert IFoA tutor does not optimise “messages drained” or “handlers fired.” The tutor optimises **faithful educational succession**: the student experiences the next constitutional step that published law already authorised — in the right order, with honest evidence, intact ownership, and reconstructable history.

These objectives bind every Runtime A event-processing behaviour and every successor runtime that claims constitutional compliance.

---

## 2. Primary Objective

### EPO-01 — Consume constitutional events

**Definition.** Ensure that runtime receives and processes only published constitutional event classes (CE-01…CE-07) whose producers and meanings originate in the Constitution, EIP, Programme VI, or Programme VII — or honestly refuse when no published event mapping authorises consumption.

**Includes:**

- Accepting only catalogue events with identifiable constitutional producers.
- Mapping Programme VII educational stimuli (e.g. WE-xx) into CE-02 processing under published law — without inventing rival stimulus meanings.
- Preferring lawful refusal / deferral / escalation over inventing an “almost CE” for infrastructure convenience.
- Binding every material consumption to RC-01…RC-07 as applicable.
- Preserving claim-ladder and evidence honesty when CE-01 evidence events are consumed.

**Excludes:**

- Inventing unpublished event types “to keep the product moving.”
- Treating broker payloads, Adaptive signals, Twin estimates, or UI clicks as constitutional events without a published CE mapping.
- Optimising for throughput, latency, or engagement as a substitute for constitutional fidelity.
- Executing “close enough” approximations of event law without documenting a corpus amendment.

**Tutor rationale.** Professional exam preparation fails when software invents educational reasons from notifications. Consumption is care; improvisation is harm.

---

## 3. Supporting Objectives

### EPO-02 — Preserve execution order

**Definition.** Ensure that published succession, stage order, handoff order, and continuity obligations survive event processing — so coaching does not leapfrog, rewind, or parallelise unlawfully because a queue reordered work.

**Tutor rationale.** A tutor who answers tomorrow’s exam tip before today’s recovery warrant, merely because messages arrived out of order, has abandoned educational care for delivery convenience.

**Manifestations:**

- Published workflow stage / transition / completion order is respected under CE-02 + RC-03.
- Concurrent events are dispositioned under published authority / conflict law (CE-03 + RC-04), not by arrival-time theatre.
- Continuity (EIP-005) forbids erasing prior lawful history to “catch up” a backlog.
- Retries and replacements re-enter at published points; they do not invent shortcut stages.

---

### EPO-03 — Preserve constitutional integrity

**Definition.** Ensure that event processing never redefines Programme VI meaning, transfers ownership, invents tips, invents EST/CST postures, reinterprets Evidence, or bypasses Programme VII workflow law.

**Tutor rationale.** An event handler that “helpfully” rewrites revision as first learning, or coverage as mastery, destroys constitutional layering even if the pipeline looks healthy.

**Manifestations:**

- Processing consumes meaning; it does not amend it.
- CE categories specialise delivery of published behaviour; they do not mint behaviour.
- Forbidden actions in `EVENT_BOUNDARIES.md` are hard stops.
- MS001 RCO-02 / RCO-03 integrity obligations remain binding during processing.

---

### EPO-04 — Support auditability

**Definition.** Ensure that every material processed event leaves a reconstructable constitutional trail: which CE was received, which RC / corpus authorised processing, which artefacts were consumed, which outputs were produced, and which boundaries were preserved.

**Tutor rationale.** A tutor who cannot later say *which signal* triggered yesterday’s advice cannot be trusted. Event processing without audit is educational amnesia.

**Manifestations:**

- Audit records preserve constitutional references, not only technical delivery logs.
- Continuity (EIP-005) is preserved across retries, replacements, and redeploys.
- Missing provenance is a defect, not an acceptable optimisation.
- RC-07 Audit Contract obligations apply to all material CE processing; CE-06 Audit Events specialise audit-facing signals without replacing RC-07.

---

### EPO-05 — Preserve deterministic execution

**Definition.** Ensure that the same published event instance facts, the same published learner constitutional inputs, and the same published corpora yield the same processing disposition (execute path / refuse / defer / escalate) — absent a published non-deterministic exception (none are granted by this Model for educational meaning).

**Tutor rationale.** A coach who gives different educational next steps for the same facts depending on which server woke first is not coaching; they are gambling.

**Manifestations:**

- Classification and evaluation are corpus-bound and reproducible.
- Infrastructure concurrency, sharding, and retry jitter must not change constitutional disposition.
- Explicit multi-event warrant sets use published conflict / authority rules, not random handler races.
- “Eventually consistent educational meaning” is a constitutional defect.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| EPO-01 conflicts with draining an unpublished payload | Constitutional consumption wins — refuse / remap under amendment |
| EPO-02 conflicts with parallelising work for throughput | Execution order / published succession wins |
| EPO-03 conflicts with convenience rewriting inside a handler | Integrity wins |
| EPO-04 conflicts with log volume reduction that erases constitutional refs | Auditability wins |
| EPO-05 conflicts with race-dependent handler outcomes | Determinism wins |

No supporting objective authorises violating EPO-01.

These objectives specialise — and never weaken — MS001 RCO-01…RCO-06 for the event-processing horizon.

---

## 5. Non-Objectives

Constitutional event processing does **not** optimise for:

- message throughput, broker utilisation, or handler concurrency as educational success;
- inventing educational certainty when warrants are incomplete;
- collapsing CE categories into one mega-handler that owns meaning;
- making a particular queue or bus irreplaceable;
- using Twin / Adaptive / UI signals as substitutes for constitutional producers;
- treating documentation as optional commentary on handler behaviour.

---

## 6. Closing Statement

> **A runtime that processes events quickly, quietly, and constitutionally unfaithfully is a failed educational system.  
> A runtime that consumes only published events, in published order, with integrity, audit, and determinism intact, is doing its only event-processing job.**
