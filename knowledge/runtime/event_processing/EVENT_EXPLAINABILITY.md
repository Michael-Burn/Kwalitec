## 1. Purpose

An expert IFoA tutor who cannot say *which signal* triggered a study action — which contract authorised processing, which artefacts were used, what was produced, and which limits were preserved — is not coaching; they are performing.

After Programmes VI and VII have made meaning, ownership, tips, and context speakable, and after MS001 has made contract execution speakable, Programme VIII still needs one event-speech answer:

> **“Which constitutional event was received, under which contract, consuming which artefacts, producing which outputs, while preserving which boundaries?”**

That answer must cover every material processed event without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting evidence, or inventing unpublished CE types.

---

## 2. What Event Processing Explainability Is

**Constitutional Event Processing Explainability** is the constitutional obligation to narrate **processing of published events under published contracts** — not to invent a second tutor voice from delivery machinery.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Event received** | Named CE-01…CE-07 category (and upstream stimulus ID when applicable, e.g. WE-xx) | Which constitutional event was received? |
| **Authorising contract** | Named RC-01…RC-07 binding(s) that authorised processing | Which constitutional contract authorised processing? |
| **Artefacts consumed** | Published corpora, evidence, warrants, ownership maps, recommendation artefacts, context postures, conditions | Which constitutional artefacts were consumed? |
| **Outputs produced** | Published execution paths’ results: workflow advances, dispositions, surfaced tips/sets, state postures, audit records, refuse/defer/escalate | Which constitutional outputs were produced? |
| **Boundaries preserved** | Explicit confirmation that forbidden inventions / reinterpretations / transfers / bypasses did not occur | Which constitutional boundaries were preserved? |

Event Processing Explainability is:

- **processing-centred** — it narrates receive → evaluate → execute under law;
- **catalogue-bound** — every justification cites published CE and RC identities;
- **corpus-bound** — every justification cites published producers;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, or MS001 contract speech;
- **non-inventive** — explanation never becomes a back door to mint meaning, tips, CE types, or mastery;
- **audit-aligned** — explanation components match RC-07 / CE-06 reconstruction needs;
- **determinism-honest** — explanations must not paper over race-dependent dispositions.

Event Processing Explainability is **not**:

- a rewrite of Programme VI educational meaning explainability;
- a substitute for workflow, authority, recommendation, state, or MS001 contract explainability corpora;
- a rendering system, UI template, log shipper, broker console, or analytics dashboard;
- a claim that clear processing speech guarantees learning or a pass;
- a licence to present scores, acks, or optimiser confidence as constitutional proof.

## 3. Mandatory Explanation Questions

Every processed material constitutional event should answer all five questions:

### EPEQ-01 — Which constitutional event was received?

Name the primary CE-01…CE-07 category. When an upstream Programme VII stimulus applies, also name it (for example CE-02 ← WE-03). Unpublished payload names are not constitutional events.

### EPEQ-02 — Which constitutional contract authorised processing?

Name the primary RC-01…RC-07 contract(s). Cross-cutting processing names all bound contracts (for example RC-03 + RC-05 + RC-07). “Handler registered” is not a constitutional contract.

### EPEQ-03 — Which constitutional artefacts were consumed?

Distinguish:

- EIP-002 Educational Evidence of understanding (when actually used);
- Programme VI warrants / artefacts;
- Programme VII orchestration, ownership, recommendation, or context facts;
- published condition evaluations;
- MS001 contract references that bound the act.

Never present coverage, time, engagement, broker metadata, or Twin estimates as understanding evidence unless the Evidence Model permits that classification.

### EPEQ-04 — Which constitutional outputs were produced?

Name only published output classes: workflow advances / events, authority dispositions, recommendation artefacts / sets, EST/CST postures, audit / execution records, or explicit refuse/defer/escalate outcomes.

### EPEQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `EVENT_BOUNDARIES.md` that were checked — especially non-invention of CE types, non-reinterpretation of meaning, non-transfer of authority, non-bypass of workflows, and non-generation of unpublished recommendations.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **EPEC-01** | Event identity | Named CE-01…CE-07 (+ upstream stimulus ID when applicable) |
| **EPEC-02** | Contract identity | Named RC-01…RC-07 binding(s) |
| **EPEC-03** | Authorising corpus refs | Documented constitutional producers |
| **EPEC-04** | Artefact / evidence refs | What was consumed, with claim-class honesty |
| **EPEC-05** | Output catalogue | What published artefacts / dispositions / records resulted |
| **EPEC-06** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **EPEC-07** | Order / determinism note | How published succession was preserved; disposition reproducibility |
| **EPEC-08** | Refusal / deferral honesty | When no lawful processing existed, say so |
| **EPEC-09** | Continuity note | Prior lawful history not erased (EIP-005) |
| **EPEC-10** | Non-claim honesty | Explicit refusal of mastery / pass / meaning-rewrite / CE-invention overclaim |
| **EPEC-11** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |
| **EPEC-12** | Provenance integrity | Constitutional refs survived packaging into speech / audit |

Components are **constitutional content obligations**, not database columns, API fields, queue headers, or UI widgets. Persistence and rendering are out of scope for MS002.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | What happened next, why it was allowed, what evidence supported it, and what limits apply — in plain educational language | Internal CE/RC IDs as theatre; broker traces; optimiser scores as “proof you are ready” |
| **Developer / auditor** | Full EPEQ-01…05 answers, corpus paths, CE/RC IDs, boundary checks, order/determinism notes, provenance | Product success metrics or ack counts substituted for constitutional refs |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 6. Layering with Upstream Explainability

| Layer | Corpus job | Event-processing speech role |
|-------|------------|------------------------------|
| Programme VI coach / planner explainability | Why educational guidance is warranted | Consume; do not rewrite |
| Programme VII workflow explainability | How orchestration flowed / which WE applied | Narrate CE-02 processing under RC-03 |
| Programme VII authority explainability | Why a component was permitted to decide | Narrate CE-03 processing under RC-04 |
| Programme VII recommendation explainability | Why a tip / set is speakable | Narrate CE-04 processing under RC-05 |
| Programme VII state explainability | Why context is live / how it succeeded | Narrate CE-05 processing under RC-06 |
| Programme VIII contract explainability (MS001) | Which runtime contract executed under which law | Compose with; do not replace |
| **Programme VIII event explainability (MS002)** | **Which constitutional event was processed under which contract** | **This document** |

A complete material journey may carry every layer that applied. Event speech without upstream warrant is hollow. Upstream warrant without CE/RC identity invites silent reimplementation drift.
