## Authority

This document is the constitutional overview of the **Planning Decision Engine** for Kwalitec.

It is subordinate to the Educational Constitution and specialised educational models. It governs **educational reasoning that produces planning decisions**. It does not authorise implementation shortcuts that contradict the Constitution.

Authority order for Master Planner personalisation:

> Constitution defines educational truth and curriculum primacy.  
> Knowledge & Mastery defines coverage ≠ understanding ≠ mastery.  
> Student Educational Profile (MS002) diagnoses who the student is educationally now.  
> Educational Strategy Framework (MS003) chooses which overall educational approach to adopt.  
> Educational Planning Model (MS001) defines how an expert tutor designs the journey under that strategy.  
> **This Engine (MS004) transforms Profile + Strategy + Planning Model into a structured Planning Decision Package.**  
> Planning Blueprint Model (MS005) organises that package into a date-independent study journey.  
> Future scheduling algorithms must consume that blueprint — never redefine educational reasoning in packing code.

## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabuses such as CM1/CS1 and peers).

An expert IFoA tutor does not jump from diagnosis into a filled calendar. After understanding the student and choosing an approach, the tutor first answers:

1. What educational decisions must be settled *before* any timetable exists?
2. In what order should those decisions be made so later packing cannot quietly undo earlier educational law?
3. When objectives pull in opposite directions, which educational truth wins?
4. How do we explain each material decision so the student can trust it?

That middle product — structured **planning decisions** — is what this Engine specifies.

> **The Planning Decision Engine produces educational decisions.  
> It does not generate study plans.**

This document records that tutor posture so every future Master Planner algorithm has a single educational reference for *how diagnosis becomes planning intent*.

## 2. What the Planning Decision Engine Is

The **Planning Decision Engine** is the educational reasoning process that transforms three lawful inputs into one structured output:

| Input | Role |
|-------|------|
| **Student Educational Profile** | Diagnosis — where the student is now |
| **Educational Strategy** | Approach — which overall educational approach to adopt |
| **Educational Planning Model** | Design law — objectives, constraints, phases, decision classes |

into:

| Output | Role |
|--------|------|
| **Planning Decision Package** | Structured set of educational planning decisions, each with justification |

It answers:

| Question | Educational answer |
|----------|-------------------|
| What must be decided before scheduling? | Sequencing, intensity, revision, buffers, recovery, risk posture, milestones, … |
| Why these decisions? | Trace to Profile facts/estimates, Strategy privileges/refusals, Planning Model law |
| What must algorithms not invent later? | Educational meaning, priority order, forbidden behaviours |
| What is still deferred? | Exact calendar cells, minute packing, session UI — future plan generation |

The Engine is:

- **educationally deterministic** — same Profile + Strategy + Planning Model yield the same decision posture;
- **pre-scheduling** — decisions precede timetables;
- **explainable** — every material decision speaks in plain educational language;
- **constraint-bound** — Planning Constraints and Constitution remain absolute;
- **strategy-honouring** — adaptive emphasis follows the selected strategy’s privileges and refusals;
- **package-producing** — outputs a coherent set of decisions, not isolated tips.

The Engine is **not**:

- a study plan, weekly timetable, or optimisation run;
- a Learning Mode / Revision Mode switch (strategy and decisions may *prefer* postures; constitutional modes retain daily authority);
- a numeric scoring or weighting engine;
- a claim that following the decisions guarantees a pass;
- a software class design or Runtime A service interface.

## 3. Tutor Posture (Binding Metaphor)

When producing planning decisions, the system must behave as an expert IFoA tutor would:

1. **Diagnose and choose approach first.** Decisions without Profile invent the student; decisions without Strategy invent approach in packing code.
2. **Decide before scheduling.** Revision windows, intensity bands, and feasibility judgements are educational decisions — not leftovers after a calendar fill.
3. **Work backwards from the sitting.** Protect revision and recovery capacity before packing first-pass ambition.
4. **Honour official order.** Topic sequencing follows curriculum law unless a constitutionally authorised, disclosed exception applies.
5. **Prefer sustainable intensity.** A keepable decision set beats heroic theatre the student will abandon.
6. **Separate coverage from competence.** Practice intensity and revision emphasis never mint mastery from Study Progress alone.
7. **Name infeasibility early.** When capacity cannot support honest readiness, say so — do not emit fantasy decisions that only look complete.
8. **Resolve conflicts educationally.** Priority and conflict rules in this corpus govern — not opaque optimiser convenience.
9. **Explain every material decision.** The student should understand *why Kwalitec selected each planning decision*.
10. **Refuse forbidden decisions.** The MS001 Forbidden catalogue remains absolute (impossible load, silent prerequisite skip, punishment pacing, hidden infeasibility, …).

## 5. Lawful Inputs

### 5.1 Student Educational Profile (required)

The Engine consumes the Profile as educational diagnosis — coverage, evidence posture, capacity, consistency, recovery history, previous attempts, educational state, and related dimensions.

**Rules:**

- Use Profile facts and derived measures as hard educational truth where claimed.
- Treat estimates as provisional — label them; do not harden them into certainty.
- Do not invent cold-start weakness or mastery claims absent from the Profile (or lawful declaration).
- Refresh Profile when material educational reality changes before re-running the Engine.

### 5.2 Educational Strategy (required)

The Engine consumes one primary named strategy from the Strategy Catalogue (ES-01 … ES-12).

**Rules:**

- Strategy privileges bias adaptive decisions (practice density, consolidation density, rescue triage, recovery load, …).
- Strategy refusals forbid dishonest emphases even if packing would be “easier.”
- Strategy never overrides Planning Constraints or Constitution.
- Strategy change (under MS003 transitions) requires re-running the Engine — not silent re-emphasis inside an old package.

### 5.3 Educational Planning Model (required)

The Engine consumes Planning Objectives, Constraints, Assumptions, journey phases, and the Decision Model’s mandatory / adaptive / forbidden classes.

**Rules:**

- Mandatory decisions (MS001 D1–D9 and successors) must appear in every complete package.
- Adaptive decisions vary only within constraint bounds and strategy warrant.
- Forbidden decisions (MS001 F1–F14 and successors) must never appear.

### 5.4 What is not an input

The Engine must not treat as educational authority:

- engagement metrics, gamification goals, or opaque scores;
- optimiser convenience or runtime performance preferences;
- marketing labels or UI themes;
- invented diagnosis detached from the Profile.

## 6. Planning Decision Package (Output)

### 6.1 What the package is

A **Planning Decision Package** is the complete set of educational planning decisions for a named examination sitting at a point in time, ready to be consumed by future plan generation.

It is educational intent — not a filled calendar.

### 6.2 Required package contents

Every complete package must include:

1. **Anchor decisions** — examination, sitting, starting coverage posture.
2. **Capacity & feasibility decisions** — usable capacity judgement; explicit feasibility outcome.
3. **Phase & reservation decisions** — revision window reservation; first-pass vs revision boundary intent; recovery/buffer posture.
4. **Sequencing decisions** — topic sequencing policy under official curriculum law.
5. **Intensity decisions** — sustainable intensity band; study intensity posture within that band.
6. **Protection decisions** — retention/consolidation posture; practice intensity posture; confidence protection posture; risk mitigation posture.
7. **Structure decisions** — buffer allocation; milestone positioning; mock timing intent (when educationally warranted).
8. **Strategy binding** — the active strategy ID and educational meaning the package honours.
9. **Explainability attachments** — plain-language rationale for every material decision (see `DECISION_EXPLAINABILITY.md`).
10. **Traceability** — each material decision cites Profile anchors, Strategy warrant, and Planning Model authority.

### 6.3 Package completeness rule

A package that schedules ambition without feasibility judgement, or packs first-pass without revision reservation, is educationally incomplete — even if every other field looks filled.

### 6.4 What the package is not

- Exact day-by-day timetable cells
- Minute-level session packing
- Generated lesson content
- Pass/fail probability claims
- A substitute for Learning Mode daily topic authority

## 8. Determinism & Understatement

### 8.1 Educational determinism

Given the same lawful Profile snapshot, the same primary Strategy, and the same Planning Model version, the Engine must produce the same decision posture.

Variation is allowed only when lawful inputs change (Profile evolution, strategy transition, sitting change, constraint updates).

### 8.2 Understatement

When Profile evidence is thin:

- prefer cautious intensity and stronger feasibility honesty;
- prefer labelled estimates over confident theatre;
- refuse invented cold-start diagnosis as package substance.

Understatement is an educational virtue, not an incomplete package.

## 9. Interaction With Downstream Systems

| Consumer | May use the package to… | Must not use it to… |
|----------|-------------------------|---------------------|
| Planning Blueprint (MS005) | Organise decisions into date-independent phases and components | Invent new educational reasoning absent from the package |
| Future scheduling | Place a package-derived blueprint onto calendars honouring decided envelopes | Reinvent sequencing, revision protection, or feasibility meaning |
| Daily mission / session systems | Respect intensity bands and phase posture | Silently commandeer Learning Mode topic authority |
| Student-facing narration | Explain decisions in plain language | Claim mastery or guaranteed pass from decisions alone |
| Recommendation / advisory layers | Advise within decided envelopes | Override mandatory or forbidden decisions |

Planning decisions set lawful envelopes. They do not replace constitutional daily authorities.
