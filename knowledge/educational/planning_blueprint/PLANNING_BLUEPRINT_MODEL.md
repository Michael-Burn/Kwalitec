---

## Authority

This document is the constitutional overview of the **Planning Blueprint** for Kwalitec.

It is subordinate to the Educational Constitution and specialised educational models. It governs **how settled planning decisions become a coherent, date-independent study journey structure**. It does not authorise implementation shortcuts that contradict the Constitution, and it does not invent educational meaning absent from the Planning Decision Package.

Authority order for Master Planner personalisation:

> Constitution defines educational truth and curriculum primacy.  
> Knowledge & Mastery defines coverage ≠ understanding ≠ mastery.  
> Student Educational Profile (MS002) diagnoses who the student is educationally now.  
> Educational Strategy Framework (MS003) chooses which overall educational approach to adopt.  
> Educational Planning Model (MS001) defines how an expert tutor designs the journey under that strategy.  
> Planning Decision Engine (MS004) transforms Profile + Strategy + Planning Model into a Planning Decision Package.  
> **This Blueprint (MS005) organises that package into a structured study journey ready for future scheduling.**  
> Future scheduling algorithms must place this blueprint onto a calendar — never redefine educational structure in packing code.

---

## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabuses such as CM1/CS1 and peers).

An expert IFoA tutor does not jump from planning decisions into a filled calendar. After settling sequencing, intensity, revision protection, buffers, recovery, milestones, and feasibility, the tutor first answers:

1. What educational phases compose this student’s journey?
2. Which building blocks sit inside each phase?
3. How does the student enter, progress, pause, recover, and complete those phases?
4. How do we explain the overall structure so the journey feels intentional — not random weeks?

That middle product — a **Planning Blueprint** — is what this Model specifies.

> **The Planning Blueprint describes educational structure.  
> It does not allocate dates or generate schedules.**

This document records that tutor posture so every future Master Planner scheduling algorithm has a single educational reference for *how decisions become journey shape*.

---

## 2. What the Planning Blueprint Is

The **Planning Blueprint** is the educational organisation of a Planning Decision Package into a coherent, date-independent study journey.

| Input | Role |
|-------|------|
| **Planning Decision Package** | Settled educational decisions (MS004) — sequencing, intensity, revision, buffers, recovery, practice, milestones, risk, confidence, feasibility, strategy binding, explainability |

into:

| Output | Role |
|--------|------|
| **Planning Blueprint** | Ordered phases + components + progression rules that future scheduling places onto an actual calendar |

It answers:

| Question | Educational answer |
|----------|-------------------|
| What is the journey’s shape? | Ordered educational phases with clear missions |
| What is it made of? | Learning, practice, consolidation, revision, mock, recovery, buffer, and checkpoint components |
| How does the student move? | Entry, progression, pause, recovery insertion, revision entry, completion — educational criteria only |
| What must schedulers not invent? | Phase meaning, component roles, progression law, revision protection |
| What is still deferred? | Exact calendar cells, minute packing, session UI |

The Blueprint is:

- **package-derived** — every structural element traces to package decisions;
- **date-independent** — structure exists before any timetable;
- **educationally deterministic** — same complete package yields the same blueprint posture;
- **explainable** — the student can understand why the journey is shaped this way;
- **scheduling-ready** — envelopes and order are explicit enough for future calendar placement;
- **non-inventive** — organises existing educational law; does not add new educational reasoning.

The Blueprint is **not**:

- a weekly timetable, sitting calendar, or optimisation run;
- a re-run of Profile diagnosis, Strategy selection, or Decision Engine reasoning;
- a Learning Mode / Revision Mode switch (modes retain daily constitutional authority; the blueprint records *when journey posture emphasises* each);
- a claim that following the blueprint guarantees a pass;
- a software class design or Runtime A service interface.

## 3. Derivation Rule (Binding)

### 3.1 Sole educational input

Assembly of a Planning Blueprint consumes **only** a complete Planning Decision Package (and the MS001–MS004 authorities that package already cites).

It must **not** introduce:

- new objectives, constraints, or forbidden-decision meanings;
- new strategy privileges or Profile diagnoses;
- new sequencing, intensity, or feasibility judgements;
- date maths, leave calendars, or session packing.

If the package is incomplete (e.g. missing feasibility judgement or revision reservation), **no complete blueprint may be published**. Incomplete packages yield incomplete or refused blueprints — not invented structure.

### 3.2 Organisation, not invention

| Blueprint may… | Blueprint must not… |
|----------------|----------------------|
| Name phases that embody MS001 journey phases under package decisions | Invent phases with educational jobs the package never authorised |
| Place components that realise PD-XX / D-class decisions | Invent practice density, buffer size, or mock intent absent from the package |
| State progression criteria that rest on package postures | Invent mastery thresholds or pass probabilities |
| Carry forward package explainability into journey speech | Invent confidence or readiness claims |

### 3.3 Educational determinism

Given the same complete Planning Decision Package (same decision postures and explainability attachments), the Blueprint must produce the same journey structure posture.

Variation is allowed only when the package changes (Profile evolution → re-run Engine → new package → new blueprint).

## 4. Tutor Posture (Binding Metaphor)

When assembling a blueprint, the system must behave as an expert IFoA tutor would:

1. **Decide before structuring.** No phase exists without package warrant.
2. **Structure before scheduling.** Phases and components precede calendar cells.
3. **Work backwards from the sitting in structure, not yet in dates.** Protect revision and final-approach phases as first-class journey regions because the package reserved them — not because leftover weeks appeared.
4. **Honour official order.** First-pass learning components follow the package’s sequencing policy.
5. **Prefer sustainable intensity envelopes.** Component density stays inside the package’s intensity band.
6. **Separate coverage from competence.** Practice and revision components never mint mastery from Study Progress alone.
7. **Name infeasibility in structure.** If the package judged the sitting infeasible, the blueprint must not present a complete journey theatre.
8. **Explain the shape.** Students should understand *why this journey looks like this*.
9. **Refuse forbidden structure.** Consuming protected revision for first-pass, silent prerequisite skip, punishment pacing, and hidden infeasibility remain unlawful at blueprint layer.
10. **Leave daily modes intact.** Blueprint phase emphasis does not silently commandeer Learning Mode topic authority.

## 6. Blueprint Contents (Required)

Every complete Planning Blueprint must include:

1. **Identity binding** — examination, sitting, strategy ID carried from the package (anchor decisions).
2. **Feasibility posture** — explicit package feasibility outcome; incomplete/infeasible packages cannot pretend complete journey structure.
3. **Ordered phase set** — the educational phases active for this student (see `BLUEPRINT_PHASES.md`), each linked to package phase & reservation decisions.
4. **Component inventory** — learning, practice, consolidation, revision, mock, recovery, buffer, milestone, and transition components warranted by the package (see `BLUEPRINT_COMPONENTS.md`).
5. **Progression rules** — entry, progression, pause, recovery insertion, revision entry, and completion criteria (see `BLUEPRINT_PROGRESSION.md`).
6. **Intensity & capacity envelopes** — sustainable intensity band and capacity posture from the package, attached to components without dating them.
7. **Protection regions** — revision reservation, buffer policy, recovery allowance, risk mitigation, and confidence protection as structural regions — not leftover scraps.
8. **Explainability attachments** — journey-level and phase-level plain-language reasons (see `BLUEPRINT_EXPLAINABILITY.md`), carrying package explainability forward.
9. **Traceability** — every phase and material component cites package decision IDs (PD-XX / MS001 D-classes) and inherits Profile + Strategy + Planning Model traces already on those decisions.

### 6.1 Completeness rule

A blueprint that shows first-pass ambition without a protected revision phase region, or presents a complete journey while the package marked the sitting infeasible, is educationally incomplete — even if every other field looks filled.

### 6.2 What the blueprint is not

- Exact day-by-day timetable cells
- Minute-level session packing
- Generated lesson content
- Pass/fail probability claims
- A substitute for Learning Mode daily topic authority
- A second Decision Engine

## 7. Relationship to MS001 Journey Phases

MS001 already defined the educational meaning of journey phases (Registration & Intake; Foundation & First-Pass Learning; Consolidation Windows; Protected Revision; Mock & Exam Simulation; Final Approach; Recovery / Replan).

This Blueprint:

- **preserves** those educational meanings;
- **instantiates** which phases are active and how they are composed for *this* package;
- **does not rename** educational jobs for marketing novelty;
- **does not invent** parallel phase taxonomies with different educational law.

Detail: [`BLUEPRINT_PHASES.md`](BLUEPRINT_PHASES.md).

## 8. Interaction With Downstream Systems

| Consumer | May use the blueprint to… | Must not use it to… |
|----------|---------------------------|---------------------|
| Future scheduling ([`../scheduling/`](../scheduling/)) | Place phases and components onto calendar cells honouring envelopes | Invent phase meaning, consume revision region silently, or ignore feasibility posture |
| Daily mission / session systems | Respect phase emphasis and intensity envelopes | Silently commandeer Learning Mode topic authority |
| Student-facing narration | Explain journey shape in plain language | Claim mastery or guaranteed pass from structure alone |
| Recommendation / advisory layers | Advise within blueprint envelopes | Override mandatory package decisions via “helpful” structure tweaks |

The blueprint sets lawful journey structure. It does not replace constitutional daily authorities.
