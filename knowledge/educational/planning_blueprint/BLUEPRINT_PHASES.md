## 1. Purpose

An ideal IFoA study journey is not a flat list of topics until the exam. It is a sequence of educational missions — build foundations, extend coverage, protect retention, practise application, consolidate under revision authority, rehearse exam craft, and stabilise before the sitting — with recovery available when life interrupts.

This document records those missions as **blueprint phases** so scheduling engines place educational structure onto calendars rather than inventing structure while packing.

---

## 2. Phase Principles

1. **Package-derived.** A phase appears in a student’s blueprint only when the Planning Decision Package warrants it (directly or via reserved posture).
2. **Mission-clear.** Each phase has one primary educational job the student can understand.
3. **Order-preserving.** Later phases must not silently undo earlier educational law (e.g. Final Approach must not reopen unbounded first-pass expansion).
4. **Revision-protected.** Protected Revision exists as a first-class region because the package reserved it (PD-03 / D5) — never as residual scrap after packing.
5. **Mode-respecting.** Phase emphasis guides journey posture; Learning Mode / Revision Mode retain daily constitutional authority.
6. **Coverage ≠ mastery.** Completing a first-pass phase advances coverage honesty; it does not mint mastery or pass claims.
7. **Strategy-coloured, not redefined.** Strategy privileges change *emphasis and density* inside phases; they do not invent alternate educational jobs for the same phase name.
8. **Feasibility-bound.** If the package marks the sitting infeasible, phases must not be presented as a complete honest journey without that truth.

## 3. Canonical Phase Set

Algorithms may use internal identifiers; educational meaning must match the table below. Identifiers (BP-XX) exist for traceability.

| ID | Phase | Primary educational job | Typical package warrants |
|----|-------|-------------------------|--------------------------|
| BP-00 | Registration & Intake | Establish lawful inputs and refuse fantasy starts | Package identity / completeness; D1 anchors |
| BP-01 | Foundation & Knowledge Building | Honest sequential first-pass coverage under Learning Mode posture | PD-01, PD-02, PD-06; MS001 §4.2 |
| BP-02 | Reinforcement & Question Practice | Application and evidence-building on material already studied | PD-05; strategy practice privileges |
| BP-03 | Consolidation Windows | Interleaved return during long first-pass so retention does not collapse | PD-14 / D11 |
| BP-04 | Protected Revision | Consolidate studied material under Revision Mode emphasis | PD-03, PD-04, D16; MS001 §4.4 |
| BP-05 | Mock Examinations | Timed exam simulation for craft, stamina, and evidence — not pass prophecy | PD-15 / D15 |
| BP-06 | Final Preparation | Stabilise focus; freeze syllabus expansion; protect freshness | PD-04 boundary late; MS001 §4.6 |
| BP-07 | Recovery / Replan | Restart that still counts after interruption or abandoned intensity | PD-07, PD-08, PD-16; MS001 §4.7 |

**Note on naming:** Milestone examples (Foundation, Knowledge building, Reinforcement, Question practice, Consolidation, Revision, Mock examinations, Final preparation) map onto BP-01…BP-06. They are educational missions derived from MS001 + package decisions — not copies of external commercial study guides.

## 4. Phase Specifications

### BP-00 — Registration & Intake

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Establish lawful planning inputs before committing the student to a trajectory |
| **Tutor actions (structural)** | Confirm examination and sitting; ensure package completeness (capacity, feasibility, revision reservation, sequencing); surface infeasibility early |
| **Package derivation** | Exists when a package is being formed or refreshed; a *published* blueprint for an active sitting assumes intake completed |
| **Typical components** | Identity binding; feasibility disclosure; strategy statement (see Components) |
| **Exit (educational)** | Complete Planning Decision Package exists (or lawful refusal / triage counsel). Blueprint may be published |
| **Must not** | Invent missing capacity, progress, or exam dates; publish complete journey theatre over an incomplete package |

Authority: MS001 §4.1; package completeness rules (MS004 §6).

---

### BP-01 — Foundation & Knowledge Building

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Honest sequential coverage of the official syllabus (Learning Mode posture) — foundations enabling later topics |
| **Tutor actions (structural)** | Sequence topics by official order / prerequisites; allocate sustainable intensity envelopes; begin from lawful starting coverage; keep practice honest without converting completion into mastery |
| **Package derivation** | PD-01 (sequencing), PD-02 (starting coverage), PD-06 (study intensity), PD-12 (capacity envelope). Strategy Build/Steady families typically heighten this phase |
| **Typical components** | Learning blocks; light practice blocks (when warranted); review checkpoints at syllabus section boundaries; intensity envelope |
| **Exit (educational)** | First-pass coverage complete *or* remaining first-pass work fits inside protected learning capacity before the revision boundary (PD-04) |
| **Must not** | Silent prerequisite skip; random reorder; claim mastery from coverage; consume protected revision region for unfinished first-pass by default |

Authority: MS001 §4.2; D2, D3, D7; PD-01, PD-02, PD-06.

---

### BP-02 — Reinforcement & Question Practice

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Deepen application and evidence on material **already studied** — coverage without application produces false readiness |
| **Tutor actions (structural)** | Place question-practice and reinforcement components on studied units; elevate density under Practice Intensive / Weak Topic Reinforcement / late Approach strategies; moderate under Recovery / Confidence Restoration |
| **Package derivation** | PD-05 (practice intensity); related D10/D16 adaptive posture; Knowledge & Mastery separation of coverage vs understanding |
| **Relationship to BP-01** | May **interleave** with Foundation & Knowledge Building (practice after studied topics) or concentrate later — according to package practice posture. It is not a licence to practise never-studied units as if they were covered |
| **Typical components** | Practice blocks; weak-topic reinforcement blocks; earned-confidence checkpoints |
| **Exit (educational)** | Package practice posture satisfied for current coverage maturity *or* journey moves emphasis to Protected Revision / Final Preparation under PD-04 |
| **Must not** | Treat practice completion as mastery; practise unstudied topics as coverage substitute; use practice load as punishment pacing |

Authority: PD-05; MS001 adaptive intensity / revision emphasis families; Evidence Model claim law.

---

### BP-03 — Consolidation Windows

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Interleaved return to recently studied material so retention does not collapse during a long first pass |
| **Tutor actions (structural)** | Place consolidation / spaced-return components without abandoning prerequisite order; avoid turning the whole journey into permanent revision too early |
| **Package derivation** | PD-14 / D11. Elevated under Knowledge Consolidation and long runways; light under early Foundation Building |
| **Relationship to BP-01** | **Interleaved windows** inside or beside first-pass — not a premature full switch to Revision Mode |
| **Typical components** | Consolidation / spaced-return blocks; light review checkpoints |
| **Exit (educational)** | Retention posture maintained through first-pass *or* Protected Revision phase assumes primary consolidation mission |
| **Must not** | Abandon remaining lawful first-pass without package warrant; invent cold-start weakness weights as fact |

Authority: MS001 §4.3; D11; PD-14.

---

### BP-04 — Protected Revision

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Consolidate previously studied material under Revision Mode emphasis as the examination approaches |
| **Tutor actions (structural)** | Reserve a first-class revision region that first-pass must not consume; apply revision emphasis mix (breadth vs weak-area depth) from the package; deepen application under exam-like conditions when warranted |
| **Package derivation** | PD-03 (reservation), PD-04 (phase boundary), D16 (emphasis mix). Approach / Triage / Revision Intensive strategies privilege this region |
| **Invariant** | Revision capacity is structured *because the package reserved it*. Compressing revision to “whatever packing left” is educationally unlawful |
| **Typical components** | Revision blocks; review checkpoints; practice-on-revised-scope blocks; transition point from first-pass |
| **Exit (educational)** | Revision mission complete relative to package emphasis *or* Final Preparation begins; mocks may sit inside/adjacent per PD-15 |
| **Must not** | Borrow revision region for first-pass by default (F2); invent definitive weak/strong weights without evidence or labelled declaration (F6) |

Authority: MS001 §4.4; D5, D6, D16; PD-03, PD-04; C10.

---

### BP-05 — Mock Examinations

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Calibrate timing, stamina, and exam behaviour — not invent false pass guarantees |
| **Tutor actions (structural)** | Place mock components when coverage maturity makes the exercise educationally meaningful; attach recovery capacity after mocks; treat outcomes as evidence inputs to future packages — not destiny |
| **Package derivation** | PD-15 / D15 within C11. More central under Approach / High Performer; deferred when coverage is too thin |
| **Relationship to other phases** | May appear near late first-pass, inside Protected Revision, or before Final Preparation — **intent** comes from the package; **dates** come later from scheduling |
| **Typical components** | Mock / exam-simulation blocks; recovery capacity after mocks; milestone checkpoint |
| **Exit (educational)** | Planned mock intent satisfied *or* deferred honestly when coverage remains too thin |
| **Must not** | Present mock scores as pass prophecy; schedule mocks without recovery posture when the package required recovery (PD-07) |

Authority: MS001 §4.5; D15; PD-15; O10.

---

### BP-06 — Final Preparation

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Stabilise confidence and focus; avoid last-minute syllabus expansion that destroys revision |
| **Tutor actions (structural)** | Freeze or tightly constrain new first-pass topics; emphasise high-value revision; protect sleep and cognitive freshness structurally (rest / light load components) |
| **Package derivation** | Late PD-04 boundary posture; risk mitigation (PD-10); confidence protection (PD-11); rest posture (D17) where present in package |
| **Typical components** | High-value revision blocks; rest / freshness components; final milestone checkpoint |
| **Exit (educational)** | Sitting arrives; post-exam study does not count toward this sitting (F13) |
| **Must not** | Reopen unbounded first-pass expansion; punish the student with heroic last-week overload |

Authority: MS001 §4.6; PD-04, PD-10, PD-11.

---

### BP-07 — Recovery / Replan

| Aspect | Specification |
|--------|----------------|
| **Educational purpose** | Restart that still counts after interruption, illness, leave, or abandoned intensity |
| **Tutor actions (structural)** | Insert recovery capacity; consume buffers lawfully; choose catch-up responses among package-lawful options; never shame the student for life events; re-enter an earlier phase with moderated intensity when educationally warranted |
| **Package derivation** | PD-07, PD-08, PD-16; strategies ES-07 / ES-08. May appear as an **inserted region** rather than a fixed mid-journey slot |
| **Typical components** | Recovery capacity; buffer periods; transition points back into BP-01…BP-04 under reduced intensity |
| **Exit (educational)** | Sustainable rhythm restored and package envelopes re-honoured *or* feasibility escalated honestly |
| **Must not** | Punishment pacing (F9); silent impossible compression (F1); erasure of learner history (F11) |

Authority: MS001 §4.7; D12, D13, D18; PD-07, PD-08, PD-16.

## 5. Structural Relationships (Date-Independent)

```
BP-00 Intake
   ↓
BP-01 Foundation & Knowledge Building
   ↕ interleaved (when package warrants)
BP-02 Reinforcement & Question Practice
BP-03 Consolidation Windows
   ↓ at PD-04 boundary
BP-04 Protected Revision
   ↔ adjacent (when package warrants)
BP-05 Mock Examinations
   ↓
BP-06 Final Preparation
   → Sitting

BP-07 Recovery / Replan  ← may insert after disruption at any later phase
```

Rules:

1. **Interleaving** of BP-02 / BP-03 with BP-01 is normal when the package sets practice and consolidation postures during first-pass.
2. **PD-04 boundary** is the structural change of mission from first-pass emphasis to revision emphasis — not a silent topic hop.
3. **BP-05** placement is structural *intent* from PD-15; calendar week is future scheduling’s job.
4. **BP-07** is available whenever package recovery / catch-up decisions fire — it is not optional theatre after burnout is ignored.

## 6. Strategy Colouring of Phases

Strategy changes emphasis inside phases. It does not redefine phase educational jobs.

| Strategy family | Phase colouring (from MS004 map) |
|-----------------|----------------------------------|
| Build (ES-01, ES-02) | Heighten BP-01; keep BP-02 honest on studied units; reserve BP-04 even if far |
| Deepen (ES-03, ES-04, ES-06) | Heighten BP-03 and/or BP-02; protect BP-01 integrity |
| Approach (ES-05, ES-11, ES-12) | Heighten BP-04, BP-05, BP-06; freeze expansion |
| Restore (ES-07, ES-08) | Insert/enlarge BP-07; moderate intensity in BP-01/BP-02 |
| Triage (ES-09, ES-10) | Early feasibility truth; minimum BP-04; honest shrinkage of leisurely BP-01 fiction |

Detail: `../planning_engine/DECISION_PIPELINE.md` §5.

## 7. What Scheduling May Do With Phases

| Scheduling may… | Scheduling must not… |
|-----------------|----------------------|
| Assign calendar intervals to active phases | Invent a phase the package did not warrant |
| Pack components into phase regions | Consume BP-04 capacity for BP-01 by default |
| Honour intensity envelopes inside phases | Ignore infeasibility posture while drawing a pretty phase map |
| Place BP-05 when PD-15 intent exists | Treat mock placement as pass probability engineering |
