## 1. Purpose

An expert IFoA tutor who cannot say *which rule* was checked — which evidence was assessed, which lineage was consumed, what finding resulted, and which limits were preserved — is not coaching; they are performing.

After Programmes VI–VIII have made meaning, ownership, tips, context, contracts, evidence, and runtime speech speakable, after WS1 / MS001 has made conformance speech speakable, and after WS1 / MS002 has made lineage speech speakable, Programme IX still needs one verification-speech answer:

> **“Which constitutional specifications were evaluated, which implementation evidence was assessed, which traceability relationships were consumed, which verification findings were produced, and which constitutional boundaries were preserved?”**

That answer must cover every material verification assessment without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, inventing lineage, freezing a stack as law, inventing unpublished CV types, issuing certificates, replacing MS001 evaluation, or presenting satisfaction as educational quality.

---

## 2. What Verification Explainability Is

**Constitutional Verification Explainability** is the constitutional obligation to narrate **evaluation of named implementation evidence against published constitutional specifications under published CV types, consuming established traceability relationships** — not to invent a second tutor voice from CI machinery, not to grade the student, and not to certify an implementation.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Specifications evaluated** | Named Constitution / EIP / Programme VI / VII / VIII documents (and clauses as applicable) | Which constitutional specifications were evaluated? |
| **Implementation evidence assessed** | Named evidence subjects (structure, behaviour, evidence handling, runtime, interface, API, governance) | Which implementation evidence was assessed? |
| **Traceability relationships consumed** | Named established CT-01…CT-07 links (and related provenance) | Which traceability relationships were consumed? |
| **Findings produced** | satisfied / not-satisfied / deferred / escalated (with composition notes; never certificates) | Which verification findings were produced? |
| **Boundaries preserved** | Explicit confirmation that forbidden legislation / redefinition / substitution / certification did not occur | Which constitutional boundaries were preserved? |

Verification Explainability is:

- **evidence-centred** — it narrates specs → evidence → relationships → findings under law;
- **catalogue-bound** — every justification cites published CV identities;
- **corpus-bound** — every justification cites published specifications;
- **lineage-honest** — every material justification cites established CT relationships consumed (or names the hard stop when none exist);
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-certifying** — satisfaction is never narrated as a certificate;
- **quality-honest** — satisfaction is never narrated as mastery, readiness, or educational quality;
- **conformance-honest** — satisfaction is never narrated as permanent conformity or a rewrite of CC meaning;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, MS001 conformance speech, or MS002 lineage speech;
- **audit-aligned** — explanation components match CVO-04 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions.

Verification Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–VIII / MS001 / MS002 meaning;
- a quality report on learning, coaching, or exam readiness;
- a conformity certificate or substitute for CC findings;
- a substitute for CT lineage speech;
- a substitute for Programme VIII evidence-validation or contract explainability corpora;
- a rendering system, UI template, CI badge, log shipper, or analytics dashboard;
- a claim that clear verification speech guarantees learning, a pass, permanent conformity, or a certificate;
- a licence to present coverage, lint scores, or pipeline greens as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material constitutional verification assessment should answer all five questions:

### CVEQ-01 — Which constitutional specifications were evaluated?

Name the primary published Constitution / EIP / Programme VI / VII / VIII specifications (paths and identities). When a clause or catalogue ID is material, name it (for example EIP-002 claim class; RC-02; EC-01 as *subject*). Unpublished tribal norms and “how main works” are not constitutional specifications.

### CVEQ-02 — Which implementation evidence was assessed?

Name the primary evidence under evaluation (for example structural module boundaries, behavioural disposition set, evidence-consumption path, runtime contract binding map, interface composition map, API operation set, governance trail). Protocol or vendor names alone are not sufficient without constitutional mapping.

### CVEQ-03 — Which traceability relationships were consumed?

Name the primary established CT-01…CT-07 relationships (and related provenance) consumed as inputs. If required lineage is missing, say so and record the hard stop — do not invent links in explanation prose. “Ticket mentioned a doc” is not established constitutional traceability.

### CVEQ-04 — Which verification findings were produced?

Distinguish:

- **satisfied** — required criteria passed under published law for the named evidence scope; satisfaction affirmed without certificate;
- **not-satisfied** — required criteria failed; satisfaction must not be claimed for the contemplated scope;
- **deferred** — published law requires waiting (for example incomplete evidence identity or incomplete established lineage still expected under continuity);
- **escalated** — published law requires human / corpus / authority escalation paths.

Never narrate findings as “student is ready,” “mastery confirmed,” “law updated,” “this stack is now constitutional,” “certified,” or “permanently conformant.”

### CVEQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `VERIFICATION_BOUNDARIES.md` that were checked — especially non-modification of specifications, non-redefinition of educational / constitutional meaning, non-substitution of constitutional authority, non-certification of implementations, implementation neutrality, and non-equation of satisfaction with educational quality or permanent conformity.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **CVEC-01** | Specification identity | Named Constitution / EIP / Programme VI / VII / VIII refs |
| **CVEC-02** | Evidence identity | Named implementation evidence under assessment |
| **CVEC-03** | Traceability identity | Named established CT relationships consumed (or explicit hard-stop for missing lineage) |
| **CVEC-04** | Verification type identity | Named CV-01…CV-07 binding(s) |
| **CVEC-05** | Criteria identity | Published permitted / prohibited verification criteria applied |
| **CVEC-06** | Finding disposition | satisfied / not-satisfied / deferred / escalated with composition |
| **CVEC-07** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **CVEC-08** | Authority preservation note | Confirmation that published corpora remain the standard |
| **CVEC-09** | Non-certification note | Confirmation that no implementation / stack / vendor / release certificate was issued |
| **CVEC-10** | Neutrality note | Confirmation that no stack / vendor was privileged as law |
| **CVEC-11** | Repeatability note | Disposition reproducibility from published inputs |
| **CVEC-12** | Conformance-support note | Confirmation that CV supports CC honesty without rewriting CC meaning |
| **CVEC-13** | Refusal / deferral honesty | When no lawful satisfaction existed, say so |
| **CVEC-14** | Continuity note | Prior lawful verification history not erased (EIP-005) |
| **CVEC-15** | Non-claim honesty | Explicit refusal of mastery / pass / quality / meaning-redefinition / law-amendment / stack-canonisation / certification overclaim |
| **CVEC-16** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |

Components are **constitutional content obligations**, not database columns, API fields, CI annotations, or UI widgets. Persistence and rendering are out of scope for this milestone.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | Whether the learning system’s behaviour is operating under published educational rules, why a stop occurred, and what limits apply — in plain educational language | Internal CV IDs as theatre; CI traces; coverage as “proof you are ready”; satisfaction as mastery or a certificate |
| **Developer / auditor** | Full CVEQ-01…05 answers, corpus paths, CV IDs, CT identities consumed, finding composition, boundary checks, neutrality / repeatability / non-certification notes | Product success metrics, pipeline greens, or coverage counts substituted for constitutional refs; satisfaction framed as educational quality, new law, or a certificate |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 9. Out of Scope

This milestone does **not** implement:

- explanation renderers or UI copy systems;
- CI badge systems, logging pipelines, or analytics products;
- certification registries or seal generators;
- Runtime A services or testing frameworks;
- GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, or infrastructure;
- prompt templates or LLM narration layers.

Those may later *obey* this explainability law. They do not *define* it.
