## Purpose

This folder defines **the permanent constitutional lifecycle coordinating verification activities** from initiation through production and recording of verification findings.

It answers *what the lifecycle must optimise*, *which recognised stages organise verification*, *what the lifecycle may and must never do*, and *how lifecycle progress is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, creating constitutional law, modifying constitutional specifications, redefining constitutional meaning, replacing constitutional authority, certifying implementations, or elevating lifecycle machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, or application services.

> **The constitutional verification lifecycle coordinates verification activities.  
> It produces verification findings without certifying implementations or altering constitutional law.  
> It never becomes constitutional authority.**

## Architectural requirement

The constitutional verification lifecycle coordinates **verification activities**.

| Lawful | Unlawful |
|--------|----------|
| Coordinate verification through recognised stages | Certify implementations |
| Consume constitutional specifications | Modify constitutional specifications |
| Consume implementation evidence | Redefine constitutional / educational meaning |
| Consume established traceability | Invent lineage to force progress |
| Produce verification findings | Replace conformance meaning |
| Preserve audit records | Become constitutional authority |
| Preserve repeatability, neutrality, explainability | Modify implementation artefacts under lifecycle pretext |
| Explain specs / evidence / relationships / stages / boundaries | Elevate lifecycle machinery into a constitutional producer |

**The constitutional verification lifecycle coordinates verification activities. It produces verification findings without certifying implementations or altering constitutional law.**

## How to use this corpus

1. Confirm the published Constitutional Verification Model (WS2 / MS001) is in force — refuse lifecycle theatre that invents verification types outside CV-01…CV-07.
2. Confirm published constitutional specifications, named implementation evidence, and established CT relationships for the concern are identifiable — refuse invented law or lineage.
3. Read `CONSTITUTIONAL_VERIFICATION_LIFECYCLE_MODEL.md` for stack position and integrity rules.
4. Optimise under `LIFECYCLE_OBJECTIVES.md`.
5. Sequence under `LIFECYCLE_STAGES.md` (CVL-01…CVL-07 only).
6. Enforce hard stops under `LIFECYCLE_BOUNDARIES.md`.
7. Require explainability contracts from `LIFECYCLE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing lifecycle narration.
8. Do not implement lifecycle machinery that contradicts this corpus without amending it first.
