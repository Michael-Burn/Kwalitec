## 1. Purpose

An expert IFoA tutor who cannot say *which rule* was checked — which evidence was consumed, which lineage was used, which stage produced each finding, and which limits were preserved — is not coaching; they are performing.

After Programmes VI–VIII have made meaning, ownership, tips, context, contracts, evidence, and runtime speech speakable, after WS1 has made conformance and lineage speech speakable, and after WS2 / MS001 has made verification speech speakable, Programme IX still needs one lifecycle-speech answer:

> **“Which constitutional specifications were evaluated, which implementation evidence was consumed, which traceability relationships were used, which lifecycle stage produced each finding, and which constitutional boundaries were preserved?”**

That answer must cover every material verification lifecycle without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, inventing lineage, freezing a stack as law, inventing unpublished CV or CVL types, issuing certificates, replacing MS001 evaluation, mutating artefacts, or presenting closure as educational quality.

---

## 2. What Lifecycle Explainability Is

**Constitutional Verification Lifecycle Explainability** is the constitutional obligation to narrate **coordination of named verification activities through published CVL stages** — consuming published constitutional specifications, named implementation evidence, and established traceability relationships, applying published CV types, and producing findings — not to invent a second tutor voice from CI machinery, not to grade the student, and not to certify an implementation.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Specifications evaluated** | Named Constitution / EIP / Programme VI / VII / VIII documents (and clauses as applicable) | Which constitutional specifications were evaluated? |
| **Implementation evidence consumed** | Named evidence subjects prepared and assessed | Which implementation evidence was consumed? |
| **Traceability relationships used** | Named established CT-01…CT-07 links (and related provenance) | Which traceability relationships were used? |
| **Lifecycle stage producing each finding** | Named CVL stage (especially CVL-04 / CVL-05) bound to each finding | Which lifecycle stage produced each finding? |
| **Boundaries preserved** | Explicit confirmation that forbidden certification / conformance-replacement / redefinition / mutation / substitution did not occur | Which constitutional boundaries were preserved? |

Lifecycle Explainability is:

- **coordination-centred** — it narrates specs → evidence → relationships → stages → findings under law;
- **catalogue-bound** — every justification cites published CVL and CV identities;
- **corpus-bound** — every justification cites published specifications;
- **lineage-honest** — every material justification cites established CT relationships used (or names the hard stop when none exist);
- **stage-honest** — every material finding is bound to the producing lifecycle stage;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-certifying** — satisfaction or closure is never narrated as a certificate;
- **quality-honest** — satisfaction or closure is never narrated as mastery, readiness, or educational quality;
- **conformance-honest** — closure is never narrated as permanent conformity or a rewrite of CC meaning;
- **mutation-honest** — explanation never hides artefact changes performed “so verification could proceed”;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, MS001 conformance speech, MS002 lineage speech, or WS2 / MS001 verification speech;
- **audit-aligned** — explanation components match CVLO-06 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions or private stage shortcuts.

Lifecycle Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–VIII / WS1 / WS2 MS001 meaning;
- a quality report on learning, coaching, or exam readiness;
- a conformity certificate or substitute for CC findings;
- a substitute for CT lineage speech;
- a substitute for CV verification speech;
- a CI status page, coverage report, or linter summary presented as constitutional coordination;
- a certificate for implementations, stacks, vendors, or releases;
- a licence to narrate mutated artefacts as if they were the original evidence subjects.

## 3. Mandatory Explainability Questions

Every material constitutional verification lifecycle must be able to answer:

### Q1 — Which constitutional specifications were evaluated?

**Required content**

- Named published corpus identities (Constitution / EIP / Programme VI / VII / VIII paths and clauses as applicable)
- Confirmation that unpublished customs were not used as standards

**Defect if**

- “The system was verified” with no corpus references
- Stack preference or “main branch” cited as law

---

### Q2 — Which implementation evidence was consumed?

**Required content**

- Named evidence subjects prepared at CVL-02 and assessed at CVL-04
- Binding between evidence identities and intended / applied CV types

**Defect if**

- Anonymous “the build” or “the tests” without identifiable subjects
- Evidence identities invented or mutated mid-lifecycle without disclosure and hard stop

---

### Q3 — Which traceability relationships were used?

**Required content**

- Named established CT-01…CT-07 relationships validated at CVL-03
- Provenance sufficient to reconstruct why those links were consumable

**Defect if**

- Lineage invented to force CVL-04
- “Linked somehow” without CT identity
- Treating “linked” as itself “verified” or “conformant”

---

### Q4 — Which lifecycle stage produced each finding?

**Required content**

- Binding of each verification finding to the producing CVL stage (normally CVL-04 evaluation dispositions crystallised at CVL-05)
- Honest recording of refuse-open / refuse-prepare / refuse-validate / refuse-close dispositions to the stages that produced them

**Defect if**

- Findings appear without stage binding
- Closure narrated as the producing stage for substantive satisfaction claims that actually arose earlier
- Silent stage skips when findings are claimed

---

### Q5 — Which constitutional boundaries were preserved?

**Required content**

- Explicit confirmation against `LIFECYCLE_BOUNDARIES.md` checks material to the concern (especially non-certification, non-conformance-replacement, non-redefinition, non-mutation, non-substitution)
- Disclosure of any hard stop that prevented progress or closure

**Defect if**

- Boundaries are implied, not speakable
- Closure speech smuggles certificates, conformity freezes, or law rewrites
- Artefact mutation is hidden

## 4. Audience Projections

| Audience | Vocabulary emphasis | Same truth |
|----------|---------------------|------------|
| **Student-facing** | Plain speech that the product was checked against published learning rules — not that the student mastered a topic or that the product is “certified forever” | Specs / evidence / lineage / stage / boundaries remain reconstructable |
| **Developer-facing** | Corpus paths, CV / CVL / CT identities, evidence subjects, disposition codes | No private “trust the pipeline” meaning |
| **Auditor-facing** | Full reconstruction: Q1–Q5 answers, stage traces, boundary checks | Continuity of prior lawful records |

Projections differ in vocabulary. They must not differ in constitutional facts.

## 5. Forbidden Explainability Moves

| Forbidden narration | Why | Lawful alternative |
|---------------------|-----|--------------------|
| “Lifecycle closed ⇒ certified” | Certification is forbidden | “Findings recorded; no certificate issued” |
| “Lifecycle closed ⇒ conformant forever” | Replaces CC meaning | “Verification coordinated; conformance remains WS1 / MS001” |
| “Verified ⇒ student ready / mastered” | Quality / mastery out of scope | Keep satisfaction speech distinct from educational claim classes |
| “We linked it, so it passed” | Lineage ≠ verification | Separate CT consumption speech from CV findings |
| “Stage skipped because CI was green” | Unpublished stage customs | Apply CVL-01…CVL-07 or refuse |
| “We adjusted the code so the lifecycle could finish” | Artefact mutation | Refuse-prepare / not-satisfied; propose lawful change outside lifecycle pretence |
| “This stack is now the standard” | Authority substitution / neutrality breach | Keep implementation as assessed subject |
| “Findings update the constitution” | Legislation via explanation | Propose amendment upstream; leave corpora unchanged |

## 7. Audit Alignment

Lifecycle explainability records must support reconstruction of:

1. Published specifications evaluated (Q1)
2. Implementation evidence consumed (Q2)
3. Traceability relationships used (Q3)
4. Lifecycle stage producing each finding (Q4)
5. Constitutional boundaries preserved (Q5)
6. Applied CV-01…CV-07 identities (from WS2 / MS001 speech)
7. Finding dispositions (satisfied / not-satisfied / deferred / escalated / refuse-*)
8. Continuity of prior lawful lifecycle history (EIP-005)

Missing any material element is an explainability defect under CVLO-05 / CVLO-06.
