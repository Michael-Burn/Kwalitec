## 1. Purpose

Verification that silently becomes a second constitution — rewriting specs so evidence passes, inventing educational meaning in “findings,” licensing runtime behaviour under a green badge, inventing lineage to force satisfaction, treating a preferred implementation as the new standard, or issuing certificates that freeze a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional verification** (Programme IX / WS2 / MS001) and **constitutional authorship / educational judgement / runtime authorship / conformance meaning / lineage authorship / certification** (Constitution / EIP / Programmes VI–VIII / WS1 / permitted writers).

---

## 2. Boundary Principles

1. **Evaluate, do not legislate.** Verification measures whether evidence satisfies published requirements; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as law” are hard stops as standards.
3. **Published verification types only.** Unpublished CV customs are unlawful.
4. **Named evidence only.** Assessments without identifiable implementation evidence are theatre.
5. **Established traceability only.** Invented CT relationships are hard stops as verification inputs.
6. **Exactly as published.** Successful satisfaction never rewrites specification meaning.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to a finding.
9. **Satisfied ≠ quality.** Verification never grades learning, mastery, readiness, or product success.
10. **Satisfied ≠ certified.** Verification never issues certificates for implementations, stacks, vendors, or releases.
11. **Satisfied ≠ permanently conformant.** Verification supports conformance honesty; it never replaces MS001 meaning or freezes conformity.
12. **No redefinition.** Programme VI questions, EIP claim classes, CC criteria, and CT lineage meaning survive assessment intact.
13. **No authority substitution.** A verified artefact never replaces the corpus for the next judgement.
14. **No bypass.** Product urgency never waives constitutional verification requirements.
15. **Repeatability.** Race-dependent dispositions are a defect.
16. **Explain the stop.** Students, developers, and auditors should hear when verification must refuse satisfaction.
17. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or certificates via findings.

## 3. What Verification May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Evaluate implementation evidence** | Apply CV-01…CV-07 to named evidence against published specifications |
| **Consume constitutional traceability** | Use established CT-01…CT-07 relationships as inputs; never invent them |
| **Consume conformance artefacts** | Reference identifiable WS1 / MS001 assessment records as inputs without rewriting them |
| **Produce verification findings** | Emit satisfied / not-satisfied / deferred / escalated under published criteria |
| **Preserve audit records** | Keep reconstructable trails of specs, evidence, relationships, findings, and boundaries |
| **Refuse unlawful satisfaction claims** | Prefer honest not-satisfied / deferred / escalated over improvisation |
| **Compose required types** | Apply published CV conjunctions without collapsing failed checks |
| **Remain repeatable** | Same published inputs → same disposition |
| **Remain implementation-neutral** | Honour verification law across lawful equivalent stacks |
| **Support constitutional conformance** | Strengthen fidelity honesty without replacing CC meaning or certifying conformity |
| **Explain verification** | Answer specs / evidence / relationships / findings / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **evaluate evidence against requirements**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CV types, invent CT links, author runtime behaviour, judge educational quality, or certify implementations.

## 4. What Verification Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Modify constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark not-satisfied |
| **Create constitutional law** | Findings are not legislation | Cite published law only; refuse unpublished standards |
| **Redefine educational meaning** | Programme VI owns coach / planner questions | Evaluate evidence of fidelity to published meaning; never redefine it |
| **Redefine constitutional meaning** | Published corpora own meaning | Confirm published meaning; never rewrite it in findings |
| **Substitute constitutional authority** | Published corpora remain the standard after any finding | Keep artefacts as assessed subjects, never as next-cycle law |
| **Certify implementations** | Verification is evaluative, not a certification bureau | Emit findings; never issue certificates for code, stacks, vendors, or releases |
| **Invent traceability** | CT owns lawful lineage | Consume established relationships; refuse invented links |
| **Rewrite conformance findings** | CC owns conformity meaning | Consume CC artefacts as inputs; never amend them to force satisfaction |
| **Bypass constitutional verification requirements** | Requirements are educational care, not optional polish | Prefer understatement / not-satisfied over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Evaluate obligations, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CV is a quality rubric | Keep satisfaction speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in verification machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via findings |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Evaluate against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface fidelity findings, not new tips |
| **Treat Twin / Adaptive / UI / CI noise as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / cache hits as constitutional satisfaction** | Operational proxies are not verification law | Cite published corpora and CV types |
| **Become irreplaceable by assessment topology** | Replaceability | Keep verification law implementation-independent |

## 6. Boundary Checks (Pre-Finding)

Before material constitutional verification is treated as established, assessment requires affirmative answers:

| Check | Question |
|-------|----------|
| **CVB-01 Specification identity** | Are evaluation standards published Constitution / EIP / Programme VI / VII / VIII specifications (not unpublished customs)? |
| **CVB-02 Verification class** | Are required CV-01…CV-07 types being applied (not unpublished customs)? |
| **CVB-03 Evidence identity** | Which named implementation evidence is under assessment? |
| **CVB-04 Traceability identity** | Which established CT relationships are consumed (none invented)? |
| **CVB-05 Criteria identity** | Which published criteria from those specifications / this catalogue apply? |
| **CVB-06 Non-legislation** | Does the assessment avoid creating or modifying constitutional specifications? |
| **CVB-07 Non-redefinition** | Does the assessment avoid redefining Programme VI educational meaning or sibling constitutional meaning? |
| **CVB-08 Non-substitution** | Does the assessment avoid treating the implementation or verification machinery as the next constitutional standard? |
| **CVB-09 Non-certification** | Does the assessment avoid issuing certificates for implementations, stacks, vendors, or releases? |
| **CVB-10 Neutrality** | Does the assessment avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CVB-11 Satisfaction ≠ quality / conformity certificate** | Is the outcome framed as evidence satisfaction — not educational quality, permanent conformity, or a certificate? |
| **CVB-12 Spec immutability** | Are constitutional corpora left unchanged by the assessment act? |
| **CVB-13 Repeatability / audit** | Is disposition reproducible; will explainability records preserve specs, evidence, relationships, findings, and boundaries? |

Any failed check → not-satisfied / deferred / escalated. Do not “best-effort” invent verification law, invent lineage, soft-amend specifications, or issue certificates in situ.
