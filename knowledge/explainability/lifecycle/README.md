## Purpose

This folder defines **the permanent constitutional lifecycle coordinating constitutional explainability** from initiation through audit intake, explanation construction, provenance validation, fidelity validation, publication, and honest closure.

It answers *how constitutional explainability is organised from audit intake through explanation publication*, *what the lifecycle must optimise*, *which recognised stages organise explanation production*, *what the lifecycle may and must never do*, and *how lifecycle progress is constitutionally explained* — without implementing Runtime A, executing constitutional rules, producing constitutional decisions, reinterpreting Educational Interpretation Principles, amending constitutional specifications, creating constitutional authority, or elevating lifecycle machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, or application services.

> **The Constitutional Explainability Lifecycle coordinates constitutional explainability.  
> It consumes completed constitutional audit records and publishes constitutional explanations without executing constitutional rules or creating constitutional authority.  
> It never becomes constitutional authority.**

## Architectural requirement

The Constitutional Explainability Lifecycle coordinates **constitutional explainability**.

| Lawful | Unlawful |
|--------|----------|
| Coordinate explanation production through recognised stages | Execute constitutional rules (WS2 engine responsibility) |
| Consume completed constitutional audit records | Begin against incomplete or unpublished audit records |
| Construct constitutional explanations | Produce constitutional decisions (WS3 responsibility) |
| Validate provenance | Re-record or re-validate constitutional audits (WS4 responsibility) |
| Validate explanation fidelity | Reinterpret Educational Interpretation Principles |
| Publish constitutional explanations | Amend constitutional specifications |
| Preserve transparency, fidelity, provenance, repeatability, understanding | Create or replace constitutional authority |
| Explain audit records / provenance / explanations / fidelity / boundaries | Elevate lifecycle machinery into a constitutional producer or executor |

**The Constitutional Explainability Lifecycle coordinates constitutional explainability while remaining entirely downstream of constitutional auditing.  
It never participates in execution, decision production, constitutional governance or constitutional authority.**

1. Confirm completed constitutional audit records exist under WS4 / MS001–MS003 — refuse explainability-lifecycle theatre against incomplete audit production.
2. Confirm the published Constitutional Explainability Architecture Model (WS5 / MS001) is in force — refuse lifecycle theatre that invents explainability components outside CEA-01…CEA-06.
3. Read `CONSTITUTIONAL_EXPLAINABILITY_LIFECYCLE_MODEL.md` for stack position and integrity rules.
4. Optimise under `LIFECYCLE_OBJECTIVES.md`.
5. Sequence under `LIFECYCLE_STAGES.md` (CEAL-01…CEAL-07 only).
6. Enforce hard stops under `LIFECYCLE_BOUNDARIES.md`.
7. Require explainability contracts from `LIFECYCLE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing lifecycle narration.
