## 1. Purpose

An Explainability Architecture that silently becomes a second constitution — re-executing rules under the label “explanation,” re-producing decisions under “construction,” re-recording audits under “intake,” reinterpreting EIP in “notes,” amending specifications so a preferred narration appears, or inventing governance outside published authority because a badge was needed — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional explanation** (Programme X / WS5 / MS001) and **constitutional execution / decision production / audit recording / legislation / independent interpretation / independent governance** (Constitution / EIP / Programmes VI–IX / WS2 / WS3 / WS4 / permitted writers).

## 2. Boundary Principles

1. **Explain, do not execute.** The Explainability Architecture explains completed activity; it does not perform constitutional rule execution.
2. **Explain, do not decide.** The Explainability Architecture explains completed decisions already recorded; it does not produce constitutional decisions.
3. **Explain, do not audit.** The Explainability Architecture explains completed audit records; it does not re-record or re-validate audits.
4. **Completed audit records only.** Incomplete or unpublished audit production is a hard stop.
5. **Published components only.** Unpublished CEA customs are unlawful.
6. **Exactly as published.** Successful explanation never rewrites specification meaning.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **EIP intact.** Educational Interpretation Principles are never reinterpreted or replaced by explanation prose.
9. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity.
10. **Explanations ≠ legislation.** Published constitutional explanations never amend constitutional specifications.
11. **Explanations ≠ decisions.** Published constitutional explanations never become substitute constitutional decisions.
12. **Explanations ≠ audits.** Published constitutional explanations never become substitute constitutional audit records.
13. **No rule execution.** Assembling explanations is not WS2 constitutional rule execution.
14. **No meaning reinterpretation.** Explanation prose never redefines Constitution / EIP / Programme VI–IX meaning.
15. **No authority substitution.** A published explanation never replaces the corpus for the next act.
16. **No authority creation.** Explanation never creates constitutional authority.
17. **No bypass.** Product urgency never waives required explainability components or completed-audit prerequisites.
18. **Repeatability.** Operator-dependent or ambient-only explanation that cannot be reconstructed is a defect.
19. **Explain the stop.** Students, developers, and auditors should hear when explanation must refuse.
20. **No emergency exemption.** Deadlines and demos never mint constitutional amendment, re-decision, or re-audit power via the Explainability Architecture.
21. **Fidelity before publish.** Invalid constructions must not be published as constitutionally valid.
22. **Upstream honesty.** Constitutional audit records remain audit records; explanation never rewrites them into new law, new dispositions, or new audits.
23. **Downstream-only.** The Explainability Architecture remains entirely downstream of constitutional auditing.

## 3. What the Explainability Architecture May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Explain completed constitutional activity** | Admit completed audit records and construct explanation content via CEA-01 / CEA-02 |
| **Preserve provenance** | Resolve reconstructable lineage via CEA-03 |
| **Validate explanation fidelity** | Confirm faithfulness via CEA-04 |
| **Publish constitutional explanations** | Make validated explanations available for transparency and understanding via CEA-05 |
| **Manage explanation state** | Record speakable Explainability Architecture progress via CEA-06 |
| **Refuse incomplete explanation** | Prefer honest refuse / invalid over improvisation |
| **Cite constitutional authority** | Name governing published corpora without replacing them |
| **Remain repeatable** | Same completed audit records + same provenance inputs ⇒ same explanation disposition |
| **Remain implementation-neutral** | Honour explainability law across lawful equivalent stacks |
| **Explain explanations** | Answer audit consumed / activities / provenance / explanation / boundaries without rewriting meaning |
| **Compose required components** | Bind published CEA conjunctions without collapsing missing components |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change before a lawful explanation can be produced |

## 4. What the Explainability Architecture Must Never Do (Unlawful)

| Unlawful action | Why it is forbidden |
|-----------------|---------------------|
| **Execute constitutional rules** | Rule execution belongs to WS2 Constitutional Execution Engine; explanation consumes completed audit records |
| **Produce constitutional decisions** | Decision production belongs to WS3 Constitutional Decision Architecture; explanation never re-decides |
| **Reinterpret constitutional meaning** | Meaning remains owned by Constitution / EIP / Programmes VI–IX |
| **Reinterpret Educational Interpretation Principles** | EIP is referenced as published; explanation notes never author new interpretation |
| **Amend constitutional specifications** | Explanations never soft-amend published law |
| **Modify constitutional specifications** | Clarifying notes must not rewrite published text |
| **Create constitutional authority** | Explanation never mints new constitutional ownership |
| **Replace constitutional authority** | Explainability machinery never becomes the standard for the next act |
| **Re-record or re-validate constitutional audits** | Audit recording belongs to WS4; explanation consumes completed audit records |
| **Begin against incomplete audit records** | Incomplete WS4 audit production is a hard stop |
| **Invent unpublished CEA components** | Closed CEA-01…CEA-06 catalogue only |
| **Publish invalid candidates as valid** | CEA-04 must validate before CEA-05 publication |
| **Invent provenance theatre** | Provenance must be reconstructable from completed audit records and published corpora |
| **Re-prepare or re-resolve execution context** | WS1 owns preparation; CEA consumes completed audit records |
| **Complete unfinished execution** | WS2 owns execution completion; CEA never finishes the mark sheet under an explanation label |
| **Complete unfinished decision production** | WS3 owns decision completion; CEA never finishes deciding under an explanation label |
| **Complete unfinished audit production** | WS4 owns audit completion; CEA never finishes filing under an explanation label |
| **Freeze a stack as law** | Implementation neutrality forbids stack elevation by explanation proximity |
| **Claim educational quality from publication** | Explanation ≠ mastery, readiness, or learning success |
| **Suppress lawful refuse** | Honesty requires speakable stops |

## 6. Hard Stops

Explanation **must stop** (refuse / invalid) when any of the following hold:

1. Required constitutional audit records are incomplete, unpublished, or non-reconstructable.
2. Required provenance cannot be resolved without inventing unpublished lineage.
3. Applying the only available “custom” would require executing constitutional rules, producing constitutional decisions, re-recording audits, reinterpreting EIP, or amending specifications.
4. The candidate explanation would create or replace constitutional authority, or determine constitutional decisions.
5. Fidelity validation (CEA-04) fails and no lawful repair exists without violating boundaries.
6. Required CEA components cannot be applied without inventing unpublished component identities.
7. Repeatability cannot be preserved for the material concern.
8. Explainability-of-explainability questions cannot be answered honestly without fabricating traces.

Product urgency, demo schedules, CI pressure, and founder preference never waive these hard stops.
