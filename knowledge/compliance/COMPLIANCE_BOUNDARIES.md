## 1. Purpose

Compliance that silently becomes a second constitution — rewriting specs so a report passes, inventing educational meaning in “determinations,” licensing runtime behaviour under a green seal, inventing or rewriting findings to force satisfaction, inventing lineage to force a pass, treating a preferred implementation as the new standard, or issuing certificates that freeze a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional compliance** (Programme IX / WS3 / MS001) and **constitutional authorship / educational judgement / runtime authorship / conformance meaning / lineage authorship / verification authorship / certification** (Constitution / EIP / Programmes VI–VIII / WS1 / WS2 / permitted writers).

---

## 2. Boundary Principles

1. **Determine, do not legislate.** Compliance judges whether obligations have been satisfied; it does not create law.
2. **Published obligations only.** Unpublished customs and “main as law” are hard stops as standards.
3. **Published compliance types only.** Unpublished CCM customs are unlawful.
4. **Identifiable findings only.** Determinations without identifiable verification findings (when required) are theatre.
5. **Established traceability only.** Invented CT relationships are hard stops as compliance inputs.
6. **Exactly as published.** Successful satisfaction never rewrites specification meaning.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to a determination.
9. **Satisfied ≠ quality.** Compliance never grades learning, mastery, readiness, or product success.
10. **Satisfied ≠ certified.** Compliance never issues certificates for implementations, stacks, vendors, or releases.
11. **Satisfied ≠ permanently conformant / verified.** Compliance speaks to obligation status; it never replaces MS001 or WS2 meaning or freezes conformity / verification.
12. **No redefinition.** Programme VI questions, EIP claim classes, CC criteria, CT lineage meaning, and CV finding meaning survive determination intact.
13. **No authority substitution.** A compliant artefact never replaces the corpus for the next judgement.
14. **No bypass.** Product urgency never waives constitutional compliance requirements.
15. **Consistency.** Race-dependent or contradictory dispositions for equivalent inputs are a defect.
16. **Explain the stop.** Students, developers, and auditors should hear when compliance must refuse satisfaction.
17. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or certificates via determinations.

## 3. What Compliance May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Determine constitutional obligation status** | Apply CCM-01…CCM-07 to named published obligations using consumed findings and specifications |
| **Consume verification findings** | Use identifiable CV findings (and lawful lifecycle / completion artefacts) as inputs; never invent or rewrite them |
| **Consume constitutional specifications** | Reference published Constitution / EIP / Programme VI / VII / VIII corpora as the sole obligation standard |
| **Consume constitutional traceability** | Use established CT-01…CT-07 relationships as inputs; never invent them |
| **Consume conformance relationships** | Reference identifiable WS1 / MS001 relationships / assessment records as inputs without rewriting them |
| **Preserve audit records** | Keep reconstructable trails of obligations, findings, specifications, determinations, and boundaries |
| **Refuse unlawful satisfaction claims** | Prefer honest not-satisfied / deferred / escalated over improvisation |
| **Compose required types** | Apply published CCM conjunctions without collapsing failed checks |
| **Remain consistent** | Same published inputs → same determination |
| **Remain implementation-neutral** | Honour compliance law across lawful equivalent stacks |
| **Support without replacing neighbours** | Strengthen obligation honesty without replacing CC / CT / CV meaning or certifying conformity / verification |
| **Explain compliance** | Answer obligations / findings / specs / determination / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **determine obligation status**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CCM types, invent CT links, invent or rewrite CV findings, author runtime behaviour, judge educational quality, or certify implementations.

## 4. What Compliance Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Certify implementations** | Compliance is evaluative of obligation status, not a certification bureau | Emit determinations; never issue certificates for code, stacks, vendors, or releases |
| **Modify constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark not-satisfied |
| **Replace constitutional authority** | Published corpora remain the standard after any determination | Keep artefacts as assessed subjects, never as next-cycle law |
| **Redefine educational meaning** | Programme VI owns coach / planner questions | Determine obligation status against published meaning; never redefine it |
| **Create constitutional law** | Determinations are not legislation | Cite published law only; refuse unpublished standards |
| **Redefine constitutional meaning** | Published corpora own meaning | Confirm published meaning; never rewrite it in determinations |
| **Invent or rewrite verification findings** | CV owns evidence-satisfaction findings | Consume identifiable findings; refuse invented or altered findings |
| **Invent traceability** | CT owns lawful lineage | Consume established relationships; refuse invented links |
| **Rewrite conformance findings** | CC owns conformity meaning | Consume CC relationships as inputs; never amend them to force satisfaction |
| **Bypass constitutional compliance requirements** | Requirements are educational care, not optional polish | Prefer understatement / not-satisfied over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Determine obligations, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CCM is a quality rubric | Keep obligation-status speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in compliance machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via determinations |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Determine against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface obligation-status findings, not new tips |
| **Treat Twin / Adaptive / UI / CI noise as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / cache hits / seals as constitutional satisfaction** | Operational proxies are not compliance law | Cite published corpora and CCM types |
| **Become irreplaceable by determination topology** | Replaceability | Keep compliance law implementation-independent |

## 6. Boundary Checks (Pre-Determination)

Before material constitutional compliance is treated as established, determination requires affirmative answers:

| Check | Question |
|-------|----------|
| **CCMB-01 Obligation / specification identity** | Are determination standards published Constitution / EIP / Programme VI / VII / VIII obligations and specifications (not unpublished customs)? |
| **CCMB-02 Compliance class** | Are required CCM-01…CCM-07 types being applied (not unpublished customs)? |
| **CCMB-03 Finding identity** | Which named verification findings are consumed (none invented or rewritten)? |
| **CCMB-04 Traceability identity** | Which established CT relationships are consumed (none invented)? |
| **CCMB-05 Criteria identity** | Which published criteria from those specifications / this catalogue apply? |
| **CCMB-06 Non-legislation** | Does the determination avoid creating or modifying constitutional specifications? |
| **CCMB-07 Non-redefinition** | Does the determination avoid redefining Programme VI educational meaning or sibling constitutional meaning? |
| **CCMB-08 Non-substitution** | Does the determination avoid treating the implementation or compliance machinery as the next constitutional standard? |
| **CCMB-09 Non-certification** | Does the determination avoid issuing certificates for implementations, stacks, vendors, or releases? |
| **CCMB-10 Neutrality** | Does the determination avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CCMB-11 Satisfaction ≠ quality / certificate** | Is the outcome framed as obligation status — not educational quality, permanent conformity, permanent verification, or a certificate? |
| **CCMB-12 Spec immutability** | Are constitutional corpora left unchanged by the determination act? |
| **CCMB-13 Consistency / audit** | Is disposition consistent for equivalent published inputs; will explainability records preserve obligations, findings, specs, determination, and boundaries? |

Any failed check → not-satisfied / deferred / escalated. Do not “best-effort” invent compliance law, invent findings, invent lineage, soft-amend specifications, or issue certificates in situ.
