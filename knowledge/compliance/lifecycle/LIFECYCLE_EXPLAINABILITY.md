## 1. Purpose

An expert IFoA tutor who cannot say *which obligation* was judged — which findings were consumed, which lineage was used, which stage produced each determination, and which limits were preserved — is not coaching; they are performing.

After Programmes VI–VIII have made meaning, ownership, tips, context, contracts, evidence, and runtime speech speakable, after WS1 has made conformance and lineage speech speakable, after WS2 has made verification speech speakable, and after WS3 / MS001 has made compliance speech speakable, Programme IX still needs one lifecycle-speech answer:

> **“Which constitutional obligations were evaluated, which verification findings were consumed, which traceability relationships were used, which lifecycle stage produced each determination, and which constitutional boundaries were preserved?”**

That answer must cover every material compliance lifecycle without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, inventing lineage, rewriting findings, freezing a stack as law, inventing unpublished CCM or CCL types, issuing certificates, replacing MS001 evaluation, replacing WS2 verification, mutating artefacts, or presenting closure as educational quality.

## 2. What Lifecycle Explainability Is

**Constitutional Compliance Lifecycle Explainability** is the constitutional obligation to narrate **coordination of named compliance activities through published CCL stages** — consuming published constitutional obligations and specifications, identifiable verification findings, and established traceability relationships, applying published CCM types, and producing determinations — not to invent a second tutor voice from CI machinery, not to grade the student, and not to certify an implementation.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Obligations evaluated** | Named published constitutional duties (and corpus / clause identities as applicable) | Which constitutional obligations were evaluated? |
| **Verification findings consumed** | Named CV findings (and related lawful lifecycle / completion artefacts) used as inputs | Which verification findings were consumed? |
| **Traceability relationships used** | Named established CT-01…CT-07 links (and related provenance) | Which traceability relationships were used? |
| **Lifecycle stage producing each determination** | Named CCL stage (especially CCL-04 / CCL-05) bound to each determination | Which lifecycle stage produced each determination? |
| **Boundaries preserved** | Explicit confirmation that forbidden certification / verification-replacement / redefinition / mutation / substitution did not occur | Which constitutional boundaries were preserved? |

Lifecycle Explainability is:

- **coordination-centred** — it narrates obligations → findings → relationships → stages → determinations under law;
- **catalogue-bound** — every justification cites published CCL and CCM identities;
- **corpus-bound** — every justification cites published obligations and specifications;
- **findings-honest** — every material justification cites identifiable verification findings consumed (or names the hard stop when none exist);
- **lineage-honest** — every material justification cites established CT relationships used (or names the hard stop when none exist);
- **stage-honest** — every material determination is bound to the producing lifecycle stage;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-certifying** — satisfaction or closure is never narrated as a certificate;
- **quality-honest** — satisfaction or closure is never narrated as mastery, readiness, or educational quality;
- **verification-honest** — closure is never narrated as a verification re-run or substitute for CV / CVL / CVC;
- **conformance-honest** — closure is never narrated as permanent conformity or a rewrite of CC meaning;
- **mutation-honest** — explanation never hides artefact changes performed “so compliance could proceed”;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, MS001 conformance speech, MS002 lineage speech, WS2 verification speech, or WS3 / MS001 compliance speech;
- **audit-aligned** — explanation components match CCLO-06 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions or private stage shortcuts.

Lifecycle Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–VIII / WS1 / WS2 / WS3 MS001 meaning;
- a quality report on learning, coaching, or exam readiness;
- a conformity certificate or substitute for CC findings;
- a substitute for CT lineage speech;
- a substitute for CV verification speech;
- a substitute for CCM compliance-determination speech;
- a CI status page, coverage report, or linter summary presented as constitutional coordination;
- a certificate for implementations, stacks, vendors, or releases;
- a licence to narrate rewritten findings or mutated artefacts as if they were the original inputs.

## 3. Mandatory Explainability Questions

Every material constitutional compliance lifecycle must be able to answer:

### Q1 — Which constitutional obligations were evaluated?

**Required content**

- Named published obligation and corpus identities (Constitution / EIP / Programme VI / VII / VIII paths and clauses as applicable)
- Confirmation that unpublished customs were not used as standards

**Defect if**

- “The system was compliant” with no obligation / corpus references
- Stack preference or “main branch” cited as law

---

### Q2 — Which verification findings were consumed?

**Required content**

- Named verification findings prepared at CCL-02 and assessed at CCL-04
- Binding between finding identities and intended / applied CCM types

**Defect if**

- Anonymous “the build” or “the tests” without identifiable findings
- Findings invented, rewritten, or re-run as compliance without disclosure and hard stop

---

### Q3 — Which traceability relationships were used?

**Required content**

- Named established CT-01…CT-07 relationships confirmed at CCL-03
- Provenance sufficient to reconstruct why those links were consumable

**Defect if**

- Lineage invented to force CCL-04
- “Linked somehow” without CT identity
- Treating “linked” as itself “compliant,” “verified,” or “conformant”

---

### Q4 — Which lifecycle stage produced each determination?

**Required content**

- Binding of each compliance determination to the producing CCL stage (normally CCL-04 assessment dispositions crystallised at CCL-05)
- Honest recording of refuse-open / refuse-prepare / refuse-confirm / refuse-close dispositions to the stages that produced them

**Defect if**

- Determinations appear without stage binding
- Closure narrated as the producing stage for substantive satisfaction claims that actually arose earlier
- Silent stage skips when determinations are claimed

---

### Q5 — Which constitutional boundaries were preserved?

**Required content**

- Explicit confirmation against `LIFECYCLE_BOUNDARIES.md` checks material to the concern (especially non-certification, non-verification-replacement, non-redefinition, non-mutation, non-substitution)
- Disclosure of any hard stop that prevented progress or closure

**Defect if**

- Boundaries are implied, not speakable
- Closure speech smuggles certificates, conformity freezes, verification replacement, or law rewrites
- Findings rewriting or artefact mutation is hidden

## 4. Audience Projections

| Audience | Vocabulary emphasis | Same truth |
|----------|---------------------|------------|
| **Student-facing** | Plain speech that the product was judged against published learning obligations — not that the student mastered a topic or that the product is “certified forever” | Obligations / findings / lineage / stage / boundaries remain reconstructable |
| **Developer-facing** | Corpus paths, CCM / CCL / CT / CV identities, finding subjects, disposition codes | No private “trust the seal” meaning |
| **Auditor-facing** | Full reconstruction: Q1–Q5 answers, stage traces, boundary checks | Continuity of prior lawful records |

Projections differ in vocabulary. They must not differ in constitutional facts.

## 5. Forbidden Explainability Moves

| Forbidden narration | Why | Lawful alternative |
|---------------------|-----|--------------------|
| “Lifecycle closed ⇒ certified” | Certification is forbidden | “Determinations recorded; no certificate issued” |
| “Lifecycle closed ⇒ verified again” | Replaces WS2 verification | “Compliance coordinated; verification remains WS2” |
| “Lifecycle closed ⇒ conformant forever” | Replaces CC meaning | “Compliance coordinated; conformance remains WS1 / MS001” |
| “Compliant ⇒ student ready / mastered” | Quality / mastery out of scope | Keep obligation-status speech distinct from educational claim classes |
| “We linked it, so it passed” | Lineage ≠ compliance | Separate CT consumption speech from CCM determinations |
| “We rechecked the tests in compliance” | Verification replacement | Consume published CV findings; refuse invented re-runs |
| “Stage skipped because CI was green” | Unpublished stage customs | Apply CCL-01…CCL-07 or refuse |
| “We adjusted the code so the lifecycle could finish” | Artefact mutation | Refuse-prepare / not-satisfied; propose lawful change outside lifecycle pretence |
| “This stack is now the standard” | Authority substitution / neutrality breach | Keep implementation as assessed subject |
| “Determinations update the constitution” | Legislation via explanation | Propose amendment upstream; leave corpora unchanged |

## 7. Audit Alignment

Lifecycle explainability records must support reconstruction of:

1. Published constitutional obligations evaluated (Q1)
2. Verification findings consumed (Q2)
3. Traceability relationships used (Q3)
4. Lifecycle stage producing each determination (Q4)
5. Constitutional boundaries preserved (Q5)
6. Applied CCM-01…CCM-07 identities (from WS3 / MS001 speech)
7. Determination dispositions (satisfied / not-satisfied / deferred / escalated / refuse-*)
8. Continuity of prior lawful lifecycle history (EIP-005)

Missing any material element is an explainability defect under CCLO-05 / CCLO-06.
