## 1. Purpose

A lifecycle that silently becomes a second constitution — rewriting specs so stages “complete,” inventing educational meaning in “determinations,” licensing runtime behaviour under a closed seal, inventing lineage to force CCL-04, rewriting verification findings so obligations look satisfied, treating a preferred implementation as the new standard, mutating artefacts mid-lifecycle, or issuing certificates that freeze a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional compliance lifecycle coordination** (Programme IX / WS3 / MS002) and **constitutional authorship / educational judgement / runtime authorship / conformance meaning / lineage authorship / verification authorship / compliance-type authorship / certification / artefact mutation** (Constitution / EIP / Programmes VI–VIII / WS1 / WS2 / WS3 MS001 / permitted writers).

---

## 2. Boundary Principles

1. **Coordinate, do not legislate.** The lifecycle organises compliance; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as law” are hard stops as standards.
3. **Published stages only.** Unpublished CCL customs are unlawful.
4. **Published compliance types only.** CCL-04 applies CCM-01…CCM-07 only.
5. **Named verification findings only.** Lifecycles without identifiable findings are theatre.
6. **Established traceability only.** Invented CT relationships are hard stops as lifecycle inputs.
7. **Exactly as published.** Successful progress never rewrites specification meaning.
8. **Authority first.** Published corpora remain the sole constitutional standard.
9. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to closure.
10. **Closed ≠ quality.** Lifecycle closure never grades learning, mastery, readiness, or product success.
11. **Closed ≠ certified.** The lifecycle never issues certificates for implementations, stacks, vendors, or releases.
12. **Closed ≠ permanently conformant.** The lifecycle supports obligation honesty; it never replaces MS001 meaning or freezes conformity.
13. **Closed ≠ verified again.** The lifecycle consumes verification; it never replaces WS2 verification.
14. **No redefinition.** Programme VI questions, EIP claim classes, CC criteria, CT lineage meaning, CV verification meaning, and CCM type meaning survive coordination intact.
15. **No authority substitution.** A closed lifecycle never replaces the corpus for the next judgement.
16. **No artefact mutation.** Coordination never rewrites implementation artefacts to manufacture passable obligation status.
17. **No bypass.** Product urgency never waives constitutional lifecycle requirements.
18. **Repeatability / consistency.** Race-dependent or private stage shortcuts are defects.
19. **Explain the stop.** Students, developers, and auditors should hear when the lifecycle must refuse progress or closure.
20. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or certificates via lifecycle closure.

## 3. What the Lifecycle May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate compliance** | Organise activities through CCL-01…CCL-07 |
| **Consume constitutional specifications** | Use published Constitution / EIP / Programme VI / VII / VIII corpora as determination standards |
| **Consume verification findings** | Bind named CV findings (and lawful lifecycle / completion artefacts) for determination without inventing or rewriting them |
| **Consume established traceability** | Use established CT-01…CT-07 relationships as inputs; never invent them |
| **Consume conformance artefacts** | Reference identifiable WS1 / MS001 assessment records as inputs without rewriting them |
| **Apply compliance types** | At CCL-04, apply published CCM-01…CCM-07 only |
| **Produce compliance determinations** | Emit satisfied / not-satisfied / deferred / escalated under published criteria |
| **Preserve audit records** | Keep reconstructable trails of obligations, findings, relationships, stages, determinations, and boundaries |
| **Refuse unlawful progress** | Prefer honest refuse / defer / escalate / not-satisfied over improvisation |
| **Remain repeatable and consistent** | Same published inputs → same stage outcomes and dispositions |
| **Remain implementation-neutral** | Honour lifecycle law across lawful equivalent stacks |
| **Support constitutional conformance honesty** | Strengthen obligation honesty without replacing CC meaning or certifying conformity |
| **Explain lifecycle progress** | Answer obligations / findings / relationships / stages / determinations / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **coordinate compliance**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CCM or CCL types, invent CT links, author runtime behaviour, judge educational quality, re-run verification, certify implementations, or modify artefacts under coordination pretext.

## 4. What the Lifecycle Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Certify implementations** | Lifecycle is coordinative / evaluative, not a certification bureau | Emit determinations; never issue certificates for code, stacks, vendors, or releases |
| **Replace verification** | CV / CVL / CVC own evidence evaluation and verification completion | Consume findings; never narrate closure as a verification re-run or substitute |
| **Redefine constitutional law** | Published corpora own meaning | Confirm published meaning; never rewrite it in stage prose or determinations |
| **Modify constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark not-satisfied / refuse |
| **Modify implementation artefacts** | Coordination is not a mutation licence | Consume findings as found; refuse when identity is insufficient |
| **Create constitutional law** | Determinations and stage progress are not legislation | Cite published law only; refuse unpublished standards |
| **Redefine educational meaning** | Programme VI owns coach / planner questions | Determine obligation status against published meaning; never redefine it |
| **Substitute constitutional authority** | Published corpora remain the standard after any closure | Keep artefacts as assessed subjects, never as next-cycle law |
| **Invent traceability** | CT owns lawful lineage | Consume established relationships; refuse invented links |
| **Invent or rewrite verification findings** | CV owns verification meaning | Consume findings as inputs; never amend them to force satisfaction |
| **Rewrite conformance findings** | CC owns conformity meaning | Consume CC artefacts as inputs; never amend them to force satisfaction |
| **Invent compliance types** | CCM catalogue is closed under WS3 / MS001 | Apply CCM-01…CCM-07 only |
| **Invent lifecycle stages** | CCL catalogue is closed under this corpus | Apply CCL-01…CCL-07 only |
| **Bypass lifecycle requirements** | Requirements are educational care, not optional polish | Prefer understatement / refuse over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Coordinate obligations, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CCL stage is a quality rubric | Keep coordination speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in lifecycle machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via stages |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Assess against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface obligation-status findings, not new tips |
| **Treat Twin / Adaptive / UI / CI noise as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / cache hits as constitutional satisfaction or closure** | Operational proxies are not lifecycle law | Cite published corpora, CCM types, and CCL stages |
| **Become irreplaceable by coordination topology** | Replaceability | Keep lifecycle law implementation-independent |

## 6. Boundary Checks (Pre-Closure)

Before a material constitutional compliance lifecycle is treated as closed, coordination requires affirmative answers:

| Check | Question |
|-------|----------|
| **CCLB-01 Specification / obligation identity** | Are determination standards published Constitution / EIP / Programme VI / VII / VIII obligations and specifications (not unpublished customs)? |
| **CCLB-02 Stage class** | Are required CCL-01…CCL-07 stages being applied (not unpublished customs)? |
| **CCLB-03 Compliance class** | Are required CCM-01…CCM-07 types applied at CCL-04 (not unpublished customs)? |
| **CCLB-04 Findings identity** | Which named verification findings were consumed? |
| **CCLB-05 Traceability identity** | Which established CT relationships were used (none invented)? |
| **CCLB-06 Determination binding** | Which lifecycle stage produced each determination (especially CCL-04 / CCL-05)? |
| **CCLB-07 Non-legislation** | Does the lifecycle avoid creating or modifying constitutional specifications? |
| **CCLB-08 Non-redefinition** | Does the lifecycle avoid redefining Programme VI educational meaning or sibling constitutional meaning? |
| **CCLB-09 Non-substitution** | Does the lifecycle avoid treating the implementation or lifecycle machinery as the next constitutional standard? |
| **CCLB-10 Non-certification** | Does the lifecycle avoid issuing certificates for implementations, stacks, vendors, or releases? |
| **CCLB-11 Non-verification-replacement** | Is closure framed as compliance coordination complete — not a verification re-run or substitute for WS2? |
| **CCLB-12 Non-conformance-replacement** | Is closure framed as coordination complete — not certified conformity or permanent conformance? |
| **CCLB-13 Non-mutation** | Were implementation artefacts left unmodified by lifecycle coordination? |
| **CCLB-14 Neutrality** | Does the lifecycle avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CCLB-15 Closure ≠ quality** | Is the outcome framed as lifecycle coordination / obligation status — not educational quality? |
| **CCLB-16 Spec immutability** | Are constitutional corpora left unchanged by the lifecycle act? |
| **CCLB-17 Repeatability / audit** | Are stage outcomes reproducible; do explainability records preserve obligations, findings, relationships, stages, determinations, and boundaries? |

Any failed check → refuse-close / deferred / escalated / not-satisfied as published. Do not “best-effort” invent lifecycle law, invent lineage, soft-amend specifications, rewrite findings, mutate artefacts, or issue certificates in situ.

## 8. Closing Statement

> **The constitutional compliance lifecycle is powerful only as faithful coordination of compliance activities against published obligations using verification findings and established traceability.  
> The moment it certifies an implementation, replaces verification, redefines constitutional law, or modifies implementation artefacts — or pretends closure is educational quality — it has left constitutional education and entered product fiction.**
