## 1. Purpose

An expert IFoA tutor who cannot say *which rule* was cited — which artefact was related, which lineage category applied, what provenance was preserved, and which limits remained intact — is not coaching; they are performing.

After Programmes VI–VIII have made meaning, ownership, tips, context, contracts, evidence, and runtime speech speakable, and after MS001 has made conformance speech speakable, Programme IX still needs one traceability-speech answer:

> **“Which constitutional specification is referenced, which implementation artefact is related, which traceability category applies, which provenance is preserved, and which constitutional boundaries remain intact?”**

That answer must cover every material traceability relationship without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, freezing a stack as law, inventing unpublished CT types, replacing MS001 evaluation, or presenting lineage as educational quality or conformity.

---

## 2. What Traceability Explainability Is

**Constitutional Traceability Explainability** is the constitutional obligation to narrate **lawful relationships among named published constitutional specifications, named implementation artefacts and/or conformance findings, under published CT types** — not to invent a second tutor voice from CI link graphs, and not to grade the student or certify conformity.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Specification referenced** | Named Constitution / EIP / Programme VI / VII / VIII documents (and MS001 identities where CT-07 applies) | Which constitutional specification is referenced? |
| **Artefact related** | Named implementation subjects and/or assessment records | Which implementation artefact is related? |
| **Category applied** | Named CT-01…CT-07 type(s) | Which traceability category applies? |
| **Provenance preserved** | Reconstructable origin from published identity → related subject | Which provenance is preserved? |
| **Boundaries intact** | Explicit confirmation that forbidden legislation / redefinition / authority inference / conformance substitution did not occur | Which constitutional boundaries remain intact? |

Traceability Explainability is:

- **relationship-centred** — it narrates specs → subjects → category → provenance under law;
- **catalogue-bound** — every justification cites published CT identities;
- **corpus-bound** — every justification cites published specifications;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-evaluative-substitute** — lineage is never narrated as conformity;
- **quality-honest** — traced is never narrated as mastery, readiness, or educational quality;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, or MS001 conformance speech;
- **audit-aligned** — explanation components match CT-07 and CTO-04 reconstruction needs;
- **authority-honest** — explanations must not paper over authority inference or stack canonisation.

Traceability Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–VIII / MS001 meaning;
- a quality report on learning, coaching, or exam readiness;
- a conformance certificate or substitute for CC findings;
- a substitute for Programme VIII evidence-validation or contract explainability corpora;
- a rendering system, UI template, CI badge, dependency visualiser, or analytics dashboard;
- a claim that clear lineage speech guarantees learning, a pass, or conformity;
- a licence to present coverage, lint scores, ticket graphs, or pipeline greens as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material constitutional traceability relationship should answer all five questions:

### CTEQ-01 — Which constitutional specification is referenced?

Name the primary published Constitution / EIP / Programme VI / VII / VIII specifications (paths and identities). When CT-07 applies, name the MS001 assessment / corpus identities grounding the finding. When a clause or catalogue ID is material, name it (for example EIP-002 claim class; RC-02; EC-01 as *subject*). Unpublished tribal norms and “how main works” are not constitutional specifications.

### CTEQ-02 — Which implementation artefact is related?

Name the primary artefacts under relationship (for example structural module boundaries, behavioural disposition set, evidence-consumption path, runtime contract binding map, interface composition map, API operation set, audit trail, assessment record). Protocol or vendor names alone are not sufficient without constitutional mapping. When only findings are related under CT-07, name the assessment artefact and the implementation subjects it already cites.

### CTEQ-03 — Which traceability category applies?

Name the primary CT-01…CT-07 type(s) applied. Cross-cutting relationships name all bound types (for example CT-03 + CT-04 + CT-07). “Ticket linked” or “deps mapped” is not a constitutional category.

### CTEQ-04 — Which provenance is preserved?

Distinguish:

- **specification provenance** — which published identity anchors the relationship;
- **subject provenance** — which named artefact / finding is related and under what claimed obligation;
- **lineage walkability** — whether published specification → CT type → named subject can be reconstructed without invented hops;
- **continuity honesty** — prior lawful lineage not erased for convenience (EIP-005).

Never narrate provenance as “student is ready,” “mastery confirmed,” “law updated,” “this stack is now constitutional,” or “linked therefore conformant.”

### CTEQ-05 — Which constitutional boundaries remain intact?

Confirm the hard stops in `TRACEABILITY_BOUNDARIES.md` that were checked — especially non-modification of specifications, non-redefinition of constitutional meaning, non-inference of constitutional authority, non-substitution for conformance evaluation, implementation neutrality, and non-equation of lineage with educational quality or constitutional truth.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **CTEC-01** | Specification identity | Named Constitution / EIP / Programme VI / VII / VIII refs (+ MS001 where CT-07) |
| **CTEC-02** | Artefact / finding identity | Named implementation subjects and/or assessment records related |
| **CTEC-03** | Traceability type identity | Named CT-01…CT-07 binding(s) |
| **CTEC-04** | Provenance record | Published identity → related subject walkability |
| **CTEC-05** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **CTEC-06** | Authority preservation note | Confirmation that published corpora remain the standard |
| **CTEC-07** | Neutrality note | Confirmation that no stack / vendor was privileged as law |
| **CTEC-08** | Non-conformance-substitution note | Confirmation that linkage was not narrated as conformity |
| **CTEC-09** | Assessment-support note | Confirmation that MS001 can re-locate the same refs / subjects |
| **CTEC-10** | Refusal / deferral honesty | When no lawful lineage existed, say so |
| **CTEC-11** | Continuity note | Prior lawful lineage history not erased (EIP-005) |
| **CTEC-12** | Non-claim honesty | Explicit refusal of mastery / pass / quality / meaning-rewrite / law-amendment / stack-canonisation / conformity-from-link overclaim |
| **CTEC-13** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |

Components are **constitutional content obligations**, not database columns, API fields, CI annotations, or UI widgets. Persistence and rendering are out of scope for this milestone.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | That the learning system’s behaviour remains connected to published educational rules, why a stop occurred when lineage is incomplete, and what limits apply — in plain educational language | Internal CT IDs as theatre; CI traces; ticket graphs as “proof you are ready”; traced as mastery or as conformity |
| **Developer / auditor** | Full CTEQ-01…05 answers, corpus paths, CT IDs, provenance walks, boundary checks, neutrality and non-substitution notes | Product success metrics, pipeline greens, or coverage counts substituted for constitutional refs; lineage framed as educational quality, new law, or conformity |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

A complete material journey may carry every layer that applied. Traceability speech without upstream specification identity is hollow. Upstream law without CT identity and provenance invites silent reimplementation drift. Conformance speech without CT lineage invites unrepeatable assessment.
