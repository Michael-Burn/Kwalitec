## 1. Purpose

Linkage that silently becomes a second constitution — rewriting specs so code looks documented, inventing educational meaning in “provenance notes,” licensing runtime behaviour under a green link badge, treating a preferred implementation as the new standard, or declaring conformity because something is linked — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional traceability** (Programme IX / WS1 / MS002) and **constitutional authorship / educational judgement / runtime authorship / conformance evaluation** (Constitution / EIP / Programmes VI–VIII / MS001 / permitted writers).

---

## 2. Boundary Principles

1. **Relate, do not legislate.** Traceability preserves relationships; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as law” are hard stops as relationship anchors.
3. **Published traceability types only.** Unpublished CT customs are unlawful.
4. **Named subjects only.** Relationships without identifiable artefacts or findings are theatre.
5. **Exactly as published.** Successful lineage never rewrites specification meaning.
6. **Authority first.** Published corpora remain the sole constitutional standard.
7. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to a link.
8. **Traced ≠ quality.** Traceability never grades learning, mastery, readiness, or product success.
9. **Traced ≠ conformant.** Traceability never replaces MS001 conformance evaluation.
10. **No reinterpretation.** Programme VI questions and EIP claim classes survive linkage intact.
11. **No authority inference.** A linked artefact never becomes the next-cycle constitutional standard.
12. **No bypass.** Product urgency never waives constitutional provenance requirements.
13. **No conformance substitution.** “Linked” must never be narrated as “conformant.”
14. **Explain the stop.** Students, developers, and auditors should hear when lineage must refuse.
15. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power via lineage.

## 3. What Traceability May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Relate constitutional specifications** | Apply CT-01 among published Constitution / EIP / Programme VI / VII / VIII / MS001 identities |
| **Relate implementation artefacts** | Apply CT-02…CT-06 to named artefacts against published specifications |
| **Relate conformance findings** | Apply CT-07 to MS001 assessment records and their grounding subjects |
| **Preserve provenance** | Keep reconstructable origin from published identity → related subject |
| **Refuse unlawful lineage claims** | Prefer honest refuse / defer / escalate over improvisation |
| **Compose required types** | Apply published CT conjunctions without collapsing failed links |
| **Support repeatable assessment** | Expose stable refs MS001 can re-evaluate |
| **Remain implementation-neutral** | Honour lineage law across lawful equivalent stacks |
| **Explain traceability** | Answer specs / artefacts / category / provenance / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **preserve relationships**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CT types, author runtime behaviour, evaluate fidelity in place of MS001, or judge educational quality.

## 4. What Traceability Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Modify constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or refuse incomplete lineage |
| **Create constitutional law** | Lineage records are not legislation | Cite published law only; refuse unpublished anchors |
| **Redefine constitutional meaning** | Meaning owners own claim classes and warrants | Preserve published meaning; never rewrite it in provenance notes |
| **Infer constitutional authority** | Published corpora remain the standard after any link | Keep artefacts as related subjects, never as next-cycle law |
| **Replace conformance evaluation** | MS001 owns fidelity disposition | Supply the map assessment walks; never claim conformity from linkage alone |
| **Create educational meaning** | Programme VI owns coach / planner questions | Preserve identity of published meaning; never invent it |
| **Author runtime behaviour** | Programme VIII + permitted writers own execution law | Relate behaviour to published law; do not mint behaviour |
| **Bypass provenance requirements** | Requirements are educational care, not optional polish | Prefer understatement / refuse over invented green links |
| **Privilege a technology as constitutional** | Implementation neutrality | Relate obligations, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CT is a quality rubric | Keep lineage speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in linkage machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via lineage |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Relate against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface lineage, not new tips |
| **Treat Twin / Adaptive / UI / CI noise as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / cache hits as constitutional provenance** | Operational proxies are not traceability law | Cite published corpora and CT types |
| **Become irreplaceable by linkage topology** | Replaceability | Keep traceability law implementation-independent |

## 6. Boundary Checks (Pre-Relationship)

Before material constitutional traceability is treated as established, linkage requires affirmative answers:

| Check | Question |
|-------|----------|
| **CTB-01 Specification identity** | Are relationship anchors published Constitution / EIP / Programme VI / VII / VIII specifications (and MS001 identities where CT-07 applies) — not unpublished customs? |
| **CTB-02 Traceability class** | Are required CT-01…CT-07 types being applied (not unpublished customs)? |
| **CTB-03 Subject identity** | Which named implementation artefacts and/or conformance findings are related? |
| **CTB-04 Provenance identity** | Which published provenance is preserved from anchor → subject? |
| **CTB-05 Non-legislation** | Does the relationship avoid creating or modifying constitutional specifications? |
| **CTB-06 Non-redefinition** | Does the relationship avoid redefining constitutional meaning? |
| **CTB-07 Non-authority-inference** | Does the relationship avoid treating the implementation as the next constitutional standard? |
| **CTB-08 Non-conformance-substitution** | Does the relationship avoid claiming conformity solely from linkage? |
| **CTB-09 Neutrality** | Does the relationship avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CTB-10 Traced ≠ quality** | Is the outcome framed as lineage — not educational quality / truth? |
| **CTB-11 Spec immutability** | Are constitutional corpora left unchanged by the linkage act? |
| **CTB-12 Audit / explainability** | Will explainability records preserve specs, artefacts, category, provenance, and boundaries? |

Any failed check → refuse / defer / escalate. Do not “best-effort” invent traceability law or soft-amend specifications in situ.
