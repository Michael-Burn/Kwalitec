## 1. Purpose

An expert IFoA tutor who cannot say *which rule* was checked — which artefacts were assessed, which criteria applied, what finding resulted, and which limits were preserved — is not coaching; they are performing.

After Programmes VI–VIII have made meaning, ownership, tips, context, contracts, evidence, and runtime speech speakable, Programme IX still needs one conformance-speech answer:

> **“Which constitutional specifications were evaluated, which implementation artefacts were assessed, which conformance criteria were applied, which findings were produced, and which constitutional boundaries were preserved?”**

That answer must cover every material conformance assessment without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, freezing a stack as law, inventing unpublished CC types, or presenting conformity as educational quality.

---

## 2. What Conformance Explainability Is

**Constitutional Conformance Explainability** is the constitutional obligation to narrate **evaluation of named implementation artefacts against published constitutional specifications under published CC types** — not to invent a second tutor voice from CI machinery, and not to grade the student.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Specifications evaluated** | Named Constitution / EIP / Programme VI / VII / VIII documents (and clauses as applicable) | Which constitutional specifications were evaluated? |
| **Artefacts assessed** | Named implementation subjects (structure, behaviour, evidence handling, runtime, interface, API, audit) | Which implementation artefacts were assessed? |
| **Criteria applied** | Named CC-01…CC-07 type(s) and published criteria within those types / referenced corpora | Which conformance criteria were applied? |
| **Findings produced** | conformant / non-conformant / deferred / escalated (with composition notes) | Which findings were produced? |
| **Boundaries preserved** | Explicit confirmation that forbidden legislation / reinterpretation / authorship / substitution did not occur | Which constitutional boundaries were preserved? |

Conformance Explainability is:

- **evaluation-centred** — it narrates specs → artefacts → criteria → findings under law;
- **catalogue-bound** — every justification cites published CC identities;
- **corpus-bound** — every justification cites published specifications;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **quality-honest** — conformity is never narrated as mastery, readiness, or educational quality;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, or Programme VIII contract / evidence / validation speech;
- **audit-aligned** — explanation components match CC-07 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions.

Conformance Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–VIII meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for Programme VIII evidence-validation or contract explainability corpora;
- a rendering system, UI template, CI badge, log shipper, or analytics dashboard;
- a claim that clear conformance speech guarantees learning or a pass;
- a licence to present coverage, lint scores, or pipeline greens as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material constitutional conformance assessment should answer all five questions:

### CCEQ-01 — Which constitutional specifications were evaluated?

Name the primary published Constitution / EIP / Programme VI / VII / VIII specifications (paths and identities). When a clause or catalogue ID is material, name it (for example EIP-002 claim class; RC-02; EC-01 as *subject*). Unpublished tribal norms and “how main works” are not constitutional specifications.

### CCEQ-02 — Which implementation artefacts were assessed?

Name the primary artefacts under evaluation (for example structural module boundaries, behavioural disposition set, evidence-consumption path, runtime contract binding map, interface composition map, API operation set, audit trail). Protocol or vendor names alone are not sufficient without constitutional mapping.

### CCEQ-03 — Which conformance criteria were applied?

Name the primary CC-01…CC-07 type(s) and the published permitted / prohibited evaluation criteria applied. Cross-cutting assessment names all bound types (for example CC-03 + CC-04 + CC-07). “Pipeline green” is not a constitutional criterion.

### CCEQ-04 — Which findings were produced?

Distinguish:

- **conformant** — required criteria passed under published law; fidelity affirmed for the named scope;
- **non-conformant** — required criteria failed; fidelity must not be claimed for the contemplated scope;
- **deferred** — published law requires waiting (for example incomplete artefact identity still expected under continuity);
- **escalated** — published law requires human / corpus / authority escalation paths.

Never narrate findings as “student is ready,” “mastery confirmed,” “law updated,” or “this stack is now constitutional.”

### CCEQ-05 — Which constitutional boundaries were preserved?

Confirm the hard stops in `CONFORMANCE_BOUNDARIES.md` that were checked — especially non-modification of specifications, non-creation of educational meaning, non-authorship of runtime behaviour, non-substitution of constitutional authority, implementation neutrality, and non-equation of conformity with educational quality or constitutional truth.

## 4. Explanation Components

| ID | Component | Obligation |
|----|-----------|------------|
| **CCEC-01** | Specification identity | Named Constitution / EIP / Programme VI / VII / VIII refs |
| **CCEC-02** | Artefact identity | Named implementation subjects under assessment |
| **CCEC-03** | Conformance type identity | Named CC-01…CC-07 binding(s) |
| **CCEC-04** | Criteria identity | Published permitted / prohibited evaluation criteria applied |
| **CCEC-05** | Finding disposition | conformant / non-conformant / deferred / escalated with composition |
| **CCEC-06** | Boundary preservation record | Confirmation that forbidden acts did not occur |
| **CCEC-07** | Authority preservation note | Confirmation that published corpora remain the standard |
| **CCEC-08** | Neutrality note | Confirmation that no stack / vendor was privileged as law |
| **CCEC-09** | Repeatability note | Disposition reproducibility from published inputs |
| **CCEC-10** | Refusal / deferral honesty | When no lawful conformity existed, say so |
| **CCEC-11** | Continuity note | Prior lawful assessment history not erased (EIP-005) |
| **CCEC-12** | Non-claim honesty | Explicit refusal of mastery / pass / quality / meaning-rewrite / law-amendment / stack-canonisation overclaim |
| **CCEC-13** | Audience projection | Student-plain vs developer/auditor vocabulary over one truth |

Components are **constitutional content obligations**, not database columns, API fields, CI annotations, or UI widgets. Persistence and rendering are out of scope for this milestone.

## 5. Audience Rules

| Audience | May hear | Must not hear as educational law |
|----------|----------|----------------------------------|
| **Student** | Whether the learning system’s behaviour is operating under published educational rules, why a stop occurred, and what limits apply — in plain educational language | Internal CC IDs as theatre; CI traces; coverage as “proof you are ready”; conformity as mastery |
| **Developer / auditor** | Full CCEQ-01…05 answers, corpus paths, CC IDs, finding composition, boundary checks, neutrality and repeatability notes | Product success metrics, pipeline greens, or coverage counts substituted for constitutional refs; conformity framed as educational quality or new law |

Student and developer traces must describe the **same constitutional truth**. Vocabulary may differ; facts may not.

## 6. Layering with Upstream Explainability

| Layer | Corpus job | Conformance speech role |
|-------|------------|-------------------------|
| EIP-002 Educational Evidence meaning | What observational warrants of understanding are | Evaluate handling fidelity (CC-03); never rewrite or grade quality |
| Programme VI coach / planner explainability | Why educational guidance is warranted | Never create or reinterpret via findings |
| Programme VII workflow / authority / recommendation / state explainability | How orchestration, ownership, tips, and context are speakable | Evaluate fidelity; never author those domains |
| Programme VIII contract / event / completion explainability | Which runtime contract / event / cycle applied | Evaluate runtime / API fidelity (CC-04 / CC-06); compose with |
| Programme VIII evidence consumption / validation explainability | Which evidence was consumed / validated with which eligibility | Orthogonal eligibility speech; compose with CC-03 fidelity speech |
| Programme VIII service / interface explainability | Which services / interfaces collaborated or composed | Evaluate under CC-04 / CC-05 |
| **Programme IX conformance explainability (WS1 / MS001)** | **Which specs / artefacts / criteria / findings / boundaries applied** | **This document** |

A complete material journey may carry every layer that applied. Conformance speech without upstream specification identity is hollow. Upstream law without CC identity and finding disposition invites silent reimplementation drift.

## 9. Out of Scope

This milestone does **not** implement:

- explanation renderers or UI copy systems;
- CI badge systems, logging pipelines, or analytics products;
- Runtime A services or testing frameworks;
- GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, or infrastructure;
- prompt templates or LLM narration layers.

Those may later *obey* this explainability law. They do not *define* it.
