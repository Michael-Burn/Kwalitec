## Authority

This document is the constitutional overview of the **Constitutional Conformance Model** for Kwalitec.

It is subordinate to the Educational Constitution, Educational Interpretation Principles (EIP), Programme VI educational meaning corpora, Programme VII orchestration corpora, and Programme VIII runtime constitutional corpora. It governs **when an implementation may be considered constitutionally conformant** — its objectives, recognised conformance types, hard boundaries, and explainability. It does not authorise implementation shortcuts that contradict the Constitution, and it does not create constitutional law, modify constitutional specifications, reinterpret educational meaning, author runtime behaviour, mint recommendations, invent educational state, or substitute any implementation for constitutional authority.

Authority order for constitutional conformance:

> Constitution defines educational truth and curriculum primacy.  
> EIP defines evidence classification, continuity, explainability, claim honesty, and mutation rights.  
> Programme VI defines educational meaning and may publish learning / assessment warrants.  
> Programme VII defines orchestration flow, ownership, recommendations, context, and orchestration evidence artefacts.  
> Programme VIII defines how runtime implementations may lawfully execute published law (contracts, events, evidence, services, interfaces).  
> **This Constitutional Conformance Model (Programme IX / Workstream 1 / MS001) defines when an implementation may be considered constitutionally conformant to that published law.**  
> Downstream assessment machinery, CI theatre, product surfaces, Twin, Adaptive, and narration must evaluate under these rules — never become constitutional producers by proximity to conformance findings.

## 1. Purpose

Kwalitec coaches students preparing for demanding professional examinations (especially IFoA syllabi such as CM1/CS1 and peers).

An expert IFoA tutor does not declare a study plan “correct” because the app shipped, quietly rewrite yesterday’s syllabus rule because today’s code is convenient, or treat a green pipeline as educational truth. After the Constitution and EIP have defined *educational law*, after Programmes VI–VIII have published *meaning, orchestration, and runtime law*, the platform still needs one conformance answer:

> **“When may an implementation be considered constitutionally conformant?”**

That answer must ensure assessments evaluate implementations against published constitutional specifications, preserve constitutional authority, preserve implementation independence, and remain fully auditable and explainable — without creating constitutional law, modifying constitutional specifications, reinterpreting educational meaning, or substituting implementation for constitutional authority.

This document records that posture so every future conformance assessment (and successor) has a single constitutional reference for *how software may be judged against constitutional law*.

> **The Constitutional Conformance Model describes the constitutional relationship between an implementation and the published constitutional corpus.  
> It does not create educational meaning, invent ownership, mint tips, invent runtime behaviour, or become constitutional law.**

## 2. What Constitutional Conformance Is

**Constitutional conformance** is the binding relationship by which an **implementation** may be **evaluated against published constitutional specifications**, yielding **conformance findings** that preserve constitutional authority, implementation independence, auditability, and explainability — without becoming a source of constitutional law or educational truth.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Published constitutional corpus** | Constitution, EIP, Programme VI / VII / VIII specifications that publish educational and execution law | What is the evaluation standard? |
| **Implementation** | Code, behaviour, evidence handling, runtime posture, interfaces, APIs, and audit artefacts claimed to obey that law | What is being assessed? |
| **Conformance assessment** | A recognised CC-01…CC-07 evaluation of implementation against published specifications | Which conformance type applied? |
| **Conformance finding** | Lawful disposition: conformant / non-conformant / deferred / escalated — never “new law” | Does the implementation obey published law? |
| **Constitutional authority** | The exclusive right of published corpora to define educational and execution meaning | Who owns the standard? |
| **Implementation independence** | Conformity is judged against law, not against a preferred stack, vendor, or topology | Remains the stack replaceable? |
| **Auditability** | Every material assessment leaves reconstructable constitutional traces | Can the judgement be reconstructed? |
| **Explainability** | Specs, artefacts, criteria, findings, and boundaries are speakable | Can the judgement be narrated honestly? |

Constitutional conformance is:

- **law-evaluative** — it measures implementation against published specifications; it never authors those specifications;
- **authority-preserving** — published corpora remain the sole source of constitutional meaning;
- **implementation-neutral** — no particular language, framework, store, or CI tool is required or privileged by conformity;
- **catalogue-closed** — only CC-01…CC-07 may be applied as constitutional conformance types;
- **corpus-bound** — every material assessment cites identifiable published specifications;
- **audit-capable** — every material assessment leaves reconstructable constitutional traces;
- **explainable** — students, developers, and auditors can answer which law was evaluated against which artefacts with which findings;
- **non-substitutive** — a conformant implementation never becomes the constitutional standard for the next assessment.

Constitutional conformance is **not**:

- a second Educational Constitution, EIP, or Programme VI / VII / VIII amendment path;
- a licence to reinterpret coach meaning, ownership maps, tip warrants, or runtime contracts in assessment prose;
- a testing framework, CI/CD pipeline, GitHub Action, linter policy, or OpenAPI checker;
- a claim that “conformant” guarantees learning, mastery, exam readiness, or product success;
- a substitute for Programme VIII evidence validation (EV-xx) — EV validates evidence eligibility; CC evaluates implementation fidelity;
- a substitute for Educational Validation Framework quality review — quality release remains a distinct horizon.

## 3. Conformance Posture (Constitutional, Not Technical)

Every material constitutional conformance assessment travels through three constitutional phases. These are **normative assessment obligations**, not an implementation architecture.

```
Identify published constitutional specifications under evaluation
        │
        ▼
Assess named implementation artefacts under CC-01…CC-07
        │
        ├── non-conformant / deferred / escalated (lawful finding — law unchanged)
        │
        └── conformant → Emit findings and preserve audit records
                │
                ▼
        Explain specs / artefacts / criteria / findings / boundaries
```

| Phase | Constitutional meaning | Hard stop if … |
|-------|------------------------|----------------|
| **Identify** | Name only published constitutional specifications as the evaluation standard | Standard is unpublished custom, tribal knowledge, or “how main works today” |
| **Assess** | Apply CC-01…CC-07 against named implementation artefacts | Assessment would invent law, rewrite specs, reinterpret educational meaning, or privilege a stack as law |
| **Record** | Produce findings and audit-speakable trails without amending corpora | Path would treat findings as constitutional amendments or freeze an implementation as authority |

> **Conformance never “best-effort invents” a fourth phase called law-making, reinterpretation, or stack canonisation.**

## 4. Relationship to Upstream Law and Sibling Horizons

Conformance is an **evaluative horizon over published law** — not a parallel constitution.

| Conformance concern | Primary binding |
|---------------------|-----------------|
| Educational integrity / truth under assessment | Constitution + EIP |
| Educational meaning fidelity of implementation | Programme VI corpora |
| Orchestration / ownership / recommendation / state fidelity | Programme VII corpora |
| Runtime contract / event / evidence / service / interface fidelity | Programme VIII corpora |
| Structural layout of constitutional obligations in code | **CC-01 Structural Conformance** |
| Observable behaviour under published rules | **CC-02 Behavioural Conformance** |
| Evidence handling fidelity | **CC-03 Evidence Conformance** (+ EC / EV as subjects, not as this catalogue) |
| Runtime execution posture | **CC-04 Runtime Conformance** (+ RC as subjects) |
| Interface composition fidelity | **CC-05 Interface Conformance** |
| API surface fidelity to published contracts | **CC-06 API Conformance** |
| Reconstructable audit posture | **CC-07 Audit Conformance** |

| Sibling horizon | Relationship |
|-----------------|--------------|
| Programme VIII EV-01…EV-07 | Validates *evidence instances* for execution eligibility; does not certify implementation conformance |
| Programme VIII RC-01…RC-07 | Publish *runtime contracts* that implementations must obey; CC assesses whether they do |
| Educational Validation Framework | Judges coaching / product *quality* for release; CC judges *constitutional fidelity* of implementation |
| Architecture / Version 2 design docs | May constrain delivery; they are not constitutional law and do not replace CC evaluation of Programmes VI–VIII |

Cross-cutting assessments may bind multiple CC types simultaneously. None may invent a type outside this catalogue.

## 5. Core Responsibilities

The Constitutional Conformance Model is constitutionally responsible for:

| Responsibility | Meaning |
|----------------|---------|
| **Define conformance as evaluation** | Bind assessments as evaluations of implementation against published law (`CONSTITUTIONAL_CONFORMANCE_MODEL.md`) |
| **Bind objectives** | Enforce adherence verification, traceability, neutrality, integrity, and repeatability (`CONFORMANCE_OBJECTIVES.md`) |
| **Close the conformance catalogue** | Permit only recognised CC-01…CC-07 types (`CONFORMANCE_TYPES.md`) |
| **Draw hard boundaries** | Forbid law creation, law modification, meaning reinterpretation, and authority substitution (`CONFORMANCE_BOUNDARIES.md`) |
| **Require explainability** | Make specs, artefacts, criteria, findings, and boundaries speakable (`CONFORMANCE_EXPLAINABILITY.md`) |
| **Preserve layering** | Keep conformance subordinate to Constitution, EIP, and Programmes VI–VIII |

### 5.1 Binding non-responsibility

The Constitutional Conformance Model must **not**:

- invent new constitutional conformance types outside CC-01…CC-07 without a Programme IX amendment;
- create, modify, or deprecate constitutional specifications under Programmes VI–VIII (or Constitution / EIP) via findings;
- reinterpret Programme VI educational meaning or EIP claim classes during assessment;
- author runtime behaviour, services, APIs, or UI under the label “conformant”;
- substitute a preferred implementation, stack, or vendor as the constitutional standard;
- implement Runtime A, testing frameworks, CI/CD, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, or infrastructure;
- present green pipelines, coverage percentages, or linter scores as constitutional law or educational truth.

## 6. Educational Purpose

The Constitutional Conformance Model exists so that:

1. **Law remains upstream of code** — implementations are judged by published specifications; findings do not quietly become the specifications.
2. **Authority remains honest** — no team may treat a shipped artefact as the new constitutional source.
3. **Implementations remain replaceable** — conformity does not freeze Flask, SQLAlchemy, a particular API shape, or a CI vendor as law.
4. **Audit remains possible** — every material assessment can be reconstructed against named specs, artefacts, criteria, and findings.
5. **Repeatability remains honest** — the same published law and the same implementation facts yield the same disposition.
6. **Explainability remains intact** — conformance speech describes fidelity; it does not redefine what learning means.
7. **Students remain protected** — product theatre cannot launder non-conformant educational behaviour as “approved.”

## 7. Integrity Invariants

| ID | Invariant |
|----|-----------|
| **CCI-01** | All constitutional evaluation standards originate exclusively from Constitution, EIP, and Programme VI / VII / VIII corpora as published |
| **CCI-02** | Conformance evaluates implementation against published law; it never creates, modifies, or reinterprets constitutional specifications |
| **CCI-03** | Every material conformance assessment maps to at least one recognised CC-01…CC-07 type |
| **CCI-04** | Every material assessment cites identifiable published constitutional specifications and named implementation artefacts |
| **CCI-05** | Unpublished customs, “main branch as law,” and stack preferences are hard stops as evaluation standards |
| **CCI-06** | Constitutional authority is preserved; implementation never substitutes for the published corpus |
| **CCI-07** | Implementation independence is preserved; conformity does not privilege a particular technology as constitutional |
| **CCI-08** | Conformance explanations describe assessment fidelity; they never redefine educational meaning or constitutional truth |
| **CCI-09** | Deterministic / repeatable evaluation under published inputs is required; silent non-determinism is a constitutional defect |
| **CCI-10** | Any assessment machinery that violates these invariants is constitutionally defective regardless of CI polish |
