## 1. Purpose

Execution without a closed context catalogue invents law by proximity: whichever environment variables, tickets, or “ambient” product state happen to be present become the tutor’s “proof the system knew what it was doing.”

This catalogue names the only lawful constitutional execution context components an assembly may apply — and binds each component to purpose, inputs, outputs, and permitted / prohibited information.

---

## 2. Catalogue Overview

| ID | Component | Constitutional purpose (short) | Primary inputs | Primary outputs |
|----|-----------|--------------------------------|----------------|-----------------|
| **CECX-01** | Constitutional Authority | Identify which published corpora own meaning for the concern | Published authority / stack-position specs | Named authority references (not new law) |
| **CECX-02** | Interpretation Context | Identify which EIP principles apply to honest speech and claims | EIP corpora + concern identity | Named applicable principles (not interpretations) |
| **CECX-03** | Specification Context | Identify which constitutional specifications are in force | Published Programme VI–IX / Constitution / EIP specs | Named specification set (not rewritten specs) |
| **CECX-04** | Governance Context | Identify which governance artefacts are available as information | Published Programme IX (and related) artefact identities | Named governance artefact set (not new judgements) |
| **CECX-05** | Execution Identity | Identify which intended constitutional execution this is | Concern / instance identity materials | Stable execution identity (not a decision) |
| **CECX-06** | Execution Scope | Bound what the intended execution may lawfully address | Published scope rules + concern materials | Explicit in-scope / out-of-scope bounds (+ assumptions where explicit) |
| **CECX-07** | Execution Constraints | Preserve hard limits that remain intact | Published boundaries + integrity rules | Explicit constraint set (not soft waivers) |

Material context must map to one or more of these components as published law requires. Cross-cutting situations may bind multiple CECX components; none may invent a component outside this catalogue.

**Relation to Programme VII context:** Those corpora remain defined solely by Programme VII. CECX components assemble *pre-execution constitutional information*; they do not redefine educational or orchestration context meaning.

**Relation to Programme VIII / IX catalogues:** Those catalogues remain defined solely by Programmes VIII / IX. CECX may *reference* their published identities as information; it does not replace, re-run, or reclassify them.

**Relation to educational quality:** No CECX component judges whether learning was good, whether a tip was wise, or whether the student is ready. Context ≠ quality. Context ≠ execution outcome.

## 3. CECX-01 — Constitutional Authority

### Constitutional purpose

Identify and make available the **published constitutional authority references** that own meaning for the intended execution concern — so execution knows *who owns the standard* without inventing a second owner.

### Constitutional inputs

- Published Constitution / EIP / Programme VI / VII / VIII / IX authority and stack-position specifications.
- Named execution concern (sufficient to select which authorities apply).
- Published CECXO-01 / CECXO-02 expectations.

### Constitutional outputs

- Named authority reference set (corpus identities / paths / governing roles as published).
- Honest gap note when required authority references cannot be identified (incomplete / refused context).
- Audit-speakable authority map for the concern (references only — never new authority).

### Permitted information

- Citations to Constitution, EIP, and Programme VI–IX corpora that own meaning for the concern.
- Published subordination / stack-order statements already present in those corpora.
- Explicit statement that downstream execution remains subordinate to those authorities.

### Prohibited information

- New constitutional authority invented in context prose.
- Reassignment of meaning ownership from Programme VI / VII / VIII / IX to Runtime A, Twin, Adaptive, CI, or UI.
- “This service is now the Constitution for this run.”
- Stack, vendor, or repository topology presented as constitutional authority.

## 4. CECX-02 — Interpretation Context

### Constitutional purpose

Identify and make available the **Educational Interpretation Principles** (and related claim-honesty constraints) that apply to the intended execution — so execution knows *which interpretation principles apply* without producing interpretation outcomes.

### Constitutional inputs

- EIP corpora (especially Evidence, Continuity, Explainability, State Authority, Knowledge & Mastery as applicable).
- Named execution concern and audience posture (student / developer / auditor) where published law distinguishes them.
- Published CECXO-01 / CECXO-04 expectations.

### Constitutional outputs

- Named applicable EIP principle set (identities / paths).
- Explicit non-claim: principles are referenced, not newly interpreted.
- Honest gap note when required principles cannot be identified.

### Permitted information

- EIP document identities and published principle identifiers relevant to the concern.
- Published claim classes, continuity obligations, and explainability duties *as already published*.
- Notes that certain claim types are forbidden *because EIP forbids them* (citation, not re-authoring).

### Prohibited information

- New interpretation outcomes (“this rule now means X”).
- Soft reinterpretation of Programme VI educational questions under EIP pretext.
- Audience-specific *different truths* (vocabulary may differ; meaning may not).
- Treating Twin / Adaptive / analytics narratives as EIP amendments.

---

## 5. CECX-03 — Specification Context

### Constitutional purpose

Identify and make available the **constitutional specifications** in force for the intended execution — so execution knows *which published law documents* form its specification environment.

### Constitutional inputs

- Published Constitution / EIP / Programme VI / VII / VIII / IX specification identities required by the concern.
- Version / status markers as published by those corpora (when material).
- Published CECXO-01 / CECXO-02 / CECXO-05 expectations.

### Constitutional outputs

- Named specification set (paths / identities / catalogue families as applicable).
- Explicit exclusion of unpublished customs from the specification set.
- Honest incomplete / refused disposition when required specifications are missing.

### Permitted information

- Identifiable published constitutional specification references.
- Published catalogue families as *subjects of reference* (for example RC-xx, CC-xx) without redefining them.
- Statements that specifications are consumed exactly as published.

### Prohibited information

- Rewritten specification text presented as “context clarification.”
- Unpublished tribal norms, ticket decisions, or “how main works” as constitutional specifications.
- Selective omission of inconvenient published specifications to enlarge scope.
- Elevating architecture preference docs or Version 2 delivery notes into constitutional specifications.

---

## 6. CECX-04 — Governance Context

### Constitutional purpose

Identify and make available **governance artefacts** (especially Programme IX conformance, verification, compliance, certification, and evolution records, and related published governance identities) as *information* — so execution knows what governance material exists without re-running or replacing those judgements.

### Constitutional inputs

- Published Programme IX artefact identities and related governance records applicable to the concern.
- Traceability / continuity requirements for naming prior governance artefacts (EIP-005 / CT where applicable).
- Published CECXO-01 / CECXO-02 expectations.

### Constitutional outputs

- Named governance artefact set (identities only as information).
- Explicit non-claim: listing an artefact is not re-determining its judgement.
- Honest gap note when expected governance artefacts are absent (absence is information; invention is forbidden).

### Permitted information

- Identifiers and citations of published conformance findings, verification findings, compliance determinations, certification records, evolution dispositions, and related governance artefacts.
- Published status markers already attached to those artefacts.
- Notes distinguishing “artefact available” from “artefact re-judged.”

### Prohibited information

- New conformance / verification / compliance / certification / evolution judgements minted as “context.”
- Silent upgrade, downgrade, or erasure of prior governance dispositions.
- Treating missing governance artefacts as implicitly satisfied.
- Collapsing Programme IX catalogues into CECX component identities.

## 7. CECX-05 — Execution Identity

### Constitutional purpose

Establish a **stable, identifiable execution identity** for the intended constitutional execution — so later explanation and audit can say *which execution* this information environment prepared.

### Constitutional inputs

- Concern identity materials (named constitutional concern, activity class, or instance identity as published law requires).
- Links to CECX-01…CECX-04 reference sets for the same concern.
- Published CECXO-01 / CECXO-05 expectations.

### Constitutional outputs

- Stable execution identity (reconstructable identifier / descriptor under published naming discipline).
- Binding of that identity to the assembled authority / interpretation / specification / governance references.
- Honest refuse when identity cannot be established without inventing a concern.

### Permitted information

- Concern name / identity sufficient for reconstruction.
- Temporal or instance markers when published law requires them for repeatability.
- Explicit linkage from identity → assembled CECX reference sets.

### Prohibited information

- Anonymous ambient “global context” with no identifiable execution concern.
- Identity that silently merges unrelated constitutional concerns.
- Identity that encodes a constitutional *decision* (for example “already certified”) as if identity were judgement.
- Stack process IDs or CI run IDs presented as constitutional identity without constitutional mapping.

## 8. CECX-06 — Execution Scope

### Constitutional purpose

Define **what the intended execution may lawfully address** — and what it must not — including explicit **execution assumptions** where they are non-legislative premises of the environment — so execution does not inherit an unbounded or silently assumed world.

### Constitutional inputs

- Published scope / boundary statements from Constitution / EIP / Programme VI–IX relevant to the concern.
- Named execution identity (CECX-05) and specification set (CECX-03).
- Explicit assumption candidates that do not amend law (for example “assessment limited to named artefacts already published”).
- Published CECXO-01 / CECXO-02 expectations.

### Constitutional outputs

- Explicit in-scope / out-of-scope bounds for the intended execution.
- Explicit assumption list (each assumption non-legislative, reconstructable, and consistent with CECX-07).
- Honest incomplete / refused disposition when scope cannot be bounded under published law.

### Permitted information

- Published in-scope concerns and out-of-scope exclusions.
- Explicit assumptions that clarify *environment premises* without changing specification meaning.
- Composition notes when multiple specifications jointly bound scope.

### Prohibited information

- Unbounded “do whatever is needed” scope.
- Assumptions that soft-amend constitutional specifications or EIP claim classes.
- Scope that absorbs Programme IX judgement production or Programme VIII execution into “context.”
- Hidden assumptions not listed in the assembled environment.

## 9. CECX-07 — Execution Constraints

### Constitutional purpose

Preserve and make available the **hard execution constraints** that remain intact for the intended execution — so constitutional boundaries are speakable *before* execution begins and cannot be waived by context theatre.

### Constitutional inputs

- Published boundary corpora (Constitution / EIP / Programme VI–IX boundaries; this Model’s [`CONTEXT_BOUNDARIES.md`](CONTEXT_BOUNDARIES.md)).
- Scope and assumptions from CECX-06 (for consistency checking).
- Published CECXO-02 / CECXO-04 expectations.

### Constitutional outputs

- Explicit constraint set (what must never occur under this execution identity).
- Explicit confirmation that constraints are preserved, not negotiated away.
- Honest refuse when required constraints cannot be stated without inventing exemptions.

### Permitted information

- Published hard stops: no execution-by-context, no interpretation-by-context, no decision-by-context, no amendment-by-context, no authority substitution, no stack freeze.
- Concern-specific published constraints (for example “must not determine compliance”).
- Consistency notes between constraints and assumptions.

### Prohibited information

- Soft waivers (“constraint suspended for demo”).
- Emergency exemptions that mint amendment power via context.
- Constraints rewritten to match a preferred implementation outcome.
- Silence about material boundaries that published law requires to be explicit.

## 10. Composition Rules

1. **Closed catalogue.** Only CECX-01…CECX-07 may assemble constitutional execution context.
2. **Identity before execution.** CECX-05 must be establishable before execution may begin.
3. **Authority and specifications required.** Material contexts without CECX-01 and CECX-03 are defective.
4. **Assumptions ride with scope.** Explicit assumptions are recorded under CECX-06 and checked against CECX-07; they are never a separate unlawful eighth component inventing law.
5. **Governance is information.** CECX-04 references artefacts; it never re-judges them.
6. **Consistency across components.** Contradictions among CECX-01…CECX-07 yield incomplete / refused context (CECXO-02).
7. **No execution inside components.** No CECX component may execute constitutional logic or emit constitutional decisions.
8. **Cross-cutting binding.** Multiple components may bind together; none may invent an off-catalogue component.
