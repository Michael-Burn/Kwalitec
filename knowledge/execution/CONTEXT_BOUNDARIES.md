## 1. Purpose

Context that silently becomes a second constitution — executing rules under the label “assembly,” interpreting law in “notes,” minting decisions as “environment facts,” certifying implementations because artefacts were listed, or amending specifications so a demo can start — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional execution context** (Programme X / WS1 / MS001) and **constitutional execution / interpretation / decision / legislation** (Constitution / EIP / Programmes VI–IX / successor Programme X execution activities / permitted writers).

---

## 2. Boundary Principles

1. **Inform, do not execute.** Context assembles information; it does not run constitutional logic.
2. **Published artefacts only.** Unpublished customs and “main as law” are hard stops as information sources.
3. **Published components only.** Unpublished CECX customs are unlawful.
4. **Named identity only.** Context without identifiable execution identity is theatre.
5. **Exactly as published.** Successful assembly never rewrites specification meaning.
6. **Authority first.** Published corpora remain the sole constitutional standard.
7. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity.
8. **Context ≠ outcome.** Assembled context never grades learning, mastery, readiness, product success, conformity, verification, compliance, or certification.
9. **No interpretation.** Naming EIP principles is not producing interpretation outcomes.
10. **No decision authorship.** Listing governance artefacts is not minting judgements.
11. **No authority substitution.** An assembled context never replaces the corpus for the next act.
12. **No bypass.** Product urgency never waives required context components.
13. **Repeatability.** Race-dependent assembly is a defect.
14. **Explain the stop.** Students, developers, and auditors should hear when context must refuse completeness.
15. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power via context.
16. **Assumptions are not law.** Explicit assumptions never soft-amend specifications.
17. **Constraints survive.** Hard limits may be stated; they may not be waived by context prose.

## 3. What Execution Context May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Assemble constitutional information** | Apply CECX-01…CECX-07 to name published authority, EIP principles, specifications, and governance artefacts |
| **Define execution scope** | Bound in-scope / out-of-scope concerns under published law for a named execution identity |
| **Preserve execution assumptions** | Record explicit, non-legislative premises that clarify the information environment |
| **Preserve execution constraints** | Make hard limits speakable before execution begins |
| **Reference constitutional specifications** | Cite Constitution / EIP / Programme VI–IX corpora as available information |
| **Refuse incomplete context** | Prefer honest incomplete / refused assembly over improvisation |
| **Compose required components** | Bind published CECX conjunctions without collapsing missing components |
| **Remain repeatable** | Same published inputs → same assembled environment |
| **Remain implementation-neutral** | Honour context law across lawful equivalent stacks |
| **Explain context** | Answer artefacts / principles / governance / constraints / boundaries without rewriting meaning |
| **Make information available** | Provide the assembled environment to successor constitutional execution activities |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change before a concern can be scoped |

## 4. What Execution Context Must Never Do (Unlawful)

| Unlawful action | Why it is forbidden |
|-----------------|---------------------|
| **Execute constitutional logic** | Context is information; execution belongs to successor execution activities under published law |
| **Interpret constitutional law** | Interpretation outcomes are not context outputs; EIP is referenced, not re-authored |
| **Produce constitutional decisions** | Findings, dispositions, seals, and warrants are not minted by assembly |
| **Determine compliance** | CCM (and related) determinations remain Programme IX responsibilities |
| **Perform verification** | CV (and related) evaluation remains Programme IX responsibilities |
| **Certify implementations** | CRT (and related) recognition remains Programme IX responsibilities |
| **Evaluate conformance as law-making** | CC findings may be *referenced*; they are not re-run or elevated into new law by context |
| **Amend constitutional law** | Specifications are never modified under context pretext |
| **Modify constitutional specifications** | Clarifying notes must not rewrite published text |
| **Replace constitutional authority** | Assembled context never becomes the standard for the next judgement or execution |
| **Redefine educational meaning** | Programme VI questions survive intact |
| **Author runtime behaviour** | Programme VIII execution is not licensed by “context complete” |
| **Freeze a stack as law** | Neutrality forbids privileging Runtime A / vendor / topology |
| **Waive constraints** | Demo urgency never suspends CECX-07 |
| **Invent unpublished artefacts** | Missing information yields incomplete / refused context — not fiction |
| **Collapse neighbour horizons** | Programme VII educational context, Programme VIII runtime execution, and Programme IX judgements remain distinct |

## 5. Lawful vs Unlawful Contrasts

| Situation | Lawful | Unlawful |
|-----------|--------|----------|
| Missing specification | Refuse / incomplete; explain the gap | Invent a custom rule so execution can start |
| EIP principle named | Cite EIP identity as applicable | Emit a new interpretation outcome as “context note” |
| Prior compliance record exists | List CCM artefact identity under CECX-04 | Re-determine compliance inside context |
| Scope unclear | Bound scope under published law or refuse | Declare unbounded “do what is needed” |
| Assumption needed | State non-legislative premise under CECX-06 | Soft-amend a specification via assumption |
| Constraint inconvenient | Keep constraint; refuse execution start if needed | Waive constraint for demo |
| Stack preference | Remain silent on vendors as law | Require Flask / SQLAlchemy / OpenAPI as constitutional context |
| Governance artefact absent | Record absence as information | Treat absence as implicit certification |

## 6. Boundary with Successor Execution

Constitutional Execution Context ends where **constitutional execution** begins.

| Horizon | May |
|---------|-----|
| **This corpus (MS001)** | Assemble information; define scope; preserve assumptions and constraints; explain the environment |
| **Successor Programme X execution activities** | Consume the assembled environment and perform published constitutional execution under Programmes VI–IX law |
| **Programme VIII runtime** | Execute *software* under published runtime contracts — orthogonal to this pre-execution information environment |
| **Programme IX governance** | Produce evaluative / determinative / recognition / evolution judgements — referenceable by CECX-04, never performed by CECX |

Hard separation:

> **Execution Context may assemble constitutional information, define execution scope, and preserve execution assumptions.  
> Execution Context must never execute constitutional logic, determine compliance, certify implementations, or amend constitutional law.**

---

## 7. Enforcement Posture

When a proposed context act would cross a boundary:

1. **Stop assembly completeness** — emit incomplete / refused rather than unlawful completeness.
2. **Explain the stop** under [`CONTEXT_EXPLAINABILITY.md`](CONTEXT_EXPLAINABILITY.md).
3. **Preserve records** of what was available and what was missing.
4. **Do not begin constitutional execution** on an unlawful or incomplete information environment.
5. **Escalate upstream** for corpus amendment only when published law itself must change — never soft-amend via context.
