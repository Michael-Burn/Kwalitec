## 1. Purpose

An expert IFoA tutor does not optimise “context blob filled” or “pipeline green.” The tutor optimises **lawful pre-execution honesty**: only when constitutional scope, consistency, neutrality, explainability, and repeatability are preserved may constitutional execution be said to have a lawful information environment.

These objectives bind every constitutional execution context assembly and every successor machinery that claims to prepare constitutional execution.

---

## 2. Primary Objective

### CECXO-01 — Establish constitutional scope

**Definition.** Ensure that every material execution context establishes — for a named execution identity — which published constitutional artefacts, interpretation principles, governance artefacts, scope bounds, assumptions, and constraints are available, so the intended execution has an identifiable constitutional scope before it begins.

**Includes:**

- Binding every material context to identifiable Constitution / EIP / Programme VI / VII / VIII / IX specifications and artefacts.
- Applying the closed CECX-01…CECX-07 catalogue required by published law for the concern.
- Distinguishing in-scope constitutional concerns from out-of-scope delivery fashion, tribal custom, or unpublished “how main works.”
- Preferring lawful incomplete / refused context over inventing unpublished artefacts so execution can “start anyway.”
- Keeping scope establishment distinct from execution, interpretation, decision, educational quality, mastery, readiness, or constitutional amendment.

**Excludes:**

- Treating filled JSON, ticket fields, CI greens, Twin estimates, Adaptive scores, or UI ticks as established constitutional scope.
- Soft-amending specifications, inventing unpublished customs, or privileging a preferred stack to force “scope complete.”
- Optimising for throughput, latency, or demo continuity as a substitute for constitutional scope honesty.
- Declaring scope “close enough” without documenting missing published artefacts.

**Tutor rationale.** Professional exam preparation fails when software pretends an execution may begin without knowing which syllabus rules apply. Scope honesty is care; context theatre is harm.

## 3. Supporting Objectives

### CECXO-02 — Preserve execution consistency

**Definition.** Ensure that the assembled information environment is internally consistent — authority references, interpretation principles, specifications, governance artefacts, identity, scope, assumptions, and constraints do not contradict one another under published law — so execution does not inherit an incoherent constitutional picture.

**Tutor rationale.** A coach who cites yesterday’s syllabus and today’s contradictory unpublished custom in the same breath cannot be trusted. Inconsistent context is educational confusion.

**Manifestations:**

- Authority references (CECX-01) align with the specifications named under CECX-03.
- Interpretation principles (CECX-02) do not license claims forbidden by named evidence / continuity / explainability standards.
- Governance artefacts (CECX-04) are cited as published identities, not rewritten to match a preferred narrative.
- Scope (CECX-06) and constraints (CECX-07) do not silently cancel each other.
- Material inconsistency is a defect requiring refused / incomplete context — never silent “best-effort” merge into execution.

---

### CECXO-03 — Preserve implementation neutrality

**Definition.** Ensure that execution context assembly evaluates and presents published constitutional information independently of programming language, framework, datastore, CI vendor, cloud topology, or preferred Runtime A shape — so no stack becomes constitutional by proximity to context.

**Tutor rationale.** A coach who declares only one notebook brand “in scope” has abandoned educational law for vendor preference.

**Manifestations:**

- CECX criteria speak to constitutional information obligations, not “must use Flask / SQLAlchemy / OpenAPI.”
- Equivalent lawful stacks under the same published law may share the same constitutional context.
- Replacing a stack that still obeys published law does not itself invalidate a correctly assembled context.
- “Our reference implementation does it this way” is never a substitute for a published specification identity.

---

### CECXO-04 — Preserve explainability

**Definition.** Ensure that every material execution context can answer which constitutional artefacts are available, which interpretation principles apply, which governance artefacts are available, which execution constraints exist, and which constitutional boundaries remain intact — without rewriting constitutional meaning.

**Tutor rationale.** A coach who cannot say *which rules* were on the desk before work began is performing, not teaching.

**Manifestations:**

- Context narration obeys [`CONTEXT_EXPLAINABILITY.md`](CONTEXT_EXPLAINABILITY.md) (CECXEQ-01…CECXEQ-05).
- Students, developers, and auditors receive truthful speech appropriate to audience vocabulary — not different truths.
- Missing explanation for a material context component is a defect.
- Explanation never pretends that naming artefacts equals executing rules or producing decisions.

---

### CECXO-05 — Preserve repeatability

**Definition.** Ensure that the same published artefacts, identity, scope, assumptions, and constraints assemble into the same constitutional execution context — so context is reproducible and not race-dependent, operator-dependent, or silently mutable.

**Tutor rationale.** A coach who cannot reconstruct yesterday’s starting desk cannot stand behind today’s judgement. Non-repeatable context is constitutional amnesia.

**Manifestations:**

- Context assembly cites corpus paths and artefact identities, not only ticket IDs or commit SHAs.
- Continuity (EIP-005) forbids erasing prior lawful context history to simplify the next start.
- Opaque “ambient” context without reconstructable inputs is a defect.
- Same published inputs → same assembled CECX environment (or same honest incomplete / refused disposition).

---

## 4. Objective Composition

Material constitutional execution context must serve **all** of CECXO-01…CECXO-05. No objective may be traded away for delivery urgency.

| If this is sacrificed… | …the failure mode is |
|------------------------|----------------------|
| CECXO-01 Scope | Execution begins against unpublished or unbounded concerns |
| CECXO-02 Consistency | Execution inherits contradictory constitutional pictures |
| CECXO-03 Neutrality | A stack freezes itself as law via context |
| CECXO-04 Explainability | Students / auditors cannot reconstruct what was available |
| CECXO-05 Repeatability | Context becomes theatre — unreproducible and unaccountable |

> **Objectives optimise the integrity of the information environment.  
> They never authorise constitutional execution, interpretation, or decision inside context assembly.**
