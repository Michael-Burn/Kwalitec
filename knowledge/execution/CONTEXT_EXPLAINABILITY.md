## 1. Purpose

An expert IFoA tutor who cannot say *what was on the desk* before work began — which artefacts were available, which interpretation principles applied, which governance records existed, which constraints held, and which boundaries remained intact — is not coaching; they are performing.

After Programmes VI–IX have made meaning, ownership, tips, context, contracts, evidence, runtime, conformance, verification, compliance, certification, and evolution speech speakable, Programme X still needs one pre-execution-speech answer:

> **“Which constitutional artefacts are available, which interpretation principles apply, which governance artefacts are available, which execution constraints exist, and which constitutional boundaries remain intact?”**

That answer must cover every material execution context without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, freezing a stack as law, inventing unpublished CECX components, executing constitutional logic, or presenting context completeness as educational quality or governance outcome.

---

## 2. What Execution Context Explainability Is

**Constitutional Execution Context Explainability** is the constitutional obligation to narrate **the assembled pre-execution information environment under published CECX components** — not to invent a second tutor voice from ambient product state, and not to grade the student or mint constitutional decisions.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Constitutional artefacts available** | Named Constitution / EIP / Programme VI / VII / VIII / IX documents (and clauses as applicable) assembled under CECX-01 / CECX-03 | Which constitutional artefacts are available? |
| **Interpretation principles applicable** | Named EIP principles referenced under CECX-02 | Which interpretation principles apply? |
| **Governance artefacts available** | Named Programme IX (and related) governance identities referenced under CECX-04 | Which governance artefacts are available? |
| **Execution constraints existing** | Named hard limits preserved under CECX-07 (and scope / assumptions under CECX-06 as needed) | Which execution constraints exist? |
| **Boundaries remaining intact** | Explicit confirmation that forbidden execution / interpretation / decision / amendment / substitution did not occur | Which constitutional boundaries remain intact? |

Execution Context Explainability is:

- **information-centred** — it narrates what was available before execution, not what execution decided;
- **catalogue-bound** — every justification cites published CECX identities;
- **corpus-bound** — every justification cites published specifications and artefacts;
- **non-executive** — explanation never pretends that naming artefacts equals running rules;
- **non-interpretive** — explanation never smuggles interpretation outcomes into “principle notes”;
- **non-decisional** — explanation never presents context completeness as conformance, verification, compliance, or certification;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **quality-honest** — context completeness is never narrated as mastery, readiness, or educational quality;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, Programme VIII contract / evidence speech, or Programme IX judgement speech;
- **repeatability-honest** — explanations must not paper over race-dependent or anonymous ambient context.

Execution Context Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–IX meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for Programme VII educational-context explainability, Programme VIII runtime explainability, or Programme IX judgement explainability corpora;
- a rendering system, UI template, CI badge, log shipper, or analytics dashboard;
- a claim that clear context speech guarantees learning, a pass, or lawful execution success;
- a licence to present filled forms, environment variables, or pipeline greens as constitutional proof.

## 3. Mandatory Explanation Questions

Every material constitutional execution context should answer all five questions:

### CECXEQ-01 — Which constitutional artefacts are available?

Name the primary published Constitution / EIP / Programme VI / VII / VIII / IX specifications and authority references assembled under CECX-01 and CECX-03 (paths and identities). When a clause or catalogue family is material, name it (for example EIP-002; RC-02 as *referenced subject*; CC-01 as *referenced subject*). Unpublished tribal norms and “how main works” are not constitutional artefacts.

### CECXEQ-02 — Which interpretation principles apply?

Name the primary EIP principles referenced under CECX-02. Distinguish *principles applicable* from *interpretation outcomes produced*. Context explanation must not emit new meaning under the label “interpretation note.”

### CECXEQ-03 — Which governance artefacts are available?

Name the primary Programme IX (and related) governance artefact identities referenced under CECX-04 — for example named conformance findings, verification findings, compliance determinations, certification records, or evolution dispositions *as published identities*. Distinguish *artefact available* from *judgement re-determined*. Absence of an expected artefact must be speakable.

### CECXEQ-04 — Which execution constraints exist?

Name the primary hard limits preserved under CECX-07, and where material the scope bounds and explicit assumptions under CECX-06. Constraints must be stated as intact limits — never as waived preferences. Assumptions must be listed explicitly when they form part of the environment.

### CECXEQ-05 — Which constitutional boundaries remain intact?

Confirm explicitly that the assembled context did **not**:

- execute constitutional logic;
- interpret constitutional law into new outcomes;
- produce constitutional decisions;
- determine compliance or perform verification;
- certify implementations;
- amend or modify constitutional specifications;
- replace constitutional authority;
- freeze a stack as law.

If any boundary was at risk, the explanation must narrate the refuse / incomplete stop — not a false completeness claim.

## 4. Audience Postures

| Audience | Vocabulary emphasis | Forbidden drift |
|----------|---------------------|-----------------|
| **Student-facing** | Plain speech about what rules and limits are in play before coaching acts | Presenting context completeness as “you are ready” or “the plan is certified” |
| **Developer-facing** | Corpus paths, CECX IDs, artefact identities, incomplete/refused dispositions | Treating context assembly as Runtime A execution success |
| **Auditor-facing** | Reconstructable identity, component coverage, boundary preservation record | Accepting ambient env/CI state as constitutional artefact identity |

Truth is shared across audiences. Vocabulary may differ; claims may not.

---

## 5. Explanation Integrity Rules

1. **Answer all five CECXEQ questions** for every material context.
2. **Cite published identities** — paths, corpus IDs, CECX component IDs — not only tickets or commits.
3. **Separate information from outcome** — available artefacts ≠ executed rules ≠ produced decisions.
4. **Name gaps** — missing artefacts / principles / governance items / constraints are part of the explanation.
5. **Preserve continuity** — do not erase prior lawful context history to simplify the next narration (EIP-005).
6. **Remain implementation-neutral** — do not narrate vendor preference as constitutional necessity.
7. **Refuse false completeness** — if boundaries were not intact, say so.
8. **Do not replace neighbour speech** — tip warrants, ownership, runtime contracts, and Programme IX judgements keep their own explainability corpora.

---

## 6. Defective Explanations (Non-Exhaustive)

The following are constitutionally defective as execution-context explanations:

- “Context was ready” with no named artefacts, principles, governance items, constraints, or boundaries.
- “EIP applies” without naming which principles.
- “Compliance is fine” as a context note that re-determines CCM.
- “Certified because context assembled.”
- “We used the usual stack, so authority is satisfied.”
- “Assumptions were implicit.”
- “Constraints were relaxed for the demo.”
- Student speech that converts context completeness into mastery or exam readiness.
- Developer speech that converts context completeness into Runtime A success or constitutional amendment.
