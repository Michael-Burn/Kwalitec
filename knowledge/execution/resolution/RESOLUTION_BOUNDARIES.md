## Authority

## 1. Purpose

Resolution that silently becomes a second constitution — executing rules under the label “selection,” interpreting law in “assembly notes,” minting decisions as “resolved facts,” determining compliance because artefacts were chosen, certifying implementations because the view published, or amending specifications so a demo can resolve — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional execution context resolution** (Programme X / WS1 / MS002) and **constitutional execution / independent interpretation / decision / legislation / evaluative judgement** (Constitution / EIP / Programmes VI–IX / MS001 assembly obligations / successor Programme X execution activities / permitted writers).

---

## 2. Boundary Principles

1. **Select and assemble, do not execute.** Resolution builds a resolved view; it does not run constitutional logic.
2. **Published artefacts only.** Unpublished customs and “main as law” are hard stops as selectable information.
3. **Published stages only.** Unpublished CECR customs are unlawful.
4. **Consumable context only.** Resolutions without an identifiable MS001 Execution Context are theatre.
5. **Named identity only.** Resolution without identifiable execution identity is theatre.
6. **Exactly as published.** Successful resolution never rewrites specification meaning.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity.
9. **Resolved ≠ outcome.** A published resolved view never grades learning, mastery, readiness, product success, conformity, verification, compliance, or certification.
10. **No independent interpretation.** Naming EIP principles in the resolved view is not producing interpretation outcomes.
11. **No decision authorship.** Selecting governance artefacts is not minting judgements.
12. **No authority substitution.** A resolved view never replaces the corpus for the next act.
13. **No bypass.** Product urgency never waives required resolution stages.
14. **Determinism / repeatability.** Race-dependent or private selection shortcuts are defects.
15. **Explain the stop.** Students, developers, and auditors should hear when resolution must refuse completeness or publication.
16. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power via resolution.
17. **Exclusions are speakable.** Silent omission of available artefacts is a defect.
18. **Constraints survive.** Hard limits may be carried into the resolved view; they may not be waived by resolution prose.
19. **MS001 integrity.** Resolution consumes CECX components; it never redefines them.
20. **Consistency or refuse.** Material contradiction is a hard stop, not a soft merge.

## 3. What Resolution May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Select constitutional artefacts** | Choose published artefacts from the consumable Execution Context under CECR-03 |
| **Assemble execution context** | Build a resolved execution context through CECR-01…CECR-06 from available CECX information |
| **Validate consistency** | Apply CECR-05 checks so the resolved view does not contradict itself under published law |
| **Record exclusions** | Name available artefacts left out of the resolved view with reconstructable reasons |
| **Assemble published dependencies** | Carry published relationships into the resolved view under CECR-04 |
| **Consume the Execution Context** | Use MS001 CECX-01…CECX-07 as the sole information horizon for selection |
| **Bound resolution scope** | Apply CECR-02 under published law for a named execution identity |
| **Refuse incomplete resolution** | Prefer honest incomplete / refused resolution over improvisation |
| **Remain deterministic and repeatable** | Same published inputs → same resolved view (or same refuse) |
| **Remain implementation-neutral** | Honour resolution law across lawful equivalent stacks |
| **Explain resolution** | Answer selection / exclusion / dependencies / checks / boundaries without rewriting meaning |
| **Publish a resolved execution context** | Make the resolved view available to successor constitutional execution activities under CECR-06 |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change before a concern can be resolved |

## 4. What Resolution Must Never Do (Unlawful)

| Unlawful action | Why it is forbidden |
|-----------------|---------------------|
| **Execute constitutional logic** | Resolution is selection and assembly; execution belongs to successor execution activities under published law |
| **Interpret constitutional law independently** | Interpretation outcomes are not resolution outputs; EIP is referenced, not re-authored |
| **Produce constitutional decisions** | Findings, dispositions, seals, and warrants are not minted by resolution |
| **Determine compliance** | CCM (and related) determinations remain Programme IX responsibilities |
| **Perform verification** | CV (and related) evaluation remains Programme IX responsibilities |
| **Certify implementations** | CRT (and related) recognition remains Programme IX responsibilities |
| **Evaluate conformance as law-making** | CC findings may be *selected* as information; they are not re-run or elevated into new law by resolution |
| **Amend constitutional law** | Specifications are never modified under resolution pretext |
| **Modify constitutional specifications** | Clarifying notes must not rewrite published text |
| **Replace constitutional authority** | A resolved view never becomes the standard for the next judgement or execution |
| **Redefine educational meaning** | Programme VI questions survive intact |
| **Author runtime behaviour** | Programme VIII execution is not licensed by “resolved” |
| **Redefine MS001 CECX components** | Resolution consumes context components; it does not amend MS001 meaning |
| **Freeze a stack as law** | Neutrality forbids privileging Runtime A / vendor / topology |
| **Waive constraints** | Demo urgency never suspends carried CECX-07 limits |
| **Invent unpublished artefacts** | Missing information yields incomplete / refused resolution — not fiction |
| **Silently exclude available artefacts** | Exclusions must be reconstructable |
| **Collapse neighbour horizons** | MS001 context assembly, Programme VII educational context, Programme VIII runtime execution, and Programme IX judgements remain distinct |

## 5. Lawful vs Unlawful Contrasts

| Situation | Lawful | Unlawful |
|-----------|--------|----------|
| Missing required artefact | Refuse / incomplete; explain the gap | Invent a custom rule so resolution can complete |
| EIP principle selected | Cite EIP identity in the resolved view | Emit a new interpretation outcome as “resolution note” |
| Prior compliance record exists | Select CCM artefact identity as information | Re-determine compliance inside resolution |
| Scope unclear | Bound scope under published law or refuse | Declare unbounded “select what is needed” |
| Exclusion needed | Name the artefact and reason | Silently omit inconvenient available artefacts |
| Consistency fails | Refuse / inconsistent; do not publish complete | Soft-amend specs to manufacture consistency |
| Constraint inconvenient | Keep constraint; refuse publication if needed | Waive constraint for demo |
| Stack preference | Remain silent on vendors as law | Require Flask / SQLAlchemy / OpenAPI as constitutional resolution |
| Governance artefact absent | Record absence; refuse if required | Treat absence as implicit certification |
| Context incomplete under MS001 | Refuse-open or incomplete resolution | Pretend ambient env/CI state is an Execution Context |

## 6. Boundary with Neighbours

Constitutional Execution Context Resolution ends where **constitutional execution** begins, and remains distinct from **context assembly** and **governance judgement**.

| Horizon | May |
|---------|-----|
| **MS001 Execution Context** | Assemble the complete pre-execution information environment (CECX-01…CECX-07) |
| **This corpus (MS002)** | Select and assemble a resolved execution context from that environment through CECR-01…CECR-06; validate consistency; publish or refuse |
| **Successor Programme X execution activities** | Consume the resolved execution context and perform published constitutional execution under Programmes VI–IX law |
| **Programme VIII runtime** | Execute *software* under published runtime contracts — orthogonal to this selection-and-assembly horizon |
| **Programme IX governance** | Produce evaluative / determinative / recognition / evolution judgements — selectable as information, never performed by CECR |

Hard separation:

> **Resolution may select constitutional artefacts, assemble execution context, and validate consistency.  
> Resolution must never execute constitutional logic, determine compliance, certify implementations, or amend constitutional law.**

---

## 7. Enforcement Posture

When a proposed resolution act would cross a boundary:

1. **Stop resolution completeness** — emit incomplete / refused / inconsistent rather than unlawful completeness.
2. **Explain the stop** under [`RESOLUTION_EXPLAINABILITY.md`](RESOLUTION_EXPLAINABILITY.md).
3. **Preserve records** of what was selected, excluded, assembled, checked, and what was missing.
4. **Do not publish a complete resolved execution context** on an unlawful or incomplete resolution.
5. **Do not begin constitutional execution** on an unpublished or refused resolved view presented as complete.
6. **Escalate upstream** for corpus amendment only when published law itself must change — never soft-amend via resolution.
