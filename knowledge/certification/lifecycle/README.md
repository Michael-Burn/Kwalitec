## Purpose

This folder defines **the permanent constitutional lifecycle coordinating certification activities** from initiation through production, recording, and publication of certification decisions.

It answers *what the lifecycle must optimise*, *which recognised stages organise certification*, *what the lifecycle may and must never do*, and *how lifecycle progress is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, creating constitutional law, modifying constitutional specifications, redefining constitutional meaning, replacing constitutional authority, performing verification, determining compliance, or elevating lifecycle machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, or application services.

> **The constitutional certification lifecycle coordinates certification activities.  
> It consumes completed compliance and produces certification decisions without performing verification, determining compliance, or altering constitutional law.  
> It never becomes constitutional authority.**

## Architectural requirement

The constitutional certification lifecycle coordinates **certification activities**.

| Lawful | Unlawful |
|--------|----------|
| Coordinate certification through recognised stages | Perform verification |
| Consume completed compliance | Determine compliance / re-run CCM determination |
| Validate certification prerequisites | Modify constitutional specifications |
| Produce certification decisions | Redefine constitutional / educational meaning |
| Preserve certification records | Replace constitutional authority |
| Preserve repeatability, neutrality, explainability, auditability | Become constitutional authority |
| Explain completed compliance / prerequisites / stages / records / boundaries | Elevate lifecycle machinery into a constitutional producer |

**The constitutional certification lifecycle coordinates certification activities. It recognises completed constitutional governance without altering constitutional law or replacing compliance.**

## How to use this corpus

1. Confirm the published Constitutional Certification Model (WS4 / MS001) is in force — refuse lifecycle theatre that invents certification types outside CRT-01…CRT-07.
2. Confirm identifiable completed compliance activities (CCM determinations + lawful CCC completion) for the concern are available — refuse invented compliance or incomplete compliance theatre.
3. Read `CONSTITUTIONAL_CERTIFICATION_LIFECYCLE_MODEL.md` for stack position and integrity rules.
4. Optimise under `LIFECYCLE_OBJECTIVES.md`.
5. Sequence under `LIFECYCLE_STAGES.md` (CRTL-01…CRTL-07 only).
6. Enforce hard stops under `LIFECYCLE_BOUNDARIES.md`.
7. Require explainability contracts from `LIFECYCLE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing lifecycle narration.
8. Do not implement lifecycle machinery that contradicts this corpus without amending it first.
