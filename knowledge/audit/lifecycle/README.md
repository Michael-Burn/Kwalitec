## Purpose

This folder defines **the permanent constitutional lifecycle coordinating constitutional auditing** from initiation through decision intake, audit construction, provenance recording, integrity validation, publication, and honest closure.

It answers *how constitutional auditing is organised after completed constitutional decisions*, *what the lifecycle must optimise*, *which recognised stages organise audit production*, *what the lifecycle may and must never do*, and *how lifecycle progress is constitutionally explained* — without implementing Runtime A, executing constitutional rules, producing constitutional decisions, reinterpreting Educational Interpretation Principles, amending constitutional specifications, creating constitutional authority, or elevating lifecycle machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, or application services.

> **The Constitutional Audit Lifecycle coordinates constitutional auditing.  
> It consumes completed constitutional decisions and publishes constitutional audit records without executing constitutional rules or creating constitutional authority.  
> It never becomes constitutional authority.**

## Architectural requirement

The Constitutional Audit Lifecycle coordinates **constitutional auditing**.

| Lawful | Unlawful |
|--------|----------|
| Coordinate audit production through recognised stages | Execute constitutional rules (WS2 engine responsibility) |
| Consume completed constitutional decisions | Begin against incomplete or unpublished decisions |
| Construct constitutional audit records | Produce constitutional decisions (WS3 responsibility) |
| Preserve provenance | Reinterpret Educational Interpretation Principles |
| Validate audit integrity | Amend constitutional specifications |
| Publish constitutional audit records | Create or replace constitutional authority |
| Preserve accountability, repeatability, explainability, fidelity | Elevate lifecycle machinery into a constitutional producer or executor |
| Explain decisions / provenance / integrity / records / boundaries | Collapse auditing into rule re-execution, re-decision, or independent governance |

**The Constitutional Audit Lifecycle coordinates constitutional auditing while remaining entirely downstream of constitutional decision production.  
It never participates in execution, decision production or constitutional governance.**

## How to use this corpus

1. Confirm completed constitutional decisions exist under WS3 / MS001–MS003 — refuse audit-lifecycle theatre against incomplete decision production.
2. Confirm the published Constitutional Audit Architecture Model (WS4 / MS001) is in force — refuse lifecycle theatre that invents audit components outside CAA-01…CAA-06.
3. Read `CONSTITUTIONAL_AUDIT_LIFECYCLE_MODEL.md` for stack position and integrity rules.
4. Optimise under `LIFECYCLE_OBJECTIVES.md`.
5. Sequence under `LIFECYCLE_STAGES.md` (CAAL-01…CAAL-07 only).
6. Enforce hard stops under `LIFECYCLE_BOUNDARIES.md`.
7. Require explainability contracts from `LIFECYCLE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing lifecycle narration.
8. Do not implement lifecycle machinery that contradicts this corpus without amending it first — and do not treat lifecycle closure as constitutional execution, decision re-production, EIP replacement, or constitutional amendment.
