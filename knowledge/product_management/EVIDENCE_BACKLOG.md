**Document type:** Master product backlog — research → engineering-ready work  
**Programme inputs:** EP-004 Private Beta Blind Review  
**Backlog date:** 25 July 2026  
**Scope constraint:** Converts qualitative research into engineering-ready work. Does not inspect application code, invent capabilities absent from the corpus, or specify UI/implementation design.

**Evidence corpus (exclusive):**  
`BLIND_REVIEW_META_ANALYSIS.md` · `BLIND_REVIEW_META_ANALYSIS_V2.md` · `BLIND_REVIEW_RESEARCH_SYNTHESIS.md` · `EVIDENCE_TO_STRATEGY.md`

**Organisation rule:** Work is organised by **Educational Capability**, not pages, screens, or features.

## How to read this backlog

### Prioritisation formula

Every initiative is ranked by:

**Educational Severity × Research Confidence × Strategic Importance**

— not by implementation convenience.

| Factor | Scale used here |
|---|---|
| Educational Severity | Critical · High · Moderate · Low (from Synthesis §3 severity matrix) |
| Evidence Confidence | High · Strong · Medium · Emerging · Persona Specific (from meta-analyses + synthesis) |
| Strategic Importance | Critical · High · Medium · Low (from Evidence to Strategy §4–§9) |
| Priority band | **P0** Critical educational impact · **P1** High · **P2** Medium · **P3** Deferred / boundary |

### Strategic principles (must map to every item)

| ID | Principle |
|---|---|
| SP1 | Trust before intelligence |
| SP2 | Inspectable decisions before AI claims |
| SP3 | Organisation before optimisation |
| SP4 | Evidence before persuasion |
| SP5 | Single authoritative workflow |
| SP6 | Honesty infrastructure over mastery theatre |
| SP7 | Adjacency over displacement |
| SP8 | Separate organisation success from learning-depth claims |

### Complexity (educational scope only)

Estimated without code inspection:

| Label | Meaning |
|---|---|
| S | Local consistency or copy/contract change in one educational behaviour |
| M | Cross-surface consistency of one educational rule or ritual |
| L | Multi-capability behaviour (e.g. decision + trust + workflow) |
| XL | Systemic educational architecture change with secondary capabilities gated on it |

### Work-item schema

Each item includes: Title · Educational problem · Research evidence · Supporting reviewers · Evidence confidence · Educational severity · Strategic principle · Desired educational outcome · Acceptance criteria · Success metrics · Dependencies · Priority · Estimated implementation complexity.

# 1. Navigation

Educational job: Students always know which surface owns “what next?” and “continue where?” Split authority is an educational reliability failure, not a preference. (Evidence to Strategy Principle 5; Synthesis Cluster A.)

---

### EB-NAV-001 — Establish a single authoritative start / continue path

| Field | Content |
|---|---|
| **Title** | Single authoritative start and continue path |
| **Educational problem** | Dual homes / dual “what next” surfaces force reconciliation under time pressure, tax trust, and make organisational benefit path-conditional. Students cannot tell which surface is educationally authoritative. |
| **Research evidence** | Cluster A start-path authority collapse: dual homes → thin overview → duration conflict → reduced planning trust → path-dependent recoverability → conditional adoption. Navigation friction degrades the organisational gift. (Synthesis Cluster A, §8.2; Meta V2 §4.1, Conclusion B; Evidence to Strategy Risk 2, Risk 5, Investment Theme 1.) |
| **Supporting reviewers** | SV-001, SV-002, SV-003, SV-004, SV-006, SV-007, SV-009, SV-010, SV-014, SV-016, SV-020 |
| **Evidence confidence** | High (Near Universal) |
| **Educational severity** | High |
| **Strategic principle** | SP5 Single authoritative workflow; SP3 Organisation before optimisation |
| **Desired educational outcome** | One defensible answer to “what should I do next?” and “where do I continue?” so organisational relief is not spent on navigation management. |
| **Acceptance criteria** | (1) At any moment, a student can identify a single authoritative next-study action without reconciling competing start surfaces. (2) Continue/resume language is consistent with that authority. (3) Reviewer-style “which home is real?” hesitation is eliminated on the primary evening path. |
| **Success metrics** | Reduction in reported start-path reconciliation; increase in first-action clarity on first and returning evenings; path-conditional adoption language disappears in subsequent reviews. |
| **Dependencies** | None (foundation for Workflow, Recovery, Behaviour) |
| **Priority** | P0 |
| **Estimated implementation complexity** | L |
