CCF-01…CCF-07 are *family classifications* for assessment — not domain catalogue IDs.

## 1. Purpose

Catalogue integrity without recognised families invents law by proximity: whichever prefix a document happens to use becomes the tutor’s “proof the constitution speaks one language.”

This catalogue names the only lawful constitutional catalogue families an assessment may classify under — and the only catalogue integrity categories an assessment may apply — and binds each to purpose, scope, namespace expectations, inputs, outputs, validation rules, and permitted / prohibited behaviours.

**Hard constraint:** This document never creates new domain catalogue identifiers, never renumbers existing catalogues, never amends constitutional specifications, and never creates constitutional authority.

## 2. Recognised Catalogue Families (CCF-01…CCF-07)

| ID | Catalogue family | Constitutional scope (illustrative published prefixes) | Namespace expectation |
|----|------------------|--------------------------------------------------------|----------------------|
| **CCF-01** | Foundational / EIP identity family | EGI, EIP capability / model identities | Foundational IDs remain reconstructable to Constitution / EIP; never absorb programme catalogues |
| **CCF-02** | Programme VI educational meaning catalogues | Educational strategy / intervention / obstacle / pathway / session / reflection / coach catalogues (e.g. ES, LI, and published educational closed sets) | Meaning catalogues own educational warrants; they never absorb governance / runtime prefixes |
| **CCF-03** | Programme VII orchestration catalogues | Workflow, authority, recommendation, state, conflict, transition catalogues (e.g. CST and published orchestration closed sets) | Orchestration catalogues coordinate flow; they never redefine Programme VI meaning IDs |
| **CCF-04** | Programme VIII runtime catalogues | RC, EC (runtime evidence), EV, RS, RI, CE (events), and published runtime completion / composition catalogues | Runtime catalogues execute published law; overlapping labels with non-runtime families require published disambiguation |
| **CCF-05** | Programme IX governance catalogues | CC, CT, CV, CCM, CRT, CEG, and published lifecycle / completion / objective / explainability families (CVL, CCL, CRTL, CCC, CVC, CTC, …) | Governance catalogues evaluate / recognise; they never renumber runtime or educational meaning catalogues |
| **CCF-06** | Programme X execution catalogues | CECX, CECR, CECC, CEE, CEEL, CEEC, CDA, CDAL, CDAC, CAA, CAAL, CAAC, CEA, CEAL, CEAC, and published objective / explainability siblings | Execution catalogues organise activity; they never absorb Programme IX disposition catalogues |
| **CCF-07** | Programme XI assurance catalogues | CDI, CDIL, CDIC, CDIO, CDIR, CDIB, CDIEQ, CDII, and this corpus’s CCI / CCF / CCIO / CCIR / CCIB / CCIEQ / CCII families | Assurance catalogues validate corpus structure; they never rewrite upstream domain catalogues |

Material assessments must classify every assessed catalogue under one or more of these families as published law requires. Cross-cutting situations may bind multiple families; none may invent a family outside this catalogue.

**Relation to domain catalogues:** Domain catalogues (CC, CT, RC, EV, CDI, …) remain defined solely by their owners. CCF membership *classifies them for integrity assessment*; it does not replace, renumber, or redefine them.

**Relation to educational quality:** No CCF family judges whether learning was good, whether a tip was wise, or whether the student is ready. Intact ≠ quality. Intact ≠ conformant. Intact ≠ certified.

### 2.1 Role layers within families (non-authoring classification)

Within any CCF family, assessments may further note the published *role* of a catalogue without inventing new IDs:

| Role layer | Typical job | Examples (owned elsewhere) |
|------------|-------------|----------------------------|
| **Meaning / type / component catalogues** | Close what kinds exist | CC, CT, CV, CCM, CRT, RC, EC, EV, CDI, CEE, CEA, … |
| **Lifecycle stage catalogues** | Close when activities occur | CVL, CCL, CRTL, CEEL, CDAL, CAAL, CEAL, CDIL, … |
| **Completion criteria catalogues** | Close when fulfilment may be affirmed | CVC, CCC, CRTC, CEEC, CDAC, CAAC, CEAC, CDIC, … |
| **Objective catalogues** | Close what assessment must optimise | CCO, CTO, CDIO, CCIO, … |
| **Boundary / explainability catalogues** | Close hard stops and speech contracts | `*_BOUNDARIES.md`, `*_EXPLAINABILITY.md`, EQ families |

Role-layer notes support explainability. They never authorise collapsing distinct role catalogues into one ID space.

## 3. Catalogue Integrity Categories (CCI-01…CCI-07)

| ID | Integrity category | Constitutional purpose (short) | Primary inputs | Primary outputs |
|----|--------------------|--------------------------------|----------------|-----------------|
| **CCI-01** | Identifier Uniqueness | Detect duplicate IDs for incompatible meanings | Published catalogue entries + meanings | Uniqueness findings |
| **CCI-02** | Identifier Consistency | Confirm one published meaning per ID within namespace | Catalogue ownership + meaning statements | Consistency findings |
| **CCI-03** | Namespace Separation | Validate family / prefix separation and lawful disambiguation | CCF membership + prefix maps + disambiguation tables | Namespace findings |
| **CCI-04** | Collision Detection | Identify and classify identifier collisions across families | Overlapping labels + published disambiguation | Collision findings |
| **CCI-05** | Numbering Integrity | Validate published ranges, gaps, and succession honesty | Published numbering declarations | Numbering findings |
| **CCI-06** | Extensibility Integrity | Confirm lawful amendment-only growth rules remain intact | Closure statements + amendment paths | Extensibility findings |
| **CCI-07** | Assessment Integrity | Preserve reconstructable catalogue assessment records | Assessment records + catalogue / family identities | Assessment-lineage / integrity records |

Material assessments must map to one or more of these categories as published law requires. Cross-cutting situations may bind multiple CCI types; none may invent a type outside this catalogue.

**Relation to CT / CC / CV / CCM / CRT / CDI:** Those catalogues remain defined solely by their owners. CCI categories *validate constitutional catalogue consistency*; they do not replace lineage preservation, fidelity evaluation, verification, compliance determination, certification recognition, or dependency validation.

## 4. Global Validation Rules

These rules apply to every CCF family and every CCI category:

| Rule ID | Validation rule |
|---------|-----------------|
| **CCIR-01 Uniqueness** | No two published catalogue entries may share the same identifier for incompatible constitutional meanings unless a published disambiguation table lawfully separates them by namespace / owning corpus. |
| **CCIR-02 Consistency** | Within an owning catalogue and namespace, an identifier must retain one published meaning. Drift without amendment is a defect. |
| **CCIR-03 Namespace separation** | Catalogues must honour CCF-01…CCF-07 family separation and published prefix conventions. Silent merges across families are defects. |
| **CCIR-04 Collision honesty** | Detected overlapping labels must be reported as collisions, published disambiguations, or violated — never silently ignored or “fixed” by renumbering in situ. |
| **CCIR-05 Numbering fidelity** | Published numbering ranges, gaps, and succession remain as published. Silent renumbering is a defect. |
| **CCIR-06 Extensibility honesty** | New entries require lawful amendment of the owning catalogue under its published closure rules. Invent-in-place is unlawful. |
| **CCIR-07 Catalogue / family closure** | Only CCF-01…CCF-07 may classify families and only CCI-01…CCI-07 may classify integrity assessments. Unpublished customs are unlawful. |
| **CCIR-08 Non-mutation** | Validation never creates, renames, renumbers, deletes, or soft-amends catalogue identifiers or specifications. Findings report; they do not rewrite. |
| **CCIR-09 Neutrality** | Validation criteria speak to constitutional identities and published catalogues — never “must use Flask / SQLAlchemy / grep / GitHub Actions.” |
| **CCIR-10 Finding honesty** | Dispositions are intact / violated / deferred / escalated only. “Close enough,” “temporary renumber,” or “demo exception” are not constitutional dispositions. |

## 5. Family Profiles

### 5.1 CCF-01 — Foundational / EIP identity family

**Purpose.** Classify Constitution / EIP capability and model identities so foundational labels remain reconstructable and are not absorbed by programme catalogues.

**Namespace expectations.**

- EGI / EIP identities remain foundational.
- Programme catalogues may *cite* them; they may not *reuse* them as programme type IDs without published ownership clarity.
- Findings may note missing foundational citation; they may not invent foundational IDs.

**Permitted assessment behaviours.** Confirm uniqueness and consistency of published EGI / EIP identities; cite them in authority chains for other families.

**Prohibited assessment behaviours.** Elevate architecture / Version 2 preference docs to EGI / EIP peers as law; create new EGI / EIP IDs under CCI pretext.

---

### 5.2 CCF-02 — Programme VI educational meaning catalogues

**Purpose.** Classify educational meaning catalogues (strategies, interventions, obstacles, pathways, session / reflection / coach closed sets) so educational warrants remain speakable and unabsorbed by runtime / governance prefixes.

**Namespace expectations.**

- Educational catalogues own educational meaning identifiers as published by Programme VI corpora.
- They must not silently reuse Programme VIII / IX / X / XI prefixes for educational meaning.
- Seed vs governing catalogue succession (where published) must remain reconstructable — succession ≠ silent renumbering of foreign families.

**Permitted.** Validate uniqueness / consistency within Programme VI ownership; report collisions with other families.

**Prohibited.** Redefine educational meanings; renumber ES / LI / peer educational IDs under integrity pretext; absorb governance catalogues into educational vocabulary.

---

### 5.3 CCF-03 — Programme VII orchestration catalogues

**Purpose.** Classify orchestration catalogues (workflow, authority, recommendation, state, conflict, transition) so coordination vocabularies remain distinct from meaning and governance.

**Namespace expectations.**

- Orchestration catalogues coordinate; they do not author Programme VI meaning IDs.
- Transition / conflict / authority catalogues remain closed as published.
- Sibling composition with Programme VI / VIII is consumption / coordination — never prefix capture.

**Permitted.** Validate CST and peer orchestration catalogues for uniqueness, consistency, and namespace honesty.

**Prohibited.** Treat orchestration IDs as educational meaning warrants; renumber orchestration catalogues to resolve collisions with governance families in situ.

---

### 5.4 CCF-04 — Programme VIII runtime catalogues

**Purpose.** Classify runtime catalogues (RC, EC, EV, RS, RI, CE, and published completion / composition sets) so execution vocabulary remains eligible-for-execution honest.

**Namespace expectations.**

- RC / EV / RS / RI / CE prefixes remain runtime-owned as published.
- **Known collision subject:** EC-xx labels also appear in Educational Validation Framework coach capability speech elsewhere. Runtime EC meaning and EVF EC meaning are *not* the same catalogue. Assessments must report this as a namespace / collision concern under CCI-03 / CCI-04 when both horizons are in scope — never silently merge, and never renumber either side under this Model.
- EV validates EC instances; EV ≠ EC.

**Permitted.** Validate runtime catalogue uniqueness / consistency; require published disambiguation when labels overlap non-runtime families.

**Prohibited.** Soft-merge runtime EC with EVF EC; invent runtime IDs; renumber RC / EV to “clear” collisions.

---

### 5.5 CCF-05 — Programme IX governance catalogues

**Purpose.** Classify governance catalogues (CC, CT, CV, CCM, CRT, CEG, lifecycles, completions, objectives, explainability) so evaluation / recognition vocabularies remain distinct and internally consistent.

**Namespace expectations.**

- CC ≠ CT ≠ CV ≠ CCM ≠ CRT ≠ CEG.
- Lifecycle families (CVL, CCL, CRTL, …) organise *when*; they are not meaning types.
- Completion families (CVC, CCC, CRTC, CTC, …) affirm *fulfilment*; they are not lifecycle stages or meaning types.
- Objective / EQ families optimise or narrate; they do not author meaning types.
- Published “Catalogue disambiguation” sections in Programme IX READMEs are primary evidence for lawful separation.

**Permitted.** Validate governance prefix separation; report collisions with non-governance families; confirm numbering fidelity within each owning catalogue.

**Prohibited.** Collapse CC into CCM because names look similar; renumber CRT to avoid CT adjacency; treat completion criteria as soft amendments of type catalogues.

---

### 5.6 CCF-06 — Programme X execution catalogues

**Purpose.** Classify execution catalogues (context, engine, decision, audit, explainability — including lifecycle and completion siblings) so activity vocabulary remains ordered and unabsorbed by Programme IX dispositions.

**Namespace expectations.**

- CECX / CECR / CECC ≠ CEE / CEEL / CEEC ≠ CDA / CDAL / CDAC ≠ CAA / CAAL / CAAC ≠ CEA / CEAL / CEAC.
- Programme X catalogues may *consume* Programme IX published identities as inputs; they may not *become* conformance / verification / compliance / certification types.
- Cross-workstream composition must respect published MS001 → MS002 → MS003 succession without inventing IDs.

**Permitted.** Validate execution family uniqueness / consistency / numbering; report collisions with Programme IX / VIII prefixes.

**Prohibited.** Soft-absorb CRT / CCM into CEA speech; renumber CEEL to look like CVL; invent execution IDs under integrity pretext.

---

### 5.7 CCF-07 — Programme XI assurance catalogues

**Purpose.** Classify assurance catalogues (dependency integrity and this catalogue integrity corpus) so Programme XI validators remain validators — never authors of upstream domain catalogues.

**Namespace expectations.**

- CDI / CDIL / CDIC families validate *dependencies*; CCI / CCF families validate *catalogues* — compose, do not conflate.
- CCI must not be confused with CC (conformance), CCM (compliance), or CCC (compliance completion).
- CCF family IDs classify assessment subjects; they are not replacements for CC / CT / RC / EV / CDI entries.
- Assurance findings never create, rename, or renumber upstream catalogues.

**Permitted.** Validate uniqueness of CDI / CCI meta-families against the wider corpus; report collisions; preserve assessment records under CCI-07.

**Prohibited.** Use CCI findings to renumber Programme VI–X catalogues; treat CCF membership as a soft rewrite of domain meaning; elevate Programme XI into foundational law.

## 6. Integrity Category Profiles

### 6.1 CCI-01 — Identifier Uniqueness

**Purpose.** Validate that published identifiers are unique for their constitutional meanings (or lawfully disambiguated).

**Inputs.** Catalogue entries, owning specifications, published meanings, disambiguation tables.  
**Outputs.** Uniqueness findings (intact / violated / deferred / escalated).  
**Rules.** Apply CCIR-01 / CCIR-04 / CCIR-08. Prefer violated over renumbering.

### 6.2 CCI-02 — Identifier Consistency

**Purpose.** Validate that each ID retains one published meaning within its owning namespace.

**Inputs.** Meaning statements across the assessment scope for the same ID.  
**Outputs.** Consistency findings.  
**Rules.** Apply CCIR-02 / CCIR-08. Drift without amendment is violated.

### 6.3 CCI-03 — Namespace Separation

**Purpose.** Validate CCF family membership and prefix separation.

**Inputs.** Family classifications, prefix maps, published disambiguation sections.  
**Outputs.** Namespace findings.  
**Rules.** Apply CCIR-03 / CCIR-07. Silent merges are defects.

### 6.4 CCI-04 — Collision Detection

**Purpose.** Identify overlapping labels across families and classify them as published disambiguation, collision defect, or incomplete (deferred / escalated).

**Inputs.** Overlapping identifier strings / prefixes + owning corpora.  
**Outputs.** Collision catalogue with disposition.  
**Rules.** Apply CCIR-04 / CCIR-08 / CCIR-10. Never “fix” by renumbering in situ.

### 6.5 CCI-05 — Numbering Integrity

**Purpose.** Validate that published numbering ranges, gaps, and succession remain as published.

**Inputs.** Published catalogue tables and succession / closure statements.  
**Outputs.** Numbering findings.  
**Rules.** Apply CCIR-05 / CCIR-08. Gaps may be lawful if published; silent renumbering is not.

### 6.6 CCI-06 — Extensibility Integrity

**Purpose.** Confirm that lawful amendment-only growth rules remain reconstructable and that invent-in-place is absent from assessment claims.

**Inputs.** Closure statements, amendment paths, assessment claims about “new IDs.”  
**Outputs.** Extensibility findings.  
**Rules.** Apply CCIR-06 / CCIR-08. Extensibility ≠ permission for this Model to create IDs.

### 6.7 CCI-07 — Assessment Integrity

**Purpose.** Preserve reconstructable records of catalogue integrity assessments.

**Inputs.** Assessment scope, CCF / CCI identities, collision notes, findings, boundary confirmations.  
**Outputs.** Assessment integrity / lineage records.  
**Rules.** Apply CCIR-09 / CCIR-10 and explainability obligations. Missing reconstructability is a defect.

## 7. Cross-Family Collision Posture

| Situation | Lawful disposition |
|-----------|-------------------|
| Same prefix, same owning catalogue, same meaning | Consistent — not a collision |
| Same prefix string, different owning families, published disambiguation | Disambiguated — disclose; do not merge |
| Same prefix string, different owning families, no published disambiguation | Collision defect — violated / deferred / escalated |
| Adjacent numbering across different catalogues | Not a collision unless meanings / IDs collide |
| “Looks similar” names (CC vs CCM vs CCI) | Require explicit disambiguation speech; similarity alone is not identity |
| Proposal to renumber to clear a collision | Report finding; propose upstream amendment — never renumber under this Model |

## 8. Closing Statement

> **Catalogue families classify. Integrity categories validate.  
> Neither creates identifiers, renumbers catalogues, amends specifications, nor becomes constitutional authority.  
> Uniqueness, consistency, namespace separation, numbering fidelity, and lawful extensibility are the only catalogue-integrity jobs.**
