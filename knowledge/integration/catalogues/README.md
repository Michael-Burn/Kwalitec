## Purpose

This folder defines **the permanent constitutional mechanism for validating catalogue consistency** throughout the constitutional corpus.

It answers *what catalogue integrity must optimise*, *which recognised catalogue families and namespace expectations exist*, *what catalogue integrity assessment may and must never do*, and *how catalogue integrity is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, creating catalogue identifiers, renumbering existing catalogues, amending constitutional specifications, creating constitutional authority, or elevating catalogue machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, databases, or application services.

> **Constitutional Catalogue Integrity validates catalogue consistency across the published corpus.  
> It never becomes constitutional law itself.  
> It never creates catalogue identifiers, renumbers catalogues, amends specifications, or creates constitutional authority.**

## Architectural requirement

Constitutional Catalogue Integrity validates **catalogue consistency**.

| Lawful | Unlawful |
|--------|----------|
| Analyse catalogue structures | Rename identifiers |
| Validate uniqueness and consistency | Alter catalogue numbering |
| Validate namespace separation | Redefine catalogue meanings |
| Validate numbering integrity | Amend constitutional specifications |
| Validate future extensibility | Create catalogue identifiers |
| Produce catalogue integrity findings | Create constitutional authority |
| Preserve explainability and auditability | Elevate scanners or CI into constitutional producers |
| Explain families / namespaces / collisions / findings / boundaries | Treat findings as soft renumbering orders |

**Constitutional Catalogue Integrity validates the catalogue corpus. It never authors catalogues or renumbers them.**

## How to use this corpus

1. Confirm the published Constitution / EIP and Programme VI–XI corpora in scope are identifiable — refuse catalogue theatre over unpublished customs.
2. Read `CONSTITUTIONAL_CATALOGUE_INTEGRITY_MODEL.md` for stack position and integrity rules.
3. Optimise under `CATALOGUE_OBJECTIVES.md`.
4. Classify and validate under `CATALOGUE_FAMILIES.md` (CCF-01…CCF-07 and CCI-01…CCI-07 only).
5. Enforce hard stops under `CATALOGUE_BOUNDARIES.md`.
6. Require explainability contracts from `CATALOGUE_EXPLAINABILITY.md` before student-, developer-, or auditor-facing catalogue narration.
7. Do not implement catalogue machinery that contradicts this corpus without amending it first.
8. When collisions or numbering defects are found, report findings and propose upstream amendment — never renumber in situ.
