## 1. Purpose

An expert IFoA tutor who cannot say *which catalogue families* were assessed — which namespace rules were applied, which identifier validations were performed, which findings were produced, and which limits remained intact — is not coaching; they are performing.

After Programmes VI–X have made meaning, ownership, tips, context, contracts, evidence, runtime, governance, and execution speech speakable, after Programme XI / WS1 has made dependency integrity speech speakable, and after WS2 / MS001 has made catalogue integrity speech speakable, Programme XI still needs one lifecycle-speech answer:

> **“Which catalogue families were assessed, which namespace rules were applied, which identifier validations were performed, which findings were produced, and which constitutional boundaries remained intact?”**

That answer must cover every material catalogue integrity lifecycle without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, creating or renumbering catalogue identifiers, creating constitutional authority, freezing a stack as law, inventing unpublished CCI / CCF / CCIL types, replacing MS001 validation meaning, or presenting publication as educational quality.

## 2. What Lifecycle Explainability Is

**Constitutional Catalogue Integrity Lifecycle Explainability** is the constitutional obligation to narrate **coordination of named catalogue assessments through published CCIL stages** — discovering published catalogues under CCF families, validating namespace separation, validating identifier uniqueness and consistency, validating numbering and extensibility, applying published CCI types, and producing / publishing findings — not to invent a second tutor voice from string scanners, not to grade the student, and not to replace constitutional authority.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Catalogue families assessed** | Named CCF-01…CCF-07 memberships and the catalogues under assessment | Which catalogue families were assessed? |
| **Namespace rules applied** | Reconstructable CCIR / family prefix / disambiguation rules applied at CCIL-03 | Which namespace rules were applied? |
| **Identifier validations performed** | Uniqueness / consistency / numbering / extensibility validations under CCI-01…CCI-06 across CCIL-04…CCIL-05 | Which identifier validations were performed? |
| **Findings produced** | intact / violated / deferred / escalated (with stage binding and composition notes) | Which findings were produced? |
| **Boundaries remaining intact** | Explicit confirmation that forbidden identifier creation / renumbering / legislation / meaning redefinition / authority-creation / substitution did not occur | Which constitutional boundaries remained intact? |

Lifecycle Explainability is:

- **coordination-centred** — it narrates families → namespace rules → identifier validations → findings under law;
- **catalogue-bound** — every justification cites published CCIL, CCI, and CCF identities;
- **corpus-bound** — every justification cites published corpora and catalogues;
- **discovery-honest** — every material justification cites identifiable published catalogues / families assessed (or names the hard stop when none exist);
- **namespace-honest** — every material justification cites applied namespace rules and collision status (or names the hard stop when unmet);
- **identifier-honest** — every material justification cites uniqueness / consistency / numbering / extensibility validation without hiding or “fixing” defects by renumbering;
- **finding-honest** — every material finding is bound to the producing lifecycle stages;
- **record-honest** — every material lifecycle cites which assessment records were preserved / published;
- **non-legislative** — explanation never becomes a back door to amend corpora;
- **non-authoritative** — publication is never narrated as a freeze of stack authority or a substitute for published corpora;
- **quality-honest** — intact status is never narrated as mastery, readiness theatre, or educational quality;
- **mutation-honest** — explanation never hides identifier creation or renumbering performed “so the lifecycle could proceed”;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, Programme IX governance speech, Programme X activity speech, WS1 dependency integrity speech, or WS2 / MS001 catalogue integrity speech;
- **audit-aligned** — explanation components match CCILO-06 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions or private stage shortcuts.

Lifecycle Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–X / WS1 / WS2 / MS001 meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for CCI findings speech, CT lineage speech, CDI / CDIL speech, or Programme IX–X evaluative / execution speech;
- a CI status page, coverage report, string-scanner summary, or linter summary presented as constitutional coordination;
- a freeze of implementations, stacks, vendors, or releases as constitutional law;
- a licence to narrate invented catalogues, invented uniqueness, or renumbered identifiers as if they were lawful inputs.

## 3. Mandatory Explainability Questions

Every material constitutional catalogue integrity lifecycle must be able to answer:

### CCILEQ-01 — Which catalogue families were assessed?

**Required content**

- Named CCF-01…CCF-07 family memberships and published catalogue identities discovered at CCIL-02
- Binding between catalogue identities and intended / applied CCI types
- Confirmation that unpublished customs, invented prefixes, or scanner noise were not used as constitutional catalogues

**Defect if**

- “Catalogues are fine” with no family or catalogue references
- Anonymous “the docs” or “the prefixes” without identifiable published catalogues / families
- Catalogues invented, renamed, renumbered, or deleted as assessment without disclosure and hard stop

---

### CCILEQ-02 — Which namespace rules were applied?

**Required content**

- Named namespace rules confirmed at CCIL-03 (relevant CCIR-01…CCIR-10 rules, family prefix expectations, published disambiguation tables)
- Explicit refuse-validate-namespace disposition when separation was unmet
- Confirmation that namespace rules or disambiguation links were not invented or silently skipped
- Collision status where material (none detected / collision detected / inconclusive — with named overlapping labels when detected)

**Defect if**

- Assessment proceeds with “namespaces assumed”
- Disambiguation invented mid-lifecycle to force intact status
- Silent omission of mandatory family / prefix identities
- Detected collisions quietly dropped from publication speech

---

### CCILEQ-03 — Which identifier validations were performed?

**Required content**

- Uniqueness / consistency validation status from CCIL-04 under CCI-01 / CCI-02
- Numbering integrity and extensibility posture from CCIL-05 under CCI-05 / CCI-06
- Confirmation that identifiers were not created, renamed, or renumbered under lifecycle pretence
- Explicit refuse-validate-identifier / refuse-number dispositions when validations were unmet

**Defect if**

- Identifier-validation status omitted when findings are claimed
- Narration that uniqueness or numbering defects were “resolved” by creating or renumbering identifiers under lifecycle pretence
- Silent omission of extensibility posture when growth claims are implied

---

### CCILEQ-04 — Which findings were produced?

**Required content**

- Named catalogue integrity findings from CCIL-06 (intact / violated / deferred / escalated)
- Binding of each finding to producing CCIL stages (especially CCIL-03…CCIL-06)
- Publication artefacts from CCIL-07 where material (or refuse-publish identity)
- Continuity sufficient to reconstruct corpora, catalogues, families, namespace rules, identifier validations, CCI types, stages, findings, and boundaries

**Defect if**

- “Intact” with no reconstructable finding identity
- Findings that drop stage-to-finding binding or catalogue / family identity
- Silent erasure of prior lawful assessment / lifecycle history
- Publication that invents intact status or hides violated dispositions

---

### CCILEQ-05 — Which constitutional boundaries remained intact?

**Required content**

- Explicit confirmation against `LIFECYCLE_BOUNDARIES.md` checks material to the concern (especially non-identifier-creation, non-renumbering, non-legislation, non-redefinition, non-authority-creation, non-substitution)
- Disclosure of any hard stop that prevented progress or publication

**Defect if**

- Boundaries are implied, not speakable
- Publication speech smuggles identifier creation, renumbering, meaning redefinition, authority creation, or law rewrites
- Artefact / catalogue mutation or invented catalogues are hidden

## 5. Forbidden Explainability Moves

| Forbidden narration | Why | Lawful alternative |
|---------------------|-----|--------------------|
| “Lifecycle published ⇒ new constitutional law” | Legislation via publication | “Findings recorded; corpora unchanged” |
| “Lifecycle published ⇒ catalogues renumbered” | Identifier mutation | “Structure assessed as found; identifiers unchanged” |
| “Lifecycle published ⇒ identifiers created” | Identifier creation | “Assessment coordinated; published catalogues remain the vocabulary” |
| “Lifecycle published ⇒ authority created” | Authority creation | “Assessment coordinated; published corpora remain the standard” |
| “Intact ⇒ student ready / mastered” | Quality / mastery out of scope | Keep structure speech distinct from educational claim classes |
| “We invented the missing prefix so namespaces validated” | Invented namespace rules | Refuse-validate-namespace; propose lawful amendment upstream |
| “We fixed the collision in the lifecycle” | Identifier renumbering | Report collision / violated; refuse renumbering under assessment pretence |
| “Stage skipped because the scanner was green” | Unpublished stage customs | Apply CCIL-01…CCIL-07 or refuse |
| “We adjusted the docs so the lifecycle could finish” | Specification / catalogue mutation | Refuse-discover / violated; propose lawful change outside lifecycle pretence |
| “This stack is now the standard” | Authority substitution / neutrality breach | Keep implementation as assessed subject |
| “Findings update the constitution” | Legislation via explanation | Propose amendment upstream; leave corpora unchanged |
| “Linked in CT ⇒ catalogue intact forever” | CT / CCI conflation | Compose with CT; keep catalogue integrity speech distinct |
| “Dependency intact ⇒ catalogue intact forever” | CDI / CCI conflation | Compose with CDI / CDIL; keep catalogue integrity speech distinct |

## 7. Audit Alignment

Lifecycle explainability records must support reconstruction of:

1. Catalogue families assessed (CCILEQ-01)
2. Namespace rules applied (CCILEQ-02)
3. Identifier validations performed (CCILEQ-03)
4. Findings produced and records / publication artefacts preserved (CCILEQ-04)
5. Constitutional boundaries remaining intact (CCILEQ-05)
6. Applied CCI-01…CCI-07 and CCF-01…CCF-07 identities (from WS2 / MS001 speech)
7. Finding dispositions (intact / violated / deferred / escalated / refuse-*)
8. Continuity of prior lawful lifecycle history (EIP-005)

Missing any material element is an explainability defect under CCILO-06.
