## Purpose

This folder defines **the permanent constitutional mechanism for validating constitutional boundaries** throughout the constitutional corpus.

It answers *what boundary integrity must optimise*, *which recognised boundary categories and validation rules exist*, *what boundary integrity assessment may and must never do*, and *how boundary integrity is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, creating constitutional authority, modifying constitutional responsibilities, reinterpreting constitutional meaning, amending constitutional specifications, or elevating boundary machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, databases, or application services.

> **Constitutional Boundary Integrity validates constitutional boundaries across the published corpus.  
> It never becomes constitutional law itself.  
> It never creates authority, redefines responsibilities, reinterprets meaning, or amends constitutional specifications.**

## Architectural requirement

Constitutional Boundary Integrity validates **constitutional boundary consistency**.

| Lawful | Unlawful |
|--------|----------|
| Analyse constitutional boundaries | Redefine constitutional authority |
| Validate authority and responsibility boundaries | Modify responsibilities |
| Validate may / must / must-not constraints | Alter constitutional constraints |
| Validate consumption and production boundaries | Amend constitutional specifications |
| Validate constitutional separation of concerns / layer boundaries | Create constitutional authority |
| Produce boundary integrity findings | Reinterpret constitutional meaning |
| Preserve explainability and auditability | Elevate scanners or CI into constitutional producers |
| Explain boundaries / constraints / separations / findings | Treat findings as soft amendments of boundary law |

**Constitutional Boundary Integrity validates the boundary corpus. It never authors boundaries or rewrites published responsibilities.**

1. Confirm the published Constitution / EIP and Programme VI–XI corpora in scope are identifiable — refuse boundary theatre over unpublished customs.
2. Read `CONSTITUTIONAL_BOUNDARY_INTEGRITY_MODEL.md` for stack position and integrity rules.
3. Optimise under `BOUNDARY_OBJECTIVES.md`.
4. Classify and validate under `BOUNDARY_TYPES.md` (CBI-01…CBI-07 only).
5. Enforce hard stops under `BOUNDARY_BOUNDARIES.md`.
6. Require explainability contracts from `BOUNDARY_EXPLAINABILITY.md` before student-, developer-, or auditor-facing boundary narration.
7. Do not implement boundary machinery that contradicts this corpus without amending it first.
8. When boundary collisions or constraint contradictions are found, report findings and propose upstream amendment — never rewrite boundaries in situ.
