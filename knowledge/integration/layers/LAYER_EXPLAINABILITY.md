## 1. Purpose

An expert IFoA tutor who cannot say *which layers* were checked — which authority paths were validated, whether bypasses or cycles were found, what finding resulted, and which assessment limits were preserved — is not coaching; they are performing.

After Programmes VI–X have made meaning, ownership, tips, context, contracts, evidence, runtime, governance, and execution speech speakable, and after Programme XI / WS1–WS4 have made dependency, catalogue, boundary, and vocabulary speech speakable, Programme XI still needs one layer-speech answer:

> **“Which layers were assessed, which authority paths were validated, were any layer bypasses detected, were any architectural cycles detected, and which findings were produced?”**

That answer must cover every material layer integrity assessment without inventing educational meaning, transferring authority, minting tips, inventing state, rewriting specifications, redefining layers, modifying authority hierarchy, freezing a stack as law, inventing unpublished CLI / CL types, or presenting intact status as educational quality or student readiness.

## 2. What Layer Explainability Is

**Constitutional Layer Integrity Explainability** is the constitutional obligation to narrate **validation of named architectural layers under published CLI categories and CL classifications** — not to invent a second tutor voice from architecture scanners, and not to grade the student.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Layers assessed** | Named CL-01…CL-04 layers and CLI-01…CLI-07 classifications under validation | Which layers were assessed? |
| **Authority paths validated** | Named reconstructable superior → subordinate paths applied to those layers | Which authority paths were validated? |
| **Layer bypasses detected** | Skipped required superior layers found (or confirmed absent) | Were any layer bypasses detected? |
| **Architectural cycles detected** | Authority-circularising closed paths found (or confirmed absent) | Were any architectural cycles detected? |
| **Integrity findings** | intact / violated / deferred / escalated (with composition notes) | Which findings were produced? |

Layer Explainability is:

- **validation-centred** — it narrates layers → authority paths → bypasses / cycles → findings under law;
- **catalogue-bound** — every justification cites published CLI / CL identities;
- **corpus-bound** — every justification cites published specifications and layer / path statements;
- **non-legislative** — explanation never becomes a back door to amend corpora, redefine layers, or invent maps;
- **quality-honest** — intact status is never narrated as mastery, readiness, or educational quality;
- **technology-honest** — explanation never presents a stack preference or scanner green as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence speech, Programme IX governance speech, Programme X execution / decision / audit / explanation speech, or Programme XI / WS1–WS4 assurance speech;
- **audit-aligned** — explanation components match CLI-07 reconstruction needs;
- **repeatability-honest** — explanations must not paper over race-dependent dispositions.

Layer Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–XI meaning;
- a quality report on learning, coaching, or exam readiness;
- a substitute for Programme IX CT explainability, Programme XI / WS1–WS4 assurance explainability, or Programme X explainability architecture corpora;
- a rendering system, UI template, CI badge, log shipper, architecture-diagram product, or analytics dashboard;
- a claim that clear layer speech guarantees learning or a pass;
- a licence to present scanner greens, folder maps, or pipeline badges as constitutional proof or educational quality;
- a licence to narrate layer redefinition as “integrity repairs.”

## 3. Mandatory Explanation Questions

Every material constitutional layer integrity assessment should answer all five questions:

### CLIEQ-01 — Which layers were assessed?

Name the primary published layers and the CLI-01…CLI-07 categories / CL-01…CL-04 classifications under validation (for example CL-01 / CL-02 foundational path under CLI-02; CL-03 programme order VI→VIII under CLI-01; CL-04 assurance isolation under CLI-06). Unpublished tribal diagrams and “neighbouring folder labels” are not constitutional layers.

### CLIEQ-02 — Which authority paths were validated?

Name the reconstructable superior → subordinate paths (and relevant CLIR-01…CLIR-10 rules) applied to the assessment. Missing path identity is a defect to disclose — not a gap to invent. “Supported by ticket #1234,” “supported by architecture slide,” or “supported by import graph” is not a constitutional authority path.

### CLIEQ-03 — Were any layer bypasses detected?

Name bypass outcomes under review and their disposition:

- **None detected (within scope)** — required superior layers remain on reconstructable paths for the assessment scope.
- **Bypass detected** — a required superior layer was skipped to obtain authority or meaning; name the skipped layer(s) and path.
- **Incomplete** — path identity missing; disposition must be deferred / escalated, not silently intact.

Peer composition that is published as lawful multi-horizon collaboration is not automatically a bypass; undeclared shortcuts that skip required superiors are.

### CLIEQ-04 — Were any architectural cycles detected?

Name cycle outcomes under review and their disposition:

- **None detected (within scope)** — no closed path circularises or inverts layer authority for the assessment scope.
- **Cycle detected** — a closed path circularises or inverts authority; name the path and implicated layers / programmes.
- **Incomplete** — graph identity missing; disposition must be deferred / escalated, not silently intact.

Lawful peer composition / cross-reference that preserves superior authorship is not automatically a cycle; mutual foundational authorship is.

### CLIEQ-05 — Which findings were produced?

Distinguish:

- **intact** — published layering satisfies applicable CLI categories and CLIR rules for the assessment scope;
- **violated** — ordering, authority flow, dependency direction, bypass absence, cycle absence, isolation, or catalogue rules failed;
- **deferred** — lawful pause pending identifiable missing published inputs;
- **escalated** — requires corpus governance / human constitutional review beyond ordinary assessment.

Composition notes must name which CLI-01…CLI-07 categories (and CL classifications) bound the finding. “Layers look fine” is not a finding.

When narrating findings, also confirm assessment limits held: the assessment did **not** redefine layers, modify authority hierarchy, amend specifications, create constitutional authority, substitute Programme XI for upstream authority, narrate intact status as educational quality / mastery / student exam readiness, or privilege a technology / scanner / CI vendor as constitutional law. Failed assessment-limit confirmation → the explanation is constitutionally defective even if a disposition string exists.

## 5. Explanation Anti-Patterns

| Anti-pattern | Why defective | Lawful alternative |
|--------------|---------------|--------------------|
| “Layers are fine because CI is green” | Proxy theatre | Cite CLI / CL categories, authority paths, and findings |
| “We fixed integrity by redrawing the stack” | Mutation under explanation pretext | Report violation; propose upstream amendment |
| “Intact means the student is ready” | Quality conflation | Keep layer integrity distinct from student readiness |
| “Authority path is the Jira epic” | Non-constitutional origin | Cite Constitution / EIP / programme paths and CLIR IDs |
| “No conflicts in the import graph / folder tree” | Wrong subject horizon | Map to published layers or refuse |
| “Programme XI now defines Programme VI layers” | Authority / meaning substitution | Preserve VI meaning; XI validates only |
| “Temporary bypass for the demo” | Emergency exemption | Deferred / escalated / violated — never demo law |
| “Trust us — the architecture is obvious” | Opacity | Answer CLIEQ-01…CLIEQ-05 explicitly |
| “We collapsed those layers to make integration simpler” | Isolation rewrite | Report absorption as violated; propose upstream amendment |
| “CBI-06 already checked layers, so CLI is redundant theatre” | Horizon conflation | Compose CBI-06 with CLI; do not erase CLI obligations |
