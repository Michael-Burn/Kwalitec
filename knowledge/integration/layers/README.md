## Purpose

This folder defines **the permanent constitutional mechanism for validating architectural layering** throughout the constitutional corpus.

It answers *what layer integrity must optimise*, *which recognised constitutional layers and validation rules exist*, *what layer integrity assessment may and must never do*, and *how layer integrity is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, redefining constitutional layers, modifying authority flow, reinterpreting constitutional meaning, amending constitutional specifications, creating constitutional authority, or elevating layer machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, databases, or application services.

> **Constitutional Layer Integrity validates architectural layering across the published corpus.  
> It never becomes constitutional law itself.  
> It never redefines layers, modifies authority flow, reinterprets meaning, or amends constitutional specifications.**

## Architectural requirement

Constitutional Layer Integrity validates **architectural layering of the constitutional corpus**.

| Lawful | Unlawful |
|--------|----------|
| Analyse architectural layers | Redefine constitutional layers |
| Validate constitutional layer ordering | Modify authority hierarchy / flow |
| Validate authority flow between layers | Amend constitutional specifications |
| Validate dependency direction between layers | Create constitutional authority |
| Validate absence of layer bypasses | Reinterpret constitutional meaning |
| Validate absence of layer cycles | Elevate scanners or CI into constitutional producers |
| Produce layer integrity findings | Treat findings as soft redefinitions of published layers |
| Preserve explainability and auditability | Narrate intact status as educational quality |
| Explain layers / authority paths / bypasses / cycles / findings | Invent unpublished “preferred layer maps” as law |

**Constitutional Layer Integrity validates the layer corpus. It never authors layers or rewrites published authority flow.**

## How to use this corpus

1. Confirm the published Constitution / EIP and Programme VI–XI corpora in scope are identifiable — refuse layer theatre over unpublished customs.
2. Read `CONSTITUTIONAL_LAYER_INTEGRITY_MODEL.md` for stack position and integrity rules.
3. Optimise under `LAYER_OBJECTIVES.md`.
4. Classify and validate under `LAYER_MODEL.md` (CL-01…CL-04 and CLI-01…CLI-07 only).
5. Enforce hard stops under `LAYER_BOUNDARIES.md`.
6. Require explainability contracts from `LAYER_EXPLAINABILITY.md` before student-, developer-, or auditor-facing layer narration.
7. Do not implement layer machinery that contradicts this corpus without amending it first.
8. When layer violations, bypasses, or cycles are found, report findings and propose upstream amendment — never rewrite layers in situ.
