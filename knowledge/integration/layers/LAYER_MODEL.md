## 1. Purpose

Layer integrity without a closed catalogue invents law by proximity: whichever folder adjacency, architecture slide, or pipeline annotation happens to exist becomes the tutor’s “proof the constitution is layered.”

This catalogue names the only lawful constitutional architectural layers and layer integrity categories an assessment may apply — and binds each to purpose, scope, inputs, outputs, validation rules, and permitted / prohibited interactions.

**Hard constraint:** This document never creates constitutional authority, never redefines layers, never modifies authority flow, never amends constitutional specifications, and never invents new domain layers under validation pretext.

## 2. Recognised Constitutional Layers (CL-01…CL-04)

| ID | Layer | Constitutional role | Lawful interactions |
|----|-------|---------------------|---------------------|
| **CL-01** | Constitution | Foundational educational truth and curriculum primacy | Authorises all subordinate layers; never authorised by them |
| **CL-02** | Educational Interpretation Principles | Evidence classification, continuity, explainability, claim honesty, mutation rights | Interprets and specialises Constitution; never replaces it; authorises programme / assurance consumption |
| **CL-03** | Constitutional Programmes | Programmes VI–XI as published meaning, orchestration, runtime, governance, execution, and integration programme bands | Consume CL-01 / CL-02; programme order VI→VII→VIII→IX→X→XI; never author Constitution / EIP |
| **CL-04** | Constitutional Assurance | Programme XI integrity / readiness validation posture (dependency, catalogue, boundary, vocabulary, layer integrity and successors) | Validates corpus structure under published law; never authors upstream meaning; never becomes foundational law |

### 2.1 Lawful authority flow

```
CL-01 Constitution
        │  defines educational truth and curriculum primacy
        ▼
CL-02 Educational Interpretation Principles
        │  specialises evidence, continuity, explainability, claim honesty, mutation rights
        ▼
CL-03 Constitutional Programmes
        │  VI meaning → VII orchestration → VIII runtime →
        │  IX governance → X execution → XI integration programme band
        ▼
CL-04 Constitutional Assurance
        │  validates dependency / catalogue / boundary / vocabulary / layer integrity
        │  produces findings — never new constitutional authorship
```

**Authority-flow rules:**

1. Authority flows **downward** from CL-01 toward CL-04.
2. A lower layer may **consume** published superior law; it may not **author**, **reinterpret**, or **soft-amend** that law via layer assessment.
3. CL-04 may **validate** CL-01…CL-03 corpora; it may not become their peer foundational authority.
4. Within CL-03, lawful programme order is **VI → VII → VIII → IX → X → XI**.
5. Sibling composition within Programme XI assurance workstreams is lawful when published as composition — never as mutual foundational authorship.

### 2.2 Architectural interaction rules

| Interaction | Lawful | Unlawful |
|-------------|--------|----------|
| CL-03 consumes CL-01 / CL-02 | Cite published Constitution / EIP as superior | Soft-replace Constitution / EIP with programme prose |
| CL-03 programme → later programme | Later programme consumes earlier published law | Later programme authors earlier programme meaning |
| CL-04 validates CL-01…CL-03 | Emit integrity findings against published corpora | Treat findings as amendments or new layers |
| Cross-horizon composition | Published composition / consumption rights | Bypass required superior layer to mint authority |
| Peer Programme XI WS composition | Compose CDI / CCI / CBI / CVI / CLI as published | Collapse into one mega-authority that rewrites layers |

### 2.3 What layers are not

- Folder trees, repository adjacency, or package namespaces are **not** constitutional layers.
- Product / architecture / Version 2 design docs are **not** CL-01…CL-04 members unless separately published as constitutional corpora under those layers.
- Runtime A, Twin, Adaptive, CI, and UI are **assessed subjects**, not architectural layers.

## 3. Layer Integrity Categories Overview (CLI-01…CLI-07)

| ID | Integrity category | Constitutional purpose (short) | Primary inputs | Primary outputs |
|----|--------------------|--------------------------------|----------------|-----------------|
| **CLI-01** | Layer Ordering Integrity | Validate CL-01…CL-04 (and VI→…→XI) order | Published layer map + corpus identities | Ordering findings |
| **CLI-02** | Authority Flow Integrity | Validate reconstructable superior → subordinate authority paths | Authority path identities + owning layers | Authority-flow findings |
| **CLI-03** | Inter-Layer Dependency Direction | Validate lawful dependency orientation between layers | Named inter-layer edges + published direction | Direction findings |
| **CLI-04** | Layer Bypass Detection | Detect unlawful skipping of required superior layers | Candidate paths + required intermediate layers | Bypass findings |
| **CLI-05** | Layer Cycle Detection | Detect closed paths that circularise or invert layer authority | Named layer graph / paths | Cycle findings |
| **CLI-06** | Architectural Isolation Integrity | Validate separation of concerns among layers | Horizon ownership statements + isolation claims | Isolation findings |
| **CLI-07** | Assessment Integrity | Preserve reconstructable layer assessment records | Assessment records + layer / path identities | Assessment-lineage / integrity records |

Material assessments must map to one or more of these categories as published law requires. Cross-cutting situations may bind multiple CLI types; none may invent a type outside this catalogue.

**Relation to CT / CC / CV / CCM / CRT / CDI / CCI / CBI / CVI:** Those catalogues remain defined solely by their owners. CLI categories *validate constitutional architectural layer integrity*; they do not replace lineage preservation, fidelity evaluation, verification, compliance determination, certification recognition, dependency validation, catalogue validation, boundary validation, or vocabulary validation.

**Relation to educational quality:** No CLI type judges whether learning was good, whether a tip was wise, or whether the student is ready. Intact ≠ quality. Intact ≠ conformant. Intact ≠ certified. Intact ≠ educationally ready.

## 4. Global Validation Rules

These rules apply to every CLI category:

| Rule ID | Validation rule |
|---------|-----------------|
| **CLIR-01 Ordering fidelity** | Every material assessment must honour CL-01 → CL-02 → CL-03 → CL-04 and lawful VI→…→XI order within CL-03. Layer inversion is a defect. |
| **CLIR-02 Authority-path fidelity** | Every material authority path must be reconstructable from superior layers to the assessed subject. Orphan or invented authority is a defect. |
| **CLIR-03 Direction fidelity** | Inter-layer dependencies must respect superior → subordinate / consumer orientation. Reverse authorship is a defect. |
| **CLIR-04 Bypass refusal** | Relationships that skip required superior layers to obtain authority or meaning are defects when used as intact bases. |
| **CLIR-05 Acyclicity** | No closed path among layers may circularise or invert constitutional authority. Detected cycles → violated (or deferred / escalated when incomplete identity prevents confirmation). |
| **CLIR-06 Isolation fidelity** | Layers must not absorb another layer’s authorship. Silent horizon merger without published warrant is a defect. |
| **CLIR-07 Catalogue closure** | Only CL-01…CL-04 and CLI-01…CLI-07 may classify constitutional layer integrity assessments. Unpublished customs are unlawful. |
| **CLIR-08 Non-mutation** | Validation never creates, deletes, reorders, or soft-amends constitutional layers or specifications. Findings report; they do not rewrite. |
| **CLIR-09 Neutrality** | Validation criteria speak to constitutional identities and published layer relationships — never “must use Flask / npm / folder layout X.” |
| **CLIR-10 Finding honesty** | Dispositions are intact / violated / deferred / escalated only. “Close enough,” “temporary bypass,” or “demo exception” are not constitutional dispositions. |

## 5. CLI-01 — Layer Ordering Integrity

### Constitutional purpose

Validate lawful **ordering of recognised architectural layers** — so Constitution, EIP, Programmes, and Assurance remain sequenced as published.

### Constitutional scope

CL-01…CL-04 identities and lawful programme order within CL-03. Does **not** invent new layers or merge programmes by “stacking harder.”

### Constitutional inputs

- Published CL-01…CL-04 layer identities and programme order.
- Named corpus identities claiming constitutional meaning.
- Published CLIO-01 expectations.

### Constitutional outputs

- Ordering finding under CLI-01.
- Named order confirmation (or inversion note).
- Audit-speakable confirmation that published order was applied (true/false).

### Validation rules (category-specific)

- Lawful macro-order: CL-01 → CL-02 → CL-03 → CL-04.
- Lawful programme order within CL-03: VI → VII → VIII → IX → X → XI.
- Findings may note missing order declaration; they may not invent a new order.

### Permitted relationships

- Confirm a Programme VIII corpus sits in CL-03 after Programme VII and before Programme IX.
- Confirm CL-04 assurance corpora remain after CL-03 programme publication for the assessed concern.
- Record lawful workstream / milestone subordination within a programme without inventing a fifth macro-layer.

### Prohibited relationships

- Treat CL-04 findings as CL-01 / CL-02 peer foundational law.
- Soft-elevate architecture / Version 2 docs into CL-01 via ordering prose.
- Invent unpublished “preferred layer maps” as peer law.
- Use CLI-01 to create or reorder constitutional layers.

## 6. CLI-02 — Authority Flow Integrity

### Constitutional purpose

Validate **reconstructable authority paths** from superior layers to assessed subjects — so authority remains speakable and unabsorbed.

### Constitutional scope

Named authority paths among CL-01…CL-04 and programme intermediates. Does **not** mint new authority or reinterpret EIP claim classes.

### Constitutional inputs

- Superior corpus identities (Constitution / EIP / programme owners).
- Assessed subordinate corpus identities.
- Published CLIO-02 expectations.

### Constitutional outputs

- Authority-flow finding under CLI-02.
- Named authority-path note.
- Confirmation that superior authorship was not inverted (true/false).

### Validation rules (category-specific)

- Every material constitutional corpus under CL-03 / CL-04 must reconstruct to CL-01 / CL-02 (directly or via published intermediates).
- Paths that treat product UX, Twin, Adaptive, or CI as constitutional producers are defects when used as authority.
- Findings may note missing path segments; they may not invent foundational authority.

### Permitted relationships

- Trace a Programme IX conformance model to Constitution / EIP through published programme intermediaries.
- Trace a Programme XI layer-integrity finding back to the corpora it validates without elevating the finding into law.

### Prohibited relationships

- Treat a layer finding as a Constitution / EIP amendment.
- Soft-author Programme VI meaning from Programme XI assurance prose.
- Use CLI-02 to modify authority hierarchy.

## 7. CLI-03 — Inter-Layer Dependency Direction

### Constitutional purpose

Validate **lawful orientation of dependencies between layers** — so subordinates consume superiors and never reverse authorship.

### Constitutional scope

Named inter-layer edges and published direction declarations. Does **not** rewrite CDI edge catalogues; composes with them.

### Constitutional inputs

- Named edges between layer identities / programme bands.
- Published direction / consumption rights.
- Published CLIO-03 expectations.

### Constitutional outputs

- Direction finding under CLI-03.
- Named orientation (superior → subordinate / consumer).
- Reverse-authorship notes when detected.

### Validation rules (category-specific)

- Lower layers may depend on / consume superior published law.
- Superior layers must not depend on subordinate findings as authorship sources.
- Peer composition within CL-04 is lawful only when published as composition, not mutual authorship of upstream law.

### Permitted relationships

- Programme VIII consumes Programme VI / VII published law.
- CL-04 consumes published CL-01…CL-03 corpora as assessment subjects.

### Prohibited relationships

- Programme VI “depends on” Programme XI findings as meaning authority.
- Reverse edges used to force intact status.
- Use CLI-03 to create, reverse, or delete constitutional dependencies (CDI owns dependency mutation refusal; CLI refuses direction violations).

## 8. CLI-04 — Layer Bypass Detection

### Constitutional purpose

Detect **unlawful skipping of required superior layers** — so authority or meaning cannot be obtained by shortcut.

### Constitutional scope

Candidate authority / meaning paths that omit required intermediate layers. Does **not** invent required intermediates not published by law.

### Constitutional inputs

- Candidate paths from assessed subject to claimed authority.
- Published required intermediates for the path class.
- Published CLIO-01 / CLIO-02 / CLIO-04 expectations.

### Constitutional outputs

- Bypass finding under CLI-04.
- Named skipped layer(s), if any.
- Disposition: none detected / bypass detected / incomplete.

### Validation rules (category-specific)

- A path from CL-03 programme law to educational truth that skips CL-01 / CL-02 when those are required is a bypass defect.
- A path that treats CL-04 findings as direct educational meaning without CL-03 owners is a bypass defect.
- Incomplete path identity → deferred / escalated, never silent intact.

### Permitted relationships

- Confirm a Programme VII recommendation model cites Programme VI warrant owners and EIP as required.
- Confirm assurance findings cite assessed programme corpora rather than inventing meaning directly.

### Prohibited relationships

- “Demo shortcut” paths that skip Constitution / EIP.
- Soft-bypass via “everyone knows the intent.”
- Use CLI-04 to invent new required layers outside CL-01…CL-04.

## 9. CLI-05 — Layer Cycle Detection

### Constitutional purpose

Detect **architectural cycles** among layers that circularise or invert constitutional authority.

### Constitutional scope

Closed paths among CL-01…CL-04 (and programme bands within CL-03). Does **not** treat every mutual citation as a cycle — only paths that invert or circularise authority.

### Constitutional inputs

- Named layer / programme graph edges under assessment.
- Published acyclicity expectations (CLIO-01 / CLIR-05).

### Constitutional outputs

- Cycle finding under CLI-05.
- Named cycle path, if any.
- Disposition: none detected / cycle detected / incomplete.

### Validation rules (category-specific)

- Closed paths that make A authorise B and B authorise A as foundational peers are defects.
- Lawful peer composition / cross-reference that preserves superior authorship is not automatically a cycle.
- Incomplete graph identity → deferred / escalated, never silent intact.

### Permitted relationships

- Detect a cycle where Programme XI findings are treated as EIP amendments that then re-authorise the same Programme XI corpora as law.
- Detect programme-band cycles that invert VI↔IX authorship under layer prose.

### Prohibited relationships

- Declare “temporary cycles OK for demos.”
- Use CLI-05 to delete published corpora so the cycle disappears in situ.
- Conflate CDI edge cycles with CLI layer cycles without composition notes — report both honestly when both apply.

## 10. CLI-06 — Architectural Isolation Integrity

### Constitutional purpose

Validate **separation of concerns among layers** — so one layer does not absorb another’s authorship.

### Constitutional scope

Horizon ownership and isolation statements across CL-01…CL-04. Does **not** soften CBI boundaries; composes with CBI-06.

### Constitutional inputs

- Published ownership / isolation / responsibility statements.
- Candidate absorption or merger claims.
- Published CLIO-04 expectations.

### Constitutional outputs

- Isolation finding under CLI-06.
- Named absorption / merger risk, if any.
- Confirmation that layer authorship remained separated (true/false).

### Validation rules (category-specific)

- CL-04 must not absorb CL-03 meaning authorship.
- CL-03 programmes must not absorb CL-01 / CL-02 foundational authorship.
- Published sibling composition among Programme XI workstreams preserves isolation when horizons remain distinct.

### Permitted relationships

- Confirm vocabulary integrity (WS4) and layer integrity (WS5) compose without merging into one authorship engine.
- Confirm Programme VIII runtime law does not absorb Programme VI educational meaning.

### Prohibited relationships

- Silent mega-merge of Programmes VI–XI into one undifferentiated “platform law.”
- Soft-absorption of EIP into programme prose under integrity pretext.
- Use CLI-06 to redefine responsibilities (CBI / programme owners own those statements).

## 11. CLI-07 — Assessment Integrity

### Constitutional purpose

Preserve **reconstructable layer assessment records** — so findings remain auditable and explainable.

### Constitutional scope

Assessment records, layer identities, authority paths, bypass / cycle notes, and dispositions. Does **not** invent educational outcomes or freeze stacks as law.

### Constitutional inputs

- Assessment record identities.
- Related CL / CLI classifications and path notes.
- Published CLIO-05 / CLIEQ obligations.

### Constitutional outputs

- Assessment-integrity finding under CLI-07.
- Reconstructable record references.
- Continuity notes relative to prior lawful assessments when applicable.

### Validation rules (category-specific)

- Material assessments must leave speakable trails answering CLIEQ-01…CLIEQ-05.
- Missing layer identity, authority-path note, bypass / cycle note, or disposition is a defect.
- Records never become soft amendments of layer law.

### Permitted relationships

- Preserve lineage between a CLI finding and the CL layers / corpora assessed.
- Compose with Programme IX CT records for reconstruction without conflating CT and CLI.

### Prohibited relationships

- Opaque “trust us” badges without reconstructable records.
- Erasing prior violated findings to force later intact status.
- Presenting scanner logs alone as constitutional assessment integrity.
