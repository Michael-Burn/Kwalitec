## 1. Purpose

An expert IFoA tutor does not optimise “scanner greens,” “tickets closed,” or “layer graphs shown.” The tutor optimises **honest closing of constitutional layer assessment work**: when the published lifecycle for a concern has lawfully concluded, layer ordering / authority flow / dependency direction / bypass and cycle validations have completed, findings published, and the assessment formally closed, the tutor can say so — without pretending layers were rewritten, without inverting authority hierarchy so the report looks tidy, without pretending the student has mastered the topic, and without amending the syllabus because the machinery stopped cleanly.

These objectives bind every constitutional layer integrity completion judgement and every successor assessment machinery that claims layer assessment fulfilment.

## 2. Primary Objective

### CLICO-01 — Confirm lawful assessment completion

**Definition.** Ensure that runtime / assessment / audit speech affirms layer integrity completion only when a published assessment concern under WS5 / MS001–MS002 has concluded the required CLIL-01…CLIL-08 lifecycle obligations — or honestly refuses close when fulfilment criteria are not met.

**Includes:**

- Assessing only concerns that lawfully opened under WS5 / MS001–MS002 initiation → discovery → ordering validation → authority-flow validation → dependency-direction validation → bypass and cycle validation → finding construction → publication law.
- Affirming completion only when `COMPLETION_CRITERIA.md` conditions (CLIC-01…CLIC-05) hold.
- Preferring lawful “not yet” / refuse-close over inventing a “done enough” status for product convenience.
- Distinguishing lawful stop dispositions (refuse / defer / escalate / violated as published outcomes that exhaust remaining *assessment* duties with honest recording) from abandoned lifecycle duties.
- Binding every material completion judgement to reconstructable constitutional references.

**Excludes:**

- Declaring complete because a CI job exited, a ticket closed, an import scanner glowed, or a UI spinner stopped.
- Treating Twin / Adaptive / Experience / Mission heuristics as completion warrants.
- Optimising for throughput, latency, or demo continuity as a substitute for assessment honesty.
- Collapsing “layer assessment complete” into “layers redefined,” “authority hierarchy modified,” “meaning reinterpreted,” “specifications amended,” “constitutional authority created,” or “student succeeded.”

**Tutor rationale.** Professional exam preparation fails when software celebrates unfinished layer assessment — or celebrates finished scanner machinery as finished architecture rewriting or authority invention. Honest confirmation is care; completion theatre is harm.

## 3. Supporting Objectives

### CLICO-02 — Preserve architectural layering

**Definition.** Ensure that affirming completion never invents, reorders, merges, or silently rewrites published CL-01…CL-04 layers (or lawful VI→…→XI programme order within CL-03) — so every closed assessment leaves architectural layering reconstructable as published.

**Tutor rationale.** A coach who “helpfully” stacks Assurance above Constitution so the assessment can finish has abandoned educational honesty even if the completion UX looks clean.

**Manifestations:**

- Completion leaves named layer identities and ordering dispositions reconstructable.
- Close never substitutes folder adjacency, package namespaces, or architecture slides for published layer findings.
- Continuity (EIP-005) forbids erasing or silently rewriting prior lawful ordering dispositions to simplify the next report.
- Inventing or reordering layers under “completion cleanup” is a defect.

---

### CLICO-03 — Preserve authority hierarchy

**Definition.** Ensure that affirming completion never invents missing authority paths, inverts superior → subordinate flow, or absorbs superior authority into a subordinate — so every closed assessment leaves authority hierarchy reconstructable as published.

**Tutor rationale.** A tutor who cannot later say which superior layer still authorises yesterday’s subordinate claim — because close “tidied” authority — cannot be trusted. Completion that invents authority is educational fiction dressed as done.

**Manifestations:**

- Affirmed closes leave authority-path identities reconstructable with findings.
- Silent authority invention, reverse authorship, and superior absorption are defects.
- Continuity forbids deleting prior lawful authority-flow walks to “clean up” completion.
- Incomplete authority-flow validation for a required concern scope blocks affirmation.

---

### CLICO-04 — Preserve dependency integrity

**Definition.** Ensure that affirming completion never invents reverse inter-layer authorship, silently rewrites dependency direction, or upgrades unvalidated / violated bypass or cycle findings into “intact” — so inter-layer dependency orientation, bypass absence, and cycle absence remain consistent with published law after close.

**Tutor rationale.** A coach who “helpfully” erases a layer bypass or cycle so the assessment can finish has abandoned educational honesty even if the completion UX looks clean.

**Manifestations:**

- Completion leaves named inter-layer edges, bypass findings, and cycle findings reconstructable.
- Close never substitutes import scanners, folder adjacency, or ticket states for published direction / bypass / cycle findings.
- Continuity (EIP-005) forbids erasing or silently rewriting prior lawful dependency dispositions to simplify the next report.
- Mutating dependency direction or inventing intact bypass / cycle status under “completion cleanup” is a defect.

---

### CLICO-05 — Preserve assessment repeatability

**Definition.** Ensure that the same published corpora, same discovered layers, same CLI applications, and same CLIL stage sequence yield the same completion disposition for the same concern — so close never invents contradictory stories from identical constitutional inputs.

**Tutor rationale.** A coach who marks the same syllabus architecture “complete” on Monday and “not yet” on Tuesday without a published corpus change has abandoned care for theatre.

**Manifestations:**

- Completion dispositions are deterministic under published inputs.
- Silent non-determinism, ambient “main branch as architecture,” and demo-only close rules are defects.
- Optional honesty checks (CLIC-06…CLIC-10) support, never replace, CLIC-01…CLIC-05.
- Repeatability failures void lawful affirmation even if a badge looks green.

---

### CLICO-06 — Preserve explainability and auditability

**Definition.** Ensure that every material completion judgement leaves a reconstructable, speakable trail: which constitutional layers were assessed, which authority paths were validated, which dependency relationships were validated, whether any bypasses or cycles were identified, and which findings were published.

**Tutor rationale.** A tutor who can only say “the layer check is done somewhere” is performing, not teaching. Speakable completion is care.

**Manifestations:**

- Audit records preserve constitutional references, not only technical job logs or CI annotations.
- Explainability obligations in `COMPLETION_EXPLAINABILITY.md` apply to all material completion judgements (CLICQ-01…CLICQ-05).
- Missing CLIC identity against criteria, missing layer refs, missing authority-path identity, missing dependency identity, missing bypass / cycle identity, or missing finding identity is a defect.
- Student / developer / auditor projections share one truth with different vocabulary.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| CLICO-01 conflicts with inventing unpublished layers so close can complete | Assessment honesty wins — refuse / defer / escalate |
| CLICO-02 conflicts with reordering or inventing layers for tidy close | Architectural layering wins |
| CLICO-03 conflicts with inventing authority or absorbing superior rights so hierarchy looks complete | Authority hierarchy wins |
| CLICO-04 conflicts with rewriting dependency direction or hiding bypasses / cycles for tidy close | Dependency integrity wins |
| CLICO-05 conflicts with ambient non-determinism or demo-only close rules | Repeatability wins |
| CLICO-06 conflicts with opaque complete badges | Explainability / auditability wins |
| Any CLICO conflicts with redefining layers / modifying authority hierarchy / reinterpreting meaning / amending specifications / creating authority | Non-legislative honesty wins — refuse the overclaim |

No supporting objective authorises violating CLICO-01.

These objectives specialise — and never weaken — Constitution / EIP integrity obligations, Programme VI–X authority preservation, MS001 CLIO duties, and MS002 CLILO duties for the *completion* horizon.

## 5. Non-Objectives

Constitutional layer integrity completion does **not** optimise for:

- redefining, reordering, inventing, or deleting constitutional layers via close;
- modifying authority hierarchy or inventing authority paths via close;
- inventing, softening, deleting, or rewriting inter-layer dependency direction, bypass findings, or cycle findings;
- reinterpreting Programme VI–X / EIP meaning during close;
- amending constitutional specifications under “completion” pretext;
- creating constitutional authority or soft-amending corpora via close;
- constitutional conformance disposition, fidelity scoring, or “assessed therefore conformant” theatre;
- verification success, compliance disposition, certification seals, or implementation-approval judgement;
- educational quality scoring, mastery grading, or exam-readiness judgement;
- CI throughput, flaky-scan suppression, or demo continuity as educational or constitutional success;
- inventing constitutional certainty when required assessment duties are incomplete;
- collapsing CLIC criteria into one mega-flag that owns meaning;
- making a particular language, framework, store, or CI vendor irreplaceable;
- using Twin / Adaptive / UI / analytics signals as substitutes for published completion criteria;
- treating scanner greens as optional commentary that silently becomes law;
- declaring layer redefinition, authority-hierarchy modification, meaning reinterpretation, specification amendment, or authority creation solely because completion was affirmed.

## 6. Closing Statement

> **A concern that becomes “layer assessment complete” by redefining layers, modifying authority hierarchy, reinterpreting meaning, amending specifications, or creating constitutional authority is a failed educational system.  
> A concern that confirms only lawful assessment conclusion — with architectural layering, authority hierarchy, dependency integrity, repeatability, and explainability intact — is doing its only completion job.**
