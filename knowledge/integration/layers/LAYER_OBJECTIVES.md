## 1. Purpose

An expert IFoA tutor does not optimise “folder tree looks stacked” or “we redrew the architecture overnight so the report looks clean.” The tutor optimises **honest layer integrity**: only architectural relationships that preserve published layering, authority hierarchy, dependency direction, isolation, and speakable readiness posture may be called intact — without rewriting those layers so a readiness report can pass.

These objectives bind every constitutional layer integrity assessment and every successor assessment machinery that claims constitutional layer integrity meaning.

---

## 2. Primary Objective

### CLIO-01 — Preserve constitutional layering

**Definition.** Ensure that every material layer integrity assessment determines — for named published corpus identities under recognised CL-01…CL-04 layers and CLI-01…CLI-07 categories — whether architectural layers remain in published superior → subordinate order (including lawful Programme VI→…→XI order within CL-03), or honestly reports violated / deferred / escalated when layering cannot be confirmed.

**Includes:**

- Applying the closed CL / CLI catalogues required by published law for the assessment scope.
- Binding every material assessment to identifiable published Constitution / EIP / Programme VI–XI specifications and subordinate workstream / milestone corpora.
- Detecting inverted, collapsed, or invented layer maps that contradict published CL-01…CL-04 order.
- Preferring lawful violated / deferred / escalated findings over redefining layers so readiness “passes.”
- Keeping layer integrity distinct from educational quality, mastery, readiness theatre, product success, or constitutional amendment.
- Preserving the Model’s posture: findings validate layer structure; they do not become law or rewrite layer maps.

**Excludes:**

- Treating green import graphs, folder-adjacency scans, Twin estimates, Adaptive scores, or UI ticks as constitutional layering.
- Soft-amending specifications, inventing unpublished layer maps, reordering layers, or privileging “how main is organised” to force intact status.
- Optimising for throughput, latency, or demo continuity as a substitute for layer integrity.
- Declaring “close enough” layering without documenting a corpus amendment.
- Treating CBI-06 boundary-layer findings or CDI layering rules as automatic substitutes for CLI assessment — they compose; they do not replace.

**Tutor rationale.** Professional exam preparation fails when software pretends inverted constitutional architecture is fine because integration needs a green path. Layer honesty is care; layer theatre is harm.

## 3. Supporting Objectives

### CLIO-02 — Preserve authority hierarchy

**Definition.** Ensure that every material layer assessment validates reconstructable authority flow from superior layers to subordinate layers — so subordinates never silently become foundational authority, and superior meaning is never authored from below.

**Tutor rationale.** A coach who treats a worksheet tip as the syllabus itself cannot be audited. Authority hierarchy is institutional memory.

**Manifestations:**

- Findings cite authority paths through CL-01 → CL-02 → CL-03 (and CL-04 as assurance, never authorship of upstream meaning).
- Authority flow under CLI-02 requires published reconstructability; missing path → deferred / escalated, never invent-in-place.
- Continuity (EIP-005) forbids erasing prior lawful layer assessment history to simplify the next report.
- Programme XI assurance findings never soft-elevate into Constitution / EIP / Programme VI–X authorship.
- Programme IX CT lineage may support reconstruction; CLI never treats CT records as a licence to reorder authority.

---

### CLIO-03 — Preserve dependency direction

**Definition.** Ensure that inter-layer dependencies respect published superior → subordinate / consumer orientation — so reverse authorship edges and unlawful upward authorship claims are impossible without a published amendment.

**Tutor rationale.** A tutor who lets tomorrow’s revision redefine yesterday’s syllabus destroys trust. Direction drift is educational amnesia.

**Manifestations:**

- Dependency-direction checks under CLI-03 compare published inter-layer orientations for the assessment scope.
- Intact findings confirm that subordinate layers may *consume* superior law and must not *author* it via layer prose.
- Violated / deferred / escalated findings block honest claims that reverse edges are “ready.”
- Dependency direction never authorises rewriting edges under CLI pretext.
- Preserving direction never authorises inventing a “temporary reverse edge” for demos.

---

### CLIO-04 — Preserve architectural isolation

**Definition.** Ensure that layer assessments detect and report absorption of one layer’s authorship by another — so separation of concerns is never silently treated as intact when layers collapse.

**Tutor rationale.** A tutor who lets exam tips rewrite the syllabus, or lets a scanner rewrite ownership maps, abandons clarity for convenience.

**Manifestations:**

- Isolation breaches are assessed under CLI-06 and reported honestly as absorption, bypass-assisted collapse, or violated.
- Published composition among sibling Programme XI assurance workstreams is lawful isolation-preserving composition — not a licence to merge horizons into one mega-authority.
- Forbidden actions in `LAYER_BOUNDARIES.md` are hard stops.
- Architectural isolation never authorises inventing a new layer outside CL-01…CL-04 without amendment.
- Cross-programme collaboration remains consumption / composition as published; it never becomes mutual authorship that collapses distinct layers.

---

### CLIO-05 — Preserve implementation readiness

**Definition.** Ensure that every material layer integrity assessment leaves a reconstructable, speakable trail that supports honest Programme XI integration and readiness judgements — which layers were assessed, which authority paths were validated, whether bypasses or cycles were detected, which findings were produced, and which assessment limits were preserved — so implementation readiness remains bound by intact layer structure without mistaking layer findings for educational readiness.

**Tutor rationale.** A tutor who cannot later say *why* an architecture was accepted cannot be trusted. Silent green scans destroy student and auditor trust. Readiness that ignores broken layering is readiness theatre.

**Manifestations:**

- Audit records preserve constitutional references, not only technical scanner logs.
- Explainability obligations in `LAYER_EXPLAINABILITY.md` apply to all material assessments.
- Missing CLI identity, missing corpus refs, missing layer / authority-path note, missing bypass / cycle note, or missing finding disposition is a defect.
- Intact findings may inform downstream readiness; they never themselves certify educational readiness, mastery, or product success.
- Violated / deferred / escalated findings block honest readiness claims that depend on the broken layer structure.
- Student / developer / auditor projections share one truth with different vocabulary.
- Implementation readiness never authorises publishing layer findings as new constitutional law.
- Repeatability: same published layers, same CLI criteria → same disposition, independently of language, framework, datastore, CI vendor, or preferred Runtime A shape.

## 4. Objective Interactions

| If … | Then … |
|------|--------|
| CLIO-01 conflicts with “helping” inverted layers look ready | Constitutional layering wins — violated / deferred / escalated |
| CLIO-02 conflicts with elevating Programme XI findings into foundational law | Authority hierarchy wins |
| CLIO-03 conflicts with reverse authorship so demos pass | Dependency direction wins |
| CLIO-04 conflicts with collapsing layers so integration looks simple | Architectural isolation wins |
| CLIO-05 conflicts with opaque “trust us” layer badges or false readiness | Implementation readiness honesty wins |

No supporting objective authorises violating CLIO-01.

These objectives specialise — and never weaken — Constitution / EIP integrity obligations and Programme VI–XI authority preservation for the layer integrity horizon.

## 5. Non-Objectives

Constitutional layer integrity does **not** optimise for:

- educational quality scoring, mastery grading, or exam-readiness judgement;
- CI throughput, flaky-test suppression, or coverage theatre as educational success;
- inventing constitutional certainty when specifications or layer maps are incomplete;
- collapsing CLI categories into one mega-check that owns meaning;
- making a particular language, framework, store, or CI vendor irreplaceable;
- using Twin / Adaptive / UI / analytics / import-graph / folder-adjacency signals as substitutes for published constitutional layering;
- creating, reordering, inventing, or deleting constitutional layers so reports look tidy;
- replacing Programme IX CT lineage preservation, Programme XI / WS1–WS4 assurance horizons, or Programme IX–X evaluative / execution horizons;
- treating documentation as optional commentary on whatever code already shipped.
