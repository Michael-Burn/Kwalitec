## 1. Purpose

A lifecycle that silently becomes a second constitution — rewriting layers so stages “complete,” softening authority hierarchy in “findings,” licensing a preferred documentation topology under a published badge, inventing layer maps to force CLIL-07, treating a preferred implementation as the new standard, mutating corpora mid-lifecycle, or freezing a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional layer integrity lifecycle coordination** (Programme XI / WS5 / MS002) and **constitutional authorship / educational judgement / layer redefinition / authority-hierarchy mutation / meaning reinterpretation / specification amendment / authority creation** (Constitution / EIP / Programmes VI–X / WS1–WS4 / WS5 / MS001 / permitted writers).

---

## 2. Boundary Principles

1. **Coordinate, do not legislate.** The lifecycle organises layer assessment; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as layer map” are hard stops as standards.
3. **Published stages only.** Unpublished CLIL customs are unlawful.
4. **Published layer categories only.** Stages apply CLI-01…CLI-07 and CL-01…CL-04 only.
5. **Published layers only.** Lifecycles without identifiable published layer identities are theatre.
6. **Exactly as published.** Successful progress never rewrites specification meaning, layers, or authority hierarchy.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to publication.
9. **Published ≠ quality.** Lifecycle publication never grades learning, mastery, readiness, or product success.
10. **Published ≠ rewritten layers.** The lifecycle never mutates layers so findings look intact.
11. **Published ≠ new authority.** The lifecycle never elevates Programme XI into foundational law by coordinating others.
12. **No reinterpretation.** Programme VI–X meanings, EIP claim classes, and CLI criteria survive coordination intact.
13. **No authority substitution.** A published finding never replaces the corpus for the next judgement.
14. **No layer mutation.** Coordination never redefines, invents, reorders, or deletes constitutional layers.
15. **No hierarchy mutation.** Coordination never modifies published authority hierarchy.
16. **No bypass.** Product urgency never waives constitutional lifecycle requirements.
17. **Repeatability / consistency.** Race-dependent or private stage shortcuts are defects.
18. **Explain the stop.** Students, developers, and auditors should hear when the lifecycle must refuse progress or publication.
19. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or authority creation via lifecycle publication.
20. **Layering honesty.** Lower horizons never absorb superior authority via lifecycle prose.

## 3. What the Lifecycle May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate layer assessment** | Organise activities through CLIL-01…CLIL-08 |
| **Validate architectural composition** | Apply published CLI / CLIR / CL law to discovered published layers |
| **Validate layer ordering** | Confirm CL-01→CL-02→CL-03→CL-04 and lawful VI→…→XI order at CLIL-03 |
| **Validate authority flow** | Confirm reconstructable superior → subordinate paths at CLIL-04 |
| **Validate dependency direction** | Confirm lawful inter-layer orientation at CLIL-05 |
| **Validate absence of bypasses and cycles** | Detect and report skipped superiors and authority-circularising closed paths at CLIL-06 |
| **Identify architectural findings** | Emit intact / violated / deferred / escalated under published criteria |
| **Publish assessment findings** | Communicate findings and records under published honesty rules |
| **Consume constitutional specifications** | Use published Constitution / EIP / Programme VI–XI corpora as assessment standards |
| **Preserve established traceability in records** | Carry established CT-01…CT-07 relationships into assessment records; never invent them |
| **Apply layer integrity categories** | Across stages, apply published CLI-01…CLI-07 and CL-01…CL-04 only |
| **Refuse unlawful progress** | Prefer honest refuse / defer / escalate / violated over improvisation |
| **Remain repeatable and consistent** | Same published inputs → same stage outcomes and dispositions |
| **Remain implementation-neutral** | Honour lifecycle law across lawful equivalent stacks |
| **Support governance integrity** | Strengthen corpus-layer honesty without becoming educational readiness or constitutional authority |
| **Explain lifecycle progress** | Answer layers / authority paths / dependency paths / bypasses / cycles / findings / intact limits without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **coordinate layer assessment**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CLI or CLIL types, invent CT links, author runtime behaviour, judge educational quality, create constitutional authority, redefine layers, modify authority hierarchy, reinterpret meaning, or amend specifications under coordination pretext.

## 4. What the Lifecycle Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Redefine constitutional layers** | Layers are published corpus facts under CL-01…CL-04, not lifecycle outputs | Report layer structure as found; refuse redefinition theatre |
| **Modify authority hierarchy** | Superior → subordinate authority is published law | Report authority paths as found; refuse hierarchy mutation |
| **Reinterpret constitutional meaning** | Programme VI–X and EIP own meaning | Assess against published meaning; never redefine it |
| **Amend constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark violated / refuse |
| **Create constitutional authority** | Published corpora alone own constitutional meaning | Never elevate findings or stages into foundational law |
| **Invent layer maps** | Discovery organises published layers | Refuse-discover when layers are missing |
| **Invent authority or dependency paths** | Fidelity requires real published identities | Refuse-validate when paths cannot be reconstructed |
| **Hide bypasses or cycles** | Bypass / cycle honesty | Report violated; never invent temporary exceptions |
| **Absorb superior layers** | Layering honesty | Report layer violations; never soft-absorb superiors |
| **Invent layer integrity categories** | CLI catalogue is closed under WS5 / MS001 | Apply CLI-01…CLI-07 only |
| **Invent lifecycle stages** | CLIL catalogue is closed under this corpus | Apply CLIL-01…CLIL-08 only |
| **Invent traceability** | CT owns lawful lineage | Preserve established relationships in records; refuse invented links |
| **Bypass lifecycle requirements** | Requirements are educational care, not optional polish | Prefer understatement / refuse over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Coordinate assessment, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CLIL stage is a quality rubric | Keep coordination speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in lifecycle machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via stages |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Assess against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface integrity findings, not new tips |
| **Treat Twin / Adaptive / UI / CI / scanners as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / scanner greens as constitutional integrity or publication** | Operational proxies are not lifecycle law | Cite published corpora, CLI types, CL layers, and CLIL stages |
| **Become irreplaceable by coordination topology** | Replaceability | Keep lifecycle law implementation-independent |

| **Replace MS001 layer meaning** | CLI owns validation meaning | Sequence assessments; never rewrite CLI / CL criteria |
| **Replace Programme XI WS1–WS4** | CDI / CCI / CBI / CVI own their integrity horizons | Compose with those horizons; never absorb them |

## 6. Boundary Checks (Pre-Publication)

Before a material constitutional layer integrity lifecycle is treated as lawfully published, coordination requires affirmative answers:

| Check | Question |
|-------|----------|
| **CLILB-01 Specification / corpus identity** | Are assessment standards published Constitution / EIP / Programme VI–XI corpora (not unpublished customs)? |
| **CLILB-02 Stage class** | Are required CLIL-01…CLIL-08 stages being applied (not unpublished customs)? |
| **CLILB-03 Integrity class** | Are required CLI-01…CLI-07 categories applied (not unpublished customs)? |
| **CLILB-04 Layer class** | Are assessed subjects classified under CL-01…CL-04 as required? |
| **CLILB-05 Layer identity** | Which named published layers were assessed? |
| **CLILB-06 Authority-path identity** | Which authority paths were validated (none invented)? |
| **CLILB-07 Dependency-path identity** | Which dependency paths were validated (none reverse-authored or invented)? |
| **CLILB-08 Bypass / cycle status** | Were any bypasses or cycles identified and honestly reported? |
| **CLILB-09 Finding binding** | Which lifecycle stages produced the layer integrity findings (especially CLIL-03…CLIL-07)? |
| **CLILB-10 Record identity** | Which assessment records were preserved? |
| **CLILB-11 Non-legislation** | Does the lifecycle avoid creating or amending constitutional specifications? |
| **CLILB-12 Non-reinterpretation** | Does the lifecycle avoid redefining Programme VI–X educational / constitutional meaning? |
| **CLILB-13 Non-mutation** | Were layers and authority hierarchy left unmodified by lifecycle coordination? |
| **CLILB-14 Non-authority-creation** | Does the lifecycle avoid creating constitutional authority or treating findings as new law? |
| **CLILB-15 Non-substitution** | Does the lifecycle avoid treating the implementation or lifecycle machinery as the next constitutional standard? |
| **CLILB-16 Non-MS001-replacement** | Is publication framed as assessment coordination complete — not a rewrite of CLI / CL meaning? |
| **CLILB-17 Neutrality** | Does the lifecycle avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CLILB-18 Publication ≠ quality** | Is the outcome framed as lifecycle coordination / layer integrity — not educational quality? |
| **CLILB-19 Repeatability / audit** | Are stage outcomes reproducible; do explainability records preserve layers, authority paths, dependency paths, bypasses, cycles, findings, and intact limits? |

Any failed check → refuse-publish / deferred / escalated / violated as published. Do not “best-effort” invent lifecycle law, invent layers, soft-amend specifications, redefine layers, modify authority hierarchy, create constitutional authority, or replace constitutional authority in situ.
