## 1. Purpose

Assessment that silently becomes a second constitution — rewriting layers in “findings,” inventing preferred architecture maps, elevating Programme XI into an authorship layer, or treating a folder diagram as the new standard — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional layer integrity** (Programme XI / WS5 / MS001) and **constitutional authorship / educational judgement / layer mutation** (Constitution / EIP / Programmes VI–XI / permitted writers).

---

## 2. Boundary Principles

1. **Validate, do not legislate.** Layer integrity measures architectural layering; it does not create law.
2. **Published layers only.** Unpublished architecture diagrams and “main as layer map” are hard stops as standards.
3. **Published layer categories only.** Unpublished CLI / CL customs are unlawful.
4. **Named corpus identities only.** Assessments without identifiable constitutional subjects are theatre.
5. **Exactly as published.** Successful intact status never rewrites specification meaning or layer maps.
6. **Authority first.** Published corpora remain the sole constitutional standard.
7. **No layer mutation.** Findings never create, redefine, reorder, invent, delete, or soft-amend constitutional layers.
8. **No authority-flow rewrite.** Authority hierarchy remains with owning corpora as published.
9. **No new authority.** Programme XI never becomes foundational law by validating others.
10. **No specification amendment.** Soft-amendment via findings destroys integrity.
11. **No reinterpretation.** Programme VI–X meanings and EIP claim classes survive assessment intact.
12. **Bypass / cycle honesty.** Violations are reported, not “fixed” in situ by redefinition.
13. **Intact ≠ quality.** Layer integrity never grades learning, mastery, readiness, or product success.
14. **Implementation independence.** No stack, vendor, or scanner becomes law by proximity.
15. **No bypass of integrity requirements.** Product urgency never waives constitutional layer integrity requirements.
16. **Repeatability.** Race-dependent dispositions are a defect.
17. **Explain the stop.** Students, developers, and auditors should hear when assessment must refuse intact status.
18. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power via findings.

## 3. What Layer Integrity May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Analyse architectural layers** | Inspect published corpus identities and recognised CL-01…CL-04 layers under CLI-01…CLI-07 |
| **Validate constitutional layer ordering** | Confirm CL-01→CL-02→CL-03→CL-04 and lawful VI→…→XI order under CLI-01 / CLIR-01 |
| **Validate authority flow** | Confirm reconstructable superior → subordinate paths under CLI-02 / CLIR-02 |
| **Validate dependency direction between layers** | Confirm lawful orientation under CLI-03 / CLIR-03 |
| **Validate absence of layer bypasses** | Detect and report skipped required superiors under CLI-04 / CLIR-04 |
| **Validate absence of layer cycles** | Detect and report authority-circularising closed paths under CLI-05 / CLIR-05 |
| **Validate architectural isolation** | Confirm separation of concerns under CLI-06 / CLIR-06 |
| **Identify layer integrity findings** | Name inversions, reverse edges, bypasses, cycles, or absorption risks |
| **Report architectural observations** | Emit intact / violated / deferred / escalated under published criteria |
| **Preserve audit records** | Keep reconstructable trails under CLI-07 |
| **Refuse unlawful intact claims** | Prefer honest violated / deferred / escalated over improvisation |
| **Compose required categories** | Apply published CLI / CL conjunctions without collapsing failed checks |
| **Remain repeatable and neutral** | Same published inputs → same disposition; no stack privilege |
| **Explain layer integrity** | Answer layers / authority paths / bypasses / cycles / findings without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when published layering itself must change |

These actions **validate layer consistency**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CLI / CL types, amend programme law, redefine layers, modify authority hierarchy, or judge educational quality.

## 6. Boundary Checks (Pre-Finding)

Before material constitutional layer integrity is treated as established, assessment requires affirmative answers:

| Check | Question |
|-------|----------|
| **CLIB-01 Corpus identity** | Are assessed subjects published Constitution / EIP / Programme VI–XI corpus identities (not unpublished diagrams)? |
| **CLIB-02 Integrity class** | Are required CLI-01…CLI-07 categories being applied (not unpublished customs)? |
| **CLIB-03 Layer class** | Are assessed subjects classified under CL-01…CL-04 as required? |
| **CLIB-04 Layer identity** | Which named published layers are under assessment? |
| **CLIB-05 Authority path** | Which reconstructable superior → subordinate paths were validated? |
| **CLIB-06 Ordering** | Does layer order remain CL-01→CL-02→CL-03→CL-04 (and lawful VI→…→XI within CL-03)? |
| **CLIB-07 Dependency direction** | Do inter-layer edges respect superior → subordinate / consumer orientation? |
| **CLIB-08 Bypass** | Have skipped required superior layers been identified and reported? |
| **CLIB-09 Cycle** | Have authority-circularising closed paths been identified and reported? |
| **CLIB-10 Non-legislation** | Does the assessment avoid creating constitutional authority or amending specifications? |
| **CLIB-11 Non-mutation** | Does the assessment avoid redefining, reordering, inventing, or deleting constitutional layers? |
| **CLIB-12 Non-reinterpretation** | Does the assessment avoid redefining Programme VI–X / EIP meaning? |
| **CLIB-13 Non-substitution** | Does the assessment avoid treating Programme XI findings or any assessed corpus as the next constitutional standard? |
| **CLIB-14 Neutrality / intact ≠ quality** | Does the assessment avoid stack privilege and quality / student-readiness conflation? |
| **CLIB-15 Repeatability / audit** | Is disposition reproducible; will CLI-07 / explainability records preserve layers, authority paths, bypasses, cycles, findings, and assessment limits? |

Any failed check → violated / deferred / escalated. Do not “best-effort” invent layer law, redefine layers, or soft-amend specifications in situ.
