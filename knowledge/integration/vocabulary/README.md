## Purpose

This folder defines **the permanent constitutional mechanism for validating semantic consistency** throughout the constitutional corpus.

It answers *what vocabulary integrity must optimise*, *which recognised vocabulary term categories and validation rules exist*, *what vocabulary integrity assessment may and must never do*, and *how vocabulary integrity is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, redefining constitutional terminology, reinterpreting constitutional meaning, amending constitutional specifications, creating constitutional authority, or elevating vocabulary machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, databases, or application services.

> **Constitutional Vocabulary Integrity validates semantic consistency across the published corpus.  
> It never becomes constitutional law itself.  
> It never redefines terminology, reinterprets meaning, amends specifications, or creates constitutional authority.**

## Architectural requirement

Constitutional Vocabulary Integrity validates **semantic consistency of constitutional terminology**.

| Lawful | Unlawful |
|--------|----------|
| Analyse constitutional terminology | Redefine constitutional terminology |
| Validate canonical term recognition | Alter constitutional meaning |
| Validate semantic consistency | Amend constitutional specifications |
| Validate terminology reuse honesty | Create constitutional authority |
| Validate ambiguity avoidance | Reinterpret constitutional meaning |
| Validate definition stability | Elevate spell-checkers or CI into constitutional producers |
| Produce vocabulary integrity findings | Treat findings as soft redefinitions of published terms |
| Preserve explainability and auditability | Narrate intact status as educational quality |
| Explain terms / definitions / inconsistencies / findings | Invent unpublished “preferred glossaries” as law |

**Constitutional Vocabulary Integrity validates the vocabulary corpus. It never authors terminology or rewrites published meanings.**

## How to use this corpus

1. Confirm the published Constitution / EIP and Programme VI–XI corpora in scope are identifiable — refuse vocabulary theatre over unpublished glossaries.
2. Read `CONSTITUTIONAL_VOCABULARY_INTEGRITY_MODEL.md` for stack position and integrity rules.
3. Optimise under `VOCABULARY_OBJECTIVES.md`.
4. Classify and validate under `VOCABULARY_TERMS.md` (CVT-01…CVT-10 and CVI-01…CVI-07 only).
5. Enforce hard stops under `VOCABULARY_BOUNDARIES.md`.
6. Require explainability contracts from `VOCABULARY_EXPLAINABILITY.md` before student-, developer-, or auditor-facing vocabulary narration.
7. Do not implement vocabulary machinery that contradicts this corpus without amending it first.
8. When semantic inconsistencies or ambiguous reuse are found, report findings and propose upstream amendment — never redefine terms in situ.
