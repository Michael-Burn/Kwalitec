## 1. Purpose

A lifecycle that silently becomes a second constitution — rewriting edges so stages “complete,” inventing authority chains in “findings,” licensing a preferred documentation topology under a published badge, inventing relationships to force CDIL-06, treating a preferred implementation as the new standard, mutating corpora mid-lifecycle, or freezing a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional dependency integrity lifecycle coordination** (Programme XI / WS1 / MS002) and **constitutional authorship / educational judgement / dependency mutation / authority creation / meaning reinterpretation / specification amendment** (Constitution / EIP / Programmes VI–X / WS1 / MS001 / permitted writers).

---

## 2. Boundary Principles

1. **Coordinate, do not legislate.** The lifecycle organises dependency assessment; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as graph” are hard stops as standards.
3. **Published stages only.** Unpublished CDIL customs are unlawful.
4. **Published dependency categories only.** Stages apply CDI-01…CDI-07 only.
5. **Published relationships only.** Lifecycles without identifiable published relationships are theatre.
6. **Exactly as published.** Successful progress never rewrites specification meaning or edge orientation.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to publication.
9. **Published ≠ quality.** Lifecycle publication never grades learning, mastery, readiness, or product success.
10. **Published ≠ rewritten graph.** The lifecycle never mutates dependencies so findings look intact.
11. **Published ≠ new authority.** The lifecycle never elevates Programme XI into foundational law by coordinating others.
12. **No reinterpretation.** Programme VI–X meanings, EIP claim classes, and CDI criteria survive coordination intact.
13. **No authority substitution.** A published finding never replaces the corpus for the next judgement.
14. **No dependency mutation.** Coordination never creates, deletes, reverses, or soft-amends constitutional relationships.
15. **No bypass.** Product urgency never waives constitutional lifecycle requirements.
16. **Repeatability / consistency.** Race-dependent or private stage shortcuts are defects.
17. **Explain the stop.** Students, developers, and auditors should hear when the lifecycle must refuse progress or publication.
18. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or authority creation via lifecycle publication.
19. **Acyclicity honesty.** Cycles that confuse authority are reported, not “fixed” in situ.
20. **Layering honesty.** Lower horizons never absorb superior authority via lifecycle prose.

## 3. What the Lifecycle May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate dependency assessment** | Organise activities through CDIL-01…CDIL-07 |
| **Validate dependency relationships** | Apply published CDI / CDIR law to discovered published relationships |
| **Validate authority chains** | Confirm reconstructable superior → subordinate authority paths at CDIL-03 |
| **Evaluate dependency direction** | Confirm lawful orientation under published rules |
| **Detect circular dependencies** | Report cycle status at CDIL-04 without mutating edges |
| **Validate constitutional layering** | Confirm published programme / workstream order at CDIL-05 |
| **Identify integrity findings** | Emit intact / violated / deferred / escalated under published criteria |
| **Publish assessment findings** | Communicate findings and records under published honesty rules |
| **Consume constitutional specifications** | Use published Constitution / EIP / Programme VI–X corpora as assessment standards |
| **Preserve established traceability in records** | Carry established CT-01…CT-07 relationships into assessment records; never invent them |
| **Apply dependency categories** | Across stages, apply published CDI-01…CDI-07 only |
| **Refuse unlawful progress** | Prefer honest refuse / defer / escalate / violated over improvisation |
| **Remain repeatable and consistent** | Same published inputs → same stage outcomes and dispositions |
| **Remain implementation-neutral** | Honour lifecycle law across lawful equivalent stacks |
| **Support readiness honesty** | Strengthen corpus-structure honesty without becoming educational readiness or constitutional authority |
| **Explain lifecycle progress** | Answer dependencies / authority chains / cycles / findings / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **coordinate dependency assessment**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CDI or CDIL types, invent CT links, author runtime behaviour, judge educational quality, create constitutional authority, reinterpret meaning, amend specifications, or modify dependencies under coordination pretext.

## 4. What the Lifecycle Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Create constitutional authority** | Published corpora alone own constitutional meaning | Cite published law only; refuse unpublished standards; never elevate lifecycle progress into authority |
| **Alter dependency relationships** | Edges are published corpus facts, not lifecycle outputs | Report structure as found; refuse mutation theatre |
| **Reinterpret constitutional meaning** | Programme VI–X and EIP own meaning | Assess against published meaning; never redefine it |
| **Amend constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark violated / refuse |
| **Invent dependency relationships** | Discovery organises published edges | Refuse-discover when relationships are missing |
| **Invent authority chains** | Authority traceability requires real superior links | Refuse-validate when chains cannot be reconstructed |
| **Erase cycles in situ** | Acyclicity honesty | Report cycle-detected; never rewrite the graph |
| **Absorb superior layers** | Layering honesty | Report layer violations; never soft-absorb superiors |
| **Invent dependency categories** | CDI catalogue is closed under WS1 / MS001 | Apply CDI-01…CDI-07 only |
| **Invent lifecycle stages** | CDIL catalogue is closed under this corpus | Apply CDIL-01…CDIL-07 only |
| **Invent traceability** | CT owns lawful lineage | Preserve established relationships in records; refuse invented links |
| **Bypass lifecycle requirements** | Requirements are educational care, not optional polish | Prefer understatement / refuse over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Coordinate assessment, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CDIL stage is a quality rubric | Keep coordination speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in lifecycle machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via stages |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Assess against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface integrity findings, not new tips |
| **Treat Twin / Adaptive / UI / CI / scanners as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / scanner greens as constitutional integrity or publication** | Operational proxies are not lifecycle law | Cite published corpora, CDI types, and CDIL stages |
| **Become irreplaceable by coordination topology** | Replaceability | Keep lifecycle law implementation-independent |
| **Freeze stack authority via publication** | Neutrality / authority preservation | Publish findings; never make the stack the next standard |
| **Replace MS001 dependency meaning** | CDI owns validation meaning | Sequence assessments; never rewrite CDI criteria |
| **Replace Programme IX CT** | CT owns lineage | Compose with CT; never treat “linked” as “dependency intact forever” |

## 6. Boundary Checks (Pre-Publication)

Before a material constitutional dependency integrity lifecycle is treated as lawfully published, coordination requires affirmative answers:

| Check | Question |
|-------|----------|
| **CDILB-01 Specification / corpus identity** | Are assessment standards published Constitution / EIP / Programme VI–X corpora (not unpublished customs)? |
| **CDILB-02 Stage class** | Are required CDIL-01…CDIL-07 stages being applied (not unpublished customs)? |
| **CDILB-03 Dependency class** | Are required CDI-01…CDI-07 categories applied (not unpublished customs)? |
| **CDILB-04 Relationship identity** | Which named dependency relationships were assessed? |
| **CDILB-05 Authority-chain identity** | Which authority chains were validated (none invented)? |
| **CDILB-06 Cycle status** | Were any cycles detected (none hidden; none “fixed” by mutation)? |
| **CDILB-07 Layering status** | Was published constitutional layering confirmed or honestly reported violated? |
| **CDILB-08 Finding binding** | Which lifecycle stages produced the dependency integrity findings (especially CDIL-03…CDIL-06)? |
| **CDILB-09 Record identity** | Which assessment records were preserved? |
| **CDILB-10 Non-legislation** | Does the lifecycle avoid creating or amending constitutional specifications? |
| **CDILB-11 Non-reinterpretation** | Does the lifecycle avoid redefining Programme VI–X educational / constitutional meaning? |
| **CDILB-12 Non-mutation** | Were dependency relationships left unmodified by lifecycle coordination? |
| **CDILB-13 Non-authority-creation** | Does the lifecycle avoid creating constitutional authority or treating findings as new law? |
| **CDILB-14 Non-substitution** | Does the lifecycle avoid treating the implementation or lifecycle machinery as the next constitutional standard? |
| **CDILB-15 Non-MS001-replacement** | Is publication framed as assessment coordination complete — not a rewrite of CDI meaning? |
| **CDILB-16 Neutrality** | Does the lifecycle avoid privileging a language, framework, protocol, or CI vendor as law? |
| **CDILB-17 Publication ≠ quality** | Is the outcome framed as lifecycle coordination / structure integrity — not educational quality? |
| **CDILB-18 Repeatability / audit** | Are stage outcomes reproducible; do explainability records preserve dependencies, authority chains, cycles, findings, and boundaries? |

Any failed check → refuse-publish / deferred / escalated / violated as published. Do not “best-effort” invent lifecycle law, invent relationships, soft-amend specifications, mutate edges, create constitutional authority, or replace constitutional authority in situ.
