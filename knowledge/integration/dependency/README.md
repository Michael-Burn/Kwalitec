## Purpose

This folder defines **the permanent constitutional mechanism for validating lawful dependency relationships** throughout the constitutional corpus.

It answers *what dependency integrity must optimise*, *which recognised dependency categories and validation rules exist*, *what dependency integrity assessment may and must never do*, and *how dependency integrity is constitutionally explained* — without implementing Runtime A, testing frameworks, CI/CD, creating constitutional authority, modifying constitutional meaning, introducing new constitutional law, amending constitutional specifications, reinterpreting constitutional law, modifying constitutional dependencies, or elevating dependency machinery into a constitutional authority.

It does **not** implement Runtime A, test runners, CI/CD pipelines, GitHub Actions, Python, Flask, SQLAlchemy, REST, OpenAPI, infrastructure, databases, or application services.

> **Constitutional Dependency Integrity validates lawful relationships across the published corpus.  
> It never becomes constitutional law itself.  
> It never creates authority, reinterprets meaning, amends specifications, or rewrites dependencies.**

## Architectural requirement

Constitutional Dependency Integrity validates **lawful dependency relationships**.

| Lawful | Unlawful |
|--------|----------|
| Analyse published dependencies | Alter constitutional relationships |
| Validate direction and authority chains | Establish new authority |
| Detect circular dependencies | Redefine constitutional meaning |
| Preserve constitutional layering | Amend constitutional specifications |
| Produce dependency integrity findings | Modify / invent / reverse / delete dependencies |
| Preserve explainability and auditability | Become constitutional authority |
| Explain dependency / authority / cycles / findings / boundaries | Elevate scanners or CI into constitutional producers |

**Constitutional Dependency Integrity validates the corpus graph. It never authors the corpus or rewrites its edges.**
