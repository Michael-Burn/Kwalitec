## 1. Purpose

Dependency without a closed catalogue invents law by proximity: whichever citation, folder adjacency, or pipeline annotation happens to exist becomes the tutor’s “proof the constitution is coherent.”

This catalogue names the only lawful constitutional dependency categories an assessment may apply — and binds each category to purpose, scope, inputs, outputs, validation rules, and permitted / prohibited relationships across programmes, workstreams, and milestones.

---

## 2. Catalogue Overview

| ID | Dependency category | Constitutional purpose (short) | Primary inputs | Primary outputs |
|----|---------------------|--------------------------------|----------------|-----------------|
| **CDI-01** | Foundational Authority Dependency | Validate subordination to Constitution / EIP | Constitution / EIP identities + subordinate corpus identities | Authority-dependency findings |
| **CDI-02** | Programme Layer Dependency | Validate lawful Programme VI→X layering edges | Programme corpus identities + published stack order | Layer-dependency findings |
| **CDI-03** | Workstream Dependency | Validate workstream subordination within a programme | Workstream / milestone identities + parent programme models | Workstream-dependency findings |
| **CDI-04** | Milestone Composition Dependency | Validate milestone succession / composition within a workstream | Milestone identities + published predecessor / composition declarations | Milestone-dependency findings |
| **CDI-05** | Cross-Horizon Consumption Dependency | Validate lawful consumption across horizons without authorship reversal | Consumer + consumed corpus identities + published consumption rights | Consumption-dependency findings |
| **CDI-06** | Cycle & Direction Integrity | Detect cycles and validate dependency direction | Named edges + declared orientation | Cycle / direction findings |
| **CDI-07** | Assessment Integrity Dependency | Preserve reconstructable dependency assessment records | Assessment records + related corpus / edge identities | Assessment-lineage / integrity records |

Material assessments must map to one or more of these categories as published law requires. Cross-cutting situations may bind multiple CDI types; none may invent a type outside this catalogue.

**Relation to CT / CC / CV / CCM / CRT:** Those catalogues remain defined solely by their owners. CDI categories *validate constitutional corpus dependency structure*; they do not replace lineage preservation, fidelity evaluation, verification, compliance determination, or certification recognition.

**Relation to educational quality:** No CDI type judges whether learning was good, whether a tip was wise, or whether the student is ready. Intact ≠ quality. Intact ≠ conformant. Intact ≠ certified.

## 3. Global Validation Rules

These rules apply to every CDI category:

| Rule ID | Validation rule |
|---------|-----------------|
| **CDIR-01 Direction** | Every material edge must declare (or inherit from published law) a lawful orientation: superior / authority → subordinate / consumer. Reverse orientation as authorship is a defect. |
| **CDIR-02 Authority chain** | Every material edge must be reconstructable to a published authority chain reaching Constitution / EIP (directly or through published programme intermediates). Orphan edges are defects. |
| **CDIR-03 Acyclicity** | No closed path may invert or circularise constitutional authority among the assessed corpus identities. Detected cycles that confuse authority → violated (or deferred / escalated when incomplete identity prevents confirmation). |
| **CDIR-04 Layering** | Edges must honour Constitution / EIP → VI → VII → VIII → IX → X → XI and lawful workstream / milestone subordination. Layer inversion is a defect. |
| **CDIR-05 Catalogue closure** | Only CDI-01…CDI-07 may classify constitutional dependency integrity assessments. Unpublished customs are unlawful. |
| **CDIR-06 Non-mutation** | Validation never creates, deletes, reverses, or soft-amends constitutional dependencies or specifications. Findings report; they do not rewrite. |
| **CDIR-07 Neutrality** | Validation criteria speak to constitutional identities and published relationships — never “must use Flask / SQLAlchemy / npm / GitHub dependency graphs.” |
| **CDIR-08 Repeatability** | Same published identities, same edges, same CDI criteria → same disposition. Race-dependent outcomes are defects. |
| **CDIR-09 Peer composition honesty** | Sibling / peer composition is lawful only when published as composition — never as mutual authorship that collapses distinct horizons. |
| **CDIR-10 Finding honesty** | Dispositions are intact / violated / deferred / escalated only. “Close enough,” “temporary cycle,” or “demo exception” are not constitutional dispositions. |

## 4. CDI-01 — Foundational Authority Dependency

### Constitutional purpose

Validate lawful **subordination of programme and workstream corpora to the Educational Constitution and EIP** — so no subordinate corpus silently becomes foundational authority.

### Constitutional scope

Published Constitution / EIP identities and all Programme VI–XI corpora that claim constitutional meaning. Does **not** create new foundational documents or elevate architecture / Version 2 preference docs to Constitution / EIP status.

### Constitutional inputs

- Constitution / EIP specification identities.
- Named subordinate corpus identities claiming constitutional meaning.
- Published CDIO-01 / CDIO-02 / CDIO-03 expectations.

### Constitutional outputs

- Foundational-authority dependency finding under CDI-01.
- Named authority-chain note to Constitution / EIP.
- Audit-speakable confirmation that foundational authority was not inverted (true/false).

### Validation rules (category-specific)

- Every material constitutional corpus under Programme VI–XI must reconstruct to Constitution / EIP authority (directly or via published intermediates).
- Edges that treat architecture, product roadmap, or Runtime A docs as Constitution / EIP peers are defects when used as foundational law.
- Findings may note missing foundational citation; they may not invent a foundational amendment.

### Permitted relationships

- Relate a Programme VI coach model to EIP-002 / Constitution authorities it cites as superior.
- Relate a Programme IX conformance model to Constitution / EIP authorities it cites as superior.
- Record lawful subordination of Programme XI dependency corpora to Constitution / EIP.

### Prohibited relationships

- Treat a Programme XI finding as a Constitution / EIP amendment.
- Soft-elevate Version 2 / Adaptive / Twin design docs to foundational authority via dependency prose.
- Invent unpublished foundational customs as peer law.
- Use CDI-01 to create or modify constitutional law.

## 5. CDI-02 — Programme Layer Dependency

### Constitutional purpose

Validate lawful **edges among Programme VI–X (and XI as validator)** according to published constitutional layering — so meaning, orchestration, runtime, governance, and execution horizons remain ordered.

### Constitutional scope

Programme-level corpus identities and their published stack / subordination declarations. Does **not** merge programmes or rewrite programme meanings by “linking harder.”

### Constitutional inputs

- Programme VI–XI corpus identities and published layer order.
- Declared programme-to-programme dependency / subordination / consumption relationships.
- Published CDIO-01 / CDIO-03 expectations.

### Constitutional outputs

- Programme-layer dependency finding under CDI-02.
- Named layer orientation (superior programme → subordinate / consuming programme).
- Cycle / inversion notes when CDIR-03 / CDIR-04 are implicated.

### Validation rules (category-specific)

- Lawful order: Constitution / EIP → VI → VII → VIII → IX → X → XI (validator; never author of upstream meaning).
- A lower programme may *consume* published superior law; it may not *author* or *reinterpret* that law via dependency.
- Programme XI may validate dependencies across VI–X; it may not rewrite VI–X meanings to make edges look intact.

### Permitted relationships

- Programme VIII runtime corpora subordinate to Programme VII orchestration and Programme VI meaning as published.
- Programme IX governance corpora subordinate to Programmes VI–VIII as published.
- Programme X execution corpora subordinate to Programmes VI–IX as published.
- Programme XI dependency integrity consumes VI–X identities as assessment subjects.

### Prohibited relationships

- Programme VIII authoring Programme VI educational meaning through reverse citation.
- Programme IX conformance findings becoming Programme VI law.
- Programme X execution outcomes becoming Programme IX certification law via circular “completion” edges.
- Collapsing VI–X into one mega-programme via dependency theatre.

## 6. CDI-03 — Workstream Dependency

### Constitutional purpose

Validate lawful **workstream subordination within a programme** — so workstreams remain reconstructably under their parent programme models and do not absorb sibling workstream authority unlawfully.

### Constitutional scope

Workstream folder / model identities within Programmes VI–XI and their published parent programme authorities. Does **not** invent workstreams or transfer ownership among workstreams.

### Constitutional inputs

- Parent programme model identities.
- Workstream corpus identities and published subordination declarations.
- Published CDIO-02 / CDIO-03 expectations.

### Constitutional outputs

- Workstream-dependency finding under CDI-03.
- Parent → workstream authority-chain note.
- Sibling-composition notes only when published.

### Validation rules (category-specific)

- Every material workstream corpus must cite (or inherit) its parent programme authority.
- Sibling workstreams may compose as published; they may not silently become each other’s superior.
- Workstream edges that bypass parent programme models to claim cross-programme authorship are defects unless a published CDI-05 consumption relationship authorises consumption (not authorship).

### Permitted relationships

- Programme IX WS4 certification corpora subordinate to Programme IX certification / compliance predecessors as published.
- Programme X WS3 decision corpora subordinate to Programme X WS1 / WS2 preparation and execution as published.
- Programme XI WS1 dependency corpora subordinate to Programme XI Integration & Readiness posture (this Model).

### Prohibited relationships

- A workstream amending its parent programme meaning via dependency findings.
- Silent absorption of another workstream’s catalogue (for example CRTL stages becoming CCM types) through adjacency.
- Inventing a workstream identity solely to break a detected cycle.

## 7. CDI-04 — Milestone Composition Dependency

### Constitutional purpose

Validate lawful **milestone succession and composition within a workstream** — so MS002 / MS003 successors remain reconstructably related to MS001 (and peers) without inventing amendment paths or circular milestone authorship.

### Constitutional scope

Milestone specification identities (models, objectives, types/stages, boundaries, explainability, completion) and published predecessor / successor / composition declarations. Does **not** reorder milestones for delivery convenience or treat completion as a soft amendment of meaning.

### Constitutional inputs

- Milestone corpus identities within a workstream.
- Published predecessor / succession / composition statements.
- Published CDIO-01 / CDIO-04 expectations.

### Constitutional outputs

- Milestone-composition dependency finding under CDI-04.
- Predecessor → successor orientation notes.
- Refusal notes when succession would reverse meaning authority.

### Validation rules (category-specific)

- Successors may specialise coordination / completion of published meaning; they may not rewrite the predecessor’s constitutional meaning via dependency.
- Completion models confirm fulfilment; they never become the meaning model they complete.
- Lifecycle models organise activity; they never invent types owned by the meaning / catalogue milestone.
- Circular MS1 ⇄ MS2 “each defines the other” authorship is a defect.

### Permitted relationships

- MS002 lifecycle corpora subordinate to MS001 meaning / catalogue corpora as published.
- MS003 completion corpora subordinate to MS001 / MS002 as published.
- Objectives / boundaries / explainability documents subordinate to their milestone Model overview.

### Prohibited relationships

- MS003 completion amending MS001 catalogue meaning so closure can pass.
- MS002 lifecycle inventing types outside the MS001 catalogue under dependency pretext.
- Treating delivery ticket order as constitutional milestone succession.

## 8. CDI-05 — Cross-Horizon Consumption Dependency

### Constitutional purpose

Validate lawful **consumption of published law across horizons** — so a consumer may use superior / sibling published artefacts as inputs without becoming their author or reversing authority.

### Constitutional scope

Declared consumption relationships (for example certification lifecycle *consumes* completed compliance; explainability lifecycle *consumes* audit records; dependency integrity *consumes* corpus identities). Does **not** grant mutation, reinterpretation, or ownership transfer rights.

### Constitutional inputs

- Consumer corpus identity and consumed corpus identity.
- Published consumption / non-authorship statements.
- Published CDIO-02 / CDIO-03 / CDIO-04 expectations.

### Constitutional outputs

- Consumption-dependency finding under CDI-05.
- Consumer / consumed orientation with non-authorship confirmation.
- Escalation when consumption is claimed without published right.

### Validation rules (category-specific)

- Consumption is lawful only when published (or clearly implied by published stack posture without inventing rights).
- Consumer may not re-determine, rewrite, or soft-amend the consumed artefact’s meaning.
- “We cite it, therefore we own it” is a defect.
- Cross-horizon consumption must still satisfy CDIR-01…CDIR-04.

### Permitted relationships

- Programme IX certification lifecycle consumes completed compliance activities without re-determining CCM.
- Programme X explainability consumes completed audit records without re-auditing.
- Programme XI dependency integrity consumes Programme VI–X identities as assessment subjects without amending them.
- Programme IX CT lineage may be consumed as supporting reconstruction evidence without replacing CDI validation.

### Prohibited relationships

- Consuming a superior corpus as if the consumer authored it.
- Using consumption edges to create circular authority between producer and consumer.
- Treating Twin / Adaptive / UI / CI outputs as constitutional producers consumed as law.

## 9. CDI-06 — Cycle & Direction Integrity

### Constitutional purpose

**Detect circular dependencies** and **validate dependency direction** across any combination of programme, workstream, and milestone edges — so acyclicity and orientation remain constitutional first-class concerns rather than scanner afterthoughts.

### Constitutional scope

Named dependency edges under assessment in any CDI-01…CDI-05 scope. Does **not** rewrite edges to eliminate cycles; it reports them.

### Constitutional inputs

- Named corpus identities and declared / assessed edges.
- Declared orientation (superior → subordinate / consumer) where published.
- Published CDIO-01 / CDIO-06 expectations.

### Constitutional outputs

- Cycle detection status: none detected / cycle detected / inconclusive (deferred / escalated).
- Direction status: lawful / inverted / undeclared (defect when material).
- Dependency integrity finding under CDI-06 (often composed with CDI-01…CDI-05).

### Validation rules (category-specific)

- Apply CDIR-01 and CDIR-03 explicitly for every material multi-edge assessment.
- A cycle among peers that does not invert authority still requires published peer-composition justification (CDIR-09); otherwise escalate / violate.
- Undeclared direction on a material edge is a defect — do not invent orientation to force intact status.
- CDI-06 never “fixes” a cycle by deleting or reversing edges in situ.

### Permitted relationships

- Report a cycle between a completion model and a meaning model that each claim to define the other.
- Confirm lawful one-way consumption from compliance completion → certification lifecycle.
- Compose with CDI-02 / CDI-03 / CDI-04 when layer or milestone paths are implicated.

### Prohibited relationships

- Quietly reverse an edge to break a cycle under assessment pretext.
- Declare “temporary cycles allowed for demos.”
- Treat package-manager cycles or code-import cycles as automatic constitutional cycles — or as automatic proof of constitutional integrity — without mapping to published corpus identities.

## 10. CDI-07 — Assessment Integrity Dependency

### Constitutional purpose

Preserve **reconstructable records of dependency integrity assessments** — so findings, authority chains, cycle statuses, and boundary confirmations remain auditable without becoming new constitutional law.

### Constitutional scope

Dependency integrity assessment records and their links to assessed corpus identities / edges / CDI categories. Does **not** replace Programme IX CT-07 assessment traceability for conformance findings; compose when both apply.

### Constitutional inputs

- Assessment record identities.
- Related CDI-01…CDI-06 findings and corpus / edge identities.
- Published CDIO-05 / CDIO-06 expectations.

### Constitutional outputs

- Assessment-integrity record under CDI-07.
- Reconstructable bundle: dependency assessed, authority chain, cycle status, findings, boundaries.
- Continuity-preserving archival note (EIP-005).

### Validation rules (category-specific)

- Every material assessment must leave a CDI-07-capable record when findings are treated as established.
- Records cite CDI categories and corpus paths; ticket-only or CI-log-only records are defective as constitutional proof.
- Assessment records never amend the assessed corpora.

### Permitted relationships

- Link a violated finding to the named cycle path and authority-chain break.
- Preserve deferred / escalated dispositions with incomplete-identity notes.
- Compose with Programme IX CT records when implementation artefacts are also in scope — without conflating CT and CDI meanings.

### Prohibited relationships

- Treating assessment records as constitutional amendments.
- Erasing prior lawful dependency findings to simplify a release narrative.
- Presenting scanner logs without corpus identities as CDI-07 fulfilment.

| Assessment → record | CDI-07 | Reconstructable findings preserved | Record-as-law or erased history |

## 12. Closing Statement

> **Only CDI-01…CDI-07 may classify constitutional dependency integrity.  
> Validation rules constrain direction, authority chains, acyclicity, and layering — they never invent edges, rewrite law, or mint constitutional authority.  
> Intact means the published corpus remains lawfully related — not that learning occurred, code shipped, or a scanner was green.**
