## 1. Purpose

Assessment that silently becomes a second constitution — rewriting edges so graphs look acyclic, inventing authority chains in “findings,” elevating Programme XI into an authorship layer, or treating a preferred documentation topology as the new standard — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional dependency integrity** (Programme XI / WS1 / MS001) and **constitutional authorship / educational judgement / dependency mutation** (Constitution / EIP / Programmes VI–X / permitted writers).

---

## 2. Boundary Principles

1. **Validate, do not legislate.** Dependency integrity measures relationship integrity; it does not create law.
2. **Published relationships only.** Unpublished customs and “main as graph” are hard stops as standards.
3. **Published dependency categories only.** Unpublished CDI customs are unlawful.
4. **Named corpus identities only.** Assessments without identifiable constitutional subjects are theatre.
5. **Exactly as published.** Successful intact status never rewrites specification meaning or edge orientation.
6. **Authority first.** Published corpora remain the sole constitutional standard.
7. **No dependency mutation.** Findings never create, delete, reverse, or soft-amend constitutional relationships.
8. **No new authority.** Programme XI never becomes foundational law by validating others.
9. **No reinterpretation.** Programme VI–X meanings and EIP claim classes survive assessment intact.
10. **Acyclicity honesty.** Cycles that confuse authority are reported, not “fixed” in situ.
11. **Layering honesty.** Lower horizons never absorb superior authority via dependency prose.
12. **Intact ≠ quality.** Dependency integrity never grades learning, mastery, readiness, or product success.
13. **Implementation independence.** No stack, vendor, or scanner becomes law by proximity.
14. **No bypass.** Product urgency never waives constitutional dependency integrity requirements.
15. **Repeatability.** Race-dependent dispositions are a defect.
16. **Explain the stop.** Students, developers, and auditors should hear when assessment must refuse intact status.
17. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power via findings.

## 3. What Dependency Integrity May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Analyse dependencies** | Inspect published corpus identities and declared / lawfully implied relationships under CDI-01…CDI-07 |
| **Validate direction** | Confirm superior → subordinate / consumer orientation under CDIR-01 |
| **Validate authority traceability** | Confirm reconstructable authority chains under CDIR-02 |
| **Detect circular dependencies** | Apply CDIR-03 / CDI-06 and report cycle status |
| **Preserve constitutional layering** | Confirm Constitution / EIP → VI–X → XI order under CDIR-04 / CDI-02…CDI-04 |
| **Report dependency findings** | Emit intact / violated / deferred / escalated under published criteria |
| **Identify integrity violations** | Name broken direction, missing authority chains, cycles, or layer inversions |
| **Preserve audit records** | Keep reconstructable trails under CDI-07 |
| **Refuse unlawful intact claims** | Prefer honest violated / deferred / escalated over improvisation |
| **Compose required categories** | Apply published CDI conjunctions without collapsing failed checks |
| **Remain repeatable and neutral** | Same published inputs → same disposition; no stack privilege |
| **Explain dependency integrity** | Answer dependency / authority chain / cycles / findings / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when published relationships themselves must change |

These actions **validate relationship integrity**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CDI types, amend programme law, rewrite edges, or judge educational quality.

## 4. What Dependency Integrity Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Alter constitutional relationships** | Only corpus governance may change published dependencies | Leave edges unchanged; report violations; propose amendment upstream |
| **Establish new authority** | Findings are not legislation; Programme XI is not foundational law | Cite published authority only; refuse unpublished standards |
| **Create constitutional law** | Dependency integrity is validation, not authorship | Cite published law only |
| **Redefine constitutional meaning** | Meaning owners own claim classes and warrants | Confirm published meaning; never rewrite it in findings |
| **Reinterpret constitutional law** | EIP and programme owners own interpretation boundaries | Obey published law; do not reinterpret under graph pretext |
| **Amend constitutional specifications** | Soft-amendment via findings destroys integrity | Leave specs unchanged; mark violated / deferred / escalated |
| **Modify constitutional dependencies** | Validation must not rewrite the graph it assesses | Report; never create / delete / reverse edges in situ |
| **Substitute constitutional authority** | Published corpora remain the standard after any finding | Keep assessed corpora as subjects, never as next-cycle law |
| **Bypass dependency integrity requirements** | Requirements are educational care, not optional polish | Prefer understatement / violated over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Evaluate corpus relationships, not Flask / npm / scanner fashion |
| **Determine educational quality** | No CDI is a quality rubric | Keep integrity speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in graph machinery |
| **Replace Programme IX CT / CC / CV / CCM / CRT** | Distinct governance horizons | Compose; do not conflate or absorb |
| **Replace Programme X execution / decision / audit / explainability** | Distinct activity horizons | Validate dependencies; never execute those activities |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via findings |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Evaluate against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface integrity findings, not new tips |
| **Treat Twin / Adaptive / UI / CI / package graphs as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scanner greens / import acyclicity / coverage as constitutional integrity** | Operational proxies are not dependency law | Cite published corpora and CDI types |
| **Become irreplaceable by assessment topology** | Replaceability | Keep dependency law implementation-independent |

## 6. Boundary Checks (Pre-Finding)

Before material constitutional dependency integrity is treated as established, assessment requires affirmative answers:

| Check | Question |
|-------|----------|
| **CDIB-01 Corpus identity** | Are assessed subjects published Constitution / EIP / Programme VI–X (and lawful XI) corpus identities (not unpublished customs)? |
| **CDIB-02 Dependency class** | Are required CDI-01…CDI-07 categories being applied (not unpublished customs)? |
| **CDIB-03 Edge identity** | Which named dependency relationships are under assessment? |
| **CDIB-04 Direction** | Is lawful superior → subordinate / consumer orientation confirmed or honestly reported missing / inverted? |
| **CDIB-05 Authority chain** | Is a reconstructable authority chain to Constitution / EIP present? |
| **CDIB-06 Acyclicity** | Has cycle detection been applied; are authority-confusing cycles absent or honestly reported? |
| **CDIB-07 Layering** | Does the assessment preserve published programme / workstream / milestone layering? |
| **CDIB-08 Non-legislation** | Does the assessment avoid creating constitutional authority or amending specifications? |
| **CDIB-09 Non-mutation** | Does the assessment avoid altering, inventing, reversing, or deleting constitutional relationships? |
| **CDIB-10 Non-reinterpretation** | Does the assessment avoid redefining Programme VI–X / EIP meaning? |
| **CDIB-11 Non-substitution** | Does the assessment avoid treating Programme XI findings or any assessed corpus as the next constitutional standard? |
| **CDIB-12 Neutrality** | Does the assessment avoid privileging a language, framework, protocol, scanner, or CI vendor as law? |
| **CDIB-13 Intact ≠ quality** | Is the outcome framed as corpus relationship integrity — not educational quality / truth / student readiness? |
| **CDIB-14 Spec / edge immutability** | Are constitutional corpora and published dependencies left unchanged by the assessment act? |
| **CDIB-15 Repeatability / audit** | Is disposition reproducible; will CDI-07 / explainability records preserve dependency, authority chain, cycles, findings, and boundaries? |

Any failed check → violated / deferred / escalated. Do not “best-effort” invent dependency law, reverse edges, or soft-amend specifications in situ.
