## 1. Purpose

A lifecycle that silently becomes a second constitution — inventing completed assurance so stages “complete,” inventing certification gaps out of existence in “findings,” licensing a preferred deployment topology under a published badge, inventing dimensions to force CXCL-06, treating a preferred implementation as the new standard, mutating corpora mid-lifecycle, executing Runtime A under a certification seal, collapsing into Programme IX CRT, or freezing a stack as law — destroys student trust and educational integrity.

This document draws a bright line between **lawful constitutional certification lifecycle coordination** (Programme XI / WS7 / MS002) and **constitutional authorship / educational judgement / artefact mutation / authority creation / meaning reinterpretation / specification amendment / runtime execution** (Constitution / EIP / Programmes VI–X / WS1–WS6 / WS7 / MS001 / permitted writers / Programme VIII runtime owners / Programme IX CRT owners).

## 2. Boundary Principles

1. **Coordinate, do not legislate.** The lifecycle organises certification assessment; it does not create law.
2. **Published specifications only.** Unpublished customs and “main as certified” are hard stops as standards.
3. **Published stages only.** Unpublished CXCL customs are unlawful.
4. **Published certification dimensions only.** Stages apply CXCD-01…CXCD-05 only.
5. **Completed assurance only.** Lifecycles without identifiable completed WS1–WS6 assurance / readiness (or honest gaps) are theatre.
6. **Exactly as published.** Successful progress never rewrites specification meaning or assurance outcomes.
7. **Authority first.** Published corpora remain the sole constitutional standard.
8. **Implementation independence.** No stack, vendor, or reference implementation becomes law by proximity to publication.
9. **Published ≠ quality.** Lifecycle publication never grades learning, mastery, student exam readiness, or product success.
10. **Published ≠ executed runtime.** The lifecycle never runs Runtime A so findings look proven.
11. **Published ≠ rewritten artefacts.** The lifecycle never mutates constitutional artefacts so findings look certified.
12. **Published ≠ new authority.** The lifecycle never elevates Programme XI into foundational law by coordinating others.
13. **Published ≠ Programme IX CRT.** Corpus certification lifecycle never substitutes for implementation certification.
14. **No reinterpretation.** Programme VI–X meanings, EIP claim classes, WS1–WS6 assurance / readiness meaning, and CXCD criteria survive coordination intact.
15. **No authority substitution.** A published finding never replaces the corpus for the next judgement.
16. **No artefact mutation.** Coordination never creates, deletes, soft-amends, or rewrites constitutional artefacts.
17. **No bypass.** Product urgency never waives constitutional lifecycle requirements.
18. **Repeatability / consistency.** Race-dependent or private stage shortcuts are defects.
19. **Explain the stop.** Students, developers, and auditors should hear when the lifecycle must refuse progress or publication.
20. **No emergency exemption.** Deadlines and demos never mint constitutional amendment power or authority creation via lifecycle publication.
21. **Assurance honesty.** Unfinished WS1–WS6 assurance or unreadiness is reported as gaps, not “fixed” in situ by inventing completion.
22. **Non-execution.** Certification coordination never becomes runtime behaviour.

## 3. What the Lifecycle May Do (Lawful)

| Lawful action | Constitutional meaning |
|---------------|------------------------|
| **Coordinate certification assessments** | Organise activities through CXCL-01…CXCL-07 |
| **Evaluate certification evidence** | Gather and consume identifiable WS1–WS6 completion / readiness outcomes at CXCL-02 |
| **Validate certification prerequisites** | Confirm completeness and published preconditions at CXCL-03 |
| **Evaluate certification dimensions** | Apply published CXCD-01…CXCD-04 under MS001 rules at CXCL-04 |
| **Determine certification status** | Aggregate under CXCD-05 at CXCL-05 |
| **Identify certification gaps** | Name missing / incomplete assurance, readiness shortfalls, dimension shortfalls, and coherence defects |
| **Construct certification findings** | Emit certified / not-certified / deferred / escalated under published criteria |
| **Publish certification findings** | Communicate findings, decisions, and records under published honesty rules |
| **Consume constitutional specifications** | Use published Constitution / EIP / Programme VI–X corpora as assessment standards |
| **Preserve established traceability in records** | Carry established CT-01…CT-07 relationships into assessment records; never invent them |
| **Apply certification dimensions** | Across stages, apply published CXCD-01…CXCD-05 only |
| **Refuse unlawful progress** | Prefer honest refuse / defer / escalate / not-certified over improvisation |
| **Remain repeatable and consistent** | Same published inputs → same stage outcomes and dispositions |
| **Remain implementation-neutral** | Honour lifecycle law across lawful equivalent stacks |
| **Support certification honesty** | Strengthen corpus-certification honesty without becoming educational readiness, Programme IX CRT, or constitutional authority |
| **Explain lifecycle progress** | Answer workstreams / readiness / dimensions / status / evidence / boundaries without rewriting meaning |
| **Propose corpus amendments upstream** | Recommend (not enact) amendments when law itself must change |

These actions **coordinate certification assessment**. They do **not** publish a new Constitution, invent coach warrants, mint tips, author ownership maps, invent CXCD or CXCL types, invent CT links, author runtime behaviour, judge educational quality, create constitutional authority, redefine meaning, amend specifications, modify artefacts, issue Programme IX CRT seals, or execute Runtime A under coordination pretext.

## 4. What the Lifecycle Must NEVER Do

| Forbidden action | Why | Lawful alternative |
|------------------|-----|--------------------|
| **Create constitutional authority** | Published corpora alone own constitutional meaning | Cite published law only; refuse unpublished standards; never elevate lifecycle progress into authority |
| **Modify constitutional artefacts** | Artefacts are published corpus facts, not lifecycle outputs | Report certification as found; refuse mutation theatre |
| **Redefine constitutional meaning** | Programme VI–X and EIP own meaning | Assess against published meaning; never redefine it |
| **Execute runtime behaviour** | Programme VIII / Runtime A own execution; certification coordinates evaluation only | Report certification status; never run services, adapters, or product behaviour under lifecycle pretence |
| **Amend constitutional specifications** | Only corpus governance may amend law | Leave specs unchanged; propose amendment upstream or mark not-certified / refuse |
| **Implement Runtime A** | Runtime A is an assessed subject, not a lifecycle output | Keep Runtime A replaceable; refuse execution theatre |
| **Invent completed assurance or readiness** | Collection organises published completion | Refuse-collect when assurance or readiness is missing or unfinished |
| **Invent certification dimensions** | CXCD catalogue is closed under WS7 / MS001 | Apply CXCD-01…CXCD-05 only |
| **Invent lifecycle stages** | CXCL catalogue is closed under this corpus | Apply CXCL-01…CXCL-07 only |
| **Re-author WS1–WS6 findings** | WS1–WS6 own integrity / readiness assessments | Consume completed outcomes; refuse re-authorship |
| **Skip unfinished prerequisites** | Completeness honesty | Record gaps; refuse-validate / not-certified |
| **Invent traceability** | CT owns lawful lineage | Preserve established relationships in records; refuse invented links |
| **Substitute Programme IX CRT / CRTL** | CRT / CRTL own implementation certification | Keep corpus certification distinct; refuse horizon collapse |
| **Bypass lifecycle requirements** | Requirements are educational care, not optional polish | Prefer understatement / refuse over invented green |
| **Privilege a technology as constitutional** | Implementation neutrality | Coordinate assessment, not Flask / SQLAlchemy / REST / OpenAPI fashion |
| **Determine educational quality** | No CXCL stage is a quality rubric | Keep coordination speech distinct from quality speech |
| **Determine constitutional truth** | Constitution / EIP own truth | Obey published law; do not adjudicate truth in lifecycle machinery |
| **Transfer authority** | Programme VII WS2 owns ownership, permission, and conflict disposition | Apply Authority corpora; refuse domain absorption via stages |
| **Invent educational state** | Programme VII WS4 owns EST/CST context law | Assess against published postures only |
| **Generate unpublished recommendations** | Programme VII WS3 + Programme VI owners own tip warrant | Surface certification findings, not new tips |
| **Treat Twin / Adaptive / UI / CI / gates as constitutional producers** | They are subjects / delivery surfaces | Require published corpus mapping or refuse |
| **Present scores / coverage / acks / gate greens as constitutional certification or publication** | Operational proxies are not lifecycle law | Cite published corpora, CXCD types, and CXCL stages |
| **Become irreplaceable by coordination topology** | Replaceability | Keep lifecycle law implementation-independent |
| **Freeze stack authority via publication** | Neutrality / authority preservation | Publish findings; never make the stack the next standard |
| **Replace MS001 certification meaning** | CXC / CXCD own evaluation meaning | Sequence assessments; never rewrite CXCD criteria |
| **Replace Programme IX CT** | CT owns lineage | Compose with CT; never treat “linked” as “certified forever” |
| **Replace Programme VIII runtime law** | Programme VIII owns how software may execute law | Evaluate corpus certification assessment sequencing; never execute |

## 6. Boundary Checks (CXCLB)

Material lifecycles must be able to affirm the following checks (or name the hard stop):

| ID | Check |
|----|-------|
| **CXCLB-01** | Assessment organised only through CXCL-01…CXCL-07 |
| **CXCLB-02** | Only published CXCD-01…CXCD-05 applied |
| **CXCLB-03** | Completed WS1–WS6 assurance / readiness gathered or honest gaps recorded |
| **CXCLB-04** | Prerequisites validated without inventing completion |
| **CXCLB-05** | No constitutional authority created by lifecycle progress |
| **CXCLB-06** | Constitutional artefacts unchanged by coordination |
| **CXCLB-07** | Constitutional meaning not redefined by stages or findings |
| **CXCLB-08** | No runtime behaviour executed under lifecycle pretence |
| **CXCLB-09** | Runtime A not implemented under lifecycle pretence |
| **CXCLB-10** | Constitutional specifications not amended by publication |
| **CXCLB-11** | Implementation neutrality preserved |
| **CXCLB-12** | No stack / vendor frozen as law via certified / published |
| **CXCLB-13** | Educational quality / mastery / student exam readiness not adjudicated |
| **CXCLB-14** | WS1–WS6 findings not re-authored |
| **CXCLB-15** | Programme IX CRT / CRTL not substituted for corpus certification |
| **CXCLB-16** | CT lineage not invented; established CT preserved in records only |
| **CXCLB-17** | Certification gaps disclosed when material |
| **CXCLB-18** | Repeatable outcomes under same published inputs |
| **CXCLB-19** | Explainability questions answerable before student / developer / auditor narration |

Failure of any material check is a boundary defect — prefer refuse-progress / not-certified / refuse-publish over improvisation.
