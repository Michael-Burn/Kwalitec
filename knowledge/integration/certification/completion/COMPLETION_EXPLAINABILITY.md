## 1. Purpose

An expert IFoA tutor who cannot say *which assurance workstreams* were considered — whether runtime readiness was confirmed, which certification dimensions were satisfied, what certification status was determined, and which evidence supported the certification decision — is not closing honestly; they are performing.

After Programmes VI–X have made meaning, ownership, tips, context, contracts, evidence, governance, and execution speech speakable, after WS1–WS6 have made integrity and readiness speech speakable, and after WS7 / MS001–MS002 have made certification and lifecycle speech speakable, Programme XI still needs one certification-assessment-completion-speech answer:

> **“Which assurance workstreams were considered, was runtime readiness confirmed, which certification dimensions were satisfied, what certification status was determined, and which evidence supported the certification decision?”**

That answer must cover every material affirmed (or refused) completion without inventing educational success, creating constitutional authority, modifying artefacts, executing Runtime A, amending constitutional specifications, transferring authority, minting tips, inventing state, rewriting specifications, performing Programme IX CRT, or freezing a stack as law.

## 2. What Certification Completion Explainability Is

**Constitutional Certification Completion Explainability** is the constitutional obligation to narrate **fulfilment (or lawful refusal of fulfilment) of the required constitutional certification assessment lifecycle** — not to invent a second tutor voice from CI complete badges, and not to grade the student, create constitutional authority, rewrite artefacts, execute Runtime A, or amend constitutional specifications.

| Concept | Definition | Primary question |
|---------|------------|------------------|
| **Assurance workstreams considered** | Named completed WS1–WS5 assurance workstream identities consumed under the assessment | Which assurance workstreams were considered? |
| **Runtime readiness confirmed** | Named WS6 / CRR / CRRD readiness confirmation (or honest gap) for the concern | Was runtime readiness confirmed? |
| **Certification dimensions satisfied** | Named CXCD-01…CXCD-04 dimension outcomes under the concern | Which certification dimensions were satisfied? |
| **Certification status determined** | Named CXCD-05 disposition for the concern | What certification status was determined? |
| **Evidence supporting the decision** | Named completed assurance / readiness / finding identities that supported status determination | Which evidence supported the certification decision? |

Certification Completion Explainability is:

- **fulfilment-centred** — it narrates why CXCC criteria hold (or why close is refused);
- **catalogue-bound** — every justification cites published CXCD / CXCL / CXCC identities where applicable;
- **corpus-bound** — every justification cites published specifications, completed assurance / readiness identities, named dimensions, named status, and named findings / evidence;
- **non-legislative** — explanation never becomes a back door to create authority or amend corpora;
- **non-executing** — explanation never narrates completion as Runtime A warrant or runtime execution;
- **non-mutating** — explanation never narrates completion as artefact rewrite or specification amendment;
- **finding-honest** — explanation never silently upgrades published findings;
- **quality-honest** — complete is never narrated as mastery, exam readiness, or educational quality;
- **horizon-honest** — complete is never narrated as Programme IX CRT / CRTC implementation certification;
- **technology-honest** — explanation never presents a stack preference as constitutional law;
- **audience-aware** — student speech and developer/auditor traces differ in vocabulary, not in truth;
- **layer-honest** — it does not replace Programme VI tip warrant speech, Programme VII ownership / workflow / state speech, EIP-002 evidence meaning speech, Programme VIII contract / evidence / validation speech, Programme IX evaluative speech, Programme X execution speech, WS1–WS6 integrity / readiness speech, MS001 certification speech, or MS002 lifecycle speech;
- **audit-aligned** — explanation components match CXCC reconstruction needs;
- **authority-honest** — explanations must not paper over authority inference or stack canonisation.

Certification Completion Explainability is **not**:

- a rewrite of Constitution / EIP / Programme VI–X / WS1–WS6 / WS7 meaning;
- a quality report on learning, coaching, or exam readiness;
- a constitutional authority instrument or amendment warrant;
- a Runtime A execution warrant or silent artefact-rewrite mechanism;
- a Programme IX CRT / CRTC seal report as constitutional law;
- a substitute for WS7 / MS001 certification explainability or WS7 / MS002 lifecycle explainability (compose with; do not replace);
- a substitute for Programme XI WS1–WS6 completion explainability (compose with; do not collapse);
- a substitute for Programme IX CTC / CVC / CCC / CRTC completion explainability (compose with; do not collapse);
- a rendering system, UI template, CI badge, seal dashboard, or analytics dashboard;
- a claim that clear completion speech guarantees learning, a pass, conformity, Runtime A success, constitutional amendment, or artefact rewrite;
- a licence to present seal badges, lint scores, ticket graphs, or pipeline greens as constitutional proof or educational quality.

## 3. Mandatory Explanation Questions

Every material completion judgement (affirm or refuse close) should answer all five questions:

### CXCCQ-01 — Which assurance workstreams were considered?

Name the primary completed WS1–WS5 assurance workstream identities consumed under the assessment concern — dependency, catalogue, boundary, vocabulary, and/or layer — including which completion outcomes were cited and which required assurance remains missing when refusing close. Never narrate invented unfinished assurance as lawful evaluation subjects. “The corpus was scanned somewhere” is not a constitutional assurance-workstream identity.

### CXCCQ-02 — Was runtime readiness confirmed?

Name the WS6 / CRR / CRRD readiness confirmation outcome for the concern (confirmed / not confirmed / deferred / escalated / gap) — or name why readiness confirmation remains incomplete when refusing close. Never narrate unfinished readiness as confirmed, and never narrate readiness confirmation as Runtime A permission or constitutional amendment. “Looks ready enough” is not a constitutional readiness confirmation.

### CXCCQ-03 — Which certification dimensions were satisfied?

Name the primary CXCD-01…CXCD-04 dimension identities assessed under the concern and their dispositions (satisfied / not satisfied / deferred / escalated / gap) — or name which required dimensions remain unassessed when refusing close. Include lawful shortfalls honestly. Never narrate invented dimensions as assessed subjects, and never narrate silent upgrade of unsatisfied dimensions into satisfied. “Looks certified enough” is not a constitutional certification-dimension identity.

### CXCCQ-04 — What certification status was determined?

Name the CXCD-05 overall certification status for the concern (certified / not-certified / deferred / escalated) and which subordinate dimension outcomes composed it — or name why status determination remains incomplete when refusing close. Never narrate certified while required subordinate dimensions remain unresolved without composition notes. Never narrate certification status as constitutional authority, Runtime A permission, educational success, Programme IX CRT seal, or constitutional amendment. “Looks green enough” is not a constitutional certification-status disposition.

### CXCCQ-05 — Which evidence supported the certification decision?

Name the primary completed assurance / readiness / finding identities that supported the CXCD-05 disposition — including named WS1–WS6 completion outcomes, named CXCD dimension outcomes, and named certification findings — or name which required evidence remains missing when refusing close. Never narrate invented evidence, ticket IDs alone, seal badges, or pipeline greens as constitutional supporting evidence. “Evidence existed somewhere” is not a constitutional evidence identity.

## 6. Forbidden Explanation Patterns

| Pattern | Why forbidden |
|---------|---------------|
| “Complete — therefore constitutional authority created” | Completion is assessment fulfilment, not legislation |
| “Complete — therefore artefacts rewritten” | Artefacts remain published corpus truth |
| “Complete — therefore meaning redefined” | Meaning remains owned by upstream corpora |
| “Complete — therefore Runtime A may execute” | Close never executes or authorises runtime |
| “Complete — therefore specifications amended” | Specs remain unchanged under close |
| “Complete — therefore student exam-ready” | Educational outcomes are orthogonal |
| “Complete — therefore Programme IX CRT sealed” | Horizons must not collapse |
| “Complete because CI / ticket / seal badge was green” | Theatre is not constitutional evidence |
| “Trust the complete badge” without CXCCQ answers | Mute theatre fails explainability |
| Silent upgrade of not-certified into certified in narration | Finding honesty forbids disposition rewrite |
